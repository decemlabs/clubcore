The Phase 8 migration creates GIN trgm expression indexes via raw `op.execute(...)` DDL (Plan 01). These have no counterpart in `Base.metadata` because expressing `lower(col) gin_trgm_ops` reliably in SA `__table_args__` is fragile. To prevent `alembic check` from reporting them as "missing", add an `include_object` filter to env.py.

**Define a top-level helper** in `alembic/env.py` (above `run_migrations_online`):
```python
def _include_object(object_, name: str, type_: str, reflected: bool, compare_to) -> bool:  # type: ignore[no-untyped-def]
    """Skip raw-DDL GIN trigram expression indexes from autogenerate comparison.

    These indexes are created via op.execute() in 0002_clients.py because
    `lower(col) gin_trgm_ops` cannot be reliably expressed in SQLAlchemy
    __table_args__. Excluding them here keeps `alembic check` clean (TEST-08
    supporting; Pitfall 1 from RESEARCH.md).
    """
    if type_ == "index" and name in (
        "ix_clients_last_name_trgm",
        "ix_clients_first_name_trgm",
    ):
        return False
    return True
```
