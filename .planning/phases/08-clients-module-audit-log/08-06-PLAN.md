**`create_client` (CLIENTS-06, D-11, D-08 client_created payload):**
```python
async def create_client(
    session: AsyncSession,
    actor: User,
    data: ClientCreateRequest,
) -> ClientResponse:
    """Create a new client; audit emit + flush co-transactionally (D-03, D-11)."""
    client = await repository.insert_client(session, actor.id, data)
    try:
        await session.flush()
    except IntegrityError as exc:
        await session.rollback()
        constraint = getattr(exc.orig, "constraint_name", None) or ""
        if constraint == "uq_clients_phone_alive" or "uq_clients_phone_alive" in str(exc.orig):
            raise PhoneExistsError("phone_exists") from exc
        raise

    # D-08 client_created payload: minimal PD-safe fields only
    await audit.emit(
        session, "client_created",
        actor_user_id=actor.id,
        resource_type="client",
        resource_id=client.id,
        full_name=_full_name(client),
        phone=client.phone,
        has_email=client.email is not None,
        has_telegram=client.telegram_user_id is not None,
    )
    return ClientResponse.model_validate(client)
```

**Note on emit ordering vs flush:** the comment in CONTEXT.md says emit happens INSIDE the same transaction as the mutation (D-03). For `create_client`, the structural problem is that the IntegrityError surfaces only on flush — so the order is:
1. `repository.insert_client(...)` (session.add)
2. `session.flush()` (triggers DB constraint check; may raise IntegrityError)
3. ON SUCCESS: `await audit.emit(session, "client_created", ...)`
4. **No additional flush needed** — the next caller-side commit (in route exit via `get_db` async context manager) will write both rows.

This deviates slightly from PATTERNS.md sequence "emit BEFORE flush" — for **inserts** it has to be flush-then-emit because we need to confirm the row took before claiming it via audit. For **updates and soft-deletes**, emit BEFORE flush is fine (no new constraint risk).

**`update_client` (CLIENTS-07, D-01, D-08, D-09, D-11):**
```python
async def update_client(
    session: AsyncSession,
    actor: User,
    client_id: UUID,
    data: ClientUpdateRequest,
) -> ClientResponse:
    """Partial update with PATCH semantics (D-01); skip emit on no-op (D-09)."""
    client = await repository.get_alive(session, client_id)
    if client is None:
        raise ClientNotFoundError("client_not_found")

    changed_previous = await repository.update_client(session, client, data)

    if not changed_previous:
        # D-09: no fields changed → skip audit emit, skip flush, return current state
        return ClientResponse.model_validate(client)

    # Try to flush early to surface phone-conflict before emitting audit (D-11)
    try:
        await session.flush()
    except IntegrityError as exc:
        await session.rollback()
        constraint = getattr(exc.orig, "constraint_name", None) or ""
        if constraint == "uq_clients_phone_alive" or "uq_clients_phone_alive" in str(exc.orig):
            raise PhoneExistsError("phone_exists") from exc
        raise

    # D-08 payload: changed_fields list + previous_phone (only when phone changed)
    payload: dict[str, object] = {"changed_fields": sorted(changed_previous.keys())}
    if "phone" in changed_previous:
        payload["previous_phone"] = changed_previous["phone"]

    await audit.emit(
        session, "client_updated",
        actor_user_id=actor.id,
        resource_type="client",
        resource_id=client.id,
        **payload,
    )
    return ClientResponse.model_validate(client)
```

**`soft_delete_client` (CLIENTS-08, D-08):**
```python
async def soft_delete_client(
    session: AsyncSession,
    actor: User,
    client_id: UUID,
) -> None:
    """Soft-delete; owner-only is enforced at router via require_permission (CLIENTS-08)."""
    client = await repository.get_alive(session, client_id)
    if client is None:
        raise ClientNotFoundError("client_not_found")

    captured_full_name = _full_name(client)
    captured_phone = client.phone

    await repository.soft_delete_client(session, client)

    # Emit BEFORE flush — no new constraint risk on soft-delete (just sets deleted_at)
    await audit.emit(
        session, "client_soft_deleted",
        actor_user_id=actor.id,
        resource_type="client",
        resource_id=client.id,
        full_name=captured_full_name,
        phone=captured_phone,
    )
    await session.flush()
```

**Critical compliance notes:**
- D-09: `if not changed_previous: return` — explicit no-op; do NOT call audit.emit and do NOT call session.flush.
- D-08 client_created: `{full_name, phone, has_email, has_telegram}` — no notes/birthday/emergency_contact (PII protection).
- D-08 client_updated: `{changed_fields, previous_phone?}` — `previous_phone` ONLY when phone changed.
- D-08 client_soft_deleted: `{full_name, phone}` — captured BEFORE soft-delete sets deleted_at.
- All three mutation functions take `actor: User` second positional arg per D-19; `actor.id` becomes `created_by_user_id` (insert) and `actor_user_id` (audit).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| router→service | Router has already gated RBAC + CSRF; service trusts `actor: User` is authorised for the action. Service does NOT re-check role. |
| service→DB | Service relies on DB-level partial unique index for phone uniqueness. Race-safe — can't be bypassed by app-level pre-check. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-30 | Tampering | Phone uniqueness race (two clients with same phone created concurrently) | mitigate | DB partial unique index + IntegrityError catch in `create_client`. SA wraps asyncpg's `UniqueViolationError`; service detects via `e.orig.constraint_name` substring match. |
| T-08-31 | Information Disclosure | Audit payload leaks PII (notes, birthday, emergency_contact) | mitigate | D-08 fixed payload shape: only `full_name`, `phone`, `has_email`, `has_telegram` for client_created; only `changed_fields` + optional `previous_phone` for client_updated. Implementation copies fields explicitly — no full state dump. |
| T-08-32 | Repudiation | client_updated emit lost when no-op detected | accept | D-09 explicitly: no-op PATCH does not emit. Trade-off: we lose "user touched the client" trace but gain noise reduction. v1.2 may add `client_touched` event if needed. |
| T-08-33 | Repudiation | client_soft_deleted payload empty after soft-delete (deleted_at set) | mitigate | `_full_name(client)` and `client.phone` captured into local variables BEFORE `repository.soft_delete_client(session, client)` runs. Both values are passed to audit.emit verbatim. |
| T-08-34 | Elevation of Privilege | service called with wrong actor (impersonation) | accept | Service trusts router's `Depends(require_permission(...))` to populate `actor: User` with the authenticated session's user. Cross-actor impersonation requires forging an auth cookie, mitigated upstream by Phase 4/5 cookie security. |
| T-08-35 | Tampering | update_client returns success without flush (no-op edge case) | accept | D-09 deliberately skips flush on no-op. Updated_at column has `onupdate=func.now()` but no actual UPDATE statement is issued because no field changed (SA dirty-tracking). Acceptable. |
| T-08-36 | Information Disclosure | get_client returns 404 vs 403 for soft-deleted clients viewable to reception | accept | RBAC-04: 404 vs 403 must not leak existence; for VIEW resource the user has permission, so 404 (deleted_at IS NULL not satisfied) is the correct response. Reception has VIEW for clients, so distinction does not arise. |
