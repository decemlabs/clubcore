**Critical ordering (RBAC-04):** `Depends(require_permission(...))` MUST come BEFORE `Depends(verify_csrf)` in the dependency list so that 401 fires before 403, and 403 (forbidden) fires before CSRF check (which would otherwise leak that the user is at least authenticated). FastAPI executes dependencies left-to-right by signature order; the order in each endpoint above is `actor → _csrf → session`. Phase 6 D-22/D-24 already enforced this in auth/logout.

**Note on `ClientListQuery` as Query string:**
- `Annotated[ClientListQuery, Depends()]` — FastAPI binds query-string parameters into the Pydantic model.
- camelCase wire input names (`pageSize`, `createdFrom`, `hasTelegram`) map to snake_case fields via `populate_by_name=True` and `alias_generator=to_camel`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP→FastAPI router | First gate: parse + validate Pydantic body/query. Second gate: `require_permission` (RBAC). Third gate: `verify_csrf` for mutations. Service is invoked only after all three gates pass. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-37 | Spoofing | Unauthenticated user accesses /clients | mitigate | `require_permission` runs `get_current_user` first → 401 if no valid `sz_access` cookie. Phase 4/5 cookie security applies. |
| T-08-38 | Elevation of Privilege | Reception role calls DELETE /clients/{id} | mitigate | `require_permission(Action.DELETE, Resource.CLIENTS)` checks `OWNER_ONLY` set; reception → 403 forbidden. Backed by Phase 6 RBAC-05 + parity test (TEST-06). |
| T-08-39 | Tampering | CSRF attack on POST/PATCH/DELETE from cross-origin | mitigate | `Depends(verify_csrf)` validates `X-CSRF-Token` header against `sportzal_csrf` cookie. Phase 6 CSRF-02. |
| T-08-40 | Information Disclosure | 403 vs 404 leaks existence of soft-deleted clients | accept | Reception has VIEW permission on CLIENTS → can fetch any alive client. Soft-deleted → 404 from service layer (CLIENTS-05). No 403/404 ambiguity for users with VIEW permission. RBAC-04 invariant holds. |
| T-08-41 | DoS | Unbounded list query via page_size manipulation | mitigate | `PageQuery.page_size: Field(default=20, ge=1, le=100)` (Phase 4). Pydantic rejects page_size > 100 with 422. |
| T-08-42 | Tampering | Query string filter injection (e.g., createdFrom=' OR 1=1) | mitigate | Pydantic field types (`datetime`, `Gender`, `bool`) reject non-conforming strings with 422 before reaching SQL. SA Core parameter binding in repository. |
| T-08-43 | Information Disclosure | OpenAPI docs publish operator-only endpoints | accept | OpenAPI is internal — Phase 9 ships `/openapi.json` which lists all routes including admin ones. Admin-only endpoints are protected by `require_permission` at runtime; OpenAPI publication is informational. Future hardening: hide owner-only routes from public schema (v1.2). |
</threat_model>
