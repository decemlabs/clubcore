**`apps/backend/app/workers/arq_app.py`** — real WorkerSettings (per WORK-01 + CONTEXT.md Discretion):

```python
"""ARQ worker settings entry point.

Run with `arq app.workers.arq_app.WorkerSettings` (in a future phase, once tasks land).
Phase A: empty `functions` list — defining the WorkerSettings shape now stabilizes
the import path so future tasks plug in without restructuring.
"""
from typing import Any

from arq.connections import RedisSettings

from app.core.config import get_settings


class WorkerSettings:
    """ARQ WorkerSettings skeleton (WORK-01).

    Future: add task functions to `functions`, configure cron jobs via `cron_jobs`,
    add `on_startup` / `on_shutdown` hooks. Phase A keeps it minimal.
    """

    functions: list[Any] = []
    # TODO Phase B+: register real task functions here, e.g.
    # functions = [tasks.notifications.send_telegram, tasks.reminders.send_visit_reminder]
    redis_settings = RedisSettings.from_dsn(str(get_settings().redis_url))
```

The `from typing import Any` + `list[Any]` annotation is required for mypy strict (RESEARCH.md line 1049 — bare `list` is forbidden).

`RedisSettings.from_dsn(str(...))` — the `str()` cast is required because `RedisDsn` is a pydantic v2 type, not a plain string. The cast is verified safe because Settings.redis_url is validated at instantiation time.

`get_settings()` is called at MODULE IMPORT time — this means `app.workers.arq_app` cannot be imported without REDIS_URL being set in the environment (or via .env). This is intentional: the ARQ worker process needs Redis to run anyway, and failing fast at import surfaces config errors early. Plan 08's verification can either set REDIS_URL or skip importing this module in mypy/ruff smoke (those tools don't execute the module body).
