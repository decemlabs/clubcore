**RESET-06 contract surface (REQUIREMENTS.md):**

`POST /api/v1/auth/password-reset/request {email: str}` must return — for ALL 4 cases below — identical HTTP 202, identical response body, and timing differences ≤ 100ms:

1. **existing-active** — user with `is_active=True, deleted_at IS NULL`.
2. **existing-deactivated** — user with `is_active=False`.
3. **owner-account** — user with `role='owner'`.
4. **non-existent** — email that has never appeared in `users`.

Plus: in cases 1 and 2, an `audit_log` row with `event='password_reset_requested'` is emitted with the resolved `target_user_id`; in case 3 same as 1; in case 4, the row is emitted with `target_user_id=None` (D-41-10 system-emit + RESET-01 anti-oracle requires audit in BOTH branches).

- Real Postgres via SAVEPOINT per-test isolation (existing pytest fixture in this codebase — `db_session` async fixture wraps test in a SAVEPOINT and rollbacks on exit).

- 4 fixture users seeded per-test (NOT module-scoped — deterministic isolation).
- Timing assertion: `time.perf_counter()` deltas; bounded equality at 100ms tolerance — `max(timings) - min(timings) < 0.100`.
