## Accomplishments

- All 11 v1.6 (event, resource_type) keys locked in Plan 41-01 now resolve to a matching Pydantic-v2 `BaseModel` subclass via `AUDIT_PAYLOAD_SCHEMAS.get((event, resource_type))` — the `audit.emit()` payload-validation lookup at `audit.py:286-288` will hard-fail on unknown kwargs / missing required kwargs for every v1.6 event when Phases 42/43/44/45 ship.
- Every new payload carries `audit_correlation_id: UUID | None` (D-41-20) — the async email-event chain (e.g. `password_reset_requested` → `email_sent`) is reconstructible from `audit_log` alone via shared UUID. Caller-supplied; chain-starters pass None.
- Anti-oracle field shape on `PasswordResetRequestedPayload` — `target_user_id: UUID | None` supports BOTH branches of RESET-01 without needing a separate event name; the unknown-email branch passes None while `email_hint` preserves the forensic chain (D-41-10 system-emit pattern).
- `extra='forbid'` enforced on every new payload — unknown kwargs raise `pydantic.ValidationError` at the audit boundary (Phase 30 D-30-03 hard-fail discipline carried verbatim). Two `Literal[...]` discriminator fields (`EmailSendFailedPayload.reason`, `PaymentReceiptEmailedPayload.receipt_kind`) add a second layer of finite-vocabulary enforcement.
- New anti-drift gate test `test_v16_pairs_all_have_payload_schemas` cross-checks every v1.6 pair against BOTH `LOCKED_AUDIT_EVENTS` and `AUDIT_PAYLOAD_SCHEMAS` — first such two-registry consistency test; future milestones can mirror this shape verbatim.
- UUID-from-str coercion preserved (REG-36-03) — `str(uuid)` at the callsite is accepted by every UUID field; verified by `test_v16_payloads_accept_uuid_as_str`.
