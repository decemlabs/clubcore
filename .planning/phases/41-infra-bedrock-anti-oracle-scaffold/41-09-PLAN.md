<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Token URL fragment / email body → DB lookup | Raw token never stored — sha256 hash only (token_hash column); compare via constant-time at Phase 44 callsite. |
| Phase 44 confirm endpoint → atomic-consume | `UPDATE ... WHERE consumed_at IS NULL RETURNING` is single-statement race-safe; replay → 0 rows updated → 410 Gone. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-09-01 | Information disclosure | Raw reset token recoverable from DB compromise | mitigate | `token_hash` is sha256(raw_token); raw token never written. Recovery from hash is computationally infeasible. |
| T-41-09-02 | Tampering | Token replay (multiple confirms with same token) | mitigate | Atomic UPDATE … RETURNING via partial-UNIQUE (user_id, purpose) WHERE consumed_at IS NULL ensures only one active token per (user, purpose); replay sets consumed_at then second UPDATE returns 0 rows. |
| T-41-09-03 | Spoofing | Cross-purpose token reuse (invitation token used for password reset) | mitigate | `purpose` column + CHECK constraint + service-layer filter (Phase 44 queries `WHERE purpose='password_reset'`); a row issued for invitation cannot satisfy a password-reset confirm. |
| T-41-09-04 | Denial of service | Token table unbounded growth | mitigate | Cleanup cron lands in Phase 44 (D-41-06) — daily ARQ job DELETE WHERE expires_at < NOW() - INTERVAL '30 days'. |
</threat_model>
