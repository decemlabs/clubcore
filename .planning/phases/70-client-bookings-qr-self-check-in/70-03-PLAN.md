<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA client → POST /client/booking | untrusted body; client identity must come from the principal, never the body |
| concurrent clients → same slot | partial-UNIQUE arbiter resolves the race |
| client A → client B's booking | cancel must not act on or reveal a non-owned booking |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-09 | Information Disclosure / IDOR | client_cancel_booking | mitigate | client.id is the only ownership source (no body/path client_id); non-owned -> 404 booking_not_found. Tested in test_client_booking_idor.py. |
| T-70-10 | Tampering / race (criterion #1) | client_create_booking | mitigate | Delegates to the partial-UNIQUE-guarded core; loser gets 409 slot_already_booked. Tested with real-commit parallel POSTs. |
| T-70-11 | Spoofing / forgery | request body client_id | mitigate | ClientCreateBookingRequest has NO client_id field; principal from require_client() is authoritative. |
| T-70-12 | Repudiation | Idempotency replay | mitigate | verify_idempotency + idempotent_execute; same key replays the same booking, distinct keys race at the DB (D-70-02). |
| T-70-13 | Information Disclosure | available-slots projection | mitigate | Client-safe projection only (trainer name/specialization, times) — no owner-only economics (D-69-05). |
</threat_model>
