<objective>
Close APAY-04: notify the client about the autopay outcome on both channels (Telegram
primary + email mirror), idempotently. The success path piggybacks on the existing
post-commit `dispatch_payment_notification` (the webhook already enqueues it with the
autopay kind from Plan 02 and an online_payments row exists, so it keeps online_payment_id
idempotency); this plan adds the autopay-specific success copy/templates. The failure path
is a brand-new task fired by the cron's sync-decline branch (Plan 02) — and because a decline
creates NO online_payments row, it CANNOT key on online_payment_id; it keys on the
always-present autopay_charges.id via the dedicated autopay_charge_notifications claim table
created in Plan 01.

Purpose: Channel-idempotent, best-effort, owner-signed notifications — the success path
reuses claim_payment_notification (UNIQUE online_payment_id+kind+channel); the failure path
uses a small dedicated claim_autopay_failure_notification (UNIQUE autopay_charge_id+kind+channel)
because no online_payments row exists on decline. Both follow the 999.2 email-mirror discipline.

Output: autopay success/failure renderers + email templates + the success-kind branch in
dispatch_payment_notification + a failure-notification task (keyed on autopay_charge_id) wired
into the cron's decline path + full idempotency / best-effort tests.
</objective>
