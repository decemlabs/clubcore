<architecture_note>
**Charge-ledger method + success-DM discriminator (planner decision — resolves a CONTEXT tension).**
CONTEXT locks both "charge-ledger method='autopay'" AND "reuse the succeeded webhook, no handler
changes". A strict literal reading is contradictory: the webhook hardcodes `method="online"` at
handlers.py:457. Resolution (Task 3): add ONE additive nullable discriminator column reused from
Plan 01 — the cron sets a marker the webhook reads to choose `method="autopay"` for the ledger row
AND to select the autopay success-DM copy. This does NOT change activation logic (D-06 webhook-locked
renewal is preserved verbatim) — it only changes the ledger `method` label and the notification kind.
The simplest carrier is the `online_payments.confirmation_type` value: the cron writes
`confirmation_type='autopay'` (off-session has no real redirect/qr confirmation), and the webhook maps
`confirmation_type == 'autopay'` → recorder `method="autopay"` + `kind="autopay_charge_succeeded"`.
This avoids a new migration while keeping the change additive and reversible.
</architecture_note>
