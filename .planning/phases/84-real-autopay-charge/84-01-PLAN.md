<objective>
Lay the foundation layer for real off-session autopay charges: the `autopay_charges`
idempotency-ledger table + the `autopay_charge_notifications` per-channel claim table
(migration 0056), the YooKassa adapter off-session extension, and the two new LOCKED
audit events — all registered BEFORE any callsite per INFRA-15.

Purpose: This is the contract/foundation wave. The cron (Plan 02) and notifications
(Plan 03) depend on the tables, the adapter param, and the pre-registered audit events
existing first. The dedicated `autopay_charge_notifications` claim table exists because
the FAILURE notification (Plan 03) fires on a DECLINE — where no `online_payments` row
exists yet — so its idempotency must key on the always-present `autopay_charges.id`, not
on `online_payment_id`. Registering audit events before callsites is a hard INFRA-15
ordering requirement enforced by the AST gate and count-lock tests.

Output: `autopay_charges` table + `autopay_charge_notifications` claim table +
`AutopayCharge`/`AutopayChargeNotification` models + 0056 migration + env.py/.importlinter
registration; `create_payment(payment_method_id=...)` off-session support; two pre-registered
LOCKED audit events with payload schemas and bumped count-locks.
</objective>
