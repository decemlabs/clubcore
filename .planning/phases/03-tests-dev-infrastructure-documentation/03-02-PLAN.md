    Create apps/backend/Dockerfile with this exact content (per D-01, D-02, D-03, D-04 verbatim — D-04 dictates that hot-reload lives in compose, NOT here):

    ```dockerfile
    # syntax=docker/dockerfile:1.7
    # Multi-stage build per Phase 3 CONTEXT D-01..D-04.
    # Builder: official astral-sh/uv image with Python 3.12 (carries `uv` binary).
    # Runtime: bare python:3.12-slim-bookworm (no `uv`, smaller image).

    # ---- Stage 1: builder -------------------------------------------------------
    FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim AS builder

    # Make uv predictable inside CI/Docker.
    ENV UV_LINK_MODE=copy \
        UV_COMPILE_BYTECODE=1 \
        UV_PROJECT_ENVIRONMENT=/app/.venv

    WORKDIR /app

    # Layer split (D-02): deps-only first so source changes don't bust the deps cache.
    COPY pyproject.toml uv.lock ./
    RUN --mount=type=cache,target=/root/.cache/uv \
        uv sync --frozen --no-install-project --no-dev

    # Bring in the project source and finalize the install.
    COPY app ./app
    COPY alembic ./alembic
    COPY alembic.ini ./alembic.ini
    RUN --mount=type=cache,target=/root/.cache/uv \
        uv sync --frozen --no-dev

    # ---- Stage 2: runtime -------------------------------------------------------
    FROM python:3.12-slim-bookworm AS runtime

    # Non-root system user (D-03).
    RUN groupadd --system app && useradd --system --gid app --create-home app

    WORKDIR /app

    # Carry the prebuilt venv + project from the builder.
    COPY --from=builder --chown=app:app /app /app

    # The venv lives at /app/.venv (UV_PROJECT_ENVIRONMENT). Put it on PATH so
    # `uvicorn` and `alembic` resolve without `uv run`.
    ENV PATH="/app/.venv/bin:$PATH" \
        PYTHONDONTWRITEBYTECODE=1 \
        PYTHONUNBUFFERED=1

    USER app
    EXPOSE 8000

    # Production-shape CMD (D-03). Hot-reload is a compose override (D-04), not here.
    # Matches Phase 2 verification command exactly.
    CMD ["uvicorn", "app.main:create_app", "--factory", "--host", "0.0.0.0", "--port", "8000"]
    ```

    Critical constraints (verbatim from D-01..D-04):
    1. Builder FROM `ghcr.io/astral-sh/uv:python3.12-bookworm-slim` (carries uv) — exact tag.

    5. Non-root `app` user via `groupadd --system app && useradd --system --gid app --create-home app`. `COPY --from=builder --chown=app:app`. `USER app`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build context → image layers | Anything inside `apps/backend/` not in `.dockerignore` is baked into intermediate layers — secrets risk. |
| host filesystem → container | The non-root `app` user has no sudo; container processes cannot escalate to host root. |
| registry → local cache | `ghcr.io/astral-sh/uv:python3.12-bookworm-slim` is pulled by tag; image content is not pinned by digest. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Information Disclosure | .dockerignore — secret leakage into image | mitigate | `.env*` and `.git/` excluded by D-13 (acceptance grep enforces both). Build context never carries `.env` or git history. |
| T-03-06 | Elevation of Privilege | runtime container user | mitigate | `groupadd --system app && useradd --system --gid app --create-home app` then `USER app`. CMD runs as uid != 0. Acceptance criterion enforces `^USER app$` line presence. |
| T-03-07 | Tampering | uv lockfile | mitigate | Both `uv sync` invocations use `--frozen` against the committed `apps/backend/uv.lock`. uv verifies hash of every package per Phase 2 STATE.md note. |
| T-03-08 | Information Disclosure | dev-deps in production image | mitigate | Both `uv sync` invocations pass `--no-dev`. ruff/mypy/import-linter/pytest/asgi-lifespan never reach the runtime stage. |
| T-03-09 | Tampering / Supply Chain | base image tag drift | accept | `slim-bookworm` pin (D-01) prevents Debian channel drift. Pinning by digest is deferred to Phase X+ production hardening. Phase A is local-dev only. |
| T-03-10 | Denial of Service | uncached build context | accept | `.dockerignore` keeps build context small. BuildKit cache mounts on `/root/.cache/uv` cache deps across builds. Acceptable for local dev. |
