    Step 1 — Create apps/backend/scripts/backup_db.sh with this exact content (per D-13 verbatim):

    ```bash
    #!/usr/bin/env bash
    # Phase A backup helper. Targets the compose-network postgres service so
    # the host doesn't need pg_dump installed.
    #
    # Usage:
    #   ./scripts/backup_db.sh                       # default ./backups/sportzal-<UTC>.sql.gz
    #   ./scripts/backup_db.sh /tmp/my-dump.sql.gz   # custom path
    #
    # Requires: `docker compose up postgres` running (see ../docker-compose.yml).
    set -euo pipefail

    OUT="${1:-./backups/sportzal-$(date -u +%Y%m%dT%H%M%SZ).sql.gz}"
    mkdir -p "$(dirname "$OUT")"

    docker compose exec -T postgres pg_dump -U app -d sportzal | gzip > "$OUT"

    SIZE=$(stat -f%z "$OUT" 2>/dev/null || stat -c%s "$OUT")
    echo "Wrote $OUT (${SIZE} bytes)"
    ```

    Constraints (D-13):
    1. Shebang: `#!/usr/bin/env bash` (portable).
    2. `set -euo pipefail` — fail on error, undefined var, pipe failure.
    3. UTC timestamp via `date -u +%Y%m%dT%H%M%SZ` (DST-safe).
    4. Default output `./backups/sportzal-<UTC>.sql.gz`; overridable via `$1`.
    5. `mkdir -p "$(dirname "$OUT")"` — creates `./backups/` if missing.
    6. `docker compose exec -T postgres pg_dump -U app -d sportzal` — relies on the compose stack from Plan 03-05; the `-T` flag disables TTY allocation so the pipe works.
    7. `| gzip > "$OUT"` — gzip-compress to keep dumps small.
    8. Portable size reporting: `stat -f%z` (BSD/macOS) || `stat -c%s` (GNU/Linux).
    9. File MUST be committed executable: `chmod +x apps/backend/scripts/backup_db.sh`.
