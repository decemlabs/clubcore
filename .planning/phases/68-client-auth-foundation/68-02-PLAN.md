<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client cookie → API | a presented JWT must be provable to be a client token, never confused with a staff token |
| same-origin cookie store | staff `cc_*` and client `cc_client_*` cookies coexist; one must not overwrite the other |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-68-05 | Spoofing | cross-principal token confusion | mitigate | `decode_client_token` asserts `aud=="client"`; staff `decode_access_token` validates `role` against the staff Role enum — a client token (no role) fails staff decode, a staff token (no aud, or aud!="client") fails client decode (CISO-01/CISO-02) |
| T-68-06 | Tampering | JWT signature forgery | mitigate | HS256 with `settings.secret_key`; `decode` raises `InvalidAccessToken("invalid_token")` on bad signature |
| T-68-07 | Elevation | cookie collision overwriting staff session | mitigate | distinct cookie names (`cc_client_*`) + refresh cookie `Path=/api/v1/client` so it is never sent on staff `/api/v1/*` paths; no mutual overwrite (CISO-05) |
| T-68-08 | Information disclosure | silent cookie-deletion failure on logout | mitigate | `clear_client_session_cookies` replicates issuer Path/HttpOnly/SameSite/Secure exactly so deletion is honored |
| T-68-09 | Repudiation | client CSRF cookie readable by JS | accept | `clubcore_client_csrf` is intentionally `httponly=False` for double-submit; value is a CSRF nonce, not a session secret (mirrors staff `clubcore_csrf`) |
</threat_model>
