<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → /otp/request,/otp/verify | pre-auth public endpoints; must not leak phone existence |
| authenticated client → /me, /session/* | cookie principal scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-68-22 | Information disclosure | /otp/request response oracle | mitigate | handler always returns a fixed 202 `ResponseEnvelope[None]` body; the silent-no-op + constant-time floor live in the service (Plan 04) so the HTTP response is byte-identical for every phone (CAUTH-02) |
| T-68-23 | Tampering | malformed / non-E.164 phone | mitigate | `ClientOtpRequestBody.phone` validated by `PHONE_REGEX` (CAUTH-03) → 422 before any lookup |
| T-68-24 | Spoofing | staff token reaching client endpoints | mitigate | every authenticated handler depends on `require_client()` which decodes via `decode_client_token` (aud assertion) → staff token 401 (CISO-02) |
| T-68-25 | Spoofing | CSRF on logout / PATCH /me | mitigate | `/session/logout` and `PATCH /me` depend on `verify_client_csrf`; logout orders the auth dep first (RBAC-04) so an unauthenticated CSRF probe 401s before the CSRF branch |
| T-68-26 | Information disclosure | OTP endpoints requiring auth in spec | mitigate | client OTP operationIds added to `PUBLIC_ENDPOINT_OPERATION_IDS` — correctly pre-auth, no spurious security requirement leaking that they need a session |
| T-68-27 | Information disclosure | /me over-exposing staff fields | mitigate | `ClientMeResponse` is core-identity-only (no notes/tags/membership/created_by) — D-05 |
</threat_model>
