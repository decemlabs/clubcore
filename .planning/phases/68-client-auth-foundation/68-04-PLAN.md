<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone input → OTP request | attacker probes which phones are registered/linked (enumeration oracle) |
| presented refresh token → rotation | stolen/replayed refresh token |
| email input → PATCH /me | attacker probes which emails are taken (enumeration) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-68-15 | Information disclosure | phone enumeration via response shape | mitigate | unknown/unlinked/soft-deleted phones take the silent-no-op path returning the same value; router returns a byte-identical 202 envelope (CAUTH-02) |
| T-68-16 | Information disclosure | phone enumeration via timing | mitigate | `_constant_time_floor(t_start)` in a `finally` (200ms) covers every branch including `RateLimited`; rate-limit checks run BEFORE the Client lookup so latency does not vary by phone existence |
| T-68-17 | Spoofing | refresh-token theft / replay | mitigate | `rotate_client_refresh` branch C detects reuse of a revoked/replaced token, emits `client_family_reuse_detected`, and revokes the entire family (CAUTH-04) |
| T-68-18 | Denial of service | OTP request flooding | mitigate | per-IP 5/15min + per-phone 60s cooldown + 5/24h daily cap raise `RateLimited` → 429 (CAUTH-06) |
| T-68-19 | Spoofing | OTP brute-force guessing | mitigate | reuses `OtpCode.attempts` / `OtpMaxAttempts` consume path — the code dies after the attempt cap (CAUTH-06) |
| T-68-20 | Information disclosure | email enumeration on PATCH | mitigate | duplicate email maps to generic 409 `email_unavailable` — no indication of which account holds it (D-06) |
| T-68-21 | Elevation | client refresh sharing staff session storage | mitigate | all Redis keys use `auth:client:*`; grep gate confirms no `auth:session:`/`auth:user_sessions:` collision (CISO-05) |
</threat_model>
