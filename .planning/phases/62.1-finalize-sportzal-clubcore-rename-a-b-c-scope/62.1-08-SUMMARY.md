## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Row-count query referenced non-existent `subscriptions` table**

- **Found during:** Task 1, Step 4
- **Issue:** The command sequence in the objective specified `count(*) FROM subscriptions` but the actual schema uses `memberships`. Running the original query returned `ERROR: relation "subscriptions" does not exist` on both live and smoke (exit=1 both sides — verbatim output captured in evidence file).
- **Fix:** Adapted the row-count queries to use `memberships` instead of `subscriptions`. The original error output is documented verbatim in the evidence file's row-count section for full transparency.
- **Files modified:** `.planning/milestones/v1.10-OPERATOR-EVIDENCE.md`
- **Commit:** b016e1a5

**2. [Rule 3 - Blocking] pg_dump/psql/pg_restore not on default PATH**

- **Found during:** Task 1, Step 1
- **Issue:** `pg_dump` not found on PATH (`command not found: pg_dump`).
- **Fix:** Located binaries at `/usr/local/Cellar/libpq/18.4/bin` (Homebrew libpq). Used full paths for all Postgres client commands.
- **Files modified:** None (execution-time fix only)

**3. [Non-blocking] pg_restore exit=1 (non-fatal client/server version mismatch)**

- **Found during:** Task 1, Step 3
- **Issue:** pg client 18.4 emits `SET transaction_timeout = 0` which PG16 server does not recognise (`unrecognized configuration parameter "transaction_timeout"`). pg_restore exits 1 and prints "errors ignored on restore: 1".
- **Assessment:** Not a data integrity issue. All 30 tables were verified as present in clubcore_smoke post-restore. The `transaction_timeout` parameter was added in PostgreSQL 17; this is a known client/server version skew warning.
- **Fix:** Documented verbatim in the evidence file; noted in SUMMARY. No code change needed.
- **Files modified:** `.planning/milestones/v1.10-OPERATOR-EVIDENCE.md` (with explanatory note)
