## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA→ЮKassa redirect | client leaves to ЮKassa via confirmation_url, returns to /payment/return |
| return route→status API | polls coarse status; cannot infer activation detail |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-71-18 | Information Disclosure | premature activation display | mitigate | Return route shows only "Ожидаем подтверждение" while pending; navigates Home only on `succeeded` (criterion #1) |
| T-71-19 | Information Disclosure | net-new screen backend calls | mitigate | Net-new screens render ComingSoon importing only the placeholder; Plan-04 ESLint boundary enforces no query-layer import (criterion #5) |
| T-71-20 | Tampering | checkout amount from client | mitigate | CheckoutSheet sends only planId (+ PT idempotency key); price is server-authoritative (backend Plan 01/02) |
| T-71-21 | DoS / double-charge | PT retry after redirect | mitigate | Idempotency key generated once per intent (`crypto.randomUUID()`) and carried across the redirect round-trip via the `return_url` `idempotency_key` query param (D-71-04 — sole persistence channel, no localStorage); read back from `useSearchParams()` and reused on retry |
</threat_model>
