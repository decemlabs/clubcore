<objective>
Close the BLOCKER from 71-HUMAN-UAT test 2: the registered hand-written service
worker (`public/sw.js`, cache `gym-v2`) is cache-first for all non-navigation GETs
and caches any same-origin `res.ok` response — including authed `/api/*` data
(`/client/me`, `/client/home`, `/client/plans`, …). This violates PWA-07 / T-69-07
("SW must never cache /api/*") and served STALE `/api/v1/client/plans` ([]) during
the UAT.

Canonical-SW decision (made here, documented for the executor): **keep the
hand-written `public/sw.js` and rewrite it to be PWA-07-compliant** — NOT switch to
the VitePWA-generated workbox worker. Rationale:
  - `registerPwa()` already registers `/sw.js`; the VitePWA `runtimeCaching: []` +
    `navigateFallbackDenylist` config in vite.config.ts is dead config (never the
    registered worker). Switching registration to the generated SW would mean
    losing the bespoke offline-shell + offline.html fallback and re-deriving the
    precache list, a larger and riskier change than hardening the 30-line handler.
  - The hand-written worker is the one in production behavior; fixing it directly
    guarantees the fix lands on the worker that actually runs.

Purpose: Guarantee no authed `/api/*` payload is ever cached, and evict any
`gym-v2` `/api/*` entries already sitting in existing installs.
Output: A hardened `public/sw.js` (network-only `/api/*`, activate-time `/api`
purge, bumped cache version) with the existing static-shell + offline behavior intact.
</objective>
