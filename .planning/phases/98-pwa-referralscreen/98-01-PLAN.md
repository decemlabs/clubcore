<objective>
Build the backend aggregate read endpoint `GET /api/v1/client/referral/summary` that powers the
entire PWA ReferralScreen in one round-trip: the client's referral `code`, server-built `shareUrl`,
the referral-only `accruedKopecks` sum, and the `invitees[]` list with per-friend status and bonus.

Purpose: REFER-06 requires a read surface that Phases 96/97 did not build (no invited-friends list,
no referral-only accrued sum). This plan lands the endpoint + its tests FIRST so the PWA hook in
Wave 2 has a real contract to call.

Output: ReferralInviteeItem + ReferralSummaryResponse schemas, a read-only get_referral_summary
service function, the client_router GET handler, and a full integration test file.
</objective>

| client (PWA) → /api/v1/client/referral/summary | Authenticated client request; principal is the only trusted identity source |
| referrals module → clients / loyalty_ledger tables | Cross-module data read (raw SQL; import-linter forbids ORM cross-import) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-98-02 | Elevation / IDOR | GET /referral/summary | mitigate | client_id derived from require_client() principal only — never a path/query/body param; test_summary_idor_other_client_invitees_not_leaked proves isolation |
| T-98-03 | Spoofing | GET /referral/summary auth | mitigate | require_client() gate; unauthenticated -> 401 (test_summary_no_auth_returns_401) |
| T-98-04 | Information Disclosure | accruedKopecks computation | mitigate | SUM filtered to entry_type='referral_accrual' for the principal's own client_id — does not expose total balance or other clients' ledger |
| T-98-05 | Tampering | cross-module raw SQL | accept | Parameterized text() binds (str(client_id)); no string interpolation of user input; static SQL — injection surface is the bound :cid only |
