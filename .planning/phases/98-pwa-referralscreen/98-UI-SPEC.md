## Layout & Section Order (locked — top to bottom)

The ported screen, inside SheetGate inset (chrome stripped), in this exact order:

1. **Topbar** — back button (closes sheet → `onClose`, NOT `data-go`), centered title "Приведи друга", share button (top-right, triggers native share).
2. **Hero spot illustration** — decorative two-friends + plus scene (`.spot`, `aria-hidden`), verbatim animated chips/rings. Keep animation; respects `prefers-reduced-motion`.
3. **Hero title + sub** — "Зовите друзей — тренируйтесь вместе" / reward-promise subcopy.
4. **Reward rows card** (`.rewards`) — two rows: "Вам" (−bonus, accent-soft tint) and "Другу" (free-days, neutral). Amounts from server config where available; otherwise the reference's promise copy.
5. **"Уже накоплено" card** (`.earned`) — the referral-only accrued figure (`accruedKopecks`) with optional count-up; contains the milestone tracker (HIDDEN — see below).
6. **Referral code card** (`.code-card`) — mini-label "Ваш промокод" + "Действует бессрочно"; `.code-box` with the server `code` + copy button; `.link-line` with the server `shareUrl`; `.share-row` 3-chip grid (Telegram / WhatsApp / Ссылка).
7. **"Как это работает" steps** (`.steps`) — 3 numbered steps with connector line.
8. **"Приглашённые друзья"** — mini-label header + `.friends` card list of invitee rows (status badges).
9. **Sticky CTA footer** (`.footer`) — full-width "Поделиться приглашением" button (`.btn`), blurred backdrop.
10. **Toast** (`.toast`) — transient copy/share confirmations.

### Hidden-for-future (SC-5 gamification tier tracker)

`.milestones` block (track + 5 nodes + "До месяца в подарок — ещё N друзей" + "2/5" row) stays in the DOM but is hidden (`hidden` attr or `display:none`). NOT deleted. Its count-up/pop animations may be left dormant. The tier backend does not exist (deferred), so any hardcoded `2/5`/`25%`/"2 друга" reference values must NOT be wired to real data — they are inert behind the hide.

## Data States (ChatScreen convention — Phase 94)

Single `useClientReferralSummary()` → `{ code, shareUrl, accruedKopecks, invitees: [{ firstName, joinedAt, status, bonusKopecks }] }`.

| State | Behavior |
|-------|----------|
| Loading | skeleton in place of code-box, accrued figure, and friends list (mirror ChatScreen's loading treatment); chrome/hero render immediately |
| Error | inline error fallback (not a crash, not an error page) — neutral retry affordance, same convention as ChatScreen |
| Empty invitees (`invitees == []`) | render the friends card with a single empty-state row: heading "Пока никого" + body "Поделитесь промокодом — приглашённые друзья появятся здесь." Hero, code box, share chips, and steps still render fully (the screen is useful pre-first-invite). |
| Populated | one `.fr-row` per invitee: avatar initials, `firstName`, date line from `joinedAt`, badge by `status` |

### Invitee row mapping

| Field | Reference visual | Rule |
|-------|------------------|------|
| avatar | `.fr-av` colored initials | initials from `firstName`; joined → colored bg, pending → `--border-strong` bg / `--text-2` |
| name | `.fr-name` | `firstName` only (PII-minimal; NO last name) |
| date | `.fr-date` | joined → "Присоединился(ась) {ru date}" from `joinedAt`; pending → "Перешёл по ссылке · ещё не оплатил" |
| badge | `.fr-badge` | `joined` → green badge "+{bonus} ₽" (check icon) using `bonusKopecks` via `formatMoney`-style ru grouping; `pending` → amber badge "Ждём" (clock icon) |

Date formatting: ru-RU, Europe/Moscow, date-fns `ru` locale (project convention) — NOT raw `Date`.

## Deep-Link Landing (`/i/:code` — REFER-02 PWA)

New public route in `App.jsx` (alongside `/login`); lightweight landing component (chrome-stripped, may reuse referral token palette or a minimal own style).

| Element | Copy / Behavior |
|---------|-----------------|
| Resolver call | `GET /i/<code>` → `{ valid, referrerFirstName, welcomeBonus… }` |
| Valid landing heading | "{referrerFirstName} зовёт вас в «Sportzal»" (referrer first name only) |
| Valid landing body | welcome-bonus preview from resolver (e.g. "14 дней в подарок к первому абонементу") |
| Valid CTA | "Присоединиться" → store code in `sessionStorage['clubcore:pendingReferral']`, proceed to onboarding/login |
| Invalid/expired (`valid:false`) | NEUTRAL fallback — heading "Добро пожаловать в «Sportzal»", generic "Присоединиться" CTA, NO error page, NO red state; proceed to normal onboarding with no pending code |
| Capture timing | AFTER auth/onboarding completes → `POST /client/referral/capture` with stored code, then clear sessionStorage key. Idempotent server-side (self-referral / already-bound = no-op). |

Brand string in copy: use `«Sportzal»` (CLUB_BRAND placeholder per D-62-02). Do NOT use the reference's "Мой зал" / "myzal.app" — those are prototype mock strings.

## Share / Copy Interaction Contract

| Action | Mechanism (CONTEXT-locked) |
|--------|----------------------------|
| Copy code | `navigator.clipboard.writeText(code)` with synchronous fallback; toast + confetti + button "done" state (2.2s reset) |
| Native share (topbar + footer CTA) | `navigator.share({ title, text })`; fallback toast "Приглашение готово к отправке" |
| Telegram chip | `https://t.me/share/url?url=<encoded shareUrl>&text=<encoded invite text>` via `window.open(_blank, noopener)` |
| WhatsApp chip | `https://wa.me/?text=<encoded invite text + shareUrl>` via `window.open` |
| Ссылка chip | copy `shareUrl` to clipboard; toast "Ссылка скопирована" |

**Critical:** share/link text MUST embed the SERVER-built `shareUrl` from the summary response — never a client-constructed URL. Invite text uses the real `code` and brand `«Sportzal»`.

Animations: keep `.fade-up` stagger, `.btn` shimmer, confetti, count-up — ALL must respect `@media (prefers-reduced-motion: reduce)` (reference already guards shimmer + confetti; count-up should bail to static under reduced-motion). Count-up is non-load-bearing (CONTEXT discretion): static figure acceptable if cheaper.
