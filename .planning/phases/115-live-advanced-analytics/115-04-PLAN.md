|----------|-------------|
| backend audit JSON → FE Zod + mapper | Untrusted/variable audit payload parsed and mapped before render |
| role (session) → owner-only audit feed fetch | reception must not trigger the owner-only audit-log fetch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-115-D1 | Elevation of Privilege | useActivityFeed → GET /audit-log | mitigate | `enabled: can(role,'view','audit-log')` disables the fetch for reception; backend audit-log is owner-only (Action.LIST, Resource.AUDIT_LOG) and returns 403 for reception. Owner-only hooks declared in the owner block so they never register for reception. |
| T-115-D2 | Tampering / robustness | mapAuditToActivityFeed | mitigate | Audit response is `AuditLogResponseSchema.parse`d before mapping; the mapper's switch has a default 'alert' branch so an unrecognized/new audit action renders a safe generic row instead of throwing — dashboard never crashes on a drifted/new audit taxonomy. |
| T-115-D3 | Information Disclosure | activity feed display names | accept | The feed shows the same actor/resource info the owner already sees in the full audit-log view; no new PII surface. Owner-only gate is the control. No client name is invented — falls back to actor email local-part or a generic label when absent. |
| T-115-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — reuses existing zod, @tanstack/react-query, date-fns (formatRelativeRu), existing ActivityFeed component. No package-legitimacy gate needed. |
