## Surface 1: LiveNowCounter (wiring LiveNowCard)

### What changes

`LiveNowCard` exists in `pages/load/components/LiveNowCard.tsx` and accepts
`data: LiveData`. Phase 103 left it hidden with a TODO comment. Phase 115 un-hides
it by:
1. Adding `useLoadNow` hook in `features/load/api.ts` → `GET /api/v1/reports/load/now`
2. Mapping `{ count, asOf, windowMinutes }` response to the existing `LiveData` shape
3. Inserting `<LiveNowCard data={liveData} />` above `<LoadHeatmapCard>` in
   `LoadPage.tsx` (matching the original design intent)

### LiveNowCard visual contract (existing — not changing)

The `LiveNowCard` dark gradient card is locked. No visual changes are made. The
existing structure:
- Top section: "Сейчас · {time}" pulsing dot label; large count number; fill meter
- Zones section: per-zone rows (mocked with a single "Зал" zone for now)

### Live count "approximation" copy constraint

The "Сейчас" label and live count represent a rolling-window approximation
(default ~120-minute window). The UI must NOT over-claim precision:
- The card header already reads "Сейчас · {time}" — the timestamp signals recency.
- A tooltip or sub-label on the fill meter reads:
  `"Оценка присутствующих · окно {windowMinutes} мин"`
  displayed as `text-white/55 text-[11px]` below the fill meter bar.
- Do NOT use copy that implies a real-time checkout model (no "находятся прямо сейчас"
  without the qualification).

### Loading / polling

`useLoadNow` uses `refetchInterval: 60_000` (refresh every 60 seconds).
While loading on mount: a `Skeleton` the same height as `LiveNowCard`
(`h-[200px] rounded-lg`). On error: the card is silently omitted (no error state
shown to avoid alarming the owner with a backend approximation failure).

## Surface 2: CohortRetentionCard

### Data source

New backend endpoint `GET /api/v1/reports/cohort-retention`.
Response Zod shape (Claude's Discretion — prescribe here):

```ts
CohortRetentionSchema = z.object({
  data: z.object({
    cohorts: z.array(z.object({
      cohortMonth: z.string(),  // 'YYYY-MM' — membership-start month
      label: z.string(),        // e.g. "янв 2026"
      months: z.array(z.object({
        offset: z.number(),     // 0 = start month, 1 = next month …
        retentionPct: z.number().nullable(), // null if not enough data yet
      })),
    })),
    maxOffset: z.number(),  // longest cohort tracked (up to 11)
  }),
})
```

### Visual structure

```
Card as="section"
  CardHeader
    title:    "Удержание клиентов по когортам"
    subtitle: "% клиентов с активным абонементом, совершивших визит в месяц"

  body (px-5 pb-4 overflow-x-auto):
    <table role="grid" aria-label="Таблица удержания">
      <thead>
        <tr>
          <th className="text-[11.5px] text-fg-muted">Когорта</th>
          <th>M0</th> <th>M1</th> … <th>M11</th>   ← up to maxOffset + 1 columns
        </tr>
      </thead>
      <tbody>
        {cohorts.map(cohort => (
          <tr key={cohort.cohortMonth}>
            <td className="text-[11.5px] font-medium text-fg-muted whitespace-nowrap pr-3">
              {cohort.label}
            </td>
            {cohort.months.map(m => (
              <td key={m.offset}
                  className="size-9 text-center text-[11px] tabular-nums rounded-md"
                  style={{ background: retentionBg(m.retentionPct) }}>
                {m.retentionPct != null ? `${m.retentionPct}%` : '—'}
              </td>
            ))}
          </tr>
        ))}
      </tbody>
    </table>

    <footer className="mt-3 flex items-center gap-3 text-[11px] text-fg-muted">
      [gradient swatch: low → high]
      <span>0%</span> … <span>100%</span>
    </footer>
```

### Color scale function `retentionBg(pct: number | null)`

| Condition | Background token |
|-----------|-----------------|
| `null` (no data) | `transparent` (empty cell) |
| `pct < 30` | `var(--surface-2)` |
| `30 ≤ pct < 70` | `color-mix(in srgb, var(--primary) 30%, transparent)` |
| `pct ≥ 70` | `color-mix(in srgb, var(--primary) 75%, transparent)` |

Text color on tinted cells: `text-fg` (auto-legible on all opacity levels in both
themes). Cells with `pct ≥ 70` use `font-semibold`.

### Empty state

When `cohorts.length === 0`:
```
EmptyState
  icon={BarChart3}
  title="Нет данных по когортам"
  message="Когортный анализ появится после накопления данных за несколько месяцев."
```

## Surface 3: VisitAnomalyCard

### Data source

New backend endpoint `GET /api/v1/reports/visit-anomaly`.
Response Zod shape:

```ts
VisitAnomalySchema = z.object({
  data: z.object({
    points: z.array(z.object({
      date: z.string(),       // 'YYYY-MM-DD'
      count: z.number().int().nonnegative(),
      isAnomaly: z.boolean(),
      direction: z.enum(['spike', 'drop']).nullable(),  // null if not anomaly
      label: z.string(),      // short display label, e.g. "12 июн"
    })),
    windowDays: z.number(),   // rolling mean window, e.g. 14
    sigmaThreshold: z.number(), // e.g. 2.0
    anomalyCount: z.number().int(),
  }),
})
```

### Visual structure

```
Card as="section"
  CardHeader
    title:    "Аномалии посещаемости"
    subtitle: `Дни, отклоняющиеся более чем на {sigmaThreshold}σ от скользящей средней ({windowDays} дней)`

  body (px-5 pb-4):
    {/* Anomaly summary line */}
    <p className="mb-3 text-[12.5px] text-fg-muted">
      Найдено аномалий: <b className="text-fg font-semibold">{anomalyCount}</b>
    </p>

    <ChartContainer config={ANOMALY_CHART_CONFIG} className="h-[180px] w-full">
      <AreaChart data={points} margin={{ top: 10, right: 8, left: 8, bottom: 0 }}>
        <CartesianGrid vertical={false} stroke="var(--border)" strokeOpacity={0.55} />
        <XAxis dataKey="label" tickLine={false} axisLine={false} tick={{ fontSize: 10 }}
               interval={Math.max(Math.floor(points.length / 6), 1) - 1} tickMargin={8} />
        <YAxis hide />
        <Area type="monotone" dataKey="count"
              stroke="var(--primary-deep)" strokeWidth={1.5}
              fill="url(#anomalyGrad)" isAnimationActive={false} />
        <Scatter data={spikePoints}    fill="var(--chart-1)" r={5} />  ← spike anomalies
        <Scatter data={dropPoints}     fill="var(--chart-4)" r={5} />  ← drop anomalies
        <ChartTooltip content={<AnomalyTooltip />} />
      </AreaChart>
    </ChartContainer>

    {anomalyCount > 0 && (
      <div className="mt-3 flex flex-wrap gap-2">
        <LegendChip color="var(--chart-1)" label="Пик" />
        <LegendChip color="var(--chart-4)" label="Провал" />
      </div>
    )}
```

`LegendChip` is an inline micro-component: a 10px colored circle + `text-[11.5px]
text-fg-muted` label in a flex row — no new primitives required.

### Empty state

When `points.length === 0`:
```
EmptyState
  icon={TrendingUp}
  title="Недостаточно данных"
  message="Для расчёта аномалий нужны данные минимум за 2 недели."
```

When `anomalyCount === 0` (data present but no anomalies):
Render the chart normally. The absence of scatter dots communicates "no anomalies".
Add subtitle footnote: `"Аномалий не обнаружено за указанный период"`.

## Interaction & State Contract

### Loading / fetching

Each new advanced analytics widget (`CohortRetentionCard`, `VisitAnomalyCard`,
`AtRiskWidget`) manages its own loading state independently — they hit separate
endpoints and should not block each other.

Per-widget loading skeleton height:
- `CohortRetentionCard` pending: `Skeleton h-[240px] w-full rounded-xl` inside the card body
- `VisitAnomalyCard` pending: `Skeleton h-[180px] w-full rounded-xl` inside the card body
- `AtRiskWidget` pending: three stacked `Skeleton h-[52px] rounded-xl` rows

### RBAC

All new widgets (cohort, anomaly, at-risk, live-now) are **owner-only**. The
existing `can(role, 'view', 'reports')` gate in `LoadPage` ensures reception never
sees the Load page content at all — no per-widget RBAC guard needed.

Dashboard rewired widgets (ActivityFeed, TopTrainers, RevenueChart) were already
owner-only. `useAuditLog` hook adds `enabled: can(role, 'view', 'reports')` as a
double gate (consistent with `features/reports/api.ts` pattern).

### Error states

Per-widget error: render the existing `EmptyState` with error copy (see Copywriting
Contract below). No inline `PageError` — the advanced analytics section failing
should not crash the Load page or Dashboard.

`LiveNowCard` error: silently omit the card (do not show an error). This is the
least alarming behavior for an approximation endpoint.

### Refetch / polling

- `useLoadNow`: `refetchInterval: 60_000` (60 s auto-poll, no user action).
- `useCohortRetention`, `useVisitAnomaly`, `useAtRisk`: standard `staleTime: 30_000`,
  `refetchOnWindowFocus: false` — no polling (these are expensive aggregate queries).
- `useAuditLog` (for ActivityFeed): standard `staleTime: 30_000`. The existing
  animated ping dot in `ActivityFeed` is cosmetic — it does NOT imply WebSocket.

## Accessibility Contract

- New `<section aria-label="Расширенная аналитика">` wrapper on the Load page
  provides a screen-reader landmark for the three new widgets.
- `CohortRetentionCard` renders a `<table role="grid" aria-label="Таблица удержания">`.
  Each data cell's accessible text = the percentage value or "—". Column headers use `<th scope="col">`.
  Row headers (cohort month label) use `<th scope="row">`.
- `VisitAnomalyCard` chart is an SVG via Recharts/`ChartContainer` — consistent with
  existing chart accessibility pattern. No additional `aria-label` on the chart container.
  The anomaly summary line (`"Найдено аномалий: N"`) is the text-based accessible summary.
- `AtRiskWidget` rows are read-only `<div>` elements — not links or buttons. No `role="button"`.
  The count badge in the CardHeader has `aria-label="Клиентов под риском: {count}"`.
- `LiveNowCard` is an existing interactive element (keyboard-navigable button that opens
  "present" modal) — no accessibility changes required.
- Focus management: no new focusable elements added beyond the existing `LiveNowCard`
  keyboard trigger.
