### `apps/backend/scripts/verify/_lib.sh` (shell-helper-lib, request-response w/ cookie jar)

**Analog:** none in repo (this is the first verification-helper of its kind).

**Closest convention reference:** `apps/backend/scripts/backup_db.sh` — for the `set -euo pipefail` opener and the comment-header style. NOT for the curl/cookie pattern (which is new).

**Why this is being newly authored:** Phase 36 introduces the *operator-script* discipline at the shell layer. v1.3 Phase 29 captured evidence inline in the verification log without a shell-helper layer (operator ran ad-hoc curl by hand). D-36-01 mandates "hand-authored bash scripts per scenario" with a shared `_lib.sh` for auth setup so each of the 8 scenario scripts stays terse and hermetic.

**Pattern to establish (derived from D-36-01 + D-36-04 + D-36-05 + `apps/backend/scripts/backup_db.sh:10` opener):**

```bash
#!/usr/bin/env bash
# Phase 36 verification helper library.
# Sourced by every apps/backend/scripts/verify/<NN>_*.sh scenario.
#
# Provides:
#   - BASE_URL (default http://localhost:8000)
#   - COOKIE_JAR (per-script mktemp, auto-cleaned on EXIT)
#   - login_as <role>   — POSTs /api/v1/auth/login, writes cookies + CSRF + access JWT
#   - mut <method> <path> <json-body>  — curl wrapper that adds Idempotency-Key + X-CSRF-Token
#   - psql_exec <sql>   — local psql against compose postgres (app/app/sportzal)
#
# Requires: curl, jq, uuidgen, psql (host-side or `docker compose exec postgres psql`).
set -euo pipefail

BASE_URL="${BASE_URL:-http://localhost:8000}"
COOKIE_JAR="$(mktemp -t sportzal-verify-XXXX.cookies)"
trap 'rm -f "$COOKIE_JAR"' EXIT

VERIFY_OWNER_EMAIL="${VERIFY_OWNER_EMAIL:-verify_owner@local.dev}"
VERIFY_OWNER_PASSWORD="${VERIFY_OWNER_PASSWORD:?must be exported}"
VERIFY_RECEPTION_EMAIL="${VERIFY_RECEPTION_EMAIL:-verify_reception@local.dev}"
VERIFY_RECEPTION_PASSWORD="${VERIFY_RECEPTION_PASSWORD:?must be exported}"

login_as() {
  local role="$1"  # owner | reception
  local email password
  if [ "$role" = "owner" ]; then
    email="$VERIFY_OWNER_EMAIL"; password="$VERIFY_OWNER_PASSWORD"
  else
    email="$VERIFY_RECEPTION_EMAIL"; password="$VERIFY_RECEPTION_PASSWORD"
  fi
  # /login is CSRF-exempt (apps/backend/app/modules/auth/router.py:69-89).
  # Cookies set: sportzal_session (HTTP-only), sportzal_csrf (JS-readable).
  curl -i -s -X POST "$BASE_URL/api/v1/auth/login" \
    -H 'Content-Type: application/json' \
    -c "$COOKIE_JAR" \
    -d "{\"email\":\"$email\",\"password\":\"$password\"}"
  CSRF_TOKEN="$(awk '$6=="sportzal_csrf"{print $7}' "$COOKIE_JAR")"
  export CSRF_TOKEN
}

# mut <METHOD> <PATH> <JSON_BODY>
# Adds Idempotency-Key (D-36-04) + X-CSRF-Token (every mutating verb).
mut() {
  local method="$1" path="$2" body="$3"
  local idem; idem="$(uuidgen)"
  curl -i -s -X "$method" "$BASE_URL$path" \
    -H 'Content-Type: application/json' \
    -H "Idempotency-Key: $idem" \
    -H "X-CSRF-Token: $CSRF_TOKEN" \
    -b "$COOKIE_JAR" -c "$COOKIE_JAR" \
    -d "$body"
}

# psql_exec <SQL>
# D-36-05: verification-time DB time-travel is allowed; log intent in caller.
# Credentials match apps/backend/docker-compose.yml:65 (app/app/sportzal).
psql_exec() {
  local sql="$1"
  psql "postgresql://app:app@localhost:5432/sportzal" -c "$sql"
}
```

**Critical correction to CONTEXT.md:** CONTEXT.md `code_context` § "Integration Points" says `psql "postgresql://sportzal:sportzal@localhost:5432/sportzal"`. The actual `apps/backend/docker-compose.yml:62-66` postgres credentials are `POSTGRES_USER=app`, `POSTGRES_PASSWORD=app`, `POSTGRES_DB=sportzal`. The connection string MUST be `postgresql://app:app@localhost:5432/sportzal`. Planner should fix this in `36-01-PLAN.md`.

**Cookie-jar discipline reference:** `apps/backend/app/modules/auth/router.py:81-89` (`issue_session_cookies` sets `sportzal_session` + `sportzal_csrf`) and `apps/backend/app/core/security.py` (cookie semantics). The bash `awk` extraction reads the Netscape-format cookie jar that curl writes.
