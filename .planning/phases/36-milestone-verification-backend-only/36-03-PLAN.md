**Inline-regression protocol (D-36-15..17) for race-test failures:**

Per D-36-09, Phase 36 does NOT author new race tests. If a race test FAILS, the fix is in:
- The test file (if the test is broken — rare; usually tests pre-existing) OR
- The owning service/router under `apps/backend/app/modules/<feature>/` (production-blocker regression)

Apply the protocol:
1. Reproduce: re-run the single failing test with `uv run pytest -xvs <file>::<test_name>` for full trace.
2. Diagnose root cause. Most likely categories:
   - **Race condition regression**: lock missing or refund_of partial UNIQUE broke → fix in service.py, own commit `fix(36-03): REG-36-XX <desc>`.
   - **Audit-event emission missing/wrong**: `audit.emit(...)` call drifted from `LOCKED_AUDIT_EVENTS` → fix in service.py.
   - **Test-environment drift**: SAVEPOINT cleanup leaked → fix in conftest.py or test fixture.
3. Fix inline as own commit.
4. Re-run the full D-36-08 sweep (not just the single test) to confirm no regression elsewhere.
5. Log in VERIFICATION-LOG.md `overrides:` block (same schema as 36-02 contingency).
6. Increment `overrides_applied`.
7. Hard cap (D-36-17): >5 total Wave 2 regressions → STOP + write ESCALATION.md + halt Phase 36 (36-05 will skip handoff).
