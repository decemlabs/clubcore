<objective>
Extend `auth.service.rotate_refresh`'s user-row SELECT to require `is_active = true AND deleted_at IS NULL` in the same single SELECT (race-tight; Pitfall 5 case 3 mitigation). On miss, emit `('refresh_failed','session')` with `reason='account_inactive'` and raise `InvalidSession('invalid_session')` — anti-oracle response identical to the truly-missing-user path (D-20-9 lineage, D-43-20).

Purpose: A deactivated or soft-deleted operator currently retains a valid refresh-token cookie for up to 14 days. With this extension, their next `/auth/refresh` returns 401 `invalid_session` and emits a forensic `refresh_failed` audit row indicating `account_inactive` (visible only to operators with audit-read access, never leaked to the deactivated user).

Output: Single-function modification in `auth/service.py:rotate_refresh` — replace the `session.get(User, row.user_id)` with a predicate-filtered `session.scalar(select(User).where(...))`.

```python
# Phase 43 D-43-20 — USERS-06 anti-oracle refresh chokepoint.
# Single SELECT race-tight against parallel deactivate / soft-delete
# (Pitfall 5 case 3). Predicate filtered IN the SQL — NOT a post-fetch
# Python branch (which would race against UPDATE...SET is_active=false).
user_loaded = await session.scalar(

        User.id == row.user_id,
        User.is_active.is_(True),
        User.deleted_at.is_(None),
    )
)
if user_loaded is None:
    # Anti-oracle: same response shape as truly-missing / invalid_session
    # (D-20-9 lineage). Audit emit is forensic-only — never leaks.
    await audit.emit(
        session,
        "refresh_failed",
        actor_user_id=None,
        resource_type="session",
        resource_id=None,
        audit_correlation_id=None,
        user_id=row.user_id,
        reason="account_inactive",
    )
    await session.commit()
    raise InvalidSession("invalid_session")
```
