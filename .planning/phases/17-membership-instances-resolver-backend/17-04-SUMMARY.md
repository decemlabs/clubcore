# Phase 17 Plan 04: Mount HTTP Layer + Wire Resolver + Apply Migration Summary

Phase 17 went live over HTTP: 4 endpoints under `/api/v1/memberships`, the second composition-root resolver registration in `app/main.py`, the migration `0005_memberships` applied to dev DB, and `openapi.json` regenerated byte-stably with 4 new operationIds.

## What Was Built

**Task 1 — Second APIRouter `memberships_router` in `apps/backend/app/modules/memberships/router.py`:**
- Added `memberships_router = APIRouter()` at the module level alongside the existing Phase 16 plans `router` (CD-02 router-split strategy — both coexist in the same file).
- 4 endpoints registered:
  - `GET /memberships` (list) — `Depends(require_permission(Action.VIEW, Resource.MEMBERSHIPS))`, `Annotated[MembershipListQuery, Depends()]`, returns `ResponseEnvelope[PaginatedData[MembershipResponse]]`.
  - `GET /memberships/{membership_id}` — VIEW gate, returns `ResponseEnvelope[MembershipResponse]`.
  - `POST /memberships` (sell) — `Depends(require_permission(Action.CREATE, Resource.MEMBERSHIPS))` + `Depends(verify_csrf)`, body `MembershipCreateRequest`, status 201, returns `ResponseEnvelope[MembershipResponse]`. Reception+owner allowed.
  - `POST /memberships/{membership_id}/cancel` — `Depends(require_permission(Action.CANCEL, Resource.MEMBERSHIPS))` + `Depends(verify_csrf)`, body `MembershipCancelRequest`, status 200, returns `ResponseEnvelope[MembershipResponse]`. Owner-only via OWNER_ONLY frozenset.
- RBAC-04 ordering invariant: in every mutation signature, `require_permission` parameter declared before `verify_csrf`. The route-introspection guard test confirms this statically.
- Service layer owns audit emission; router never emits.
- Existing `router = APIRouter()` symbol untouched — `app/api/v1/router.py` imports both via `from app.modules.memberships.router import memberships_router, router as plans_router`.

**Task 2 — `apps/backend/app/api/v1/router.py` mount + `apps/backend/app/main.py` resolver wiring:**
- `app/api/v1/router.py`:
  - Imports `memberships_router` alongside `router as plans_router` (ruff split into two import statements during auto-fix; semantically equivalent).
  - Adds `v1.include_router(memberships_router, prefix='/memberships', tags=['memberships'])` after the existing plans mount. Existing `plans_router` mount at `/membership-plans` preserved.
- `app/main.py`:
  - Imports `register_active_membership_resolver` from `app.core.dependencies` (alongside `register_user_loader`).
  - Imports `resolve_active_membership_by_client` from `app.modules.memberships.service` — the second composition-root carve-out, parallel to the Phase 5 user-loader.
  - `create_app()` calls `register_active_membership_resolver(resolve_active_membership_by_client)` AFTER `register_user_loader(load_user_by_id)` and BEFORE `app.include_router(api)`.
  - Module top-level docstring extended with a Phase 17 additions block documenting the second-loader pattern (mirrors WR-05 reasoning for idempotent re-registration).
  - `create_app()` docstring composition-order list extended to step 7 (resolver registration) and step 8 (include_router).
- All 3 importlinter contracts remain green: `app.core` is the scope of `core-not-depend-on-modules`, so `app.main` reaching into `app.modules.*` is intentionally allowed.

**Task 3 — Migration apply + openapi.json regenerate:**
- `uv run alembic upgrade head` applied `0005_memberships` to dev DB (was at `0004_membership_plans`).
- Verified table schema: 16 columns (id, client_id, plan_id, plan_name_snapshot, duration_days_snapshot, price_kopecks_snapshot, start_date, end_date, status, cancelled_at, cancel_reason, paid_at, notes, activation_policy, created_at, updated_at) plus the composite index `ix_memberships_client_id_status_end_date`.
- Round-trip `uv run alembic downgrade -1 && uv run alembic upgrade head` exited 0 — clean.
- `uv run python -m scripts.export_openapi` regenerated `apps/backend/openapi.json` (65,189 bytes, +498 lines vs Phase 16 baseline).
- Verified spec contains:
  - `/api/v1/memberships` with `get` (operationId `list_memberships_api_v1_memberships_get`) + `post` (`create_membership_api_v1_memberships_post`).
  - `/api/v1/memberships/{membership_id}` with `get` (`get_membership_api_v1_memberships__membership_id__get`).
  - `/api/v1/memberships/{membership_id}/cancel` with `post` (`cancel_membership_api_v1_memberships__membership_id__cancel_post`).
  - Schema components: `MembershipCreateRequest`, `MembershipCancelRequest`, `MembershipResponse`, `MembershipStatus`. (`MembershipListSort` also present per script's auto-discovery; `MembershipListQuery` is inlined as parameters[] not as a $ref — expected FastAPI behaviour for query containers.)
  - List query parameters (`clientId`, `status`, `sort`, `page`, `pageSize`) emitted in **camelCase** confirming `BackendSchemaBase.alias_generator=to_camel` is wired through correctly.
- After commit: `git diff --exit-code apps/backend/openapi.json` exits 0 — CI gate green.

## Why It Matters

This is the **HTTP go-live** moment for membership instances. After this plan:
- `POST /api/v1/memberships` produces a real sale with snapshot fields populated and a `membership_created` audit row enrolled co-transactionally.
- `POST /api/v1/memberships/{id}/cancel` performs the only allowed transition (active → cancelled), emits `membership_cancelled` audit (with `reason` key omitted when None per D-14), and returns 409 `invalid_transition` for non-active source states.
- `GET /api/v1/memberships?clientId=...&status=...` paginates per the v1.1 envelope contract.
- `resolve_active_membership(session, client_id)` returns the canonical active row (latest `end_date`, then `created_at DESC`) from anywhere that imports it — Phase 19 visits service can now wire against a real resolver instead of a stub.
- The composition-root second-loader pattern is now reproducible: future cross-module carve-outs (e.g. when visits in Phase 19 needs to register a check-in callback for billing in Phase X) follow the same shape verbatim.

- **Fix:** Rewrote as "((CANCEL, MEMBERSHIPS) in OWNER_ONLY — reception → 403)" using ASCII syntax.

- **Commit:** Folded into Task 1 commit `9f96428` (fixed before commit).
