| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-06-01 | Tampering | Silent dedup of duplicate email rows | mitigate | Pre-flight RuntimeError (D-47-05) aborts the migration before any DDL touches the table. No silent dedup, no soft-delete, no automatic backfill. Operator must resolve manually and re-run. |
| T-47-06-02 | Tampering | Partial-application state if DDL fails halfway | mitigate | The migration has exactly two operations: pre-flight SELECT (read-only) and op.create_index (atomic in PostgreSQL with default isolation). No alter_column, no add_column, no multi-step DDL. Failure modes are limited to "duplicates present" (caught before DDL) or "Postgres rejects index creation" (well-defined rollback semantics). |
| T-47-06-03 | Information Disclosure | Offending email values leaked in RuntimeError message | accept | The error surface is the operator's terminal, not user-facing. Single-gym pet-project scope — operator already has full DB access. Leaking lower-cased email values to the operator is required for actionable error remediation. |
| T-47-06-04 | Denial of Service | Long-running pre-flight SELECT on a large clients table | accept | Single-gym scale (~hundreds to low thousands of clients). The pre-flight query is GROUP BY on an indexed-eligible column; runtime is O(N) at worst. No production-scale concern. |
