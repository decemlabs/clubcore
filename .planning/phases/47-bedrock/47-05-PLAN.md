  <behavior>
    Conversion rules:

    `kopecks_to_yookassa(kopecks: int) -> str`:
      - Input must be a non-negative int. Negative input raises `ValueError`.
      - Output is a 2-decimal-places string with explicit zero padding: e.g., `19900 → "199.00"`, `0 → "0.00"`, `1 → "0.01"`, `99 → "0.99"`, `100 → "1.00"`, `9_999_999 → "99999.99"`.
      - Conversion path: `Decimal(kopecks) / Decimal(100)`, then `.quantize(Decimal("0.01"), rounding=ROUND_HALF_EVEN)`. The integer division is exact (no float arithmetic).

    `yookassa_to_kopecks(amount: str) -> int`:
      - Input must be a string representing a non-negative monetary amount with at most 2 decimal places: e.g., `"199.00"`, `"0.01"`, `"199"` (treated as `199.00`), `"00100.50"` (leading zeros tolerated — Decimal accepts them).
      - Output is an int (kopecks).
      - Conversion path: `Decimal(amount)` (raises `decimal.InvalidOperation` on bad input — propagate as `ValueError` for caller ergonomics), then `(d * Decimal(100)).quantize(Decimal("1"), rounding=ROUND_HALF_EVEN)`, cast to int.
      - Negative `Decimal` value raises `ValueError`.
      - Non-numeric / scientific-notation / NaN inputs raise `ValueError` (wrap `InvalidOperation`).
      - Inputs with > 2 decimal places are accepted by `Decimal(...)` BUT the quantize-to-cents step would silently round; explicit policy: such inputs MUST be rejected with `ValueError("amount has more than 2 decimal places")`. Detect via `Decimal(amount).as_tuple().exponent` — if `exponent < -2`, raise. (Pinning: ЮKassa never sends sub-cent precision; this rejects malformed inputs early.)
