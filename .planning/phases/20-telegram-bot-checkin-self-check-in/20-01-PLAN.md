<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram client → bot worker | Untrusted user input arrives via `update.message.text` and `update.effective_user.id`. Adversary controls update_id, telegram_user_id, chat_id. |
| Bot handler → Redis dedup | Redis is in-cluster but transient; outage must not break legitimate check-ins. |
| Bot handler → audit_log | The raw telegram_user_id is PII and must never land in audit_log payloads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Information Disclosure (oracle leak) | `checkin_handler` rejection branches DM differentiation | mitigate | D-20-7 + D-20-9 — 4 LOCKED Russian strings as module constants; `ClientNotLinkedError` reuses `_DM_NO_MEMBERSHIP` so a stranger sees the same DM as an unlinked-and-no-membership client. The string-name dispatch ladder has a docstring comment forbidding "fixing" this to a 5th honest-UX string. |
| T-20-02 | Tampering / replay (double-create) | Worker restart or Telegram resending the same Update | mitigate | DB UNIQUE on `(client_id, gym_date)` is the irrevocable invariant (Phase 19); Redis SET-NX-EX `sz:bot:update:{update_id}` TTL 1h is the polite optimization that avoids the wasted Postgres roundtrip. Single redis-py call (`nx=True, ex=3600`), atomic. |
| T-20-03 | Information Disclosure (PII) | Raw `telegram_user_id` in `audit_log.payload` | mitigate | `_hash_telegram_user_id(tg_user_id)` returns sha256 hex; the audit row only stores the hash + `chat_id` (chat_id is already considered audit-safe per Phase 7 precedent). |
| T-20-04 | Denial of Service (Redis outage) | `ctx.redis.set` raises ConnectionError/TimeoutError | mitigate (fail-open) | D-20-3 — `try/except Exception: log WARN bot_redis_dedup_unavailable; proceed`. The DB UNIQUE constraint remains the anti-replay backstop. NOT accepted as DoS because the legitimate user still gets a DM and a visit; only the dedup optimization degrades. |
</threat_model>
