    ```python
    """Wire-format contract: ContractModel hierarchy + ResponseEnvelope[T] + ProblemDetails (D-07..D-14, API-03).

    Backend-first contract (D-07):
      - Successful 2xx responses serialize to { "data": <payload> } via ResponseEnvelope[T].
      - Errors stay top-level { code, message, fields? } (D-08) — matches AppError handler output.
      - Wire format is camelCase via pydantic.alias_generators.to_camel; Python identifiers
        stay snake_case.
      - `validate_by_name=True` + `validate_by_alias=True` paired (Pydantic 2.11+) replaces
        the deprecated `populate_by_name=True`. Setting BOTH to False is invalid (raises
        PydanticUserError at class-definition time).
      - PEP 695 generics for ResponseEnvelope[T] (D-11). NO `typing.Generic[T]` / `TypeVar`.

    Phase 4 envelope (D-13) is { data: T } only — minimum viable. Optional fields
    (requestId, traceId, meta, warnings) deferred to whichever phase first needs them;
    they will be additive Optional[...] = None so existing clients ignore them.
    """

    from pydantic import BaseModel, ConfigDict
    from pydantic.alias_generators import to_camel


    class ContractModel(BaseModel):
        """Base for every API contract model. camelCase wire, snake_case Python."""

        model_config = ConfigDict(
            alias_generator=to_camel,
            validate_by_name=True,
            validate_by_alias=True,
            from_attributes=True,
            extra="ignore",
        )


    class RequestContract(ContractModel):
        """Inbound request body / query params. Strict on extras (extra='forbid')."""

        model_config = ConfigDict(
            alias_generator=to_camel,
            validate_by_name=True,
            validate_by_alias=True,
            extra="forbid",
        )


    class ResponseData(ContractModel):
        """Payload inside ResponseEnvelope. Subclassed by every domain response DTO."""


    class ResponseEnvelope[T](ContractModel):
        """Success transport wrapper. Phase 4: { data: T }. Future fields optional (D-13)."""

        data: T


    class ProblemDetails(ContractModel):
        """Error response body — documents the shape emitted by app.core.exceptions._app_error_handler.

        Used as `responses={4xx: {"model": ProblemDetails}}` on routes so OpenAPI carries the
        error schema; the runtime handler body is unchanged (top-level { code, message, fields? }
        per D-08, NOT wrapped in `data`).
        """

        code: str
        message: str
        fields: dict[str, object] | None = None


    def envelope[T](payload: T) -> ResponseEnvelope[T]:
        """Convenience helper. D-14: routes return ResponseEnvelope[X](data=...) explicitly,
        but a small wrapper is acceptable (and reduces import noise in route handlers)."""
        return ResponseEnvelope(data=payload)
    ```

    Strict requirements:
    - Module imports ONLY `from pydantic import BaseModel, ConfigDict` and `from pydantic.alias_generators import to_camel`. NO `typing.Generic`, NO `TypeVar`, NO third-party libs. Pure pydantic.
    - The `RequestContract` `model_config` is a FRESH `ConfigDict(...)` (not a copy/merge of `ContractModel.model_config`) — Pydantic merges config across MRO, so we explicitly redeclare to make `extra='forbid'` un-missable for code reviewers; alias_generator + validate_by_name + validate_by_alias are repeated for the same reason. `from_attributes` is dropped from `RequestContract` (request bodies don't validate from ORM objects).
    - `ResponseEnvelope[T]` uses PEP 695 syntax (`class Foo[T](Bar):`), NOT `class Foo(Bar, Generic[T])` — Python 3.12 + Pydantic 2.11+ support this natively (Pitfall C).
    - The `envelope` helper uses PEP 695 syntax for the function (`def envelope[T](...)` — Python 3.12+).
    - File ends with the `envelope` function definition. No module-level executable code.
    - Do NOT add `populate_by_name=True` anywhere — it's the deprecated 2.11 alias (Pitfall A).

| T-04-18 | Information disclosure | response payload accidentally leaks Python-only attributes (e.g., `_internal`, snake_case fields meant to be private) | mitigate | Domain DTOs subclass `ResponseData`; only fields declared on the DTO are serialized. `extra='ignore'` on `ContractModel` drops extras during validation but does NOT influence serialization.
