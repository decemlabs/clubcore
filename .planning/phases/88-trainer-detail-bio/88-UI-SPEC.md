## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Avatar ring gap; icon gap from label |
| sm | 8px | Row internal gap (avatar + content); hero sub-row gap; skeleton line gap |
| xs+ | 12px | Bio section vertical padding inside card; section label bottom margin |
| md | 16px | Sheet horizontal padding; card internal padding; hero card padding; CTA bar horizontal padding |
| lg | 24px | Section vertical gap between hero block and bio card; empty/error vertical centering offset |
| xl | 32px | Bottom safe-area padding; CTA bar bottom padding (above safe area) |
| 2xl | 48px | Not used in this sheet |
| 3xl | 64px | Not used in this sheet |

Exceptions (inherited from existing shipped components — do not change):

- `xs+` (12px) is a multiple of 4 but sits outside the canonical 8-point set {4,8,16,24,32,48,64}. It is **inherited from the existing shipped row pattern** (BonusHistorySheet / LoyaltySheet / GymInfoSheet compact rows) and is replicated here for visual consistency — not a new value introduced by this phase. Documented exception per Phase 86/87 UI-SPEC precedent.
- `SubSheetHeader` is reused as-is. Its internal padding is owned by the shared component and is not governed by this phase's spacing contract. Do not enumerate or modify its values.
- Sheet entry animation uses `position: absolute; inset: 0; z-index: 220` — no spacing exception; matches the existing sub-sheet pattern (BonusHistorySheet, CardSheet, GymInfoSheet, NotificationsSheet).
- `Avatar` component uses `size * 0.36` for font-size — computed from size prop; this is an internal Avatar.jsx convention, not a new inline override introduced by this phase.
- Hairline dividers use `height: 0.5px` — sub-pixel value for retina hairline; inherited from BonusRow / GymInfoSheet divider pattern.

No undocumented non-multiple-of-4 values remain. All new-to-this-phase measurements are multiples of 4.

## Layout: TrainerDetailSheet Structure

The sheet is a **full-screen sub-sheet** (z-index 220, `sheet-up` animation, `position: absolute; inset: 0`). It is read-only except for the CTA (outbound navigation — no mutations inside this sheet).

Shell structure is analogous to GymInfoSheet and NotificationsSheet — same `StatusBar` / `SubSheetHeader` / `PullToRefresh` / scroller frame.

### Visual Sections (top to bottom)

```
StatusBar
SubSheetHeader ("Тренер")
─── PullToRefresh / .scroller ──────────────────────
  [1] HERO BLOCK         — avatar (photo or initials), name, specialization
  [2] BIO SECTION        — section label + card: long-form bio text (or empty hint)
  [bottom padding: 32px]
────────────────────────────────────────────────────
─── CTA BAR (sticky bottom) ────────────────────────
  ["Записаться" primary button]
────────────────────────────────────────────────────
```

The CTA bar is sticky at the bottom of the screen (outside the scroller), using a gradient fade-to-background above it — identical pattern to BookScreen's confirmation bar and flows.jsx primary actions.

### [1] Hero Block

Container: `padding: 24px 16px 16px; display: flex; flex-direction: column; align-items: center; gap: 8px`.

Visual structure (center-aligned):

```
[Avatar — 80×80, border-radius 50%, bg+color from trainer data, or photo_url if present]
[gap 12px]
[trainer.name — .t-h2 color var(--text) text-align center]
[gap 4px]
[trainer.specialization — .t-body color var(--text-2) text-align center]
  (omitted if specialization is null)
```

**Avatar rendering rule:**
- If `photo_url` is non-null: render `<img src={photo_url} width={80} height={80} style={{ borderRadius: '50%', objectFit: 'cover' }} alt={trainer.name} />`.
- If `photo_url` is null: render `<Avatar initials={trainer.initials} bg={trainer.bg} color={trainer.color} size={80} />`.
- `initials` is derived client-side: first letter of first name + first letter of last name (e.g. "Аня Соколова" → "АС"). This mirrors the existing `BookScreen.jsx` `getInitials` helper.
- `bg` and `color` are from trainer API response — seeded per CONTEXT.md.
- Fallback if `initials`/`bg`/`color` are absent: `<Avatar initials="?" bg="var(--surface-2)" color="var(--text-3)" size={80} />`.

Container is NOT a `.card` — it sits directly on `var(--bg)` for a clean hero appearance.

### [2] Bio Section

Rendered always (section label + card always present; card content varies).

Section label: `.t-mini` color `var(--text-3)` `padding: 16px 16px 8px` → "БИОГРАФИЯ"

Container: `.card` with `padding: 12px 16px; margin: 0 16px`.

**If `bio` is non-null and non-empty:**
```
[.t-body color var(--text-2) line-height 1.6 — bio text, may wrap to multiple lines]
```

**If `bio` is null or empty:**
```
[.t-small color var(--text-3) — "Информация скоро появится."]
```

No hairline dividers inside the bio card (single-content block).

## CTA Bar

Sticky bottom bar (outside the scroller), renders always (even during loading/error — the onBook action always available).

Structure:
```
gradient fade: linear-gradient(to top, var(--bg) 60%, transparent) — height 24px above bar
bar container: padding 8px 16px 32px; background var(--bg)
  [<button className="btn btn-accent" onClick={onBook} style={{ width: '100%' }}>
    Записаться
  </button>]
```

- `height: 50px` from `.btn` base class — no inline override needed.
- `width: 100%` — full-width, consistent with BookScreen booking confirm CTA and flows.jsx primary buttons.
- `padding-bottom: 32px` accounts for the safe-area (matches BookScreen's CTA bar pattern).
- If `onBook` prop is not provided (sheet opened without booking context): button renders as disabled (`disabled` attribute, `.btn:disabled { opacity: 0.4 }`). Copy remains "Записаться".

No "Оплатить" / `onCheckout` CTA is rendered in this sheet. `onCheckout` prop is accepted but the checkout flow is initiated from BookScreen after trainer selection — TrainerDetailSheet only surfaces the booking entry point.

## Loading State

While `isLoading` (query pending, no prior cached data):

SubSheetHeader is visible (allows close). Scroller content replaced with skeletons. CTA bar remains visible.

```
[Hero block area skeleton]
  padding: 24px 16px 16px; display flex; flex-direction column; align-items center; gap 8px
  [.sk .sk-circle width:80 height:80 borderRadius:50%]   — avatar skeleton
  [.sk .sk-line width:140 height:18 margin: 8px auto]    — name skeleton
  [.sk .sk-line width:100 height:14 margin: 4px auto]    — spec skeleton

[Bio section skeleton]
  section label: .sk .sk-line width:80 margin: 16px 16px 8px
  .card padding: 12px 16px margin: 0 16px
    [.sk .sk-line width:100% marginBottom: 8px]
    [.sk .sk-line width:80%  marginBottom: 8px]
    [.sk .sk-line width:60%]
```

Skeleton containers maintain the same structural padding/margins as loaded equivalents — no layout shift on data reveal.

`.sk-circle` is the existing skeleton class for circular elements (used in NotificationsSheet; consistent with `.sk` pulsing animation).

## Error State

Inline error within the sheet (sheet stays open with `SubSheetHeader` visible — user can close or pull-to-refresh).

Visual: centered in the content area, `padding: 40px 24px; text-align: center`.

```
[Icon "alertCircle" size 32 — in 56×56 circle, background: var(--surface-2), color: var(--text-3)]
[gap 16px]
[.t-small color var(--text-2) — "Не удалось загрузить профиль тренера. Потяните вниз, чтобы повторить."]
```

Pull-to-refresh (`<PullToRefresh>`) wraps the scroller content, consistent with GymInfoSheet and NotificationsSheet.

CTA bar remains visible during error state. `onBook` is still callable (navigates to BookScreen where trainer can be selected).

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Sheet open | Fetch `GET /client/trainers/{id}` using trainer id from `ui.trainerDetail.id`; show skeleton during load |
| Pull-to-refresh | Calls `refetch()` on the trainer detail query; shows loading skeleton during re-fetch |
| "Записаться" tap | `onBook()` prop — closes TrainerDetailSheet, switches to BookScreen tab (existing App.jsx wiring: `ui.setTrainerDetail(null); handleTab('book')`) |
| Close (chevronLeft in SubSheetHeader) | `onClose()` prop — `ui.setTrainerDetail(null)` |
| Avatar photo load error | Falls back to `<Avatar initials=... />` via `img onError` handler |
| Error state pull-to-refresh | Re-triggers the query; skeleton replaces error during re-fetch |

`onCheckout` prop is wired by the parent (`App.jsx`) but not exposed as a visible button in this sheet. It is available for future use (e.g. direct checkout from trainer profile) without requiring a layout change.
