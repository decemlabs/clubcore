<objective>
Ship the two ARQ crons that close the resilience loop for Phase 51:

1. **`monitor_stale_fiscal_receipts`** (FISCAL-06) — runs every 15 min. SELECTs `fiscal_receipts` where status='pending' for >90s, flips them to 'failed' with reason='stale_pending_no_dispatch', emits `fiscal_receipt_failed` audit. Catches the upstream-error case where the Phase 50 atomic UoW inserted the row but the dispatch enqueue never fired (or the worker was down at enqueue time).

2. **`poll_pending_refunds`** (REFUND-04) — runs every 30 min. SELECTs `online_refunds` where status='pending' for >30min, calls `GET /v3/refunds/{id}` for each, and:
   - On result.status='succeeded' (the webhook was lost): synthesize the same UoW as `handle_refund_succeeded` via a shared helper `_settle_online_refund(...)` (D-51-18), with chain-root audit event `online_refund_polled_settled` instead of `yookassa_webhook_received`.
   - On result.status='canceled': UPDATE row to 'canceled', emit `online_refund_canceled` audit.
   - On result.classification != 'ok': structlog WARNING + leave for next tick.

Per D-51-17 step 6, both crons apply a 50-row loop budget per tick (Phase 27 expiring-notifications precedent).

Per D-51-Discretion + D-51-17, both use `SELECT FOR UPDATE SKIP LOCKED` (Postgres-specific) to avoid lock contention with the dispatch task / refund webhook handler.

**About the shared `_settle_online_refund` helper (D-51-18 refactor):**

This plan extracts a shared helper that BOTH callers use. **Refactor target:** since plan 51-07 ships handle_refund_succeeded with the inline body, this plan REFACTORS that body to delegate to the shared helper. """Phase 51 fiscal_receipts service helpers — exposed to ARQ crons.

Caller-owns-txn (D-32-10): NO session.flush()/commit() in helpers; the cron
wrapper owns session lifecycle and commit point.
"""
from __future__ import annotations

from datetime import UTC, datetime, timedelta
from typing import Any

import structlog
from sqlalchemy import select
from sqlalchemy.ext.asyncio import async_sessionmaker

from app.core import audit
from app.core.audit_payloads import FiscalReceiptFailedPayload
from app.modules.fiscal_receipts.constants import STATUS_FAILED, STATUS_PENDING
from app.modules.fiscal_receipts.models import FiscalReceipt

_log = structlog.get_logger("modules.fiscal_receipts.service")


async def _monitor_stale_fiscal_receipts(session_factory: async_sessionmaker[Any]) -> int:
    """Phase 51 FISCAL-06 — flip stale fiscal_receipts(pending) → failed.

    Selects fiscal_receipts with status='pending' AND created_at < now() - 90s,
    FOR UPDATE SKIP LOCKED, limit 50.

    For each: status='failed', failed_at=now(UTC), failure_reason='stale_pending_no_dispatch';
    emit fiscal_receipt_failed audit.

    Returns count of rows flipped.
    """
    flipped = 0
    cutoff = datetime.now(UTC) - timedelta(seconds=90)
    async with session_factory() as session, session.begin():
        stmt = (
            select(FiscalReceipt)
            .where(FiscalReceipt.status == STATUS_PENDING)
            .where(FiscalReceipt.created_at < cutoff)
            .limit(50)
            .with_for_update(skip_locked=True)
        )
        rows = (await session.execute(stmt)).scalars().all()
        for row in rows:
            row.status = STATUS_FAILED
            row.failed_at = datetime.now(UTC)
            row.failure_reason = "stale_pending_no_dispatch"
            await audit.emit(
                session,
                "fiscal_receipt_failed",
                actor_user_id=None,
                resource_type="fiscal_receipt",
                resource_id=row.id,
                payload=FiscalReceiptFailedPayload(
                    audit_correlation_id=row.audit_correlation_id,
                    fiscal_receipt_id=row.id,
                    failure_reason="stale_pending_no_dispatch",
                ),
            )
            flipped += 1
    return flipped
```

"""Phase 51 online_refunds cron-body helpers (REFUND-04).

Caller-owns-txn (D-32-10): per-row UoW inside the cron wrapper.
Multi-session pattern: snapshot the batch, close session, do HTTPS per row,
re-open session per row for the settle UoW (avoids holding a DB connection
across N round-trips to ЮKassa).
"""
from __future__ import annotations

from datetime import UTC, datetime, timedelta
from typing import Any
from uuid import uuid4

import structlog
from sqlalchemy.exc import IntegrityError
from sqlalchemy.ext.asyncio import async_sessionmaker

from app.core import audit
from app.core.audit_payloads import OnlineRefundCanceledPayload
from app.integrations.yookassa.client import YooKassaClient
from app.modules.online_refunds import repository as refund_repo
from app.modules.online_refunds.settle import _settle_online_refund
from app.modules.online_refunds.constants import STATUS_CANCELED
from app.modules.payments.repository import _is_refund_of_uniqueness_conflict

_log = structlog.get_logger("modules.online_refunds.cron")


async def _poll_pending_refunds(
    session_factory: async_sessionmaker[Any],
    yookassa_client: YooKassaClient,
) -> int:
    """Phase 51 REFUND-04 — reconcile pending online_refunds via get_refund.

    Sequence (D-51-17):
      1. Snapshot up to 50 pending rows older than 30 min (single short txn).
      2. For each row: call get_refund(row.yookassa_refund_id).
      3a. status='succeeded' → re-open session, call _settle_online_refund with
          chain_root_event='online_refund_polled_settled' + audit_correlation_id=fresh_uuid4.
      3b. status='canceled' → UPDATE row.status='canceled', emit online_refund_canceled audit.
      3c. classification != 'ok' → structlog WARNING, leave for next tick.
      4. Return processed count.
    """
    processed = 0
    cutoff = datetime.now(UTC) - timedelta(minutes=30)

    # Step 1 — snapshot the batch
    async with session_factory() as session:
        rows = await refund_repo.select_pending_older_than(session, cutoff=cutoff, limit=50)
        row_ids = [r.id for r in rows]
        row_refund_ids = [(r.id, r.yookassa_refund_id) for r in rows]
    # session closed; ready to make HTTPS calls

    for refund_row_id, yookassa_refund_id in row_refund_ids:
        result = await yookassa_client.get_refund(yookassa_refund_id)
        if result.classification != "ok":
            _log.warning(
                "yookassa_refund_poll_refetch_failed",
                refund_row_id=str(refund_row_id),
                classification=result.classification,
            )
            continue

        if result.status == "succeeded":
            # Step 3a — synthesize the same settle UoW as handle_refund_succeeded
            corr = uuid4()
            async with session_factory() as session, session.begin():
                try:
                    await _settle_online_refund(
                        session,
                        online_refund_id=refund_row_id,
                        chain_root_corr=corr,
                        chain_root_event="online_refund_polled_settled",
                        chain_root_event_payload_kwargs={
                            "online_refund_id": refund_row_id,
                            "yookassa_refund_id": yookassa_refund_id,
                            "settled_at": datetime.now(UTC),
                        },
                    )
                except IntegrityError as exc:
                    if _is_refund_of_uniqueness_conflict(exc):
                        _log.warning(
                            "yookassa_refund_poll_idempotent_replay",
                            refund_row_id=str(refund_row_id),
                        )
                        continue
                    raise
            processed += 1

        elif result.status == "canceled":
            # Step 3b
            async with session_factory() as session, session.begin():
                row = await refund_repo.get_online_refund_by_id(session, refund_row_id)
                if row is None:
                    _log.warning("yookassa_refund_poll_row_disappeared", refund_row_id=str(refund_row_id))
                    continue
                refund_repo.mark_canceled(row, canceled_at=datetime.now(UTC))
                cancellation_reason = result.cancellation_reason  # implementer verifies field name on YooKassaRefundResult
                await audit.emit(
                    session,
                    "online_refund_canceled",
                    actor_user_id=None,
                    resource_type="online_refund",
                    resource_id=row.id,
                    payload=OnlineRefundCanceledPayload(
                        audit_correlation_id=None,  # chain root for this terminal action
                        online_refund_id=row.id,
                        yookassa_refund_id=yookassa_refund_id,
                        cancellation_reason=cancellation_reason,
                    ),
                )
            processed += 1
        else:
            # status still 'pending' on ЮKassa side — leave for next tick
            _log.info(
                "yookassa_refund_poll_still_pending",
                refund_row_id=str(refund_row_id),
                status=result.status,
            )

    return processed
```
