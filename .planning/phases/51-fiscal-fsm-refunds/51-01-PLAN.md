## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-01-01 | Tampering | `online_refunds.status` | mitigate | DB-level CHECK constraint `status IN ('pending','succeeded','canceled')` rejects any other value; the FSM constant in plan 51-02 mirrors this for application-layer guards. |
| T-51-01-02 | Repudiation | Refund-request audit trail | mitigate | `audit_correlation_id` nullable UUID column lets every refund request chain to a fresh `online_refund_initiated` audit row (plan 51-02 + 51-08); ON DELETE RESTRICT on `requested_by_user_id` preserves operator identity. |
| T-51-01-03 | Denial of Service | Concurrent duplicate refund POSTs racing to insert two `online_refunds` rows for the same `online_payment_id` | mitigate | Partial UNIQUE `(online_payment_id) WHERE status IN ('pending','succeeded')` makes the second concurrent insert raise IntegrityError at the DB layer — the second request gets a 409, not a duplicate ЮKassa /refunds call. |
| T-51-01-04 | Tampering | Caller-supplied `idempotency_key` collision attempts | mitigate | UNIQUE on `idempotency_key` makes replays return the same row (caller-owned idempotency per D-48-11); cannot be used to overwrite an existing refund row's terminal state. |
| T-51-01-05 | Data leakage | PII in migration | accept | Migration ships schema only; no seed data, no PII. |
