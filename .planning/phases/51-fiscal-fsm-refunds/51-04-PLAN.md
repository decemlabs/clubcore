<objective>
Ship the ЮKassa-scoped Redis sliding-window circuit breaker by **copy-and-adapt** from `app/integrations/email/circuit_breaker.py` (D-51-14 — explicitly chosen over generalization to keep the `integrations-isolated` import-linter contract clean).

Purpose: Phase 51's `dispatch_fiscal_receipt` ARQ task (plan 51-05) calls `await yookassa.create_receipt(...)`. On `classification == "transient_error"` it calls `await record_failure(redis, "receipts")` and then `raise arq.Retry(...)`. Before every dispatch attempt, it checks `await is_circuit_open(redis, "receipts")` — if open, it short-circuits with `Retry(defer=300)` (Pitfall 11 step 1). This file is the implementation those checks call.

The two Redis keys are scoped to the integration:
- `sz:yookassa:circuit_window:receipts` (sorted-set of recent failure timestamps)
- `sz:yookassa:circuit:receipts` (open-marker key; EXISTS = breaker is open; TTL expiry = breaker closes)

Output: 1 new file in `app/integrations/yookassa/` + 1 unit test file + verification that the .importlinter `integrations-isolated` contract still holds.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ARQ task → Redis | Failure counter + open-marker writes; Redis is trusted within the deployment perimeter. |
| Multiple worker replicas → same Redis keys | Race condition surface for the failure counter; mitigated by atomic pipeline. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-04-01 | Race condition | Two ARQ workers calling record_failure simultaneously could miscount failures, delaying breaker opening | mitigate | `redis.pipeline(transaction=True)` wraps ZADD + ZREMRANGEBYSCORE + EXPIRE + ZCARD in a MULTI/EXEC block — ZCARD reflects post-state atomically (Pitfall 11). |
| T-51-04-02 | Tampering | Out-of-window failure timestamps left in the sorted set | mitigate | Every `record_failure` runs `ZREMRANGEBYSCORE 0 cutoff` removing entries older than `_WINDOW_SECONDS * 1000` ms; `EXPIRE` on the window key acts as a second cleanup. |
| T-51-04-03 | DoS | Breaker stuck open forever after a transient burst | mitigate | Open marker has `ex=_OPEN_TTL_SECONDS` (300s) — only closing surface is TTL expiry; no manual reset path. Acceptable per Pitfall 11 design. |
| T-51-04-04 | DoS | Failure window key growing unbounded if member uniqueness collides | mitigate | Member format `f"{now_ms}-{uuid4().hex[:8]}"` makes collisions astronomically unlikely (millisecond timestamp + 32-bit random suffix). |
| T-51-04-05 | Information Disclosure | Provider name leaking through structlog | accept | `provider` values are static literals (`"receipts"`) — not PII. |
| T-51-04-06 | Cross-integration coupling | Generalizing to `app/core/circuit_breaker.py` would let `email` and `yookassa` modules co-import, violating `integrations-isolated` contract | mitigate | D-51-14 LOCKED: copy-and-adapt, NOT generalize. lint-imports verifies. |
</threat_model>

```python
async def record_failure(redis: Redis, provider: str) -> None:
    window_key = f"{_WINDOW_KEY_PREFIX}{provider}"
    now_ms = int(time.time() * 1000)
    member = f"{now_ms}-{uuid4().hex[:8]}"
    cutoff = now_ms - _WINDOW_SECONDS * 1000

    async with redis.pipeline(transaction=True) as pipe:
        pipe.zadd(window_key, {member: now_ms})
        pipe.zremrangebyscore(window_key, 0, cutoff)
        pipe.expire(window_key, _WINDOW_SECONDS * 2)
        pipe.zcard(window_key)
        results = await pipe.execute()

    count = int(results[3])

    if count >= _FAILURE_THRESHOLD:
        await redis.set(
            f"{_CIRCUIT_KEY_PREFIX}{provider}",
            "1",
            ex=_OPEN_TTL_SECONDS,
        )
        _log.warning("circuit_open", provider=provider, failures_in_window=count)
```
