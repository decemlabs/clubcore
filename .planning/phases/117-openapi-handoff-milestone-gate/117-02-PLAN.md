<objective>
Structurally close the v3.0/v3.1 mock↔real schema-drift lesson (D-V32-DRIFT-LESSON): for each of the
five new v3.2 domains, a backend ASGITransport test hits the REAL endpoint and serializes the actual
JSON response into a shared `capture/` fixtures directory; an FE vitest contract test then loads that
captured JSON and parses it with the domain's REAL FE Zod schema, asserting it passes. The CSV
payments export is asserted at the backend tier (BOM/headers/status) since it is not a Zod-parsed body.

The captured JSON is GENERATED by the backend test from the live ASGITransport call (never
hand-authored) — this closes the loop "real backend JSON ↔ real FE Zod schema" end-to-end, the exact
failure mode that twice passed the formal gate but broke in browser-UAT.

Purpose: ≥1 real-backend contract test per new domain (HND-01 criterion #2).
Output: 6 new backend test files (5 capture + 1 CSV), 5 FE contract tests, 5 captured snapshot JSON
files, and the messages schema export needed for its contract test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ASGITransport response → capture/*.json | Test-generated snapshot of a real (in-process) backend response over synthetic seed data. |
| capture/*.json → FE Zod parse | Build-time test input; the fixture is committed and read by vitest. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-04 | Information disclosure | capture/*.json fixtures | mitigate | Capture tests run against SAVEPOINT `db_session` seeded with synthetic test data only (no real PII/secrets); seed helpers reuse the existing test seeds. Reviewer confirms captured JSON contains only synthetic fixture values before commit. |
| T-117-05 | Tampering | hand-authored fixture defeating drift guard | mitigate | Fixtures are GENERATED by the backend ASGITransport `r.json()` write (Task 1), never hand-authored; an FE contract test parsing a hand-faked fixture would defeat the drift-lesson, so the action forbids manual authoring and the backend test is the sole writer. |
| T-117-06 | Spoofing/Elevation | refund/role-change capture using owner principal | accept | Capture tests use `authed_client_owner` (owner-only endpoints) by design; RBAC enforcement itself is covered by the existing domain RBAC tests, not re-tested here. |
| T-117-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — uses already-pinned pytest/httpx (backend) and vitest/zod (FE). No legitimacy gate required. |
</threat_model>
