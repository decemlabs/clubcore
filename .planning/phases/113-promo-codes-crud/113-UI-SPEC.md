## Surface 1: "Скидки и акции" section on PlansPage

### Trigger / section head

The existing `<section ref={promosRef}>` in `PlansPage.tsx` is wired to real data.
The `SectionHead` action button changes from a toast stub to opening `PromoCodeModal`:

```
SectionHead
  title:    "Скидки и акции"
  subtitle: "Активные предложения, видны клиентам в приложении"
  action:   can(role, 'create', 'promo-codes') ?
              <button class={ADD_BTN} onClick={openCreateModal}>
                <Plus class="size-3.5" strokeWidth={2.4} />
                Создать промокод
              </button>
            : null
```

### List layout

```
<div className="grid grid-cols-1 gap-4 lg:grid-cols-2">
  {promoCodes.map(p => <PromoCard key={p.id} promo={p} ... />)}
</div>
```

Matches the existing mock layout (inherited from PlansPage).

### States

| State | Behavior |
|-------|----------|
| Loading | `<PageLoading />` |
| Error (non-403) | `<PageError onRetry={...} />` |
| Error 403 | `<EmptyState icon={Lock} title="Недостаточно прав" message="Этот раздел доступен только владельцу. Обратитесь к владельцу клуба." />` |
| Empty (0 codes) | `<EmptyState icon={Tag} title="Промокодов пока нет" message="Создайте первый промокод, чтобы он появился у клиентов в приложении." action={canCreate ? <button class={ADD_BTN}>Создать промокод</button> : null} />` |
| Loaded | Grid of `PromoCard` components |

### PromoCard data mapping (mock → real API)

The existing `PromoCard` renders a `Promo` type from `features/plans/types.ts`.
The real response shape is `PromoCodeData` (from `features/promoCodes/schemas.ts`).
PromoCard is updated or a wrapper maps API data to the card's display props:

| Card prop | Mapped from API |
|-----------|----------------|
| `title` | `code` (uppercase) |
| `codeChip` | `code` (same — displayed as monospace chip) |
| `iconKind` | Derived: `discount_type === 'percentage'` → `'percent'`, else `'discount'` |
| `status` | `is_active ? 'active' : 'inactive'` |
| `statusLabel` | `is_active ? 'Активен' : 'Неактивен'` |
| `sub` | `description ?? ''` |
| `stats` | See stats rows below |
| `actions` | Wired: Изменить (owner only), Деактивировать (owner only, only if active) |

Stats rows rendered on each card:

| Label | Value |
|-------|-------|
| Скидка | `discount_type === 'percentage'` → `{discount_value / 100}%`; else `formatKopecks(discount_value)` |
| Использований | `{used_count} / {max_uses ?? '∞'}` |
| Действует | validity window string (see Copywriting) |
| Лимит на клиента | `{per_client_limit ?? '—'}` |

### PromoCard action buttons (wired)

| Action | Condition | Behavior |
|--------|-----------|----------|
| Изменить | `can(role, 'edit', 'promo-codes')` | Opens `PromoCodeModal` in edit mode with the card's data pre-filled |
| Деактивировать | `can(role, 'delete', 'promo-codes') && is_active` | Opens `ConfirmModal` with danger tone |

Reception sees neither action (both hidden, not disabled).

## Surface 2: PromoCodeModal (create/edit)

### Trigger

- **Create:** "Создать промокод" button in `SectionHead` action — owner only.
- **Edit:** "Изменить" action on a `PromoCard` — owner only.

### Modal structure

```
AdaptiveModal
  icon:        <IconChip tone="accent" icon={Tag} />
  title:       create → "Создать промокод"
               edit   → "Редактировать промокод"
  description: create → null
               edit   → "{code}" (12.5px, fg-muted — shows current code)
  size:        "default"   (max-w-[540px])

  body (px-5 py-[18px]):

    <Section>Код и скидка</Section>

    <Field label="Промокод" required hint="Латинские буквы и цифры. Автоматически переводится в верхний регистр.">
      <ModalInput
        placeholder="SUMMER25"
        maxLength={32}
        onChange → toUpperCase on display
      />
    </Field>

    <FieldRow cols={2}>
      <Field label="Тип скидки" required>
        <ChipGroup
          options={[
            { value: 'percentage', label: 'Процент' },
            { value: 'fixed',      label: 'Фикс. сумма' },
          ]}
          value={discountType}
          onChange={setDiscountType}
        />
      </Field>
      <Field
        label={discountType === 'percentage' ? 'Размер скидки, %' : 'Размер скидки, ₽'}
        required
        hint={discountType === 'percentage'
          ? 'От 1 до 100'
          : 'Целое число рублей'}
      >
        <ModalInput
          type="number"
          min={discountType === 'percentage' ? 1 : 1}
          max={discountType === 'percentage' ? 100 : undefined}
          step={discountType === 'percentage' ? 1 : 1}
          suffix={discountType === 'percentage' ? '%' : '₽'}
        />
      </Field>
    </FieldRow>

    <Section>Ограничения</Section>

    <FieldRow cols={2}>
      <Field label="Макс. использований" optional hint="Пусто — без ограничений">
        <ModalInput type="number" min={1} step={1} placeholder="∞" />
      </Field>
      <Field label="Лимит на клиента" optional hint="Пусто — без ограничений">
        <ModalInput type="number" min={1} step={1} placeholder="∞" />
      </Field>
    </FieldRow>

    <Section>Срок действия</Section>

    <FieldRow cols={2}>
      <Field label="Начало действия" optional>
        <ModalInput type="date" />
      </Field>
      <Field label="Конец действия" optional>
        <ModalInput type="date" />
      </Field>
    </FieldRow>

    <Section>Дополнительно</Section>

    <Field label="Применять к" optional hint="Пусто — применяется ко всем тарифам">
      <ModalInput placeholder="Напр.: Тариф «Стандарт»" />
    </Field>

    <Field label="Описание" optional>
      <ModalTextarea
        placeholder="Внутренняя заметка о промокоде…"
        rows={2}
      />
    </Field>

  footerActions:
    <ModalButton variant="ghost">Отмена</ModalButton>
    <ModalButton variant="primary" disabled={!valid || busy}>
      create → "Создать промокод"
      edit   → "Сохранить изменения"
    </ModalButton>
```

### Validation states

| State | Behavior |
|-------|----------|
| Code empty | Confirm button disabled |
| Discount value empty or ≤ 0 | Confirm button disabled |
| Discount type = percentage AND value > 100 | Confirm button disabled; inline hint under field turns `text-danger`: "Процент не может быть больше 100" |
| valid_until < valid_from | Confirm button disabled; hint under «Конец действия» turns `text-danger`: "Дата окончания не может быть раньше даты начала" |
| Busy (mutation in flight) | Both buttons disabled; confirm button shows reduced opacity or spinner |
| Success (create) | Modal closes; Sonner `toast.success("Промокод создан", { description: code })` |
| Success (edit) | Modal closes; Sonner `toast.success("Промокод обновлён", { description: code })` |
| Backend 409 `promo_code_already_exists` | Modal stays open; `toast.error("Промокод с таким кодом уже существует")` |
| Backend 422 validation | Modal stays open; `toast.error("Проверьте правильность заполнения полей")` |
| Backend 5xx / network | `toast.error("Не удалось сохранить промокод. Попробуйте ещё раз.")` |

## Surface 3: Deactivate ConfirmModal

The existing generic `ConfirmModal` (via `modals-context` or direct invocation) is
used for deactivation. No new component is created.

### Configuration

```
ConfirmModal (existing universal component)
  payload:
    title:        "Деактивировать промокод"
    message:      "Промокод «{CODE}» будет деактивирован. Клиенты не смогут им воспользоваться. Это действие необратимо."
    confirmLabel: "Деактивировать"
    cancelLabel:  "Отмена"
    tone:         "danger"
    onConfirm:    () => deactivateMutation.mutateAsync(promo.id)
```

### States

| State | Behavior |
|-------|----------|
| Busy | Confirm button disabled |
| Success | Modal closes; Sonner `toast.success("Промокод деактивирован", { description: code })` |
| Backend 404 | `toast.error("Промокод не найден. Возможно, он уже удалён.")` |
| Backend 403 | Not reachable via UI (action hidden); if hit: `toast.error("Недостаточно прав")` |
| Backend 5xx | `toast.error("Не удалось деактивировать промокод. Попробуйте ещё раз.")` |

## Accessibility Contract

- All modal triggers have `aria-label` or visible text label in Russian.
- `AdaptiveModal` renders `DialogTitle` / `DrawerTitle` — screen reader announces modal title on open.
- Confirm buttons carry `disabled` attribute (not just visual opacity) when validation fails.
- Numeric `<input type="number">` fields for discount value, max_uses, per_client_limit have `min` and `step` attributes; percentage value also has `max={100}`.
- `<input type="date">` fields for validity window use native browser date picker — no custom calendar component needed for this phase.
- `ChipGroup` buttons use `aria-pressed` (already implemented in `fields.tsx`).
- Focus trap handled by Radix Dialog / Drawer primitives (inherited from `AdaptiveModal`).
- `Tag` icon in PromoCodeModal header chip: decorative — title provides context.
- Deactivate button in PromoCard is only rendered when `is_active === true`; hidden (not disabled) when `is_active === false`, preventing confusion about already-inactive codes.
