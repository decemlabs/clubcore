## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-91-IDOR | Information Disclosure | publish_read_receipt / publish_typing channel name | mitigate | Channel is ALWAYS `cc:messaging:client:{client_id}` derived from the function's client_id argument only — never from an inbound payload; reply-as-read is thread-scoped via get_or_create_thread(client_id) so it can never mark another client's thread |
| T-91-LEAK | Information Disclosure | TypingEvent payload | mitigate | TypingEvent carries only `type` + `actor` — no body, preview, or message id; asserted by the camelCase schema test (exactly two keys) |
| T-91-XTHREAD | Tampering | mark_client_messages_read WHERE clause | mitigate | UPDATE is scoped `WHERE thread_id=:tid AND role='client' AND read_at IS NULL` where tid is the resolved thread for the supplied client_id — cross-thread / cross-client read-marking is impossible |
| T-91-PHANTOM | Repudiation | read_receipt publish ordering | mitigate | publish_read_receipt is post-commit (CR-02 / DB-first); a failed commit never emits a receipt for an uncommitted read_at change |
| T-91-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies in this phase (extends existing messaging module only) — no package install task |
</threat_model>
