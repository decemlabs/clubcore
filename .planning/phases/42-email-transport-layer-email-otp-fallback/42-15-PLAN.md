<objective>
Fix CR-04 (warning-tier deploy-data-risk): `alembic/versions/0027_otp_codes_channel_discriminator.py:61-90` creates a partial-UNIQUE `uq_otp_codes_user_channel_active ON otp_codes (user_id, channel) WHERE consumed_at IS NULL` with NO defensive cleanup. Today the risk is bounded because `telegram_service.start_deep_link` writes `user_id=NULL` (NULLs distinct under UNIQUE), but ANY future writer that pairs `user_id IS NOT NULL + consumed_at IS NULL` rows across the channel will collide and the upgrade will fail with `duplicate key value violates unique constraint`.

Purpose: Add a defensive UPDATE pass BEFORE the partial-UNIQUE creation that consumes duplicate same-(user_id, channel) `consumed_at IS NULL` rows, keeping only the latest per group. Document the cleanup in the migration docstring. Add a regression test that seeds a colliding row and asserts the upgrade succeeds.

Output:
- `alembic/versions/0027_otp_codes_channel_discriminator.py` — defensive UPDATE pass + updated docstring
- `tests/integration/alembic/test_migration_0027_cleanup.py` — regression test
