<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| boto3 → Yandex Postbox over HTTPS | Outbound to `https://postbox.cloud.yandex.net` with AWS Signature V4 over static access keys |
| Settings → factory at boot | Credentials read from SecretStr-wrapped settings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-07-01 | Spoofing | attacker MITMs the endpoint_url | mitigate | Default endpoint locked to `https://postbox.cloud.yandex.net` in EmailProviderSettings (plan 42-02); TLS verification is default-on in aioboto3; non-sandbox boot fails if `/domains` probe doesn't reach the expected provider |
| T-42-07-02 | Information disclosure | credentials leak through structlog logs | mitigate | aws creds wrapped in `SecretStr`; only `.get_secret_value()` is called at the sesv2 client construction site; structlog logger in client.py logs only `to`, `subject`, `template_id` — never credentials |
| T-42-07-03 | Denial of service | provider 5xx storm collides with retry storm | mitigate | `Config(retries={'max_attempts': 1})` disables boto3 retries (D-42-02); ARQ owns retry (D-42-13 — `max_tries=2`). Plan 42-08 adds circuit breaker on top |
| T-42-07-04 | Tampering | misconfigured from_domain delivers from unverified domain | mitigate | Boot-time `/domains` probe (D-42-30) asserts VerificationStatus=='Success' and raises RuntimeError on failure; app cannot start with an unverified domain |
| T-42-07-05 | Repudiation | failed sends leave no trace | mitigate | Classification taxonomy (`ok` / `blocked` / `transient_error` / `permanent_error`) maps every transport outcome into the EmailSendResult; downstream task (plan 42-08) emits `email_send_failed` audit on non-ok |
</threat_model>
