<objective>
Wire the payment recorder Protocol slot into the existing membership sale flow so every successful membership sale atomically writes a positive-amount payments row, emits payment_recorded with payment_row_hash, and links the membership audit row via a payment_id field — all in a single UoW that rolls back end-to-end on any failure. Also gate POST /api/v1/memberships behind the Idempotency-Key dependency so double-submitted sale clicks return a cached envelope instead of duplicate state.

Purpose: Close the v1.4 MVP-gap "симуляция продажи без денег" — every membership sale now has a corresponding cash receipt entry in the ledger, server-derived from price_kopecks_snapshot (anti-fraud invariant: client cannot lie about cash received).
Output: Modified create_membership flow; modified POST /memberships endpoint; three integration tests covering snapshot symmetry, recorder failure rollback, audit chain traceability, and Idempotency-Key replay/collision semantics.
</objective>
