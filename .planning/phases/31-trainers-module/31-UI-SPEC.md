## Active Filter Pill Contract

**Component:** `ActiveFilterPill` using shadcn `<Badge>` styled as toggle tabs (NOT `<ToggleGroup>` primitive — `ToggleGroup` is not in the existing `shared/ui` inventory).

**Implementation pattern:** Three `<Button variant="ghost" size="sm">` or styled `<Badge>` elements rendered as a segmented control. Selected state uses `variant="default"` (primary fill); unselected uses `variant="outline"`.

**Options (in order):**
1. `Активные` — filter value `active=true` → URL search `?active=true`
2. `Неактивные` — filter value `active=false` → URL search `?active=false`
3. `Все` — no filter → URL search param omitted

**URL search schema** (added to route `validateSearch`):
```ts
const searchSchema = z.object({
  active: z.enum(['true', 'false']).optional(),
  page: z.coerce.number().int().min(1).default(1),
  pageSize: z.coerce.number().int().min(10).max(100).default(20),
})
```

**Default:** "Активные" (`active=true`) — trainer catalog is primarily active trainers.

Source: D-31-22 (auto-selected default: "Активные"). Mirrors v1.3 freeze filter pill UX on `/memberships`.

## Form Dialog Contract: Create / Edit Trainer

**Component:** `TrainerFormDialog` — single shared component, mode determined by whether a `trainer` prop is passed.

**Primitive:** shadcn `<Dialog>` (not Sheet — matches membership plans form pattern).

### Dialog Header
| Mode | Title |
|------|-------|
| Create | `Добавить тренера` |
| Edit | `Редактировать тренера` |

### Field Order (strictly in this order)

| # | Field | Input type | Validation | Notes |
|---|-------|-----------|-----------|-------|
| 1 | `fullName` | `<Input>` | `z.string().min(1, 'Укажите ФИО').max(200)` | Required; displayed first |
| 2 | `phone` | `<Input>` | `z.string().regex(PHONE_REGEX).nullable().optional()` | Optional; placeholder `+7 (XXX) XXX-XX-XX` |
| 3 | `isActive` | `<Checkbox>` | `z.boolean()` | **Edit mode only** — hidden on create (new trainers always active); label: `Активный тренер` |

**Zod schema location:** `apps/admin-web/src/features/trainers/model/schema.ts`

```ts
// Create schema (used by form AND mock service input validation)
export const createTrainerSchema = z.object({
  fullName: z.string().min(1, 'Укажите ФИО').max(200),
  phone: z.string().regex(PHONE_REGEX).nullable().optional(),
})

// Update schema (extends create + isActive)
export const updateTrainerSchema = createTrainerSchema.extend({
  isActive: z.boolean(),
})
```

### Form Footer Buttons (in order, right-aligned)
1. `Отмена` — `variant="outline"` — closes dialog without saving
2. Submit button:
   - Create mode: `Добавить тренера` / pending: `Добавляется…`
   - Edit mode: `Сохранить изменения` / pending: `Сохраняется…`

### Inline field errors
- `fullName` empty → `"Укажите ФИО"` (below field, `text-destructive text-sm`)
- `phone` invalid format → `"Введите телефон в формате +7XXXXXXXXXX"` (E.164)
- Phone duplicate 409 → `"Тренер с таким телефоном уже существует"` (inline `<Alert variant="destructive">` above footer)

Source: D-31-24 (RHF + Zod + @hookform/resolvers); D-31-05 (PHONE_REGEX reuse); mirrors `clients.form` pattern from `ru.ts`.

## Delete AlertDialog Contract

**Component:** `DeleteTrainerAlertDialog`

**Trigger:** Trash2 ghost button in table action column.

**Dialog structure:**
```
AlertDialogTitle:       "Удалить тренера?"
AlertDialogDescription: "Тренер {fullName} будет удалён без возможности восстановления."

  Cancel: "Не удалять"
  Confirm: "Удалить" (bg-destructive text-destructive-foreground)
```

**409 `trainer_in_use` error surface:**
- Rendered as `<Alert variant="destructive">` inside `AlertDialogContent`, between description and footer.

- Dialog stays open (does NOT close on 409 — user must dismiss manually via "Не удалять").
- Confirm button remains enabled after 409 (user can read the error and choose to close).

**Success path:** Dialog closes; Sonner toast: `"Тренер удалён"` (non-blocking ack).

Source: D-31-21 (inline error AlertDialog per 409 trainer_in_use); `CancelMembershipDialog.tsx` pattern (inline `<Alert variant="destructive">` inside AlertDialog body); D-31-06 / D-31-07.

```ts
beforeLoad: ({ context, location }) => {
  const { role } = context.getSession()
  if (!can(role, 'view', 'trainers')) {
    throw redirect({
      to: '/',
      search: { forbidden: location.pathname + (location.searchStr ?? '') },
    })
  }
}
```

**URL search schema:**
```ts
const searchSchema = z.object({
  active: z.enum(['true', 'false']).optional(),
  page: z.coerce.number().int().min(1).default(1),
  pageSize: z.coerce.number().int().min(10).max(100).default(20),
})
```

**Loader:** `context.queryClient.ensureQueryData` with `trainersKeys.list(search)` — matching the hook key used in `useTrainersList`.

**Default active filter:** URL param `active=true` pre-set when route is loaded without explicit filter (default "Активные" view).

Source: D-31-19; mirrors `membership-plans.tsx` route pattern exactly.
