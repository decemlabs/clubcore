`from`/`to` WIRE-PARAM DESIGN (route-level Query(alias=...), live-verified):
ROADMAP SC#2 + D-06 REQUIRE the literal wire params `from` and `to`. A live test on this stack
(FastAPI 0.136.1 + Pydantic 2.13.3) proved that `Field(alias="from")` on a model field passed via
`Depends()` does NOT bind the `?from=` query param — `from_` stays None. (`to` binds either way, but
for symmetry both are handled the same.) Therefore the date params are NOT model fields. They are
declared as explicit route-handler parameters:
  `from_: Annotated[date | None, Query(alias="from")] = None`
  `to: Annotated[date | None, Query(alias="to")] = None`
This is the design — there is no fallback. `AuditLogQuery` carries only the non-date filters
(actorUserId, actorEmailSnapshot, resourceType, action) plus PageQuery pagination. The route passes
`from_`/`to` into the service/repository as keyword-only args alongside `query`. Renaming to
fromDate/toDate is FORBIDDEN (would violate SC#2).
