CRITICAL `from` ALIAS NOTE — verify at runtime, do not assume:
The existing reports/schemas.py docstring (lines 18-21) warns that explicit Field(alias=...)
historically did NOT drive FastAPI Depends() query-param names (it used alias_generator only),
which is why the clients module renamed to createdFrom/createdTo. But ROADMAP SC#2 + D-06
REQUIRE the literal wire params `from` and `to`. PATTERNS.md prescribes
`from_: date | None = Field(default=None, alias="from")`. FastAPI 0.115 + Pydantic 2.11
(validate_by_alias=True) DOES honor an explicit per-field alias for Depends() query models —
so `from_`/alias="from" should expose `?from=`. Task 3 MUST include a test that asserts the
wire param is literally `from` (not `from_` or `fromDate`). If that test fails, fall back to
declaring `from`/`to` as explicit `Query(alias="from")` / `Query(alias="to")` parameters on
the route handler signature instead of model fields — do NOT rename to fromDate/toDate
(that would violate SC#2). Document whichever path is used in the SUMMARY.
