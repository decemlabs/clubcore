## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → PATCH /auth/me | authenticated staff submits full_name/email; CSRF header crosses here |
| client → POST /auth/change-password | authenticated staff submits current+new password; CSRF header crosses here |
| route → cc_refresh cookie | current refresh family resolved here to exclude from revocation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-07 | Tampering (CSRF) | PATCH /me + POST /change-password | mitigate | Task 1: both declare `verify_csrf` as a signature dep AFTER require_authenticated; Tasks 2/3 assert 403 csrf_mismatch when X-CSRF-Token is omitted |
| T-109-08 | Spoofing | unauthenticated access | mitigate | Task 1: `require_authenticated()` FIRST; Tasks 2/3 assert 401 (and 401-before-403 when both deps would fail) |
| T-109-09 | Spoofing | wrong current password | mitigate | Plan 01 verify_password (timing-equivalent); Task 3 asserts wrong-pw rejected with NO revocation + unchanged hash |
| T-109-10 | DoS (self-lockout) | session revocation on pw change | mitigate | Task 1 resolves current_family_id from cc_refresh; Task 3 asserts current family alive + GET /me still 200 after change |
| T-109-11 | Tampering (account takeover) | email change to a taken address | mitigate | Task 1 propagates the partial-UNIQUE conflict as a field error; Task 2 asserts 409/422 not 500 |
| T-109-12 | Elevation of Privilege | RBAC parity drift | mitigate | Self-service only — no permissions.py/OWNER_ONLY change; route-introspection + RBAC parity tests must stay green (verify in run) |
| T-109-13 | Information Disclosure | audit / response bodies | mitigate | Tasks 2/3 assert audit rows + responses carry no password/hash/raw-email leak; change-password is a bodiless 204 |
| T-109-SC | Tampering | npm/pip/cargo installs | accept | No new packages this plan |
</threat_model>
