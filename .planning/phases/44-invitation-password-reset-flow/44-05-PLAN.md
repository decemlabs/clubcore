**Key observations (pinned — DO NOT re-derive from scratch in Task 4):**

  1. `authenticate(...)` OWNS ITS OWN COMMIT (Phase 5 — `service.py:authenticate` calls `await session.commit()` internally). Caller does NOT commit again.
  2. `issue_tokens(session, redis, user)` is a **3-tuple** return: `(access, refresh, csrf)`. It takes `redis` as second positional arg.
  3. `issue_session_cookies` kwargs are `access_token=`, `refresh_token=`, `csrf_token=`, `secure=` (NOT `access=`/`refresh=`).
  4. **There is NO `await session.commit()` between `issue_tokens` and `issue_session_cookies`.** `issue_tokens` internally persists the refresh row via the session (caller's UoW), but `/login` relies on the implicit transaction-end at request boundary to flush — verify by grepping `issue_tokens` body in `service.py:242-290`; if it self-commits, no caller commit is needed; if it does not, the request-scoped session dependency commits at teardown.
