<objective>
Deliver PAY-06 — the PT-package-refund clawback. A new Protocol slot
`PayrollClawbackRecorder` (owned by payroll, registered in main.py, accessed via
a dependencies.py getter mirroring get_payment_refunder) lets
pt_packages.service.refund_pt_package append a NEGATIVE clawback accrual row in
the SAME unit of work — never importing payroll, never UPDATEing the original
accrual (D-58-20, D-58-03).

The slot only acts when the refunded package's revenue is covered by a
status='paid' accrual; otherwise it returns None (no payroll impact).
Attribution is assigned-at-sale: the clawback is charged to
pt_packages.trainer_id (D-58-21); a NULL trainer_id skips the clawback (the
package was never commissionable).

Purpose: Financial integrity — a refund after payroll has been paid must leave
an auditable negative correction, append-only, atomic with the refund.

Output: Protocol slot + getter, two payroll repository helpers, the slot
implementation, the main.py registration, the one-line hook in refund_pt_package,
and same-UoW integration tests. Also reconciles the SC#5 "6 LOCKED_AUDIT_EVENTS"
count against the delivered 4 (documented discrepancy — see Task 5).
</objective>
