## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → GET /messages/attachments/{id} | untrusted attachment id (IDOR/enumeration) + the response renders in a browser (stored-XSS surface) |
| client → POST /messages (attachmentId) | untrusted attachment id reference crosses here |
| service → S3 (get_object/open_stream) | object key is server-stored (never user-supplied path) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-92-10 | Information Disclosure / EoP | serve endpoint IDOR | mitigate | ownership via message_attachments.client_id == principal; get_owned_attachment returns None for non-owned/missing → 404-collapse (never 403, no existence leak), MSG-02 precedent; client_id from require_client() only |
| T-92-11 | Tampering (stored XSS) | serve response headers | mitigate | Content-Type forced from STORED validated mime (never client-derived); Content-Disposition: attachment (never inline); X-Content-Type-Options: nosniff (P7 LOCKED) — asserted in the HTTP suite |
| T-92-12 | Tampering | serve object key | mitigate | object_key read from the owned DB row only; never built from a path param or client filename → no path traversal (P8); the {attachment_id} path param is a UUID validated by FastAPI |
| T-92-13 | Spoofing | unauthenticated serve | mitigate | require_client() gates the GET; missing/expired cc_client_access → 401 |
| T-92-14 | EoP | send with foreign attachmentId | mitigate | send_client_message re-checks get_owned_attachment(attachment_id, client_id) and 404s a foreign id before persisting the message |
| T-92-SC | Tampering | package installs | mitigate | no new package installs in this plan (filetype handled in Plan 01 T-92-SC) |
