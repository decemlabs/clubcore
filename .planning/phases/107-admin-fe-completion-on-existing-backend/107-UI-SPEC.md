# Phase 107 — UI Design Contract

> Visual and interaction contract for Phase 107: Admin FE Completion on Existing Backend.
> Wire-only phase — no new visual language. Every surface MUST reuse existing admin-app
> components, tokens, and the established AdaptiveModal / fields.tsx / SubscriptionModal UX.
> Generated by gsd-ui-researcher. All copy is Russian.

## Design System

| Property | Value |
|----------|-------|

| Preset | new-york · neutral base · cssVariables: true · aliases.utils → @/lib/cn |

project-owned colors.

## Interaction States (universal contract)

These apply to ALL new dialogs in Phase 107.

### Loading (data fetch before dialog renders)
- Plan select skeleton: `h-[42px] animate-pulse rounded-xl bg-surface-3` — matches CreateScreen
- Dialog does not open until required IDs are available (modal triggered from a row that already has the data)

### Submitting (mutation in-flight)
- Primary/danger footer button: replace label with `<Loader2 className="size-[18px] animate-spin" /> Обработка…`
- ALL footer buttons: `disabled={true}` (both Cancel ghost and primary/danger)
- `onOpenChange` on AdaptiveModal replaced with `isPending ? () => {} : onOpenChange` (prevents ESC/backdrop close during submit)

### Error (mutation returns error)
- `ErrorCallout` rendered `mt-3.5` below all fields
- `ApiError.message` displayed when `error instanceof ApiError`; fallback: «Не удалось выполнить действие. Проверьте соединение и попробуйте ещё раз.»
- Dialog stays open; operator can retry
- Mutation reset on dialog re-open (`useEffect([open])`)

### Field validation error (client-side)
- Per-field `text-[12px] text-danger` below the relevant input
- Shown after first submit attempt (touched flag); or after `onBlur` for textarea
- Submit button remains disabled until all required fields pass

### Success
- `onOpenChange(false)` — dialog closes
- Sonner toast (already implemented inside mutation hooks where noted; surface-level toast for plan create/edit)

### Empty state in TrainingsTab (post-sell, all cancelled)
- Existing `<EmptyState title="Нет тренировок" message="Персональные тренировки появятся здесь." />` — no change needed

If `can()` returns false for cancel, the kebab menu item is not rendered at all — use conditional rendering `{can(role, 'cancel', 'pt-packages') && <DropdownMenuItem ...>}`.

## Money Formatting

All monetary amounts use `formatKopecks(kopecks: number)` from `@/lib/format`.
Input fields for prices accept values in Rubles (human-readable); multiply by 100 before sending to the API (backend accepts kopecks).

Field `suffix="₽"` on ModalInput for price fields.
StatRow `value={formatKopecks(kopecks)}` — produces `Intl.NumberFormat('ru-RU', {currency:'RUB'})` output with NBSPs.

---

## Date Formatting

All dates: `formatDateRu(isoString, 'd MMMM yyyy')` from `@/lib/format`.
`formatDateRu(item.createdAt, 'd MMM yyyy')` for compact row display (matches existing PtPackageRow).
