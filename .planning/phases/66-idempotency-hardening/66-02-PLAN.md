<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator (admin-web, multi-user) → /api/v1 mutations | Authenticated; client-supplied Idempotency-Key header is untrusted and human-chosen (collision-prone: "retry-1", timestamps) |
| handler → Redis | In-flight placeholder + stored envelope; failure modes can leave a stuck placeholder |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-03 | I (Information Disclosure) / S (Spoofing) | verify_idempotency Redis key (PITFALLS C-03, HIGH) | mitigate | Cross-user replay: user A's cached response served to user B on a key collision under multi-user admin. Mitigation: bind Depends(get_current_user); prefix the Redis key with current_user.id (cc:idem:{user_id}:...). Proven distinct-entry behavior is asserted in 66-05. FastAPI dedups the get_current_user node so no extra DB hit. |
| T-66-04 | D (Denial of Service) | in-flight placeholder lifecycle (PITFALLS C-02) | mitigate | 24h self-lockout: a handler that raises after begin_idempotency claims the placeholder leaves __in_flight__ stuck for the full (now 24h) TTL, so every retry gets idempotency_in_flight. Mitigation: orchestrator deletes the placeholder on unknown exceptions; the next retry is fresh. Trading at-most-once for retry-able is correct here (payment endpoints are additionally DB-layer idempotent). |
| T-66-05 | T (Tampering) | idempotency-key reuse with mismatched body | mitigate | A same-key retry with a different body must not replay the original (success OR error) response. Mitigation: body_sha256 stored in the envelope; mismatch raises 422 idempotency_key_reuse on both success-replay and error-replay paths. |
| T-66-06 | (regression) | ЮKassa webhook dedup path | accept | The webhook uses a separate cc:yookassa:webhook: SET NX EX 86400 dedup and is untouched by this plan. Confirmed not weakened: no shared key namespace, no current_user, no shared code path. D-11-IDM-WEBHOOK. |
</threat_model>
