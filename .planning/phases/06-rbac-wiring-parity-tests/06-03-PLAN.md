<objective>
Migrate Phase 5's auth-meta routes (`/me`, `/logout`, `/logout-all`) from `Depends(get_current_user)` to `Depends(require_authenticated())` (D-02), add CSRF protection to `/logout` and `/logout-all` (D-09), and update Phase 5's `test_logout.py` to echo the CSRF cookie as a header (D-24).

**Critical ordering decision (resolves PATTERNS.md latent risk for the `unauth /logout` 401-vs-403 question):** declare `verify_csrf` as a SIGNATURE dependency AFTER `require_authenticated()` (NOT as a route-decorator-level `dependencies=[...]` entry). Per FastAPI's documented behavior, signature `Depends(...)` parameters resolve in left-to-right declaration order; route-level `dependencies=[...]` execute BEFORE all signature deps. Therefore:
- Decorator-level `dependencies=[Depends(verify_csrf)]` would flip unauth `/logout` from 401 → 403 (csrf_mismatch fires before identity resolves), violating RBAC-04 (D-22).
- Signature-level `Depends(verify_csrf)` placed AFTER `Depends(require_authenticated())` preserves RBAC-04: an unauth caller hits 401 first because `require_authenticated()` resolves earlier.

Purpose: Land Phase 6's wiring on the only existing protected routes so TEST-07 (Plan 06-05) has something to enforce, and prove the gate primitives work end-to-end against a real auth flow (Plan 06-04 then layers on the OWNER_ONLY parametrized matrix via the fixture router).

Output: One router file with three migrated routes; one test file with two updated POST calls + assertions of the new CSRF behavior.
