<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /auth/sessions (self-service) | any authenticated role; session list reveals only the caller's own families |
| self-revoke of current session | must not strand the user mid-session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-09 | Denial of Service (self-lockout) | self-revoke current session | mitigate | Self-revoke routes through `publishSessionExpired()` (authBus) → RequireAuth clears cache + redirects to /login cleanly, instead of leaving the app on a dead session. Confirm modal prevents accidental trigger. |
| T-104-10 | Spoofing / EoP | session revoke endpoint | mitigate | Revoke is POST → staffRequest auto-attaches X-CSRF-Token; backend authorizes the caller against their own session families (server-authoritative). |
| T-104-11 | Information Disclosure | ProfileSection read-only | accept | No edit endpoint exposed (PATCH /auth/me absent); email/role are the caller's own data from GET /auth/me — no cross-user leak. Edit deferred. |
| T-104-SC | Tampering | npm/pnpm installs | accept | No new dependencies; no install task. |
</threat_model>
