# Phase 104 — UI Design Contract

> Visual and interaction contract for Phase 104: Dashboard + Reports + Settings.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> WIRING PHASE — the design system is ESTABLISHED and LOCKED (see Phase 100 UI-SPEC).
> Do NOT redesign tokens, spacing, typography, or color. All values inherited from P100–P103.
> The existing Dashboard, Reports, Audit, and Settings screens are ALREADY DESIGNED — do NOT
> redesign them. This contract covers ONLY the genuinely net-new or changed interaction surfaces:
>
> 1. Dashboard role-gating: owner-only card hiding + reception layout (ScheduleToday + ExpiringMemberships only)
> 2. Reports page restructure: 4 real-data report tabs + «Экспорт CSV» per report + reception Lock-EmptyState

> 5. Shared «Экспорт CSV» button: idle / downloading / error states

## Surface 1: Dashboard Role-Gating

**Requirement:** RPT-01. Dashboard `/` is the universal landing for both roles. Owner-only KPI/analytics cards are hidden for reception — not replaced with a 403 or blank space; the reception layout is a reduced but coherent operational view.

### 1.1 Owner-Only Cards (hidden for reception)

Gate via `can(role, 'view', 'reports') === false`. When `false`, do NOT render the following dashboard components — remove them from the JSX entirely, do not mount their hooks:

| Component | Gated resource | Reception treatment |
|-----------|---------------|---------------------|
| `KpiStrip` | `reports` | Absent |
| `OccupancyHours` | `reports` | Absent |
| `OccupancyNow` | `reports` | Absent |
| `RevenueChart` | `reports` | Absent |
| `TopTrainers` | `reports` | Absent |
| `ActivityFeed` | `audit-log` | Absent |
| `ClientMessages` | none (no backend) | Absent for ALL roles |

**Hooks enforcement:** use `enabled: can(role, 'view', 'reports')` on every TanStack Query hook that fetches owner-only data. Reception fires zero owner-only API calls. The `useDashboard` mock hook must be split into per-domain hooks or guarded internally per domain.

### 1.2 Reception Dashboard Layout

Reception sees only the two operational widgets, stacked in the existing page layout container:

```
[ PageHead (greeting + date — keep as-is) ]

[ ScheduleToday  (bookings — both roles) ]
[ ExpiringMemberships (memberships — both roles) ]
```

- Layout: `flex flex-col gap-4` (existing page container) — no grid needed for two cards.
- `ScheduleToday` fills full width (remove the `lg:grid-cols-[1.6fr_1fr]` grid wrapper for reception).
- `ExpiringMemberships` fills full width below.
- No empty-state placeholder for the absent owner cards — the reception layout simply omits them. Do NOT show a `Lock` icon or "этот раздел только для владельца" in the space where KPI cards would be — absence is the correct treatment (P100 pattern: absent, not locked).

### 1.3 Owner Dashboard Layout

Owner sees the full existing layout with REAL data wired from individual report hooks (not the monolithic `useDashboard`):

| Section | Data source |
|---------|------------|
| `KpiStrip` | Composite: `/reports/revenue` (netKopecks today) + `/reports/visits` (count today) + `/memberships?expiring` (expiringCount) |
| `OccupancyHours` | `/reports/visits` — hourly buckets; zero-filled (P103 pattern) |
| `OccupancyNow` | Hide (`// TODO Phase 104: wire LiveNow`) — no real-time endpoint; omit the `OccupancyNow` card for owner too. Do NOT show an empty shell. |
| `ScheduleToday` | `/bookings?date=today` |
| `ExpiringMemberships` | `/memberships?expiring=true&withinDays=7` |
| `RevenueChart` | `/reports/revenue?groupBy=day&fromDate=mskDaysAgoISO(29)&toDate=mskTodayISO()` — last 30 days |
| `TopTrainers` | `/reports/trainers?fromDate=…&toDate=…` — current month |
| `ActivityFeed` | Hide if `/audit-log` call is expensive in dashboard context — use `enabled: false` and show `EmptyState icon=Activity title=«Активность»` body=`«Доступна в журнале действий»` with a link to `/audit-log`; OR wire with `pageSize=5` at Claude's discretion. |

**Empty/zero-data guards:** every wired widget MUST guard against `undefined`, `null`, `NaN`, and all-zero buckets using the P103 zero-fill pattern. No widget may display NaN or crash on empty API response.

### 1.4 `ClientMessages` — Always Hidden

`ClientMessages` is removed from the dashboard render for ALL roles (no staff-chat backend). Do not show it for owner or reception. Note in code: `{/* ClientMessages: hidden — no staff-chat backend */}`.

### 1.5 Dashboard Page Data States

The dashboard switches from a single `useDashboard` hook to per-widget hooks. Loading and error states per widget:

| Widget | Loading | Error | Empty |
|--------|---------|-------|-------|
| `KpiStrip` (owner) | Skeleton strip — `h-[52px] w-full rounded-xl` | Silent — hide KpiStrip; no page-level error for KPI failures | Zero guard: show `«0»` not NaN |
| `ScheduleToday` (both) | `<PageLoading />` in the card area | `<PageError onRetry={refetch} />` in card | `EmptyState icon=Calendar title=«Тренировок сегодня нет»` |
| `ExpiringMemberships` (both) | Skeleton in card | Silent — hide; non-critical | `EmptyState` (title below) |
| Owner analytics widgets | `<PageLoading />` per widget card | Silent — hide widget; non-critical | EmptyState per widget (copy below) |

**Dashboard never shows a full-page `<PageLoading />`** — each widget loads independently.

### 2.2 CSV Export Button

**Button anatomy (idle state):**

```
[ Download 14px ]  Экспорт CSV
```

- Container: `inline-flex h-[38px] shrink-0 items-center gap-[7px] rounded-full border-[0.5px] border-border bg-surface px-[14px] text-[13px] font-semibold text-fg transition-colors hover:border-border-strong focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring`
- Icon: `Download` (Lucide), `size-[14px]`
- Label: `«Экспорт CSV»`
- Position: right side of the tab-level actions row (to the right of the tab selector, on the same row on desktop; below on mobile if overflow)

**Button states:**

| State | Visual | Behaviour |
|-------|--------|-----------|
| Idle | `Download` icon + `«Экспорт CSV»` label, normal opacity | Click triggers `downloadCsv()` |
| Downloading | Replace icon with `Loader2 size-[14px] animate-spin text-fg-subtle`; label stays `«Экспорт CSV»`; button `disabled` and `opacity-75` | No re-click |
| Error | Revert to idle state; show Sonner `toast.error(«Не удалось скачать файл», { description: «Проверьте соединение и попробуйте ещё раз.» })` | Button re-enabled |
| Success | Revert to idle state immediately (browser handles the download) | No toast on success |

**Endpoint mapping (GET, no CSRF):**

| Tab | CSV endpoint |
|-----|-------------|
| `«Выручка»` | `/api/v1/reports/revenue.csv?fromDate=…&toDate=…&groupBy=…` |
| `«Клиенты»` | `/api/v1/reports/clients.csv?fromDate=…&toDate=…&within=…` |
| `«Посещения»` | `/api/v1/reports/visits.csv?fromDate=…&toDate=…` |
| `«Тренеры»` | `/api/v1/reports/trainers.csv?fromDate=…&toDate=…` |

`downloadCsv(url, filename)` helper (new — `src/api/csv.ts`):
- `fetch(url, { credentials: 'include' })` → check `res.ok`; if not → throw.
- `res.blob()` → create object URL → create `<a>` anchor → `.click()` → revoke URL.
- Filename pattern: `{report}-{fromDate}-{toDate}.csv` (e.g. `revenue-2026-05-14-2026-06-13.csv`).

## Surface 4: Settings — Active Sessions

**Requirement:** SET-01. The existing `SecuritySection` renders mock session rows. Phase 104 wires `GET /api/v1/auth/sessions` + `POST /api/v1/auth/sessions/{familyId}/revoke`.

### 4.1 Session List Row (wired)

The existing `SecuritySection` session list anatomy is ALREADY DESIGNED — reuse it exactly:

```
[ Monitor/Smartphone icon chip ]  [ device label (from userAgent) ]     [ Завершить button ]
```

**«Сейчас» badge:** `isCurrent === true` → render `<span className="rounded-full bg-primary-soft px-1.5 py-px text-[9.5px] font-bold uppercase text-primary-deep dark:text-primary">Сейчас</span>` next to the device label (existing component pattern — reuse exactly).

**Meta line:** `«{channel} · {formatRelativeRu(lastUsedAt)}»` in `text-[11px] text-fg-subtle`. Channel labels: `'admin_web'` → `«Браузер»`; `'api'` → `«API»`; default → `«Браузер»`.

**Revoke button:**
- Non-current session: `<button>Завершить</button>` — `text-[12px] font-semibold text-danger hover:underline`.
- Current session: render `«—»` (`text-[12px] text-fg-subtle`) — same as existing mock. The current session CAN be self-revoked via a separate explicit action (see §4.2).

### 4.2 Self-Revoke Confirmation

**Trigger:** a separate `«Выйти со всех устройств»` ghost button BELOW the session list (inside the `SecuritySection`). This logs the user out of all non-current sessions in a single action. For current-session revoke specifically, a destructive confirm dialog is required.

**Self-revoke flow for current session (danger path):**

1. User clicks `«Завершить»` on ANY session (current or not):
   - Non-current: fire `POST /auth/sessions/{familyId}/revoke` directly (no confirm dialog). On 204: remove row from list + `toast.success('Сессия завершена')`. On error: `toast.error(...)`.
   - Current session revoke is exposed ONLY via the `«Выйти везде»` bulk action below.

2. **`«Выйти везде»` bulk action button** (below session list):
   - Anatomy: `GhostBtn danger` (existing `components/settings/controls` primitive).
   - Label: `«Выйти везде»`.
   - Click → open `AdaptiveModal` confirm dialog (reuse P101 `ConfirmModal` or the existing `open('confirm', {...})` from `useModals`):
     - Title: `«Завершить все сессии?»`
     - Body: `«Все активные сессии, включая эту, будут завершены. Вам потребуется войти снова.»`
     - Confirm button: `«Да, выйти»` (`tone: 'danger'`)
     - Cancel button: `«Отмена»`
   - On confirm: fire `POST /auth/sessions/{current.familyId}/revoke` for the current session (this is self-revoke). On 204 → clear session state → navigate to `/login` (reuse the `authBus` session-expiry path from P100 §3.4).

### 4.3 Sessions Loading/Error States

|-------|-----------|
