<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reception session → owner-only /users endpoints | reception must reach neither the list nor any mutation |
| invite-link URL (one-time secret) → DOM + clipboard | shown to owner; must not leak into audit/error states |
| user-admin mutations (state-changing) | deactivate/delete cross a privileged boundary; backend 409 guards apply |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-12 | Elevation of Privilege | TeamSection / users hooks for reception | mitigate | `useUsers` `enabled:can(role,'list','users')` + Lock-EmptyState early-return in section body → reception fires ZERO users calls; all mutations owner-only server-side (authoritative). |
| T-104-13 | Tampering / CSRF | invite + deactivate/reactivate/delete/revoke mutations | mitigate | All are POST/PATCH/DELETE → staffRequest auto-attaches X-CSRF-Token from cookie. Each destructive action gated behind an explicit confirm modal. |
| T-104-14 | Information Disclosure | invite-link display | mitigate | inviteLinkUrl rendered ONLY in the success modal (read-only input + clipboard copy); never logged, never echoed into toast/error text, not persisted. On error the link is not shown. |
| T-104-15 | Denial of Service (admin lockout) | deactivate self / last owner | mitigate | UI disables self actions («Это вы»); backend 409 guards (cannot_deactivate_self / cannot_deactivate_last_owner / already_inactive) are surfaced as Russian toasts — server remains the authority. |
| T-104-SC | Tampering | npm/pnpm installs | accept | No new dependencies; no install task. |
</threat_model>
