## CRITICAL FINDING — Step 3 «Профиль» fields do NOT exist

CONTEXT D-05 says Step 3 «Профиль» is `done` if **any of фото / рост / вес** is filled, read from `/client/me`. **None of these fields exist:**

- `ClientMeResponse` (`apps/backend/app/modules/client_auth/schemas.py:38-53`) exposes only: `id, phone, email, first_name, last_name, middle_name, birthday, gender`. **No photo, no height (рост), no weight (вес).**
- The `Client` model (`apps/backend/app/modules/clients/models.py:58-97`) has no height/weight/photo columns either.

**Planner MUST resolve this** (it is flagged in CONTEXT as "Claude's Discretion: planner verifies field names"). Two viable options without new DB columns:
1. Re-interpret Step 3 against fields that DO exist on `/client/me` (e.g. `birthday`/`gender`/`email` filled → `done`), updating the step meta copy accordingly, or
2. Hold Step 3 as always-`pending` in this phase and defer richer profile fields.
Adding height/weight/photo columns is a schema migration well beyond this phase's stated boundary — do NOT silently introduce it.

Note: `/client/me` lives in the **`client_auth`** module (`ClientMeResponse`), NOT `client_portal`. The PWA reads it via `useClientMe()` from `@/data`.

### `apps/backend/app/modules/client_portal/repository.py` (repository, CRUD read)

**Analog:** `fetch_client_membership` (`repository.py:127-159`).

Add a boolean "ever had any membership" reader. Mirror the existing reader's discipline (CROSS-MODULE READ — raw `text()` SQL, NO ORM import of `Membership`, mandatory `:client_id` bind cast to `str`, `.mappings().one()` for scalar). Verified columns (from `fetch_client_membership` docstring + `memberships/models.py:88-182`): `memberships.client_id`, `memberships.status IN ('active','expired','cancelled','frozen')`:

```python
async def client_has_any_membership(session, client_id: UUID) -> bool:
    """True if the client has EVER had any membership row (any status) — D-01 lapsed-vs-newbie.
    CROSS-MODULE READ — raw SQL text() only; NO ORM import of Membership (D-54-08/D-20-MODULE).
    IDOR: mandatory :client_id bind. A 'lapsed' member has >=1 row (typically status='expired');
    a true 'newbie' has zero rows.
    """
    row = (
        await session.execute(
            text("SELECT EXISTS(SELECT 1 FROM memberships WHERE client_id = :client_id) AS ever"),
            {"client_id": str(client_id)},
        )
    ).mappings().one()
    return bool(row["ever"])
```
Add the name to the `__all__` tuple (`repository.py:28-39`).
