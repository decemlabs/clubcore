<objective>
Add a server-derived `membershipState: 'active' | 'newbie' | 'lapsed'` enum to the `/api/v1/client/home` response (D-01, D-03) so the PWA can distinguish a true newbie (never subscribed) from a lapsed (expired/cancelled) member. `membership === null` alone is ambiguous — both newbie and lapsed members have null active membership.

Purpose: The frontend newbie Home (Plan 02) gates on `membershipState === 'newbie'`. Without this field, a lapsed member would wrongly see onboarding copy ("Аккаунт создан / Остался один шаг"). The state MUST be computed server-side — CONTEXT explicitly rejects a client-side heuristic.

Output: New repository reader `client_has_any_membership`, `membership_state` derivation in `get_client_home`, new `ClientHomeResponse.membership_state` field, and integration tests asserting all three enum values.
</objective>
