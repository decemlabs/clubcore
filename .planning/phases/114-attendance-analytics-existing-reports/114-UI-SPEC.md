All colors are **semantic tokens** from `src/styles/tokens.css`. Raw palette classes
(`bg-emerald-400`, `text-slate-900`, etc.) are banned by ESLint. Use only the tokens
below.

| Role | Token | Usage in Phase 114 |
|------|-------|---------------------|
| Dominant (60%) | `bg-surface` | Card body backgrounds; page background |

| Accent (10%) | `var(--primary-deep)` / `bg-primary-soft` | AreaTrendChart stroke/fill; bar fill for peak weekday/hour in day-of-week and peak-hour widgets |

a tone chip. This is a data-absent-by-design state, not an error state.

## Surface 1: DayOfWeekCard

### Data derivation

`getDayOfWeekStats(daily: VisitsReportDailyBucket[]): DayOfWeekStat[]`

- Group `daily[]` by weekday using `parseISO(b.date)` + `getDay()` from date-fns (MSK-safe via ISO string — no raw `new Date(dateOnly)` per CLAUDE.md DST rule).
- Return an array of 7 items `{ weekday: 0–6, label: 'Пн'|'Вт'|..., total: number, avgPerWeekday: number, daysWithData: number }`.
- Zero-fill all 7 buckets even if no visit falls on that weekday.
- Weekday order: Пн (1), Вт (2), Ср (3), Чт (4), Пт (5), Сб (6), Вс (0) — Monday-first, matching Russian convention.
- Peak weekday: highest `total`. Tie → earlier weekday in the Mon-first order.

### Visual structure

```
Card as="section"
  CardHeader
    title:    "По дням недели"
    subtitle: "Суммарная посещаемость по дням за выбранный период"

  body (px-5 pb-4):
    horizontal bar list — 7 rows, each:
      <div className="flex items-center gap-3 py-1.5">
        <span className="w-6 shrink-0 text-[11.5px] text-fg-muted">{label}</span>  ← Пн–Вс
        <div className="flex-1 overflow-hidden rounded-full bg-surface-2 h-2">
          <div
            style={{ width: `${pct}%` }}
            className={cn('h-2 rounded-full transition-all', isPeak ? 'bg-primary' : 'bg-chart-2')}
          />
        </div>
        <span className="w-8 shrink-0 text-right text-[11.5px] tabular-nums text-fg-muted">
          {total}
        </span>
      </div>
```

Bar width = `(total / maxTotal) * 100`, clamped to [0, 100]. Zero bars render at 0%
width (not hidden — preserves weekday alignment).

## Surface 2: PeakHourCard

### Data derivation

`getPeakHour(hourly: VisitsReportHourlyBucket[]): { hour: number; count: number } | null`

- Return `null` if all counts are 0 (all-zero case is handled upstream by the page-level
  EmptyState; this component will not render in that state, but guard anyway).
- If all counts are equal and non-zero, return `{ hour: 0, count }` (earliest wins).
- Tie-break: earlier hour.

### Visual structure

```
Card as="section"
  CardHeader
    title:    "Пиковый час"
    subtitle: "Час дня с наибольшим числом визитов"

  body (px-5 pb-4 pt-0):
    <KpiTile
      icon={Clock}
      label="Пиковое время"
      value={`${hour}:00–${hour + 1}:00`}
      unit={`${count} визитов`}
    />
```

`Clock` from `@/components/icons`. KpiTile reused without modification.

## Surface 3: FrequencyCard

### Data derivation

`getFrequencyBuckets(daily: VisitsReportDailyBucket[]): FrequencyBucket[]`

Returns 6 fixed buckets: `[0–4, 5–9, 10–14, 15–19, 20–24, 25+]`. Each bucket:
`{ label: string; count: number }` where `count` = number of days whose `daily.count`
falls in that range. Zero-fill all buckets.

### Visual structure

```
Card as="section"
  CardHeader
    title:    "Распределение дневной посещаемости"
    subtitle: "Сколько дней приходится на каждый диапазон визитов"

  body (px-5 pb-4):
    <AreaTrendChart
      data={buckets.map(b => ({ label: b.label, value: b.count }))}
      height={160}
    />
```

Using `AreaTrendChart` reuses the existing chart primitive. Color: existing
`var(--primary-deep)` stroke + `areaTrendFill` gradient — no new colors needed.

> **Design note:** the histogram shape is rendered as an AreaTrendChart (step-like
> trend) rather than a bar chart. A true `BarChart` is available via Recharts/shadcn
> if the executor judges it more readable — acceptable discretion, provided it uses
> only existing tokens (`var(--chart-5)` for bars) and the existing `ChartContainer`
> wrapper. No new dependencies.

## Interaction & State Contract

### Loading / fetching

The existing `LoadPage` skeleton (`Skeleton h-[320px]`) covers the entire section
below `LoadKpis` during refetch. No per-widget loading states needed.

### All-zero empty state

The existing page-level `EmptyState` ("Нет данных за этот период") replaces the
entire section when `totalVisits === 0`. New widget components do NOT render in this
state; no per-widget empty states needed.

### Zero-filled buckets

All derive functions zero-fill every bucket. Chart components receive only non-NaN
numbers. This is enforced in `derive.ts` and covered by Vitest unit tests.

### Reception / RBAC

All new widgets inherit the existing `can(role, 'view', 'reports')` page gate in
`LoadPage`. Reception users see the Lock EmptyState before any data fetches — the
widgets are never rendered for reception.

### Date range change

Date range state lives in `LoadPage` (`fromDate`/`toDate`). When changed:
1. `useLoad` re-fires; `isFetching && !isPending` → page-level `Skeleton` replaces the
   entire chart+widget section.
2. On resolution, the new `daily[]`/`hourly[]` arrays flow through `derive.ts` to all
   widgets simultaneously (single `useLoad` subscription, no extra requests).

## Accessibility Contract

- New `<section aria-label="Дополнительная аналитика">` wrapper provides landmark for
  screen readers.
- Each `<Card as="section">` + `<CardHeader>` produces a visually labeled section;
  the `CardHeader` title is rendered as `<div>` (not heading) — consistent with the
  existing `LoadHeatmapCard` pattern. No heading-level disruption.
- Bar widths in `DayOfWeekCard` are percentage-width `<div>` elements. Each row's
  accessible text = weekday label + numeric value visible in the DOM — no additional
  `aria-label` needed.
- `DurationPlaceholderCard` has no interactive controls; no `role` attribute needed.
- Chart containers (`ChartContainer`) already manage their own ARIA via Recharts SVG —
  consistent with existing `AreaTrendChart` / `IntensityHeatmap` usage.
- Focus management: no new focusable elements added to the page in this phase.
