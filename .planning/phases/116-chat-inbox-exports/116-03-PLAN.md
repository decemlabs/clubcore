## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → admin SPA | Role (owner/reception) decides composer + export-button visibility; UI gate is convenience — backend is the authority |
| SPA → /api/v1/messages, /api/v1/reports/*.csv | Cookie-credentialed staff requests; backend RBAC is the real enforcement |
| downloaded CSV → spreadsheet | Backend already BOM-prefixes + formula-sanitizes; FE just triggers the download |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-12 | Elevation of Privilege | composer + export buttons | mitigate | `can(role,'create','messages')` hides composer for reception; `can(role,'view','finance'|'reports')` hides export buttons. Backend (116-01/116-02) enforces 403 regardless — FE gate is defense-in-depth, not the authority |
| T-116-13 | Spoofing/CSRF | reply POST | mitigate | `staffRequest` injects `X-CSRF-Token` automatically on POST; backend verify_csrf enforces it |
| T-116-14 | Information Disclosure | mock data leakage | mitigate | Mock `messagesData` import removed from api.ts — no stale/placeholder client data renders (D-V32-DRIFT-LESSON: parse real shapes via Zod) |
| T-116-15 | Tampering (XSS) | message bubble body render | accept | React escapes text content by default; bodies render as text (existing bubble component), not dangerouslySetInnerHTML; no new sink introduced |
| T-116-SC | Tampering | npm package installs | mitigate | No new npm packages added (Download/Loader2 are from the existing lucide-react dep); nothing to audit |
</threat_model>
