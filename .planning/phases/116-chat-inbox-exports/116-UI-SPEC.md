# Phase 116 — UI Design Contract

> Visual and interaction contract for Phase 116: Chat Inbox & Exports.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Scope: two surfaces added to an existing admin app with a fully established design
> system. Surface 1 — wire the existing MessagesPage (ConversationList, ThreadPane,
> ClientPanel, MessageTabs, MessagesPageHead) from mock to new staff REST endpoints;
> add role-gated composer (hidden for reception) and per-screen empty states. Surface 2
> — add owner-gated "Экспорт CSV" buttons on CashboxPageHead / FinancePage (payments)
> and AttendancePageHead (visits); immediate blob download; honest loading/disabled
> state during download.
>
> All tokens, spacing, typography, and color are INHERITED from the established project
> system. This contract documents their application to the two new UI surfaces only.

## Surface 1: Staff Chat Inbox (MessagesPage wire)

### Layout (unchanged)

The existing `MessagesPage` 3-panel grid is reused verbatim:
- Left: `ConversationList` (300px / 320px on xl, `md:flex`)
- Center: `ThreadPane` (flexible)
- Right: `ClientPanel` (340px on xl, `xl:flex`)

No layout changes. No new grid columns.

### Conversation list row (wired)

Each `ConvRow` maps a `StaffThread` (from `GET /api/v1/messages/threads`) to the
existing `Conversation` shape. Mapping notes for the executor:

| Wire field | UI field | Display rule |
|-----------|----------|--------------|
| `thread.clientUnreadCount` → staff counts unread via `messagesFromClientSinceStaffRead` | `conv.unread` | Integer; `null` when 0 |
| `thread.lastMessageAt` | `conv.time` | Format as "HH:mm" (today) or "d MMM" (older) via `formatRelativeRu` |
| `thread.lastMessageBody` (truncated 60 chars) | `conv.last` | Truncated preview |
| `thread.lastMessageRole` | `conv.lastPrefix` | `role === 'staff'` → `{ text: 'Вы:', tone: 'note' }`; `role === 'client'` → null |
| `thread.clientName` | `conv.name` | Full name |
| `thread.clientInitials` | `conv.initials` | 1–2 char initials |
| `thread.staffUnreadCount > 0` | `conv.unread` | Integer badge value |

**Unread badge:** `bg-primary px-1 text-[10.5px] font-bold text-[#06120c]` pill —
pre-existing in `ConversationList.tsx`. No change needed.

**Active row indicator:** `before:bg-fg` left border — pre-existing. No change.

### Thread pane (wired)

Messages from `GET /api/v1/messages/threads/{id}` map to `ThreadItem[]`:

| Wire field | Bubble type | Visual |
|-----------|-------------|--------|
| `message.role === 'client'` | `'them'` | Left-aligned, `bg-surface border-border` bubble |
| `message.role === 'staff'` | `'me'` | Right-aligned, `bg-fg text-bg dark:bg-primary` bubble |
| Day boundary between consecutive messages | `{ kind: 'daysep', label: 'Вчера' }` | Centered divider with `text-fg-subtle` |

**Mark-read:** when a thread is opened (`onSelect` in `MessagesPage`), call
`useMarkThreadRead(threadId)` mutation immediately (fire-and-forget; no UI block).
This resets `staffUnreadCount` to 0 and the badge disappears on the next refetch.

### Composer (owner-only, reception hidden)

Conditional render in `ThreadPane` based on `can(role, 'create', 'messages')`:

```
{canSend ? (
  <div className="shrink-0 border-t-[0.5px] border-border bg-surface px-4 pb-3.5 pt-2">
    {/* existing composer — ModeTab row, quickReplies, textarea, send button */}
  </div>
) : null}
```

Reception sees the thread pane WITHOUT the composer section. The message history
(`flex min-h-0 flex-1 flex-col`) fills the full height. No "read-only" label or visual
indicator added — the absence is self-evident from the owner/reception role distinction.

**Send button state:**
- Enabled: `text.trim().length > 0` and `!isSending`
- Sending: send button shows `opacity-50 cursor-not-allowed` (disable attribute set);
  no spinner (existing `size-9` button is too small for spinner + icon — opacity is correct)
- ⌘↵ keyboard shortcut: already implemented in existing `ThreadPane`; retained

**After send:** `useSendReply` `onSettled` calls
`queryClient.invalidateQueries({ queryKey: messagesKeys.thread(threadId) })` and
`queryClient.invalidateQueries({ queryKey: messagesKeys.threads() })`.

### Inbox empty state

Rendered when `threads.length === 0` (no conversations at all):

```
<EmptyState
  icon={MessageSquare}
  title="Нет активных диалогов"
  body="Как только клиент напишет, диалог появится здесь."
/>
```

Positioned where the 3-panel grid would appear — full-width below `MessagesPageHead`.

### Empty thread pane

Rendered in the `ThreadPane` center column when `activeId` is null (no thread selected,
only possible when list is non-empty but no selection made yet on mobile):

```
<div className="flex min-h-0 flex-1 flex-col items-center justify-center gap-3 text-center">
  <MessageSquare className="size-10 text-fg-subtle" />
  <p className="text-[13.5px] text-fg-muted">Выберите диалог, чтобы открыть переписку.</p>
</div>
```

This is only visible on mobile (`md:hidden` ConversationList collapsed). On desktop,
the first thread is auto-selected.

### Inbox refetch strategy

| Trigger | Action |
|---------|--------|
| `refetchInterval` | 15 000 ms on `useThreads` (inbox list) |
| Window focus | `refetchOnWindowFocus: true` on `useThreads` only (overrides global `false`) |
| After send reply | `invalidateQueries` on both thread + threads list keys |
| Thread open | `invalidateQueries` on thread key (ensures fresh history) |

`useThread` (single thread): `refetchInterval: false`, `staleTime: 30_000`.

## Surface 2: CSV Export Buttons

### Placement

| Screen | Button placement | Owner gate |
|--------|-----------------|-----------|
| CashboxPage (`CashboxPageHead`) | Alongside the existing `DateRangePicker` in the `actions` prop | `can(role, 'view', 'finance')` (owner-only) — button hidden for reception |
| FinancePage | Alongside the existing `DateRangePicker` / page head actions | `can(role, 'view', 'finance')` — button hidden for reception |
| AttendancePage (`AttendancePageHead`) | Alongside existing `DateRangePicker` + "Чек-ин" button | `can(role, 'view', 'reports')` (owner-only) — button hidden for reception |

### Button visual spec

```
<Button
  variant="outline"
  size="sm"
  disabled={isDownloading}
  onClick={handleExport}
  className="h-[34px] shrink-0 gap-1.5 rounded-full px-3.5 text-[13px] font-semibold"
>
  {isDownloading ? (
    <Loader2 className="size-3.5 animate-spin" />
  ) : (
    <Download className="size-3.5" strokeWidth={2.2} />
  )}
  <span className="max-sm:hidden">Экспорт CSV</span>
</Button>
```

- **Variant:** `outline` (border + transparent background) — distinct from the primary
  "Чек-ин" / "Новый диалог" filled pills; avoids accent overuse.
- **Size:** `h-[34px]` — matches existing `DateRangePicker` trigger height and the
  "Чек-ин" button height on `AttendancePageHead`.
- **Loading state:** `Loader2` spinner replaces `Download` icon; button `disabled`.
  Label "Экспорт CSV" text stays visible on `sm:` and above (hidden on mobile via
  `max-sm:hidden` — icon only on mobile).
- **Icon:** `Download` from `@/components/icons` (Lucide). `size-3.5`, `strokeWidth={2.2}`
  — matches the `UserCheck` icon in `AttendancePageHead`.

### Download UX (blob pattern)

```ts
async function handleExport() {
  setIsDownloading(true)
  try {
    const blob = await staffRequest(`/reports/payments.csv?fromDate=...&toDate=...`, {
      responseType: 'blob',
    })
    const url = URL.createObjectURL(blob)
    const a = document.createElement('a')
    a.href = url
    a.download = `payments-${fromDate}-${toDate}.csv`
    a.click()
    URL.revokeObjectURL(url)
  } catch {
    toast.error('Не удалось экспортировать файл. Попробуйте ещё раз.')
  } finally {
    setIsDownloading(false)
  }
}
```

- No new tab opened. Immediate download via programmatic anchor click.
- `fromDate` / `toDate` come from the existing date-range state on each screen
  (already in scope for each page).
- File name format: `payments-YYYY-MM-DD-YYYY-MM-DD.csv` / `visits-YYYY-MM-DD-YYYY-MM-DD.csv`.
- The backend returns `Content-Type: text/csv; charset=utf-8` with a UTF-8 BOM —
  no client-side encoding work needed.

### Export button states

| State | Visual |
|-------|--------|
| Default | `outline` button, `Download` icon, label "Экспорт CSV" |
| `isDownloading` | Button `disabled`; `Loader2 animate-spin` icon; label unchanged |
| Error | Button re-enabled; Sonner `toast.error(...)` (see Copywriting) |
| 403 (reception — not reachable) | Button not rendered; `can()` gate prevents render |

## Interaction & State Contract

### Loading / fetching (MessagesPage)

- **Inbox pending:** existing `<PageLoading />` (in `MessagesPage.tsx`) covers initial
  load. No change.
- **Inbox re-fetching (background):** no skeleton; background refetch is silent. The
  conversation list updates in-place without any overlay.
- **Thread pending on selection:** a `Skeleton` row set in the ThreadPane center column
  while `useThread` `isPending`. Use 3–4 `Skeleton` lines with heights `h-8`, `h-10`,
  `h-8` to suggest message bubbles. Match existing `Skeleton` import from
  `@/components/ui/skeleton`.

### Error states (MessagesPage)

- **Inbox fetch error:** `<PageError onRetry={() => void refetch()} />` (existing pattern).
- **Thread fetch error:** inline error in the ThreadPane center column — `text-[13px] text-fg-muted` centered message with a "Попробуйте ещё раз" text button. Not a full `PageError` (would be disproportionate for a single thread).
- **Send error:** Sonner `toast.error(...)` (see Copywriting Contract). Modal stays open; composer text preserved.

### RBAC gate summary

| Action | Owner | Reception |
|--------|-------|-----------|
| View inbox thread list | YES | YES |
| View thread history | YES | YES |
| Send reply (composer visible) | YES | NO (composer hidden) |
| Export CSV payments | YES | NO (button hidden) |
| Export CSV visits | YES | NO (button hidden) |

All gates use `can(role, action, resource)` from `@/shared/session/can.ts`.
New resource: `Resource.MESSAGES` with `(CREATE, MESSAGES)` in OWNER_ONLY.
Existing resources: `FINANCE` (payments export), `REPORTS` (visits export).

## Accessibility Contract

- `ConversationList` — each `ConvRow` is a `<button type="button">` with visible text
  (client name + preview). Unread badge has `aria-label` via parent context — no
  additional `aria-label` required (badge is supplementary to the visible unread count).

  textarea has `placeholder` with keyboard shortcut hint.

  `aria-label` — add `aria-label="Экспорт CSV"` when `max-sm:hidden` hides the text.

  with a visible heading and body paragraph.
- No new modal dialogs introduced. No new focus traps.
- Loading spinner (`Loader2 animate-spin`) inside the export button: wrap with
  `aria-busy="true"` on the button when `isDownloading`.
