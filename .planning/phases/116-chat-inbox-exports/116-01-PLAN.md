<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → /api/v1/messages | Authenticated staff (owner/reception) cookie + CSRF; reception is lower-privilege and must not send |
| staff reply → client PWA | Staff-authored body reaches a client over WS/Telegram (existing channel) |
| router → message_threads/messages/clients | thread_id path param scopes the read; must not leak other threads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-01 | Elevation of Privilege | POST /threads/{id}/reply | mitigate | `(CREATE, MESSAGES) ∈ OWNER_ONLY`; reception → 403; integration test `reception POST /reply → 403` asserts it |
| T-116-02 | Spoofing/CSRF | POST /reply, POST /read | mitigate | `verify_csrf` on both writes, declared AFTER `require_permission` (RBAC-04 ordering) so a forbidden actor never reaches CSRF |
| T-116-03 | Information Disclosure | GET /threads/{id} | mitigate | thread_id resolved server-side via `get_thread_client_id`; history fetch scoped to the resolved client_id only — no cross-thread bleed; UUID path param, no client-supplied client_id |
| T-116-04 | Tampering (SQLi) | new repository raw-SQL reads | mitigate | All reads via `text()` + `:name` bind params + str(UUID) casts (D-54-08); no string interpolation of params |
| T-116-05 | Repudiation | staff reply | mitigate | `record_staff_message` emits the pre-registered `message_sent` audit event co-transactionally (INFRA-15) |
| T-116-06 | Denial of Service | GET /threads inbox | accept | Single-club scale; thread count is small; ORDER BY last_message_at with index on message_threads. Pagination of the inbox is a discretion item; not required at current scale |
| T-116-SC | Tampering | python package installs | mitigate | No new packages added in this plan; nothing to audit |
</threat_model>
