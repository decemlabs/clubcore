<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → /api/v1/reports/payments.csv | Owner-only export of the financial ledger; reception must not reach it |
| ledger cells → downloaded CSV → Excel | User-derived text (client/operator) flows into a spreadsheet that may auto-execute formulas |
| date-range query params → SQL | Untrusted range params reach the ledger query |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-07 | Elevation of Privilege | GET /payments.csv | mitigate | `(VIEW, REPORTS) ∈ OWNER_ONLY`; reception → 403; test `test_payments_csv_reception_forbidden` asserts it. Export exposes nothing beyond what owner already sees in Cashbox/Finance |
| T-116-08 | Tampering (CSV/formula injection) | free-text cells (clientName, operatorEmail) | mitigate | `csv_export.sanitize_csv_text` prefixes cells beginning with `= + - @` (existing guard) — applied to all user-derived cells incl. Cyrillic |
| T-116-09 | Tampering (SQLi) | fetch_payments_for_csv | mitigate | date-range + all params passed as `text()` `:name` bound params, never string-interpolated (D-54-08) |
| T-116-10 | Denial of Service | unbounded export | mitigate | `_validate_date_range` enforces the existing ≤366-day cap (range-too-large error); `StreamingResponse` streams rows (no full in-memory buffer) |
| T-116-11 | Information Disclosure | inverted/garbage range | mitigate | `to < from` → 422 via `_validate_date_range`; no partial/ambiguous dumps |
| T-116-SC | Tampering | python package installs | mitigate | No new packages added in this plan; nothing to audit |
</threat_model>
