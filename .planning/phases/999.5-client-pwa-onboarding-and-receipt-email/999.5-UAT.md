### 10. Continue to Payment (saves email)
expected: With a valid email entered, «Продолжить к оплате» saves the email (PATCH /client/me) and proceeds to the ЮKassa payment redirect.
result: issue
reported: "«Продолжить к оплате» saves the email correctly (PATCH /client/me → 200, DB shows andre@gmail.com) but the checkout POST returns 502 yookassa_permanent_error and no ЮKassa redirect happens — the user sees the «Не удалось оплатить» error screen."
severity: major
root_cause: |
  ЮKassa rejected create_payment with HTTP 400 invalid_request, parameter=Idempotence-Key:
  "You've already used this idempotence key for another request within the past 24 hours."
  The membership Idempotence-Key is deterministic per (subject_kind, plan_id, client_id, UTC-date)
  via _derive_idempotency_key (sha256, online_payments/service.py:93) and does NOT include the receipt
  contact. 999.5's email-gate (Plan 03/05) makes it realistic for the SAME client+plan+day to produce
  two different receipt bodies (phone-only via «Чек не нужен» vs email via the gate). When the body
  changes but the deterministic key repeats, ЮKassa rejects with invalid_request → 502.
  The local retry-key escape hatch (`idem_key = f"{key}:retry-{uuid4().hex}"`, service.py:304) only fires
  when an `existing` online_payments row is found — but a ЮKassa-rejected attempt INSERTs no row, so the
  burned key is reused on every retry, locking the client out of paying for ~24h.
  PROVEN: replaying the exact backend body with a FRESH uuid Idempotence-Key → 200 pending +
  confirmation_url; replaying with the derived deterministic key → 400 invalid_request (Idempotence-Key).
  NOTE: deterministic-per-day key predates 999.5 (D-49-08/D-71-04); 999.5's variable receipt body is what
  makes the collision reachable in normal use. In this test run the key was burned by prior same-day
  checkout activity. Graceful error UI shown (no crash) — claude-10-checkout-error.png.
  missing:
    - "Include a request-body discriminator (or the receipt-contact) in the Idempotence-Key derivation, OR"
    - "On ЮKassa invalid_request with parameter=Idempotence-Key, retry once with a fresh key even when no online_payments row exists"
