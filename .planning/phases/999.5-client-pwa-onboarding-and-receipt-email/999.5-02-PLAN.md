<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → PATCH /client/me | untrusted client input crosses into a DB write |
| client → GET /client/me | client reads own profile only |
| email value → 54-ФЗ fiscal receipt | a bad email has legal/financial consequence downstream |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-999.5-04 | Elevation/IDOR | PATCH /client/me write | mitigate | Write is scoped to `client.id` from `require_client()` principal; client_id is NEVER read from the request body — a client can only write their own row |
| T-999.5-05 | Tampering | goal / height_cm / weight_kg inputs | mitigate | service.update_client_profile rejects unknown goal (allow-list), height outside 140–210, weight outside 40–150 before write; DB CHECK on goal is the second layer (T-999.5-01) |
| T-999.5-06 | Tampering | email input → fiscal receipt | mitigate | server-side email format validation in service (not trusting the client regex); malformed email rejected with a stable error code before write |
| T-999.5-07 | Spoofing | onboarding_completed flag forge | mitigate | The flag is set only via the authenticated client's own PATCH on their own row; it cannot be set on another client. Setting it merely suppresses the auto-redirect — no privilege is granted, so forgery has no security value (worst case: a client suppresses their own questionnaire). |
| T-999.5-08 | CSRF | PATCH /client/me | mitigate | `verify_client_csrf` dependency required on the write endpoint (RBAC-04 ordering after require_client) |
| T-999.5-09 | Information disclosure | payment-status receipt destination | mitigate | receipt_email/receipt_phone populated ONLY inside the `status == 'succeeded'` branch (anti-oracle preserved); pending/canceled reveal nothing |
| T-999.5-SC | Tampering | npm/pip/uv installs | mitigate | No new packages introduced; nothing to verify |
</threat_model>
