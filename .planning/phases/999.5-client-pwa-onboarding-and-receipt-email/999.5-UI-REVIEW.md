## Top 3 Priority Fixes

1. **"ЧЕК ОТПРАВЛЕН НА" receipt-destination line removed from PaymentSucceededView** — Users who completed payment via the «Чек не нужен» path (phone receipt) and users who provided email have no on-screen confirmation of where their fiscal receipt went. This directly contradicts UI-SPEC §Screen 2 D-09: "augments existing PaymentSucceededView — a single 'чек отправлен на {dest}' line added inline." The REVISION 2 note in `PaymentReturnScreen.jsx:26` says it was removed as "not in mockup" — this conflicts with the UI-SPEC which is the design contract for this phase. Restore the `receiptEmail`/`receiptPhone` row into `PaymentSucceededView` inside the `status === 'succeeded'` branch. The backend already populates `receipt_email`/`receipt_phone` in the payment-status response (Plan 02), and `clientQueries.ts` already extends `PaymentStatusData` with `receiptEmail`/`receiptPhone`.

2. **Goal card description text 12px and metric scale labels 11.5px both diverge from spec's 13px** — `OnboardingScreen.jsx:509` uses `fontSize: 12` for goal card descriptions; `OnboardingScreen.jsx:226` uses `fontSize: 11.5` for slider scale labels. UI-SPEC §Typography specifies both as `.t-small` = 13px weight 400. At sub-13px on a mobile viewport these labels become uncomfortably small for users with any visual impairment. Fix: change `fontSize: 12` to `fontSize: 13` on the goal card `<span>` at line 509, and change `fontSize: 11.5` to `fontSize: 13` on the scale labels `<div>` at line 226.

3. **«Готово!» circle pop animation does not reliably re-trigger** — The circle's `animation` prop is toggled inline: `done ? 'pop 0.45s...' : 'none'` (`OnboardingScreen.jsx:713`). Because the element is always mounted in the DOM (the overlay is visible-hidden via opacity), browsers do not restart a CSS animation when its value changes via an inline style mutation on an already-painted element — only the first render triggers it. Result: the circle has no entrance animation when `done` flips to `true`. Fix: use a React `key` on the circle element tied to `done`, or conditionally render the overlay with `{done && <DoneOverlay />}` so the element mounts fresh and the animation fires from frame 0.

### Pillar 2: Visuals (2/4)

**BLOCKER — Receipt destination information missing from PaymentSucceededView:** UI-SPEC §"Post-payment receipt confirmation" explicitly specifies: an icon (mail, 20×20px), a label "ЧЕК ОТПРАВЛЕН НА" (11px caps, `var(--text-3)`), and a value line (`{email}` if present, else `{phone number}`). REVISION 2 of `PaymentReturnScreen.jsx` deliberately removed this: `line 26: "Removed 'ЧЕК ОТПРАВЛЕН НА' receipt-destination chip (not in mockup)"`. The UI-SPEC is the design contract for this phase, and it describes this augmentation explicitly. The backend populates `receiptEmail`/`receiptPhone` in the payment-status response (`Plan 02`), and the frontend extended `PaymentStatusData` with these fields (`Plan 05`). The wiring was built but the rendering was removed.

WARNING — «Готово!» circle pop animation unreliable: `OnboardingScreen.jsx:713` uses `animation: done ? 'pop 0.45s...' : 'none'`. When `done` transitions from `false` to `true`, the CSS animation runtime sees a style change on an already-painted element and does not restart the animation. The overlay fade-in (`opacity: 0 → 1, transition: 0.26s`) works correctly because opacity is a CSS transition, but the pop keyframe will not play. Users see the circle appear without the spec-required bouncy entrance.

PASS — Spot illustrations: both `SpotScene` (128×96px) and receipt illustration (188×188px halo, 116px receipt card, 58×58px @-badge) match spec dimensions.

PASS — Visual hierarchy: clear size/weight differentiation (25px/700 titles, 14.5px/400 subtitles, 54px CTAs), focal points established per-screen.

PASS — All decorative illustrations carry `aria-hidden="true"`.

### Pillar 3: Color (4/4)

All hardcoded hex values are the two spec-approved exceptions:
- `#06120c` (accent-button text, dark) — used 6 times across both screens, all on accent fill backgrounds as specified
- No `#a36a16` (warn icon text) usage — not needed in these screens

All color usage routes through `var(--token)` CSS custom properties:
- Accent (`var(--accent)`) confined to the 11 spec-listed elements (CTA buttons, progress fill, selected goal card, slider thumb, «Готово!» circle, @-badge, field focus ring, done-flash circle)
- `var(--danger)` confined to email validation error border and hint text only
- Shadow values use `rgba(28,25,23,…)` and `rgba(45,212,164,…)` which are spec-verbatim from the mockup, not arbitrary values

Domain chip default border correctly uses `var(--border-strong)` per spec (not accent).

Topbar buttons use `var(--surface)` background with `var(--border)` border per spec.

60/30/10 distribution maintained: `var(--bg)` dominant on all screen backgrounds; `var(--surface)` / `var(--surface-2)` on cards/chips; accent reserved for interactive elements only.

WARNING — Email topbar height: spec states `52px` for the email topbar. Implementation uses `padding: '48px 12px 4px'` on the topbar container, which combined with the `38px` button height renders the topbar visually taller than 52px (48px padding-top + 4px padding-bottom + 38px button = ~90px of vertical space). ### Pillar 6: Experience Design (3/4)

**PRESENT:**
- Loading states: `isFinishing = updateProfile.isPending` and `isSkipping = completeOnboarding.isPending` both drive spinner rendering and disabled states — `OnboardingScreen.jsx:322,323`
- Email save loading: `saving` state drives spinner in primary CTA — `ReceiptEmailGate.jsx:35,68`
- Error states: inline error `submitError` (`OnboardingScreen.jsx:664`), `skipError` (`OnboardingScreen.jsx:392`), and `saveError` (`ReceiptEmailGate.jsx:310`) all surfaced with `var(--danger)` and retry messaging
- Email validation error: `role="alert"` on hint div when `error===true` — `ReceiptEmailGate.jsx:260`
- Network error on save: `role="alert"` on saveError div — `ReceiptEmailGate.jsx:311`
- Disabled states: Goal step CTA disabled until goal selected (`disabled={ctaDisabled}`) with `opacity: 0.35` and `cursor: not-allowed` per spec — `OnboardingScreen.jsx:535`
- Email CTA disabled when field empty or invalid — `ReceiptEmailGate.jsx:335`
- Domain chip suggestion: shows after `@` typed with incomplete domain, hides on complete address — `ReceiptEmailGate.jsx:41,42`
- Anti-oracle preserved: `receiptEmail`/`receiptPhone` rendered ONLY in succeeded branch (but removed from view — see Pillar 2 finding)
- Accessibility: `aria-hidden` on inactive slides, `aria-pressed` on goal cards, `aria-label` on icon-only buttons — all correct

WARNING — «Чек не нужен» visual ack missing: UI-SPEC §Interaction States specifies: `"brief visual ack (text change per mockup: 'Хорошо, без чека' → 1.4s → reset)"` for the skip CTA. The implementation calls `onSkip()` immediately without any transient state change. Users who tap «Чек не нужен» receive no in-screen acknowledgment that their choice was registered before the gate closes.

WARNING — No initial load error handling in OnboardingScreen: the screen has no mechanism to surface a failure fetching `clientMe` data on load (required for the auto-redirect gate). The UI-SPEC says to reuse `<LoadError onRetry={…} />` for this case. If `useClientMe()` fails, the screen renders without any error state — the `onboardingCompletedAt` check silently falls through.

WARNING — `«Готово!» circle pop animation` unreliable (see Pillar 2 for detailed diagnosis). The circle animation `'pop 0.45s...'` applied via conditional inline style will not re-trigger on React state change. The overlay fade-in works, but the circle will appear without its entrance animation on most browsers.
