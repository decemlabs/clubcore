| Boundary | Description |
|----------|-------------|
| PWA → PATCH /client/me | client submits profile data (server re-validates — Plan 02) |
| onboarding flag (client-read) | the auto-redirect keys on a server-provided flag |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-999.5-13 | Tampering | client-side height/weight/goal input | mitigate | Client-side bounds are UX only; the authoritative validation is server-side in Plan 02 (rejects out-of-range / unknown goal). The frontend never assumes its own validation is trusted. |
| T-999.5-14 | Spoofing | onboarding-completed flag | accept | The flag is server-owned and read-only on the client; a tampered local value at worst suppresses the user's own questionnaire (no privilege gained) — same disposition as T-999.5-07 |
| T-999.5-15 | DoS | auto-redirect loop | mitigate | Redirect fires only on the home route with `replace: true` and a precise newbie+empty-profile+!flag condition; useEffect deps prevent re-fire after completion |
| T-999.5-SC | Tampering | npm/pnpm installs | mitigate | No new npm dependencies (UI-SPEC §Registry Safety confirms none); nothing to verify |
</threat_model>
