## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client PWA → /client/loyalty/* | untrusted client request; client_id MUST come from require_client() principal, never the URL |
| staff client → /clients/{id}/loyalty/grant | staff request; only Role.OWNER may grant; reception is untrusted for this op |
| client_created event → welcome accrual | repeated/retried creation events must not double-credit |
| owner grant body → ledger | amount_kopecks is untrusted integer input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-05 | Information Disclosure (IDOR) | GET /client/loyalty/balance + /history | mitigate | client_id sourced from require_client() principal ONLY; reads filtered by principal client_id; cross-client isolation asserted in test_loyalty_read.py (D-20-IDOR) |
| T-82-06 | Elevation of Privilege | POST /clients/{id}/loyalty/grant | mitigate | require_owner_for_loyalty_grant() admits only Role.OWNER; reception → 403 + rbac_forbidden audit; does NOT widen OWNER_ONLY/can.ts (parity + CISO-01 stay green); asserted in test_loyalty_grant.py |
| T-82-07 | Tampering (double-credit) | welcome accrual idempotency | mitigate | pg_insert on_conflict_do_nothing on uq_loyalty_ledger_welcome; audit emitted only on real insert; replay test proves zero extra rows |
| T-82-08 | Tampering (negative/overflow injection) | owner grant amount_kopecks | mitigate | service rejects amount_kopecks<=0 with 422 (grant_amount_must_be_positive); grants are accrual-only positive; owner cannot create deduction rows |
| T-82-09 | Repudiation | accrual without audit | mitigate | every successful accrual emits loyalty_accrued co-transactionally (same UoW as the ledger insert); test_loyalty_accrual + test_loyalty_grant assert the audit row exists |
| T-82-10 | Spoofing (CSRF on grant) | POST grant (state-changing) | mitigate | verify_csrf dependency in RBAC-04 order (auth→perm→csrf→db) on the grant endpoint |
| T-82-SC | Tampering | npm/pip/cargo installs | accept | No new packages this phase — all imports (sqlalchemy, fastapi, pydantic, structlog) already vetted upstream; no Package Legitimacy Gate required |
</threat_model>
