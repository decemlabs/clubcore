## Outcome

- `apps/backend/app/modules/auth/models.py` — three ORM classes: `User(Base, UUIDPkMixin, TimestampMixin)`, `RefreshToken(Base, UUIDPkMixin, TimestampMixin)`, `OtpCode(Base, UUIDPkMixin, TimestampMixin)`. Column shapes match D-01..D-07 verbatim.
- `apps/backend/alembic/env.py` — added `import app.modules.auth.models  # noqa: F401` so autogenerate sees the new tables. `target_metadata = Base.metadata` was already wired in Phase 4.
- `apps/backend/alembic/versions/0001_auth.py` — first business migration. `revision = "0001_auth"`, `down_revision = None`. Creates `users`, then `otp_codes`, then `refresh_tokens` (FK targets first), plus the composite index `ix_refresh_tokens_user_id_family_id`.
- All constraint names follow `pk_/uq_/ix_/ck_/fk_` template:
  - users: `pk_users`, `uq_users_email`, `uq_users_telegram_chat_id`, `ck_users_role`
  - refresh_tokens: `pk_refresh_tokens`, `uq_refresh_tokens_token_hash`, `fk_refresh_tokens_user_id_users`, `fk_refresh_tokens_replaced_by_id_refresh_tokens`, `ix_refresh_tokens_user_id_family_id`
  - otp_codes: `pk_otp_codes`, `uq_otp_codes_deep_link_token_hash`, `fk_otp_codes_user_id_users`
- ck_users_role enforces `role IN ('owner', 'reception')` at the DB level — fences off SQL-injection and stale-enum writes (T-05.03-04 in threat model).
- `replaced_by_id` self-FK uses `ON DELETE SET NULL` so chain repair survives ancestor deletion (T-05.03-06).
- `otp_codes` ships in its FINAL Phase 7 shape (D-03) — Phase 7 only needs to write app code, no migration churn.

## Threat Mitigations Applied

| Threat ID    | Mitigation Realized                                                                          |
| ------------ | -------------------------------------------------------------------------------------------- |
| T-05.03-01   | `password_hash TEXT NOT NULL` — never nullable                                               |
| T-05.03-02   | `refresh_tokens.token_hash` is `Text NOT NULL UNIQUE` — schema only stores SHA-256 hashes    |
| T-05.03-03   | `otp_codes.code_hash` nullable Text — only the bot worker writes hash, never plaintext       |
| T-05.03-04   | `ck_users_role` CHECK constraint blocks unknown role writes at DB level                       |
| T-05.03-06   | `replaced_by_id` self-FK ON DELETE SET NULL preserves rotation chain on ancestor delete      |
| T-05.03-07   | `TimestampMixin.updated_at` uses `func.now()` server-side; client clock cannot lie           |
| T-05.03-05   | (accepted) Refresh-token table-pruning deferred to Phase 11+ — bounded by ~100 rows for 1-2 ops |
