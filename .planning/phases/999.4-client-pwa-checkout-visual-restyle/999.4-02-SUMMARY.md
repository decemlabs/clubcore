## Decisions Made

1. **D-11 2-hop fiscal receipt join** — `fiscal_receipts.payment_id` → `payments.id` requires joining through `memberships` or `pt_packages` (no direct `online_payments.id → payments.id` link exists). The join is scoped to `op.client_id` to maintain T-999.4-15 IDOR safety. Raw SQL `text()` follows D-54-08/D-58-19 precedent (no ORM cross-module import).

2. **ValidationAppError subclasses locally in promo_codes/service.py** — Each reason code is a distinct class with a stable `code=` class attribute. Not added to `app.core.exceptions` because they are domain-specific to promo validation (bounded context). The test asserts `body["code"]` (the class-level attribute) directly.

3. **module-level import of promo_codes.service** — Used `import app.modules.promo_codes.service as _promo_service` at module level (not inside the function) since the import-linter `ignore_imports` edge was registered in Plan 01. Only `text` from `sqlalchemy` uses a local import to avoid potential circular dependency at module level.
