<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → checkout endpoint | Untrusted: code only. Discounted amount is server-computed, never client-supplied. |
| ЮKassa webhook → succeeded handler | Signature-verified (existing webhook_verifier); redemption recorded only on a verified succeeded event. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-999.4-08 | Tampering | discount sent to ЮKassa | mitigate | price_override_kopecks comes from server validate_promo_code, never the client; the row + ЮKassa both use the server amount. |
| T-999.4-09 | Elevation/Tampering | redemption-limit race (per-client + global) | mitigate | Validate-time check + record-time max_uses re-check + UNIQUE(online_payment_id); a payment can record at most one redemption, and the global cap is re-verified at record time. Residual over-grant under extreme concurrency is bounded by 1-per-payment and accepted for single-gym scale. |
| T-999.4-10 | Tampering | replayed succeeded webhook double-records | mitigate | record_promo_redemption uses on_conflict_do_nothing on uq_promo_redemptions_online_payment_id. |
| T-999.4-11 | Tampering | discount applied but redemption never recorded (limit bypass) | mitigate | promo_code_id persisted on online_payments at create; webhook reads it and records deterministically on succeeded. |
| T-999.4-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed. |
</threat_model>
