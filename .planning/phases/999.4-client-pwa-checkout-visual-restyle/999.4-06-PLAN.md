<objective>
Close the single blocker gap from 999.4-HUMAN-UAT (Test 2): the restyled CheckoutSheet renders the checkout amount 100x too small (50 ₽ for a 5 000 ₽ plan), and with a promo the discounted total renders ABOVE the strikethrough original.

Root cause (already diagnosed, do NOT re-diagnose): units mismatch. `PlansSheet.jsx` adapters set `priceTotal = priceKopecks / 100` (RUBLES). `App.jsx:268` forwards `amount: plan.priceTotal` (rubles) into `checkoutCtx.amount`. The 999.4-restyled `CheckoutSheet.jsx` documents and treats `amount` as KOPECKS (`formatMoney(ctx.amount)` divides by 100 internally), so `formatMoney(5000)` renders "50 ₽". When a promo applies, `total = promoResult.newAmountKopecks` (real server kopecks) renders at correct scale, so the discounted total appears larger than the 100x-too-small original.

Fix direction (from gap `missing`): make `checkoutCtx.amount` be in KOPECKS so it matches CheckoutSheet's `formatMoney(kopecks)` and the server's `newAmountKopecks`. Pass the raw, exact `priceKopecks` value — NOT `priceTotal * 100` (avoids reintroducing float-rounding noise that `priceKopecks` already avoids).

Purpose: A payment screen must display the amount that is actually charged. This is a consent/trust correctness bug on a payment surface.
Output: `checkoutCtx.amount` in kopecks; CheckoutSheet header, ЗАКАЗ line, strikethrough original, and "Оплатить" button all show the real price for both `sub` and `pt`; promo strikethrough original >= discounted total.
</objective>
