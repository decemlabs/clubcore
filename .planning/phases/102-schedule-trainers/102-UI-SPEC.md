## Surface 1: Schedule Management Panel (Owner-Only)

**Requirement:** SCH-01. Net-new UI for owner to publish availability slots, create recurring templates, and block time-off. Reception sees the calendar READ-ONLY — no management entry points rendered.

### 1.1 Entry Point: Schedule Management FAB (Owner Only)

The existing FAB in `SchedulePage.tsx` is labelled `«Создать сессию»` and wires to the old mock `BookModal`. For Phase 102:

- **Owner role**: FAB remains. Its label becomes `«Управление расписанием»`. Click opens the **Schedule Management modal** (see §1.2).
- **Reception role**: FAB is **not rendered** (`can(role, 'publish', 'schedule-slots') === false`). No lock icon, no disabled state — simply absent.

Icon: `Plus` (existing, unchanged). FAB class: unchanged (`fixed bottom-6 right-6 z-30 …`).

### 1.2 Schedule Management Modal

**Component pattern:** `AdaptiveModal` (size=`'default'`, max-w-540px on desktop; drawer on mobile). Single modal with three tabs (ChipGroup-style) that switch the body content.

**Modal header:**
- Icon: `IconChip` tone=`'accent'`, icon=`CalendarPlus` (Lucide)
- Title: `«Управление расписанием»`
- Description: `«Слот · Шаблон · Блокировка»`

**Tab switcher** (inside modal body, before fields): `ChipGroup` (existing `fields.tsx` primitive) with three options:

| value | label |
|-------|-------|
| `slot` | `«Слот»` |
| `template` | `«Шаблон»` |
| `timeoff` | `«Блокировка»` |

Default selected tab: `slot`.

### 1.3 Tab: Опубликовать слот (`slot`)

**API:** `POST /api/v1/trainer-slots` body `{trainerId, startTime, endTime}` + `Idempotency-Key`.

**Fields (in order):**

1. **Тренер** (required): `ModalSelect` — populated from `GET /api/v1/trainers?active=true`. Options: trainer `fullName`. Placeholder option: `«Выберите тренера»`.
2. **Дата** (required): `ModalInput` type=`date`. Label: `«Дата»`. Min: today.
3. **Время** (required): `FieldRow` cols=2:
   - `ModalInput` type=`time` label=`«Начало»`
   - `ModalInput` type=`time` label=`«Конец»`

**Validation (client-side, before send):**
- Тренер: required — `«Выберите тренера»`
- Дата: required, not in past — `«Дата не может быть в прошлом»`
- Начало/Конец: both required; Конец must be after Начало — `«Конец должен быть позже начала»`

**409 errors (inline Callout tone=`'danger'` below fields):**
| code | copy |
|------|------|
| `slot_overlap` | `«Слот пересекается с существующим слотом тренера»` |
| `slot_too_close` | `«Слот слишком близко к другому слоту (менее минимального интервала)»` |
| `slot_in_past` | `«Нельзя публиковать слот в прошлом»` |
| `trainer_inactive` | `«Тренер неактивен — сначала активируйте его»` |

**Footer actions:**
```
[ Отмена (ghost) ]   [ Опубликовать (primary) ]
```
- Primary button disabled while trainer/date/time fields are empty.
- While mutation in-flight: primary shows `Loader2` spinner, disabled; ghost also disabled.
- Success: close modal + `toast.success('Слот опубликован', { description: '{fullName} · {formatted date} {HH:MM}–{HH:MM}' })`

### 1.4 Tab: Создать шаблон (`template`)

**API:** `POST /api/v1/recurring-templates` body `{trainerId, dayOfWeek 0–6, startTime, endTime, validFrom, validUntil?}` + `Idempotency-Key`.

**Fields (in order):**

1. **Тренер** (required): `ModalSelect` — same as §1.3.
2. **День недели** (required): `ModalSelect`. Options (value=0–6):
   | value | label |
   |-------|-------|
   | 1 | `«Понедельник»` |
   | 2 | `«Вторник»` |
   | 3 | `«Среда»` |
   | 4 | `«Четверг»` |
   | 5 | `«Пятница»` |
   | 6 | `«Суббота»` |
   | 0 | `«Воскресенье»` |
3. **Время** (required): `FieldRow` cols=2 — `ModalInput` type=`time` label=`«Начало»` + label=`«Конец»`.
4. **Начало действия** (required): `ModalInput` type=`date` label=`«Действует с»`. Min: today.
5. **Конец действия** (optional): `ModalInput` type=`date` label=`«Действует до»` optional. Hint: `«Оставьте пустым — шаблон бессрочный»`.

**Validation:** trainer required, dayOfWeek required, start/end time required and end > start, validFrom required and not in past, validUntil if set must be after validFrom.

**Footer actions:**
```
[ Отмена (ghost) ]   [ Создать шаблон (primary) ]
```
- Success: close modal + `toast.success('Шаблон создан', { description: '{fullName} · {dayName} {HH:MM}–{HH:MM}' })`

### 1.5 Tab: Блокировка времени (`timeoff`)

**API:** `POST /api/v1/time-off` body `{trainerId, blockStart, blockEnd, reason?}` + `?force=true` flag + `Idempotency-Key`.

**Fields (in order):**

1. **Тренер** (required): `ModalSelect` — same as §1.3.
2. **Начало блокировки** (required): `FieldRow` cols=2 — `ModalInput` type=`datetime-local` label=`«С»`.
3. **Конец блокировки** (required): `FieldRow` cols=2 — `ModalInput` type=`datetime-local` label=`«По»`.
4. **Причина** (optional): `ModalTextarea` label=`«Причина»` placeholder=`«Болезнь, отпуск…»` optional.

**Validation:** trainer required, blockStart required, blockEnd required and after blockStart.

**409 time_off_booked_conflict flow — see Surface 2.**

**Footer actions (default):**
```
[ Отмена (ghost) ]   [ Заблокировать (primary) ]
```
- Success (no conflict): close modal + `toast.success('Период заблокирован')`.

## Surface 2: Time-Off Conflict / Force-Override Dialog

**Requirement:** SCH-01. When `POST /api/v1/time-off` returns `409 time_off_booked_conflict` with `{ data: { conflictingSlotIds: string[], conflictingBookingIds: string[] } }`, the management modal must NOT close. Instead it transitions to a conflict state with a force-override confirm.

### Conflict State (inline — replaces modal body content)

Do not close the management modal. Replace the timeoff form body with:

**Callout** tone=`'danger'` icon=`TriangleAlert`:
```
«Найдены конфликты: {N} слот(а/ов) и {M} бронирование(ий)»
«Подтверждение заблокирует эти слоты и отменит все связанные брони.»
```

Where N = `conflictingSlotIds.length`, M = `conflictingBookingIds.length`.

Use existing Russian plural helper for count labels:
- 1 слот, 2–4 слота, 5+ слотов
- 1 бронирование, 2–4 бронирования, 5+ бронирований

**StatRow** (read-only display, existing `fields.tsx` primitive):
- Label: `«Отменяемые брони»`, Value: `«{M} шт.»` (if M > 0)
- Label: `«Блокируемые слоты»`, Value: `«{N} шт.»` (if N > 0)

**Footer actions (conflict state):**
```
[ Отмена (ghost) ]   [ Заблокировать принудительно (danger) ]
```

- Danger button click → resend `POST /api/v1/time-off` with same body + `?force=true`. New Idempotency-Key per attempt.
- While force mutation in-flight: danger button shows spinner + disabled; ghost disabled.
- Force success: close modal + `toast.success('Период заблокирован', { description: 'Отменено бронирований: {M}' })`
- Force error (non-409): inline Callout tone=`'danger'` — `«Не удалось применить блокировку. Попробуйте ещё раз.»`

**Discard (ghost "Отмена"):** closes the management modal entirely, no mutation.

## Surface 3: Booking Modal (Slot Click)

**Requirement:** SCH-02. Clicking an **available** slot in `WeekCalendar` opens the booking modal for reception OR owner. Clicking an **already-booked** slot opens a booking detail/cancel view (see §3.2).

### 3.1 Calendar Slot Click Routing

The existing `onEventClick` prop in `WeekCalendar` receives a `SessionEvent`. After wiring, the merged data model will have a `type` discriminator:

- `type === 'available'` (slot with no booking): open **Booking Create modal** (§3.3).
- `type === 'booked'` (slot with booking): open **Booking Detail/Cancel modal** (§3.4).
- `type === 'time-off'` or `type === 'cancelled'`: no action (no clickable state).

Available slots: rendered as existing `EventBlock` with existing trainer color. The visual distinction for "booked" vs "available" uses a badge overlay only — do NOT invent new background colors:

| State | Visual treatment |
|-------|-----------------|
| available | Existing `EventBlock` (trainer color strip + translucent bg) — no badge |
| booked | Same `EventBlock` anatomy + small `«занято»` badge (rounded-full, `bg-fg/10 text-fg text-[8.5px] font-bold uppercase tracking-[0.3px]`) top-right of the block |
| live (booked) | Existing `ring-2 ring-primary` + `«идёт»` pulse badge (existing) |
| cancelled | Existing `opacity-50` + `«отменена»` badge (existing) |
| time-off | Diagonal-stripe bg (`repeating-linear-gradient(45deg, var(--surface-2) 0 14px, var(--surface-3) 14px 18px)`) with `«недоступно»` label in `text-fg-subtle text-[11px]`; NOT clickable |

### 3.2 Available Slot Visual Hover State

Available (unbooked) slots gain `cursor-pointer`. On hover: existing `hover:-translate-y-px hover:shadow-2` (already in EventBlock). No additional styling.

### 3.3 Booking Create Modal

**Component pattern:** `AdaptiveModal` size=`'default'`. Wires `POST /api/v1/bookings {slotId, clientId, ptPackageId}` + per-attempt `crypto.randomUUID()` Idempotency-Key.

**Modal header:**
- Icon: `IconChip` tone=`'accent'`, icon=`CalendarCheck` (Lucide)
- Title: `«Записать клиента»`
- Description: `«{trainerFullName} · {formatted date} {HH:MM}–{HH:MM}»` (from slot data)

**Body (in order):**

**Section** `«Клиент»` (required):
- `ModalInput` icon=`Search` placeholder=`«Найти по имени или телефону…»` — debounced 300 ms, queries `GET /api/v1/clients?q={value}`.
- While searching (1+ chars): show `Loader2` spinner inside the input field (right side).
- Search results: `ResultList` + `ResultItem` (existing `fields.tsx` primitives). Each item shows client initials + full name + phone.
- Selected client: show selected `ResultItem` with `active={true}` highlight. A deselect `X` button at the right of the selected row.
- No results: inline `EmptyState` (no icon) — `«Клиент не найден»`.

**Section** `«Пакет PT»` (required):
- Shown only after a client is selected (otherwise hidden).
- Loads `GET /api/v1/clients/{clientId}/pt-packages?status=active` when client is selected.
- Loading: three `Skeleton` rows (`h-11 w-full rounded-xl`).
- Results: `PlanCards` (existing `fields.tsx`) — each card shows PT-package plan name, remaining sessions (`«Осталось: {N} из {total}»`), expiry date.
- No active PT-packages: inline `EmptyState` (no icon) — `«Нет активных PT-пакетов»` · `«У клиента нет доступных персональных занятий.»`. Primary button stays disabled.

**Validation:**
- Client required, PT-package required. Primary button disabled until both selected.

**Footer info** (left of footer, same pattern as `BookModal`):
```
{clientFullName} · {trainerFullName} · {HH:MM}–{HH:MM}
```
Shown only when client is selected.

**Footer actions:**
```
[ Отмена (ghost) ]   [ Записать (primary) ]
```
- "Записать" disabled when client or PT-package not selected.
- While mutation in-flight: primary shows `Loader2`, disabled; ghost disabled. `onOpenChange` suppressed.

**409 race-conflict (slot_already_booked / slot_not_available):** do NOT close modal. Show inline `Callout` tone=`'danger'` icon=`TriangleAlert` below the PT-package picker:
```
«Слот уже занят» / «Слот недоступен»
«Кто-то успел записаться раньше. Закройте это окно — расписание обновится.»
```
Then trigger `queryClient.invalidateQueries({ queryKey: scheduleKeys.week(…) })` so the calendar refetches. Modal stays open (user manually closes).

**409 PT-package errors:**
| code | copy |
|------|------|
| `pt_package_not_active` | `«Пакет PT неактивен»` |
| `pt_package_exhausted` | `«Все занятия в пакете уже использованы»` |
| `pt_package_expired_before_slot` | `«Срок действия пакета истечёт до даты слота»` |
| `trainer_mismatch` | `«Тренер в пакете не совпадает с тренером слота»` |

All use `Callout` tone=`'danger'` inline pattern. No crash, no page-level error.

**Success:** close modal + `toast.success('Запись создана', { description: '{clientFullName} · {trainerFullName} · {formatted date} {HH:MM}' })` + invalidate schedule + bookings query keys.

### 3.4 Booking Detail / Cancel Modal

Opened by clicking a **booked** event block.

**Component pattern:** `AdaptiveModal` size=`'default'`.

**Modal header:**
- Icon: `IconChip` tone=`'accent'`, icon=`CalendarCheck`
- Title: `«Бронирование»`
- Description: `«{clientFullName} · {trainerFullName} · {formatted date}»`

**Body (read-only display):**

`StatRow` rows (existing `fields.tsx`):
- `«Клиент»` → `{clientFullName}`
- `«Тренер»` → `{trainerFullName}`
- `«Время»` → `«{HH:MM}–{HH:MM} · {formatted date}»`
- `«Статус»` → status badge (see status colors below)
- `«PT-пакет»` → plan name + remaining sessions

**Status badge colors (inline `rounded-full px-2 py-0.5 text-[11px] font-semibold`):**
| status | class |
|--------|-------|
| `confirmed` | `bg-primary-soft text-primary-deep dark:text-primary` — `«Подтверждено»` |
| `cancelled` | `bg-surface-3 text-fg-subtle` — `«Отменено»` |
| `no_show` | `bg-warning-soft text-warning-deep` — `«Не явился»` |
| `completed` | `bg-surface-3 text-fg-subtle` — `«Завершено»` |

**Footer actions (status = confirmed):**
```
[ Отмена брони (danger, ghost style) ]   [ Закрыть (ghost) ]
```
- "Отмена брони" button: `ModalButton` variant=`'ghost'` with `text-danger hover:bg-danger-soft hover:text-danger` class override (not a full `danger` variant to avoid visual weight overload in footer).
- For **completed / cancelled / no_show**: footer is just `[ Закрыть (ghost) ]` — no cancel button.

**Cancel booking flow (click "Отмена брони"):**

Open a secondary `ConfirmModal` (existing `components/modals/ConfirmModal.tsx`):
- title: `«Отменить бронирование?»`
- message:
  - If reception AND slot is more than 24h away: `«Бронирование будет отменено. Клиент получит уведомление.»`
  - If reception AND slot is within 24h: `«До занятия менее 24 часов. Отмена возможна только владельцем.»` — in this case, the confirm button is hidden; only "Закрыть" is shown. (See 409 cancel_window_expired below.)
  - If owner: `«Бронирование будет отменено. Владелец может отменить в любое время.»`
- tone: `'danger'`
- confirmLabel: `«Отменить запись»`
- cancelLabel: `«Назад»`

**Cancel mutation:** `POST /api/v1/bookings/{id}/cancel { reason: 'Отменено администратором' }` + Idempotency-Key.

**409 cancel_window_expired:** do NOT crash. Show Sonner toast (non-blocking):
```
toast.error('Окно отмены закрыто', { description: 'До занятия менее 24 часов. Отмена доступна только владельцу.' })
```
Close both modals. Calendar refetches.

**Cancel success:** close modals + `toast.success('Бронирование отменено')` + invalidate schedule + bookings keys.

**Booking "complete" / record session:** deferred. No completion endpoint located in Phase 102 scope (as noted in CONTEXT.md). When located, wire "complete" to `POST /pt-sessions {bookingId}`. Until then, the Booking Detail modal has no "complete" button. A `// TODO Phase 103: wire complete to POST /pt-sessions` comment marks the deferral point.

## Surface 4: Calendar Data-States

**Requirement:** SCH-01. The `WeekCalendar` merges real trainer slots (availability) + bookings for the visible week. The existing `PageLoading` / `PageError` / `EmptyState` pattern from P101 applies here too.

### Loading State

**Component:** `<PageLoading />` — reuse as-is. Shown while `scheduleQuery.isPending` (slots + bookings queries parallel, `isPending` = either is pending).

### Error State

**Component:** `<PageError onRetry={…} />` — reuse as-is. Shown if either slots or bookings query errors. `onRetry` calls `refetch()` on both queries.

### Empty State (no slots in visible week)

**Component:** `EmptyState` (inline, inside the `Card` wrapping `WeekCalendar`, centered in the calendar body area — `py-24`).

| Sub-state | Trigger | Copy |
|-----------|---------|------|
| No slots, owner | `slots.length === 0` AND owner role | Icon: `CalendarPlus` · Title: `«Расписание пусто»` · Body: `«Опубликуйте слоты или создайте шаблон.»` · Action: button `«Управление расписанием»` (opens management modal) |
| No slots, reception | `slots.length === 0` AND reception role | Icon: `CalendarX` · Title: `«Нет слотов на эту неделю»` · Body: `«Расписание появится здесь.»` · Action: none |

### ScheduleToolbar Reduction

The mock `ScheduleToolbar` includes a `«Зал»` filter (`hall`) which has no backend parameter. For Phase 102:

- **Remove** the `FilterSelect` for `«Зал»` (icon=`LayoutGrid`). Hall has no backend filter.
- **Keep** `FilterSelect` for `«Тренер»` (icon=`Users`) — now populated from real trainers.
- **Keep** `FilterSelect` for `«Тип»` (icon=`Activity`) — but note: backend slot model has no `kind` field. Remove or stub this filter with `'all'` only if not supported; otherwise keep for booking kind filter.
- **Week navigator** (ChevronLeft / rangeLabel / ChevronRight / Сегодня): wire to real week navigation — `fromTime`/`toTime` query params update on nav click.

## Surface 5: Payroll PayoutsTab Wiring (Owner-Only)

**Requirement:** TRN-02. Wire the existing `PayoutsTab.tsx` to real `/api/v1/payroll` endpoints. All payroll endpoints are OWNER_ONLY — reception sees a friendly permission state.

### 5.1 Reception Role — Permission State

**Component:** `EmptyState` with `Lock` icon. Same pattern as P101 Plans page 403 state.

| Element | Value |
|---------|-------|
| Icon | `Lock` (Lucide) in `rounded-full bg-surface-3 text-fg-subtle` tile |
| Title | `«Недостаточно прав»` |
| Body | `«Раздел выплат доступен только владельцу.»` |
| Action | none |
