## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser admin-app → staff API `/api/v1/bookings`, `/api/v1/pt-sessions` | Booking create/cancel/complete bodies + ids cross here; backend authoritative on slot ownership, 24h window, package validity. |
| concurrent staff sessions → same slot | Two staff may attempt to book the same slot → race condition resolved server-side. |
| UI can()-gate → backend RBAC | FAB owner-gate is defense-in-depth; cancel 24h-window is server-side (not RBAC). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-102-BK-RACE | Tampering/DoS | concurrent booking of one slot | mitigate | Server returns 409 `slot_already_booked`/`slot_not_available`; BookingModal catches it, renders a calm inline «слот занят» Callout, and triggers `invalidateQueries(scheduleKeys.all)` so the calendar refetches. NEVER crashes the page (criterion 2). Verified by BookingModal.test.tsx. |
| T-102-BK-IDEM | Tampering | booking create / cancel / pt-session complete on retry | mitigate | Fresh `crypto.randomUUID()` Idempotency-Key generated INSIDE each mutationFn at submit time — prevents double-book / double-cancel / double-accrue-via-complete. Verified by bookings/api.test.ts. |
| T-102-BK-IDOR | Elevation/Info | booking/slot/pt-package access by id | accept (UI) / mitigate (backend) | UI sends ids only; backend authoritative on ownership + package-trainer match (`trainer_mismatch`) + 24h window. No client-side authorization trust. |
| T-102-BK-WINDOW | Elevation | reception cancel within 24h | mitigate | UI hides the cancel button for reception ≤24h (UX) AND the backend enforces the window with 409 `cancel_window_expired` (authority). Both layers; the 409 path closes modals calmly, never crashes. |
| T-102-BK-COMPLETE | Tampering | complete via pt-sessions with bookingId | mitigate | Body is exactly `{ptPackageId,trainerId,performedAt,bookingId}`; `clientId` never sent (backend `extra='forbid'`); backend validates booking.status='confirmed' + package/trainer match → 409 `booking_not_confirmed`/`booking_mismatch` handled inline. |
| T-102-BK-PII | Info disclosure | 409 + error Callouts/toasts | mitigate | Fixed Russian copy maps keyed by ApiError.code; conflict copy references no other client's PII. |
| T-102-BK-SC | Tampering | npm installs | mitigate | No new dependencies (zod/@tanstack/react-query/sonner/date-fns already present). Supply-chain gate N/A. |
