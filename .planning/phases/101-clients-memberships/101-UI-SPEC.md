## Surface 2: Owner-Only Permission State

**Requirement:** AUTH-03, MEM-01. Reception staff viewing Plans page (entirely owner-only) or encountering an owner-only action that slipped past `can()` gating must see a friendly state — not a blank, crash, or 403 `ErrorPage`.

### Plans Page — Full-Page Permission State (reception role)

The Plans page is owner-only for ALL mutations (create/edit/delete tariff, create/edit/delete promo, create/edit/delete addon). However, **reception can still VIEW plans** (the list is not owner-gated on the backend). Therefore:

- Plans page renders normally for reception (read-only view).
- All Add/Edit/Delete action buttons are **hidden** (not rendered) when `can(role, 'edit', 'memberships') === false`.
- No inline permission banner is needed for the Plans page itself — absent buttons communicate read-only.

### Owner-Only Action Inline State (fallback for missed `can()` gates)

If a 403 reaches the client from any mutation that should have been `can()`-gated (e.g. a race condition or a direct API call):

- Surface via Sonner toast (non-blocking): `toast.error('Недостаточно прав', { description: 'Это действие доступно только владельцу.' })`
- Do NOT render an `ErrorPage` for mutation 403s — the user stays on the current screen.
- Only use `<ErrorPage code={403}>` for **query** 403s (entire screen is forbidden), per P100 contract.

### Owner-Only Inline Banner (Plans page when backend returns 403 on a query)

If `GET /membership-plans` returns 403 (reception viewing a future owner-gated read endpoint):

**Component:** `EmptyState` with a lock icon.
**Layout:** full-width, centred in the content area, `py-24`.
**Icon:** `Lock` (Lucide), rendered in `rounded-full bg-surface-3 text-fg-subtle` tile (existing `EmptyState` icon anatomy).

| Element | Value |
|---------|-------|
| Title | `«Недостаточно прав»` |
| Body | `«Этот раздел доступен только владельцу. Обратитесь к владельцу клуба.»` |
| Action | none |

**No destructive styling** (`bg-danger-soft` is wrong here — this is an informational state, not an error). Use default `EmptyState` neutral icon tile.

### Membership-Cancel Action — Reception Role

`POST /memberships/{id}/cancel` is OWNER_ONLY. For reception:
- The Cancel button on the client detail / membership card is **not rendered** (hidden via `can(role, 'cancel', 'memberships')`).
- If reception somehow triggers it: Sonner `toast.error('Недостаточно прав', { description: 'Отмена абонемента доступна только владельцу.' })`.

### Client Delete — Reception Role

`DELETE /clients/{id}` is OWNER_ONLY.
- The Delete button is not rendered for reception.
- If 403 received: Sonner `toast.error('Недостаточно прав', { description: 'Удаление клиента доступно только владельцу.' })`.

## Surface 3: Membership Lifecycle Action Dialogs

The existing `SubscriptionModal.tsx` covers six screens: `create`, `renew`, `freeze`, `unfreeze`, `cancel`, `history`. These are **already designed** — reuse as-is with wiring only. The net-new addition for Phase 101 is:

1. A **Refund dialog** (new — does not exist in the mock `SubscriptionModal`)
2. Loading/disabled state on all action buttons during mutation in-flight
3. Error state on mutation failure

### 3.1 Existing Dialogs — Wire-only Changes

**No visual redesign.** For each dialog, add:

**Submitting state (all dialogs):**
- Primary `ModalButton` renders `loading={true}` equivalent: `disabled` + `<Loader2 className="size-[18px] animate-spin" />` prepended to button text.
- Secondary/ghost "Отмена" button also `disabled` while mutation is in-flight.
- Dialog `onOpenChange` is suppressed during mutation (prevent accidental close).

**Success state (all dialogs):**
- Close dialog.
- Sonner `toast.success(…)` — see Copywriting Contract below for each action.
- Invalidate relevant TanStack Query keys.

**Error state (all dialogs — 4xx/5xx/network):**
- Do NOT close the dialog.
- Show inline error inside the dialog body, below the last field, using the existing `Callout` component with `tone="danger"` and `icon={TriangleAlert}`.
- Reset button to normal (not loading).
- Copy: `«Не удалось выполнить действие. Проверьте соединение и попробуйте ещё раз.»`
- If the error envelope has `message`, show it instead: `«{error.message}»`.

**Specific dialog contracts:**

| Dialog | `screen` key | Existing | Wire changes |
|--------|--------------|----------|--------------|
| Sell | `create` | Yes | Replace mock `PlanCards` options with real plans from `GET /membership-plans`; send `POST /memberships` + `Idempotency-Key`; send `clientId` + `planId` + optional `notes`; remove promo/discount mock UI (no promo endpoint in scope) |
| Renew | `renew` | Yes | `POST /memberships/{id}/renew` + `Idempotency-Key`; remove multi-period chip picker (backend `POST /renew` takes no period — it extends by one plan duration); simplify dialog body to just confirm + sum display |
| Freeze | `freeze` | Yes | `POST /memberships/{id}/freeze` (empty body) + `Idempotency-Key`; remove chip duration picker (backend freeze has no explicit duration — it uses the plan's `freezeDaysLimit`); display remaining freeze days from `MembershipResponse.freezeDaysRemaining` |
| Unfreeze | `unfreeze` | Yes | `POST /memberships/{id}/unfreeze` (empty body) + `Idempotency-Key`; display freeze info from `MembershipResponse.currentFreezePeriod` |
| Cancel | `cancel` | Yes | `POST /memberships/{id}/cancel` (optional `reason` ≤500 chars, owner-only); remove refund chip group (refund is a separate action/endpoint); keep reason textarea |
| History | `history` | Yes | Read from `MembershipResponse` history or a separate history endpoint if available; otherwise display read-only fields from `MembershipResponse` |

### 3.2 Refund Dialog (NET-NEW)

The mock `SubscriptionModal` has no Refund screen. Phase 101 introduces it.

**New `screen` key:** `'refund'`

**AdaptiveModal anatomy:**

```
Icon chip:    tone="danger", icon=ReceiptX (Lucide)
Title:        "Оформить возврат"
Description:  "{clientName} · «{planName}»"
```

**Dialog body (in order):**

1. **Callout** (tone="warn", icon=TriangleAlert):
   `«Возврат полный и необратимый. Средства вернутся тем же способом, которым была принята оплата.»`

2. **StatRow** (read-only display):
   - Label: `«Оплачено»`, Value: `formatMoney(membership.paidAmountKopecks)` — right-aligned, tabular-nums.
   - Label: `«Дата покупки»`, Value: formatted date.

3. **Field** label=`«Причина возврата»` with `required` marker (red asterisk via existing `Field` pattern):
   - `<textarea>` styled as `ModalInput` variant: `min-h-[80px] resize-none`.
   - `maxlength={200}`.
   - Character counter in bottom-right: `text-[11.5px] text-fg-subtle tabular-nums` — `«{len}/200»`.
   - Placeholder: `«Укажите причину возврата»`.
   - **Validation:** required, 1–200 chars. Submit button disabled when field is empty.
   - Inline error (shown on submit attempt with empty field): `text-[12px] text-danger mt-1.5` — `«Причина обязательна для возврата»`.

4. **No amount field.** Backend `MembershipRefundRequest` is full-refund only; do not show a partial-amount input.

**Footer actions:**

```
[ Отмена (ghost) ]   [ Вернуть {formatMoney(…)} (danger) ]
```

- Danger button is `disabled` when reason field is empty.
- While mutation in-flight: danger button shows spinner + `disabled`; ghost button also `disabled`.

**Success:** close dialog + `toast.success('Возврат оформлен', { description: 'Средства будут возвращены клиенту.' })`

**Error:** inline `Callout` `tone="danger"` as per §3.1 generic error pattern.

**API call:** `POST /memberships/{id}/refund` body `{ reason }` (no `Idempotency-Key` — refund is idempotent by nature and the backend does not specify one).

## Surface 4: Clients-List Filter/Sort Reduction

**Context:** The mock `ClientsPage` renders:
- Filter tabs (`ClientFilterTabs`): `all` / `active` / `expiring` / `frozen` / `lead` — these are mock-only; `GET /clients` has no `status` filter.
- Sort presets in `ClientsToolbar`: `expires:asc` / `name:asc` / `visits:desc` / `last:desc` — backend only supports `created_at_desc` and `last_name_asc`.
- Toolbar dropdowns: "Тип абонемента" / "Тренер" — no backend support.
- "Ещё фильтры" button — dead in mock.

**Design rule:** Remove unsupported controls entirely. Do NOT leave them rendered but disabled — absent is the correct treatment (same principle as nav gating in P100).

### 4.1 Filter Tabs — Remove Entirely

**Remove** `<ClientFilterTabs>` from `ClientsPage`. The entire `statusFilter` state variable and the `filter(c.status !== statusFilter)` logic is removed.

The row above the toolbar that showed the status pills disappears. No replacement. The toolbar alone is sufficient without status pills.

### 4.2 Sort Presets — Replace with Backend-Supported Values Only

**Current mock `SORT_PRESETS`:** 4 entries (`expires:asc`, `name:asc`, `visits:desc`, `last:desc`).

**Replacement `SORT_PRESETS`:** 2 entries only:

| value | label | backend param |
|-------|-------|---------------|
| `name:asc` | `«По имени (А–Я)»` | `sort=last_name_asc` |
| `recent:desc` | `«Недавние»` | `sort=created_at_desc` |

Default sort: `recent:desc` (maps to `created_at_desc` — most recently added clients first, matches backend default).

### 4.3 Toolbar Dropdowns — Remove Unsupported, Keep Supported

**Remove** the following `FilterSelect` dropdowns from `ClientsToolbar`:
- "Тип абонемента" (`planType` / `CreditCard` icon) — no backend parameter
- "Тренер" (`trainer` / `User` icon) — no backend parameter
- "Ещё фильтры" button — dead

**Keep / wire** the following filters (backend-supported):

| Filter | UI element | Backend param |
|--------|------------|---------------|
| Search (name/phone) | Existing `SearchInput`, debounced 300 ms, min-2-char gate | `q` |
| Пол | New `FilterSelect` icon=`Users`, label=`«Пол»` | `gender=male\|female` |
| Тег | New `FilterSelect` icon=`Tag`, label=`«Тег»` | `tag={slug}` (populated from a tags list or free-text) |
| Telegram | New toggle chip or `FilterSelect` icon=`MessageCircle`, label=`«Telegram»` options: `«Все»` / `«Есть Telegram»` | `hasTelegram=true` |
| Дата добавления | New date-range picker or two `ModalInput` date fields (can be a future iteration — mark as P101 optional if date-range picker adds scope) | `createdFrom` + `createdTo` |

**Gender filter options:**

| value | label |
|-------|-------|
| `all` | `«Все»` |
| `male` | `«Мужчины»` |
| `female` | `«Женщины»` |

**Telegram filter options:**

| value | label |
|-------|-------|
| `all` | `«Все»` |
| `true` | `«Есть Telegram»` |

### 4.4 Search Behaviour

- **Debounce:** 300 ms — existing `useDebounce` pattern.
- **Min-2-char gate:** if `q.length < 2`, send no `q` parameter to the API (treated as None by backend). While input has 1 char: show the input value but do NOT fire the query — the result list stays at the previous state.
- **Clear button:** when `q.length > 0`, show `X` icon inside the `SearchInput` to clear — existing `SearchInput` component already handles this if a `onClear` prop is wired.

### 4.5 Pagination — Server-Side

- **Replace** mock client-side `Pagination` component that used `data.currentPage` / `data.totalPages` / `data.totalCount` from mock shape with the real `{items, total, page, pageSize}` envelope.
- The existing `Pagination` component at `components/data/Pagination` is reused — only the props source changes (from mock shape to real `data.page`, `data.total`, `data.pageSize`).
- Page size: 25 (match the existing UI default — confirm against backend default; if backend default differs, pass `pageSize=25` explicitly).
- Page is synced to URL search params: `?page=N` (default omitted when page=1).
