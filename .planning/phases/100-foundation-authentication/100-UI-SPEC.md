## Color

All color values come from `tokens.css`. Use semantic class names only — raw hex is banned by ESLint.

| Role | CSS token | Tailwind class | Usage |
|------|-----------|----------------|-------|
| Dominant (60%) | `--bg` (#f5f5f4 light / #0c0c0c dark) | `bg-bg` | Page backgrounds |
| Secondary (30%) | `--surface` / `--surface-2` | `bg-surface`, `bg-surface-2` | Cards, sidebar, modals |
| Accent (10%) | `--primary` (#2dd4a4 emerald) | `bg-primary`, `text-primary` | See reserved list below |
| Destructive | `--danger` (#dc2626) | `text-danger`, `bg-danger-soft` | Error states, field errors |
| Muted text | `--fg-muted` / `--fg-subtle` | `text-fg-muted`, `text-fg-subtle` | Secondary text, placeholders |
| Warning | `--warning` / `--warning-soft` | `bg-warning-soft text-warning-deep` | Callout warnings (session expired) |

**Accent (`--primary`) is reserved exclusively for:**
- Active/focus ring on form inputs (`focus:ring-primary-soft`)
- `<ComingSoon/>` icon tile background variant (`bg-primary-soft text-primary-deep`)
- Primary action buttons in dark theme (`dark:bg-primary dark:text-primary-foreground`)
- Role badge pill accent color (emerald dot indicator)
- `AuthLink` text (`text-primary-deep` light / `text-primary` dark)

**Never use accent for:** general borders, hover backgrounds, inactive nav items, informational text.

Dark theme is toggled via `[data-theme="dark"]` attribute on `<html>` — use `dark:` utilities only where the project's `@custom-variant dark` applies. Do NOT add `.dark {}` blocks to CSS.

Source: `tokens.css`, `globals.css` — locked.

## Surface 1: `<ComingSoon/>` Placeholder

**Requirement:** FND-04. Replaces route element for deferred screens. Concept: "not broken, not wired."

**Screens using this component:**
Branches (`/branches`), Branch-Settings, System-Settings, ImportExport (`/import-export`), Duplicates, Archive, Trash, Messages (`/messages`), Roles (`/roles`), Notifications-management (`/notifications`).

### Layout

- Full available height of the `<AppLayout>` content area (flex-1 / h-full).
- Vertically and horizontally centred: `flex flex-col items-center justify-center`.
- Max-width constraint: `max-w-[400px] px-6 text-center`.
- No card border, no elevation — sits directly on `bg-bg` surface.
- Animate-in: `animate-in fade-in-0 duration-300` (same pattern as auth view transitions).

### Icon Tile

- Reuse `ScreenIcon` anatomy from `auth-ui.tsx` (52×52px, rounded-[15px]).
- Tone: `'accent'` (emerald soft background `bg-primary-soft text-primary-deep`).
- Icon: `Clock` (Lucide) — communicates "coming later", not "broken".
- Margin below: `mb-[22px]` (existing ScreenIcon pattern).

### Copy (Russian)

| Element | Copy |
|---------|------|
| Heading | `Раздел в разработке` |
| Sub-text | `Этот раздел будет доступен в следующем обновлении.\nПока продолжайте работать в текущих разделах.` |

- Heading: `text-[20px] font-bold tracking-[-0.4px] text-fg`
- Sub-text: `mt-2 text-[14px] leading-[1.55] text-fg-muted max-w-[320px]`

### No Action Button

Do not add a "На дашборд" button — the sidebar remains fully navigable. A button would imply the user is stuck; they are not.

### Accessibility

- `role="main"` or wrapped in the route's natural `<main>` element from `AppLayout`.
- No `aria-busy` (data is not loading; this is intentional absence of content).

## Surface 2: Role Visibility in the Shell

**Requirement:** AUTH-03. Owner vs reception must be visible; owner-only items gated.

### Sidebar Footer — User Card

The existing `AppSidebar.tsx` footer card shows a hardcoded "Маша Костина / Администратор" mock.

**Wired replacement contract:**

```
[ Avatar initials ]  [ full_name ]           [ → ]
                     [ role label ]
```

- **Avatar**: 32×32px circle (`size-8 rounded-full`), gradient background (keep existing `from-[#f59e0b] to-[#f97316]`), initials derived from `fullName` (first letter of each word, max 2 letters, uppercase).
- **full_name**: `text-[13px] font-semibold text-fg` — from `GET /auth/me` → `fullName`.
- **Role label**: `text-[11.5px] text-fg-subtle` — exact copy per role:
  - `owner` → `«Владелец»`
  - `reception` → `«Ресепшн»`
- **Arrow button**: existing `ChevronRight` link to Settings profile page — keep as-is.
- **Loading state**: while `useSession()` is pending, render skeleton lines: `Skeleton` (`h-3 w-24`) for name + `Skeleton` (`h-2.5 w-16`) for role. Use existing `@/components/ui/skeleton` primitive.

### Sidebar Header — Role Pill

The existing `AppSidebar.tsx` header shows `APP_ROLE_LABEL = 'ADMIN'` as a static pill.

**Wired replacement contract:**
- Replace static `APP_ROLE_LABEL` with dynamic role pill:
  - `owner` → pill text `«Владелец»` with class `bg-primary-soft text-primary-deep`
  - `reception` → pill text `«Ресепшн»` with class `bg-surface-3 text-fg-subtle`
- Pill anatomy (keep existing): `rounded-full px-[7px] py-0.5 text-[10px] font-bold tracking-[0.4px]`
- While session pending: hide pill entirely (render `null`).

### Nav Item Gating (owner-only)

Items hidden for `reception` role (removed from `NAV_SECTIONS` render, not just disabled):
- `Филиалы` (`/branches`) — already hide-for-future in Phase 100, so hidden for all roles via `<ComingSoon/>` route; remove from nav for all roles.
- Owner-only items per `OWNER_ONLY` matrix (from `can.ts` port): Finance (`/finance`), Reports (`/reports`), Audit, Payroll surfaces — not in nav scope for Phase 100 but nav items for `Финансы`, `Отчёты` must be gated.

**Phase 100 nav gating rule:** filter `NAV_SECTIONS` items at render time using `can(role, 'view', resource)`. Items where `can()` returns `false` for the current role are not rendered (not grayed, not shown with a lock — simply absent).

- **Hide-for-future items** (deferred screens): remove from `NAV_SECTIONS` entirely in Phase 100 — Сообщения (`/messages`), Уведомления (`/notifications`), Филиалы (`/branches`). These are gone from the nav regardless of role.
- **Owner-only items remaining in nav**: `Финансы`, `Отчёты` — hide for `reception`.
- **Items visible to all**: Дашборд, Клиенты, Расписание, Абонементы, Тренеры, Касса, Посещаемость, Загруженность, Настройки.

**Do not add a lock icon or disabled state** — absent is the correct treatment (PWA hide-for-future pattern).

### 403 Backend Response

A `403` from any query/mutation must surface via the existing `ErrorPage` component with `code={403}`. The existing copy is correct: "Доступ к разделу закрыт" / "У вашей роли «Ресепшн» нет прав...". Do not add a new UI pattern for this.

## Surface 3: Login Form Wiring States

**Requirement:** AUTH-01, AUTH-02. The existing `LoginForm.tsx` gains real states.

### Submitting / Pending State

Reuse the existing `PrimaryButton` `loading={true}` state (renders `<Loader2 className="size-[18px] animate-spin" />`). While the login mutation is in flight:
- Button shows spinner, text stays `«Войти»`, button is `disabled`.
- Both fields are `disabled` (add `disabled` prop to `Field` and `PasswordField`).
- No full-page overlay needed — the form area itself communicates pending.

### Error Display: `invalid_credentials` (401)

Show an inline alert banner **above the email field** (between heading and first field):

```
[ AlertCircle 16px ]  Неверный email или пароль.
```

- Container: `flex items-center gap-2 rounded-[10px] bg-danger-soft px-[14px] py-[11px] text-[13px] text-danger mb-[18px]`
- Icon: `AlertCircle` from `@/components/icons`, `size-4 shrink-0`
- Copy: `«Неверный email или пароль.»` — generic, no hint which field was wrong (anti-oracle per CONTEXT.md).
- This banner replaces field-level errors for the `invalid_credentials` case — do not mark either field as `aria-invalid` for this error (the error is not field-specific).
- Dismiss: error clears on next submit attempt (reset on `handleSubmit`).

### Error Display: 422 Field Errors (Zod / backend validation)

Inline field errors below the relevant field using the existing `Field` `error` prop pattern:
- `error` prop on the `Field` component renders `<AlertCircle 14px /> {message}` in `text-[12px] text-danger mt-1.5`.
- Map `fields.email` → `Field email error`, `fields.password` → `Field password error`.
- If both fields error: show both inline, no banner.
- Copy for common backend messages:
  - Email format: `«Введите корректный адрес почты»`
  - Password too short: `«Пароль должен содержать не менее 12 символов»`
  - Generic field error: forward backend `message` string as-is (it is already in Russian).

### Error Display: Other Codes (5xx, network)

Use a non-blocking Sonner toast (already in the project, `import { toast } from 'sonner'`):
- `toast.error('Не удалось выполнить вход', { description: 'Проверьте соединение и попробуйте ещё раз.' })`
- Do not crash the form — user can retry.

### 401 Session Expiry Redirect

When a `401` is returned by **any** query or mutation outside the login flow (i.e. during a session):
- Navigate to `/login?state=expired`.
- The existing `ExpiredScreen` view is triggered by `?state=expired` in `LoginPage.tsx`.
- Clear session state (the `useSession()` query cache).
- No additional UI needed — `ExpiredScreen` already shows: "Сессия истекла" / "Войдите снова" with a `Callout` warning about unsaved changes.

### "Remember Me" — No-op Treatment

The checkbox remains visible and functional as a UI element. Add a tooltip or a `Callout` note (use `tone='default'`) below the checkbox:

```
[ TriangleAlert ]  Сессия действует 7 дней независимо от этого параметра.
```

- Container: use `Callout` component from `auth-ui.tsx` with `tone='default'`.
- Render this callout only when the "Запомнить меня" checkbox is visible (i.e. not on recovery screens).
- Position: immediately below the checkbox, above the primary button.

### TOTP (`twofa` view) — Hidden for Future

- Remove `twofa` from `DEEP_LINKABLE` array in `LoginPage.tsx`.
- Remove `twofa` case from the `renderScreen()` switch — replace with fallback to `'login'`.
- Keep `TwoFactorScreen.tsx` file in the tree but un-imported (the file is the "future graduation" artefact).
- Remove `TwoFactorScreen` import from `LoginPage.tsx`.

### Google Workspace Button — No-op

The `GoogleButton` exists in the current form. In Phase 100:
- Keep it rendered (visual continuity).
- Wire its `onClick` to show a Sonner toast: `toast('Google Workspace вход будет доступен позже.')`
- Do not wire it to any real OAuth flow.

### Password-Reset Flow

The `ForgotScreen` / `SentScreen` / `ResetScreen` views exist and are wired to real endpoints in Phase 100 (`POST /auth/password-reset/request` + `/confirm`). Visual contract — no changes to existing components. Loading/error states follow the same pattern as login: `PrimaryButton loading`, inline errors from `Field` error prop, Sonner toast for 5xx.

## Interaction States Summary

| Surface | State | Treatment |
|---------|-------|-----------|
| Login form | idle | Existing form — no change |
| Login form | submitting | `PrimaryButton loading={true}`, fields `disabled` |
| Login form | error — 401 invalid_credentials | Red banner above email field, no field-level marks |
| Login form | error — 422 fields | Inline `Field error` prop per field |
| Login form | error — 5xx/network | Sonner `toast.error(...)`, form stays interactive |
| Session anywhere | 401 (expired) | Navigate `/login?state=expired`, clear session query |
| Session anywhere | 403 (forbidden) | `<ErrorPage code={403}/>` |
| Sidebar footer | pending session | Two `Skeleton` lines for name + role |
| Sidebar footer | loaded | Real `fullName` + localised role label |
| Sidebar header | pending session | Role pill hidden (`null`) |
| Sidebar header | loaded — owner | Emerald pill `«Владелец»` |
| Sidebar header | loaded — reception | Neutral pill `«Ресепшн»` |
| Nav items | reception role | Owner-only items absent (not rendered) |
| Nav items | hide-for-future | Deferred items absent for all roles |
| ComingSoon route | any | Static centred placeholder, no loading/error states |
