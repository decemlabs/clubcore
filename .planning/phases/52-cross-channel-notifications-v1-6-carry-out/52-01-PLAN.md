DECISION (D-52-10 resolution — Option A, DB-UNIQUE across all kinds): The subject of an idempotency row is polymorphic. `payment_succeeded` / `refund_succeeded` / `fiscal_failed` key on a real `payments` ledger row (`payment_id`). `payment_canceled` has NO `payments` ledger row (activation is webhook-gated; canceled payments never write a ledger row), so it keys on `online_payments.id` (`online_payment_id`). Both columns are nullable with an XOR CHECK (exactly one non-null), mirroring the OnlinePayment subject-XOR precedent (D-49-04). This keeps the phase's DB-UNIQUE cross-restart dedup doctrine consistent for ALL kinds — including owner alerts — rather than giving `payment_canceled` a weaker Redis-only guarantee.
