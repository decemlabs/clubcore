<objective>
Lock down the cluster security posture: encrypt secrets at rest (SealedSecret + kubeseal
+ controller-key backup), harden every pod's securityContext to ASVS-grade least
privilege, and enforce default-deny + explicit-allow network segmentation with mandatory
CoreDNS egress.

Implements SEC-01 (sealed-secrets, no plaintext committed), SEC-02 (controller RSA-key
off-node backup — HARD gate, pitfall P6), SEC-03 (securityContext hardening across all
workloads), SEC-04 (NetworkPolicy default-deny + explicit allow + CoreDNS egress, pitfall P8).

NetworkPolicies — all explicitly tagged "Phase 119 scope" in the templates. This plan
closes that handoff. Controller-key loss is the highest-risk single point of failure in
the whole milestone (P6), so the RSA-key export + off-node backup is an acceptance gate,
not post-hoc cleanup.

Output: a SealedSecret template + kubeseal helper script + key-backup runbook;
SEC-03 hardening of 4 workloads in place; 2 NetworkPolicy templates; values.yaml
networkPolicy/securityContext blocks.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git repo → cluster | Secrets must cross this boundary encrypted (SealedSecret), never as committed plaintext |
| controller RSA key → off-node store | The single decrypt key; loss = unrecoverable secrets (pitfall P6) |
| pod → pod (east-west) | NetworkPolicy is the only lateral-movement control |
| pod → CoreDNS | DNS dependency that NetworkPolicy must not sever (pitfall P8) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-119-05 | Information Disclosure | App secrets in git | mitigate | sealed-secrets: only RSA-encrypted encryptedData committed; plaintext Secret gated to local-k3d-only (SEC-01) |
| T-119-06 | Denial of Service / data loss | Controller RSA key loss on rebuild | mitigate | RSA-key export in seal-secrets.sh + off-node backup runbook as a BLOCKING human gate (SEC-02, P6) |
| T-119-07 | Elevation of Privilege | Container breakout via writable root / caps | mitigate | readOnlyRootFilesystem + drop ALL caps + allowPrivilegeEscalation:false + runAsNonRoot on every container (SEC-03) |
| T-119-08 | Lateral Movement (Spoofing/Tampering) | Unconstrained east-west pod traffic | mitigate | default-deny + explicit-allow NetworkPolicies; only declared edges permitted (SEC-04) |
| T-119-09 | Denial of Service | DNS severed by NetworkPolicy | mitigate | mandatory CoreDNS egress UDP+TCP 53 in every allow policy (P8) |
| T-119-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan (k8s manifests + bash); slopcheck N/A |
</threat_model>
