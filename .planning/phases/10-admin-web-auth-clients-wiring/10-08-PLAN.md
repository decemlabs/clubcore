<objective>
Fix the regression introduced by the CR-01 review fix (commit 9fdc8e2) which replaced
`location.href` with `location.pathname + (location.search ?? '')`. In TanStack Router,
`ParsedLocation.search` is the **parsed object** form of search params (e.g.
`{ page: 1, pageSize: 20 }`), not a string. The `+` operator triggers `Symbol.toPrimitive`
on that object, throwing `TypeError: Cannot convert object to primitive value` and
crashing the route.

The correct property is `location.searchStr` — the encoded search-string form, with
leading `?` when params exist and `''` when empty. Replace `location.search` with
`location.searchStr` in all six call sites. Preserves the security intent of CR-01
(no origin in the `forbidden`/`next` value).

Purpose: Unblock UAT Test 8 (RBAC redirect) — currently the only failing test,
flagged blocker.

Output: Six route files patched with the safe coercion-free expression, plus one
regression test that loads /finance as reception and asserts the redirect URL is a
plain pathname string (no crash, no origin).
</objective>

<!-- TanStack Router ParsedLocation shape (relevant fields). See @tanstack/react-router. -->
<!-- Executors: do NOT re-derive these — use directly. -->

interface ParsedLocation<TSearch = unknown> {
  href: string         // relative href: pathname + searchStr + hash (no origin)
  pathname: string     // e.g. "/finance"
  search: TSearch      // PARSED object form, e.g. { page: 1, pageSize: 20 } — NEVER concatenate with strings
  searchStr: string    // ENCODED form, e.g. "?page=1&pageSize=20" or "" — safe to concat
  hash: string
  state: HistoryState
  // ...
}

// The bug: `location.pathname + (location.search ?? '')`
//   When `search` is `{}` or `{ page: 1 }`, the `+` triggers `Symbol.toPrimitive`/`Object.prototype.toString`.
//   TanStack's parsed search proxy throws under that path → "Cannot convert object to primitive value".
//
// The fix: `location.pathname + (location.searchStr ?? '')`
//   `searchStr` is already a string (`""` when no params, `"?..."` otherwise), so `+` is string-string.
//   The `?? ''` guard is defensive — `searchStr` is typed as `string` and should always be defined,
//   but matching the existing nullish-coalescing style keeps the diff minimal and readable.
</interfaces>
