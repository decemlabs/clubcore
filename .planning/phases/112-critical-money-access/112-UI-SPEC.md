**Inherited — not introduced by this phase.**

Phase 112 introduces zero new font sizes and zero new font weights. It reuses
existing primitives (`AdaptiveModal`, `Field`, `ModalInput`, `ModalTextarea`,
`StatRow`, `Section` from `fields.tsx`) verbatim. The type scale below is the

**Four primary type roles used by the two new modals (Phase 112 interaction
surface only):**

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Modal title | 17px | 700 bold | tight | RefundModal title, ChangeRoleModal title |
| Body / field value | 13.5–15px | 400 regular / 700 bold | — | Input text (13.5px); StatRow amount (15px bold) |
| Field label / hint | 12–12.5px | 600 semibold / 400 regular | snug | Field labels (12px semibold); description / hints (12.5px regular) |

**Inherited system scale (not modified — documented for checker context):**

All sizes below exist in `fields.tsx` and `AdaptiveModal.tsx` prior to this
phase. Phase 112 adds none of them:

- 17px — AdaptiveModal title (`text-[17px]` bold)
- 15px — StatRow accent value (`text-[15px]` bold tabular-nums)
- 13.5px — ModalInput / ModalTextarea body text (`text-[13.5px]`)
- 12.5px — AdaptiveModal description / info callout body (`text-[12.5px]`)
- 12px — Field label (`text-[12px]` or `text-xs` semibold)
- 11.5px — Field hint, validation message, Section label (`text-[11.5px]`)

Weights used by the system (and therefore by this phase): **regular (400)** and

additional weights.

## Surface 1: RefundModal

### Trigger

- **TransactionsCard (`TransactionsCard.tsx`):** Each non-refund, non-fully-refunded payment row renders a `DropdownMenu` (trigger: `MoreHorizontal` icon, `size-7`, `aria-label="Действия"`) with a single item "Оформить возврат" (`variant="destructive"`). The menu and item are **hidden entirely** when `!can(role, 'refund', 'finance')` — the trigger is not rendered for reception.
- **Finance payments table:** Same pattern — a "Оформить возврат" destructive `DropdownMenuItem` in the existing row action menu. Hidden for reception via `can()`.
- Fully-refunded rows: no dropdown trigger rendered (row state = already refunded).

### Modal structure

```
AdaptiveModal
  icon:        <IconChip tone="warn" icon={Undo2} />
  title:       "Оформить возврат"
  description: "{subjectKind label} · {method label} · {date}"   (12.5px, fg-muted)
  size:        "default"   (max-w-[540px])

  body (px-5 py-[18px]):
    <StatRow label="Исходная сумма" value={formatRub(original)} />
    <StatRow label="Уже возвращено" value={formatRub(alreadyRefunded)} />   ← only if > 0
    <StatRow label="Доступно к возврату" value={formatRub(remaining)} accent />

    <Field label="Сумма возврата" required hint="Частичный возврат разрешён — не более доступного остатка">
      <ModalInput
        type="number"
        suffix="₽"
        defaultValue={remaining / 100}
        min={0.01}
        max={remaining / 100}
        step={0.01}
      />
    </Field>

    <Field label="Причина возврата" required hint="Минимум 3 символа · сохраняется в журнале">
      <ModalTextarea placeholder="Например: клиент передумал, ошибка кассира…" />
    </Field>

  footerInfo:    null
  footerActions:
    <ModalButton variant="ghost">Отмена</ModalButton>
    <ModalButton variant="danger" disabled={!valid || busy}>Оформить возврат</ModalButton>
```

### Validation states

| State | Behavior |
|-------|----------|
| Amount empty or 0 | Confirm button disabled |
| Amount > remaining | Confirm button disabled; inline hint under field turns `text-danger`: "Превышает доступный остаток" |
| Reason < 3 chars | Confirm button disabled |
| Busy (mutation in flight) | Both buttons disabled; confirm button shows spinner or reduced opacity |
| Success | Modal closes; Sonner toast `toast.success("Возврат оформлен", { description: formatRub(amount) })` |
| Backend 409 (over-refund / already refunded) | Modal stays open; Sonner `toast.error("Возврат невозможен: сумма превышает доступный остаток")` |
| Backend 5xx / network | Sonner `toast.error("Не удалось оформить возврат. Попробуйте ещё раз.")` |

### Row display after refund

Refund rows already render with `bg-danger-soft text-danger` chip + "Возврат" title + `text-danger` amount prefixed with "−" (U+2212). This existing `TransactionsCard` logic is unchanged.

## Surface 2: ChangeRoleModal

### Trigger

In `TeamSection` (`SectionsBottom.tsx`), active non-self user rows: the existing
`DropdownMenu` gains a new non-destructive `DropdownMenuItem` "Изменить роль"
placed **above** the existing "Деактивировать" item. This item is only rendered when
`can(role, 'update', 'users')` — already true only for owner; not rendered for reception.

### Modal structure

```
AdaptiveModal
  icon:        <IconChip tone="indigo" icon={ShieldCheck} />   ← Lucide ShieldCheck
  title:       "Изменить роль"
  description: "{user.fullName} · {current role label}"   (12.5px, fg-muted)
  size:        "default"

  body (px-5 py-[18px]):
    <Field label="Новая роль" required>
      <ChipGroup
        options={[
          { value: 'reception', label: 'Ресепшн' },
          { value: 'owner',     label: 'Владелец' },
        ]}
        value={selectedRole}
        onChange={setSelectedRole}
      />
    </Field>

    <div className="mt-3.5 rounded-xl border-[0.5px] border-border bg-surface-2 px-3.5 py-3 text-[12.5px] text-fg-muted leading-snug">
      Роль вступит в силу при следующем входе сотрудника.
      Текущая сессия продолжается с прежними правами.
    </div>

  footerActions:
    <ModalButton variant="ghost">Отмена</ModalButton>
    <ModalButton variant="primary" disabled={selectedRole === user.role || busy}>
      Сохранить роль
    </ModalButton>
```

### Validation states

| State | Behavior |
|-------|----------|
| Selected role = current role | Confirm button disabled |
| Busy | Both buttons disabled |
| Success | Modal closes; Sonner `toast.success("Роль изменена", { description: "{fullName} → {newRoleLabel}" })` |
| Backend 409 `cannot_change_own_role` | `toast.error("Нельзя изменить собственную роль")` |
| Backend 409 `cannot_demote_last_owner` | `toast.error("Нельзя понизить единственного владельца")` |
| Backend 403 | Not reachable via UI (action hidden); if hit: `toast.error("Недостаточно прав")` |
| Backend 5xx | `toast.error("Не удалось изменить роль. Попробуйте ещё раз.")` |

## Accessibility Contract

- All modal triggers have `aria-label` in Russian.
- `AdaptiveModal` renders `DialogTitle` / `DrawerTitle` — screen reader announces modal title on open.
- Confirm buttons carry `disabled` attribute (not just visual opacity) when validation fails.
- Amount `<input type="number">` has `min`, `max`, `step` attributes.
- ChipGroup buttons use `aria-pressed` (already implemented in `fields.tsx`).
- `ModalTextarea` for reason: `minLength={3}` attribute as supplementary HTML constraint.
- Focus trap is handled by Radix Dialog / Drawer primitives.
- `Undo2` icon in refund row chip: decorative, parent has text label "Возврат" — no additional `aria-label` needed.
- `ShieldCheck` icon in ChangeRoleModal header chip: decorative — title provides context.
