From apps/client-pwa/src/lib/clientQueries.ts — `ClientMeData` (the GET /client/me shape):
```typescript
interface ClientMeData {
  firstName: string
  lastName: string
  phone: string
  email: string | null
  goal: 'lose_weight' | 'gain_mass' | 'tone' | 'maintain' | null
  heightCm: number | null
  weightKg: number | null
  onboardingCompletedAt: string | null
}
```

`useUpdateClientProfile()` (lines 207-229) — mutation payload (all optional):
`{ firstName?, email?, goal?, heightCm?, weightKg?, onboardingCompleted? }`.
`onSuccess` seeds `clientPortalKeys.me()`; `onSettled` invalidates `me()` + `home()`.
`updateProfile.isPending` is the in-flight guard. `mutateAsync` throws on error.

useClientMe() (line 183) → `{ data: ClientMeData | undefined }`, staleTime 30_000.

CONSTRAINT — `goal` is a SERVER-ENFORCED 4-value enum, NOT free text. Backend
`service.update_client_profile` rejects anything outside
`{lose_weight, gain_mass, tone, maintain}` with HTTP 400 `invalid_goal`
(apps/backend/app/modules/client_portal/service.py:86,197). The UI-SPEC's "free text input
for Цель" is therefore WRONG for the writable path — see Task 2 action for the resolution
(segmented/select mapped to the enum). This is a spec correction, surfaced here so the
executor does not ship a free-text field that 400s on save.

Russian goal labels (display map): lose_weight→«Похудение», gain_mass→«Набор массы»,
tone→«Тонус», maintain→«Поддержание формы».

Current PersonalDataSheet (ProfileExtraSheets.jsx lines 39-155): hardcoded useState
initializers (name 'Саша', phone, email, dob, gender), read-only Рост/Вес/Цель FormRows
(lines 135-139), and an onSave that only does setTweak + setSaved(true). FormRow
(line 157) accepts `{ label, value, onChange, type, placeholder }`.

The PWA has NO global toast/Sonner. CheckoutSheet.jsx (lines 131-156) uses a local
`toast` state + a sheet-local `<div>`. Mirror that local-state pattern (no shared CSS class
available — use inline styles with `var(--danger)`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA client → `PATCH /client/me` | Client submits editable profile fields. Server scopes the write to the authenticated client (no client-controlled ID). |
| PWA client → `GET /client/me` | Read of the authenticated client's own profile. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-76-04 | Elevation / IDOR | `PATCH /client/me` | accept | Server scopes the update to the session client (Phase 999.5); the PWA sends no client/target ID. No client-controlled identifier crosses the boundary. |
| T-76-05 | Tampering (invalid enum) | `goal` field write | mitigate | UI constrains `goal` to the 4-value enum via a segmented control (no free text); server still allow-lists (`invalid_goal` 400) as defense-in-depth. Prevents a guaranteed 400 from a free-text field. |
| T-76-06 | Information Disclosure | DOB/Gender local state | accept | Local-only fields are never transmitted (D-76-11); no new column, no PII shift to the server. |
| T-76-07 | Tampering | npm/pnpm installs | mitigate | No new packages added (UI-SPEC §Registry Safety) — no install step to vet. |

No `high`-severity threats: the PATCH sends only the authenticated client's own editable
fields with no IDOR vector and server-side enum validation. ASVS L1 unchanged.
</threat_model>
