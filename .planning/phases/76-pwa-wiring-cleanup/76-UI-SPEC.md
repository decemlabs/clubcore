## Component Inventory: Phase 76 Touch Points

### 1. Trainer Avatar Strip — NHOME-01

**Location:** `HomeNewbie` in `apps/client-pwa/src/screens/HomeScreen.jsx` (~line 956)

**Current state:** Renders `TRAINERS.slice(0, 3)` from static mock data, with `TRAINERS.length > 3` overflow.

**Target state:** Renders live data from `useClientTrainers()`.

#### Avatar visual contract

Each avatar circle is a `<span>` (no `<img>`) of 34×34px, border-radius pill, overlapping.

| Property | Index 0 | Index 1 | Index 2 |
|----------|---------|---------|---------|
| Background | `var(--accent)` | `color-mix(in oklab, var(--accent) 60%, #6ee7c4)` | `var(--accent-deep)` |
| Text color | `var(--on-accent)` | `var(--on-accent)` | `#ffffff` |
| Font size | 12px | 12px | 12px |
| Font weight | 700 | 700 | 700 |
| Content | first Unicode code-point of `full_name` trimmed | first Unicode code-point of `full_name` | first Unicode code-point of `full_name` |

**Initials derivation (D-76-02):** `[...trainer.full_name.trim()][0]` — spread syntax to
handle multi-byte Unicode characters (same pattern as existing `tr.name` usage). Always a
single character (no two-letter monogram). Color is determined by array position (index
modulo the fixed 3-color palette above), not by trainer ID.

**Overflow counter chip (D-76-03):**

Shown only when `liveTrainerCount > 3`. Visual:

- 34×34px circle, border-radius pill, marginLeft −11px (same overlap as avatars)
- Background: `var(--surface-2)`, color: `var(--text-2)`
- Font size: 11px, weight: 700
- Content: `+{liveTrainerCount − 3}`
- Border: 2.5px solid `var(--surface)` (same separator as avatars)

#### Loading state (D-76-04)

While `useClientTrainers()` is fetching (isLoading), render a skeleton in place of the
avatar strip: 3 grey circles at 34×34px with the same 2.5px border and −11px overlap,
background `var(--surface-2)` (no pulse animation required — keep it simple, matching
existing skeleton patterns in `src/components/skeletons.jsx`).

#### Error / empty state (D-76-04)

- On error OR empty list (`data.length === 0`): show the existing static `TRAINERS`
  placeholder (fallback to current hardcoded avatars). Do NOT crash or show an error
  message — the trainer tile must always render.
- No "retry" affordance on this surface; TanStack Query handles background retries.

### 2. Plan Info Chip — NHOME-02

**Location:** `HeroNewbie` in `apps/client-pwa/src/screens/HomeScreen.jsx` (~line 330)

**Current state:** Renders a hardcoded tariff string (static labels like "Месяц / Полгода / Год").

**Target state:** A single info chip below the tariff selector showing live count and minimum
normalized monthly price from `useClientPlans()`.

#### Chip visual contract

Render as an inline chip using the existing `.chip` class from `styles.css`:

```
height: 28px; padding: 0 12px; border-radius: var(--r-pill);
background: var(--surface-2); color: var(--text-2); font-size: 13px;
font-weight: 500; border: 0.5px solid var(--border);
```

**Chip label format:** `"{N} тарифов · от {price}/мес"`

Where:
- `N` = `plans.length` (integer count from API)
- `price` = `formatMoney(minMonthlyKopecks)` — the normalized minimum monthly price
- `minMonthlyKopecks` = `Math.min(...plans.map(p => Math.round(p.price_kopecks / (p.duration_days / 30))))` (D-76-06)

**Money format (D-76-08):** `formatMoney(kopecks)` from `src/utils/format.js`:
`Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB', minimumFractionDigits: 0, maximumFractionDigits: 0 }).format(kopecks / 100)`.
Output examples: `"1 500 ₽"`, `"490 ₽"` (with NBSP thousands separator).

**Chip label example:** `"3 тарифа · от 1 500 ₽/мес"`

#### Loading / error state (D-76-09)

- While fetching or on error: show the existing hardcoded chip string (the static fallback
  currently in place). Do NOT show a spinner or error message on this surface.
- The Home screen must never block on the plans fetch.

### 3. Personal Data Sheet — PDATA-01 / PDATA-02

**Location:** `PersonalDataSheet` in `apps/client-pwa/src/screens/sheets/ProfileExtraSheets.jsx` (~lines 39-155)

**Current state:** All fields initialized from hardcoded strings; `onSave` is a local
`setSaved(true)` with no API call.

**Target state:** Fields hydrated from `useClientMe()`, saves via `useUpdateClientProfile()`.

#### Field read/write contract (D-76-10..12)

| Field | Label in UI | API field | Editable | Persisted |
|-------|-------------|-----------|----------|-----------|
| Name | Имя | `firstName` from `GET /client/me` | Yes — free text `<input>` | Yes via `PATCH /client/me` |
| Phone | Телефон | `phone` from `GET /client/me` | Read-only (existing SMS verify flow gated; PATCH does not write phone) | No (keep existing `initialPhone.current` guard) |
| Email | Email | `email` from `GET /client/me` | Yes — email `<input>` | Yes via `PATCH /client/me` |
| Date of birth | Дата рождения | — (no API field) | Local only (demo value) | No — `[местные данные]` label shown |
| Gender | Пол | — (no API field) | Local only (segmented control) | No — `[местные данные]` label shown |
| Height | Рост | `heightCm` from `GET /client/me` | Yes — numeric `<input>` with "см" suffix | Yes via `PATCH /client/me` |
| Weight | Вес | `weightKg` from `GET /client/me` | Yes — numeric `<input>` with "кг" suffix | Yes via `PATCH /client/me` |
| Goal | Цель | `goal` from `GET /client/me` | Yes — free text `<input>` | Yes via `PATCH /client/me` |

**Local-only indicator (D-76-11):** DOB and Gender rows display a small `[местные данные]`
label (or equivalent muted text in `var(--text-3)`, `t-mini` sizing) to signal they are
not synced to the server. This matches the accepted "keep local-only" option from CONTEXT.md.
The segmented control and date input remain interactive (local state only).

**Height / weight input (D-76-12):** Change from read-only display to editable numeric
`<input type="number">`. Style the input inline with existing `FormRow` pattern — no
border chrome, just the value text with the `FormRow` label column at 110px. Append
unit suffix ("см" / "кг") either as static text after the input or as `placeholder`.

#### Save action states (D-76-13)

The "Сохранить" header button cycles through these states:

| State | Button label | Visual |
|-------|-------------|--------|
| Idle | Сохранить | `color: var(--text)`, weight 600, font-size 13px |
| Loading (mutation in flight) | Сохранение… | `color: var(--text-3)`, cursor not-allowed, disabled |
| Success | Сохранено | `color: var(--accent-deep)`, weight 600 — revert to Idle after 1400ms |
| Error | Сохранить | Returns to Idle; error surfaced as toast (see Copywriting below) |

**After successful save:** `invalidate(clientPortalKeys.me())` so the sheet and any other
consumer (ProfileScreen hero) reflect persisted values on next visit.

#### Loading state for the sheet itself (PDATA-01)

While `useClientMe()` is in its initial fetch (sheet opens before data arrives):

- Show field values as empty strings or `—` placeholders rather than hardcoded demo values.
- Do NOT show a full skeleton — the sheet chrome (header, section labels, avatar, "Удалить
  аккаунт" button) renders immediately; only the field `value` props are blank.
- Once data arrives, populate all fields. TanStack Query `staleTime: 30_000` means
  subsequent opens within 30s are instant (no loading flash).

### 4. Chat Badge Removal — CLEAN-01

**Location:** `apps/client-pwa/src/App.jsx` lines ~17 (import) and ~223 (reduce)

**Current state:**
```js
import { CONVERSATIONS, TRAINERS } from '@/data';
const unreadChat = CONVERSATIONS.reduce((s, c) => s + (c.unread || 0), 0);
// ...
<TabBar active={tab} onChange={handleTab} unreadChat={unreadChat} />
```

**Target state:**
- Remove `CONVERSATIONS` from the destructured import (keep `TRAINERS` if still needed)
- Remove the `unreadChat` reduce computation
- Pass `unreadChat={0}` directly: `<TabBar active={tab} onChange={handleTab} unreadChat={0} />`

**End state visual:** The `.tab-badge` dot element on the Chat tab icon is NOT rendered
because `TabBar` renders `{t.badge ? <span>…</span> : null}` and `badge: 0` is falsy.
The Chat tab renders as a plain icon with label "Чат" — no dot, no count. This is the
correct resting state until the Chat domain is implemented.

**`aria-label` on Chat tab (accessibility):** With `badge: 0` (falsy), the `aria-label`
resolves to the simple tab label `"Чат"` (no "· N непрочитанных" suffix). No change needed
to `TabBar.jsx` — the existing conditional handles this correctly.

**Plural rule for "тариф" (Russian):** 
- 1 → тариф
- 2–4 → тарифа
- 5+ / 0 → тарифов

Implement via a simple helper:
```js
function pluralPlan(n) {
  const abs = Math.abs(n) % 100
  const mod10 = abs % 10
  if (abs >= 11 && abs <= 14) return 'тарифов'
  if (mod10 === 1) return 'тариф'
  if (mod10 >= 2 && mod10 <= 4) return 'тарифа'
  return 'тарифов'
}
```
