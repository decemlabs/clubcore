## Threat Model — Closure Notes

Per the plan's `<threat_model>`:

- **T-46-01-01 (Information Disclosure — openapi.json):** MITIGATED. `export_openapi.py` uses placeholder env vars (`SECRET_KEY=openapi-export-placeholder…`, `DATABASE_URL=…@localhost:5432/x`, etc.); no real secrets reach the spec. Verified by `jq '.paths' openapi.json` returning only path/schema keys.
- **T-46-01-02 (Information Disclosure — _internal/email/webhook):** MITIGATED. Webhook `tags: ['_internal']` confirmed via `jq '.paths."/api/v1/_internal/email/webhook".post.tags'`. **Caveat:** `jq '.paths."/api/v1/_internal/email/webhook".post.security'` returned `null` — the webhook's HMAC-signature auth (`X-Email-Webhook-Signature` per Phase 42 D-42-17) is NOT declared as an OpenAPI `securityScheme`, so the spec shows no security block on this operation. This matches what Phase 42 shipped and is **out of scope for Plan 46-01** (regen-only). Plan 46-04 Postman export filters `_internal` paths from the external handoff (D-46-08), and Plan 46-02 forward-guard for this path is type-system only (no security-scheme assertion). Flag for v1.7 hardening: declare an `apiKeyAuth`-style security scheme for the webhook so the spec carries auth metadata. Tracked here as a documentation note, not as a Plan 46-01 blocker.
- **T-46-01-03 (Tampering — schema.d.ts):** ACCEPTED. Codegen deterministic; CI drift gate `.github/workflows/ci.yml` (line ~114) reverts any manual edits.
- **T-46-01-04 (Spoofing — git commit metadata):** ACCEPTED. Standard git-author flow.
