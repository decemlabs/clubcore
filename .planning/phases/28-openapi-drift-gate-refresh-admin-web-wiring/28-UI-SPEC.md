| Role | Semantic token | Tailwind class | Light value | Dark value | Usage |
|------|---------------|---------------|-------------|------------|-------|
| Dominant (60%) | `--background` | `bg-background` | oklch(1 0 0) | oklch(0.145 0 0) | Page surface, dialog background |
| Secondary (30%) | `--card` / `--secondary` | `bg-card` / `bg-secondary` | oklch(1 0 0) / oklch(0.97 0 0) | oklch(0.205 0 0) / oklch(0.269 0 0) | Detail section cards, filter toolbar |
| Accent — active badge | `--primary` | `bg-primary text-primary-foreground` | oklch(0.205 0 0) | oklch(0.922 0 0) | `active` status badge (`variant="default"`) — existing |
| Accent — frozen badge | `--warning` | `bg-warning text-warning-foreground` | oklch(0.78 0.15 75) | oklch(0.82 0.16 75) | `frozen` status badge ONLY — see "Frozen Badge" section |
| Muted | `--muted-foreground` | `text-muted-foreground` | oklch(0.556 0 0) | oklch(0.708 0 0) | Period dates, secondary labels |
| Destructive | `--destructive` | `bg-destructive/10 text-destructive` | oklch(0.577 0.245 27.325) | oklch(0.704 0.191 22.216) | Cancel button (owner-only); cancel confirmation CTA |

Accent reserved for:
1. `active` status badge (primary token) — existing
2. `frozen` status badge (warning token) — new in this phase
3. Primary CTA buttons (`variant="default"`) — existing

The `--warning` token (`oklch(0.78 0.15 75)` light / `oklch(0.82 0.16 75)` dark with
`--warning-foreground: oklch(0.205 0 0)` / `oklch(0.145 0 0)`) is already defined in
`index.css` via reui-extras. No new CSS variables need to be introduced.

Auto-mode rationale for frozen = warning: `expired` uses `secondary` (muted grey), `cancelled`
uses `outline`, `active` uses `primary` (dark). `frozen` needs to signal "paused — attention
needed but not an error", which maps to the amber/warning semantic without implying failure.
This matches the shadcn reui-extras `--warning` token purpose.

| Status | Variant prop | Extra className | Label i18n key |

override (both `bg-warning` and `text-warning-foreground` are registered in `@theme inline`
and resolve through CSS variables).

## Interaction Contracts

### Freeze Button (FreezeSection)

States and visual rendering:

| Condition | Button label | Variant | Disabled | Extra element |
|-----------|-------------|---------|----------|--------------|
| `status==='active'` AND `freezeDaysRemaining > 0` AND user has `(CREATE, MEMBERSHIPS)` | "Заморозить" | `outline` | No | — |
| `status==='active'` AND `freezeDaysRemaining === 0` AND user has `(CREATE, MEMBERSHIPS)` | "Заморозить" | `outline` | Yes | `<Tooltip>` with `t('memberships.freeze.no_days_remaining')` |
| `status==='active'` AND mutation `isPending` | "Заморозить" | `outline` | Yes | Spinner (lucide `Loader2` icon, `animate-spin`) |
| `status==='frozen'` AND user has `(CREATE, MEMBERSHIPS)` | "Снять заморозку" | `outline` | No | Frozen badge with start date |
| `status==='frozen'` AND mutation `isPending` | "Снять заморозку" | `outline` | Yes | Spinner |
| `status !== 'active' && status !== 'frozen'` | Not rendered | — | — | — |

Tooltip implementation: wrap the disabled `<Button>` in a `<span>` (focusable) inside
`<TooltipTrigger asChild>`. Radix Tooltip does not fire on disabled elements directly.

```tsx
<TooltipProvider>
  <Tooltip>
    <TooltipTrigger asChild>
      <span tabIndex={0}>
        <Button variant="outline" size="sm" disabled>
          {t('memberships.freeze.button')}
        </Button>
      </span>
    </TooltipTrigger>
    <TooltipContent>{t('memberships.freeze.no_days_remaining')}</TooltipContent>
  </Tooltip>
</TooltipProvider>
```

Error handling: `DomainError.code` mapped to i18n key via `t('memberships.freeze.errors.<code>')`;
shown as `toast.error(...)` (non-blocking, consistent with cancel pattern).

### Renew Button + Confirm Dialog (RenewSection / RenewConfirmDialog)

The renew flow uses a non-optimistic mutation (resource UUID known only after 201).

1. Button "Продлить" (`variant="default"`, `size="sm"`) — visible when user has `(CREATE, MEMBERSHIPS)`; rendered for `status === 'active' | 'frozen' | 'expired'` (not `cancelled`).
2. Click opens `<AlertDialog>` (same pattern as `CancelMembershipDialog`).
3. Dialog body shows:
   - Plan name: `membership.planNameSnapshot`
   - Price: `formatMoney(membership.priceKopecksSnapshot)` — ru-RU RUB with NBSP
   - Computed new start date: `formatDate(computedNewStartDate)` — DD.MM.YYYY, Europe/Moscow
   - Computed new end date: `formatDate(computedNewEndDate)` — DD.MM.YYYY, Europe/Moscow
   - i18n key: `memberships.renew.confirm.body` with `{plan}`, `{price}`, `{startDate}`, `{endDate}`
4. Confirm CTA: `t('memberships.renew.confirm.cta')` → "Продлить" (`variant="default"`)
5. Cancel: `t('memberships.renew.confirm.cancel')` → "Отмена"
6. While mutation `isPending`: CTA disabled + text "…"; cancel also disabled
7. On success: `toast.success(t('memberships.renew.success'))` + `navigate({ to: '/memberships/$membershipId', params: { membershipId: newMembership.id } })`
8. On error: `toast.error(t('memberships.renew.errors.<code>'))` using `DomainError.code`; dialog closes

Date computation (display-only; server is authoritative):
- `newStartDate = status === 'expired' ? todayMSK() : addDays(parseISO(membership.endDate), 1)`
- `newEndDate = addDays(newStartDate, membership.durationDaysSnapshot - 1)`
- Use `date-fns` `addDays` + `parseISO` + `ru` locale, same as existing `formatDate` usage.

Implementation:

### Within Selector (List Page — FE-13)

Visible only when `search.expiring === true`. Renders inline in the filter row.

```
[Истекают через 7 дней]  Истекает в течение: [7 дн. ▾]
```

Implementation:
- `<Select>` from `shared/ui/select.tsx`
- Options: `[1, 3, 7, 14, 30]` mapped to `<SelectItem value="{n}">{n} {t('memberships.list.expiringWithin.option_days')}</SelectItem>`
- Label: `t('memberships.list.expiringWithin.label')` rendered as `<label>` or inline `<span>` before the Select
- Default value: `"7"` (matches `search.within` Zod default)
- On change: `navigate({ search: (prev) => ({ ...prev, within: Number(value) }) })`
- Zod schema clamps 1..30; URL tampering (e.g. `within=99`) produces Zod validation → clamped to default `7`

## Auto-Mode Choices Log

The following choices were made without user prompting (--auto mode). Review before planning.

| Decision area | Choice made | Rationale |
|--------------|-------------|-----------|
| Frozen badge semantic token | `bg-warning text-warning-foreground` | The `--warning` token (amber hue, oklch 0.78 0.15 75) already exists via reui-extras in `index.css`. It distinguishes frozen from active (primary/dark), expired (secondary/grey), and cancelled (outline). Matches D-28-10 guidance. |
| Frozen badge implementation | `variant="outline"` + `className` override | `badge.tsx` `cva` has no `warning` variant. Applying `bg-warning text-warning-foreground border-warning/50` via `className` uses semantic tokens — not raw palette — so ESLint passes. |
| Within selector widget | `<Select>` | Matches existing `shared/ui/select.tsx` primitive. D-28-12 leaves this to planner; `<Select>` is the closest match to the existing UX (no segmented control primitive exists in the repo). |
| Detail page section order | Header → Freeze → Renew → Metadata | Freeze comes before renew because freeze affects the current membership; renew creates a new one. Metadata (prev membership link) is lowest-priority context. |
| `StatusBadge` extraction | `features/memberships/components/StatusBadge.tsx` | Currently duplicated verbatim in `MembershipsListPage.tsx:26-31` and `MembershipsBlock.tsx:19-23`. Adding `frozen` to both without extraction would triple the duplication. |
| Renew confirm body format | Multiline with NBSP price and DD.MM.YYYY dates | Matches `formatMoney` + `formatDate` patterns already in use across memberships UI. |
| emptyExpiring copy | Parameterize N in the message or keep `7` | Keep the existing key `memberships.emptyExpiring.heading` for `within=7`; for other `within` values, the same message is acceptable (it will say "7 дней" even if within=14 is selected) in v1.3 — a future phase can parameterize this. Auto-mode choice: do not over-engineer. |
