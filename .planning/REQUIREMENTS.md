# Requirements: clubcore v1.11 — API Handoff + Production Hardening

**Defined:** 2026-05-26
**Milestone:** v1.11 (Phases 63-67, continues numbering from v1.10/62.1)
**Core Value:** Соло backend-разработчик с AI-агентами должен уметь поэтапно наращивать бизнес-фичи зала на стабильном, архитектурно ограниченном каркасе — без переписывания структуры по мере роста.

**Scope:** Backend-only milestone; no new business features, no new ORM entities. Goal — make the v1.0–v1.10 surface credible for v2.0 frontend integration team handoff: clean linting, curated OpenAPI contract frozen under the clubcore name, Postman v2.1 + Newman smoke + auth runbook + private Redocly doc-site, hardened `Idempotency-Key` semantics with cross-user safety, and execution of accumulated operator-pending walkthroughs.

**Phase order (locked per ARCHITECTURE.md + SUMMARY.md, 2026-05-26):** 63 → 64 → 66 → 65 → 67. Handoff artifacts (65) must reflect the final frozen spec including the `components.parameters.IdempotencyKey` added in Phase 66; Postman/Newman are generated from the post-Phase-66 spec.

**Continuity:** Derived from the 22-requirement snapshot in `.planning/milestones/v1.10-REQUIREMENTS.md` ("Planned for v1.11" section, locked 2026-05-26 per D-10-SPLIT). Refined here per `.planning/research/SUMMARY.md` findings + 4 milestone-opening decisions captured 2026-05-26 (operation_id strategy, idempotency user-scoping, sportzal_csrf defer, runbook staleness audit).

### Contract Freeze — OpenAPI Curation (Phase 64 — FRZ-*)

Single source of truth for all downstream handoff artifacts. Atomic plan 1 = "fix `title=`/`version=` stale rebrand + regen both artifacts byte-stably" before any operation_id work, else every downstream artifact carries `"Sportzal API"` / `"1.1.0"` (per PITFALLS Pitfall #4). Decision **D-11-OPID** 2026-05-26: use `generate_unique_id_function` to suffix-strip `_api_v1_{method}` from all 102 auto-generated operation IDs in a single atomic regen (rejected explicit per-route `operation_id=` annotation — too many edit sites + larger schema.d.ts churn risk).

- [ ] **FRZ-02**: All 102+ auto-generated operation IDs cleaned via `generate_unique_id_function` hook in `app/main.py` (suffix-strip `_api_v1_{method}` per D-11-OPID); single atomic regen; admin-web `schema.d.ts` callsites adjusted in the same PR.
- [ ] **FRZ-03**: Explicit `openapi_tags=[...]` defined in `app/main.py` with stable order covering all 10 business domains (Auth / Clients / Memberships / Visits / Schedule / Bookings / Trainers / Payments / Reports / Audit-log); every router declares `tags=[...]` explicitly (no auto-derived tags); Redocly preview groups operations under expected tag headings.
- [ ] **FRZ-04**: OpenAPI `info{}` metadata complete under clubcore name — `title="clubcore API"`, `version="1.11.0"`, `description` documents the contract-freeze status, `contact`/`license` set or explicitly omitted with reason; `servers[]` populated with at least 1 placeholder server (e.g. `{url: "http://localhost:8000", description: "Local dev"}`).
- [x] **FRZ-05**: `securitySchemes` wired in the curated spec — cookie auth (`cc_access` / `cc_refresh` httpOnly cookies) + CSRF header scheme (current header name `X-CSRF-Token`, cookie name `sportzal_csrf` retained as documented sportzal-era carry-over per **D-11-CSRF-DEFER** 2026-05-26: rename to `clubcore_csrf` deferred to v2.0 to avoid coordinated admin-web cutover mid-handoff); routes apply `Security()` where appropriate so downstream codegen sends auth correctly.
- [x] **FRZ-06**: Shared `components.responses` defined for the common error envelopes (`401_Unauthorized`, `403_Forbidden`, `404_NotFound`, `409_Conflict`, `422_ValidationError`, `429_RateLimited`) and referenced via `$ref` at usage sites (no inline duplicates that can drift).

### Idempotency Hardening (Phase 66 — IDM-*)

Runs BEFORE Phase 65 because Phase 65 artifacts derive from the post-Phase-66 spec (`components.parameters.IdempotencyKey` reference). Closes critique items CR-01 / CR-02 / CR-02b. Two security findings (PITFALLS Pitfalls #7 and #8) added per **D-11-IDM-USER** 2026-05-26: user-scoped Redis keys + in-flight placeholder cleanup on exception.

- [ ] **IDM-01**: Endpoint classification audit complete — every mutating endpoint (POST/PATCH/PUT/DELETE) in `apps/backend/app/api/v1/` classified as A (requires `Idempotency-Key` enforcement), B (exempt: read-only / webhook with separate dedup / idempotent-by-design), or C (currently inconsistent — to be moved to A); audit table committed to `.planning/handoff/v1.11-idempotency-audit.md`.
- [ ] **IDM-02**: CR-01 closed — `Idempotency-Key` semantics standardized: 16-128 chars, UUIDv4 conventional, Redis TTL standardized to **86400s (24h)** (was 3600s — matches ЮKassa webhook dedup window + Stripe convention), cached-response replay returns identical body+status+headers, request-body hash mismatch on same key → 422 (no silent 200).
- [ ] **IDM-03**: CR-02 closed — integration tests for double-submit on the high-priority category-A endpoints in `memberships`, `online_payments`, `pt_packages`, `pt_sessions`, `bookings` (real Postgres, real Redis, ASGITransport); replay returns cached response without re-emitting audit events.
- [ ] **IDM-04**: CR-02b closed — `components.parameters.IdempotencyKey` reusable parameter added to `openapi.json`; every category-A endpoint references it via `$ref`; semantics documented in `clubcore-auth-runbook.md` (Phase 65 dependency).
- [ ] **IDM-05**: `verify_idempotency` user-scope security fix (PITFALLS Pitfall #7) — dependency binds `Depends(get_current_user)`; Redis key includes `user.id` (`cc:idem:{user_id}:{method}:{path}:{key}`); closes cross-user replay attack under multi-user admin (v1.6); existing 3 callsites (`POST /pt-packages`, `POST /pt-sessions`, `POST /bookings`) remain green; ЮKassa webhook explicitly NOT affected (it uses separate `cc:yk:webhook:*` dedup path) per **D-11-IDM-WEBHOOK** 2026-05-26.
- [ ] **IDM-06**: In-flight placeholder cleanup on exception (PITFALLS Pitfall #8) — `verify_idempotency` exception-aware: deletes `__in_flight__` placeholder on unknown exceptions (so retries don't see stuck `idempotency_in_flight` for 24h), stores error envelope on `AppError` (so retries replay the error consistently); integration test covers DB-rollback path.
- [ ] **IDM-07**: All category-A endpoints have `Depends(verify_idempotency)` wired (currently 3 routes; expected ~7 more in `memberships` freeze/unfreeze/renew + `online_payments` create/refund + any remaining gaps from IDM-01); ЮKassa webhook explicitly excluded with code comment annotating the separate dedup path.

- [ ] **HND-01**: Curated Postman v2.1 collection generated via `openapi-to-postmanv2@6.0.1` from the frozen `openapi.json`; lives at `.planning/handoff/v1.11-clubcore.postman_collection.json`; `folderStrategy=Tags` so endpoints group under the 10 business-domain folders from FRZ-03; environment file `.planning/handoff/v1.11-clubcore.postman_environment.json` ships placeholder values for `{{baseUrl}}` / `{{accessToken}}` / `{{csrfToken}}` (no real credentials committed).

## Out of Scope (v1.11)

Explicitly excluded. Documented to prevent re-adding.

| Feature | Reason |
|---|---|
| New business features | v1.11 is pure handoff/hardening; all 8 business domains complete after v1.9. |
| New ORM entities / Alembic migrations | Backend-only milestone with zero data-shape changes. |
| Stripe payment integration | RF constraint — ЮKassa only (CLAUDE.md). |
| Public OpenAPI publication (e.g. `swagger.io` hosted, public Redocly URL) | Private commercial pet project — handoff is to a specific designer, not public consumers (CLAUDE.md). |
| `@clubcore/api-client` npm publish | Private commercial; contract distributed privately to the design team (CLAUDE.md). |
| `app/backend` PyPI publish | Same — private. |
| PDF export of OpenAPI doc-site | No use case; private commercial; Redocly preview-docs sufficient. |
| Newman wired as a CI gate | Local handoff smoke per D-11-NEWMAN-LOCAL; the 6 existing CI gates already enforce contract correctness. |
| `sportzal_csrf` → `clubcore_csrf` rename in v1.11 | Coordinated admin-web cutover risk; deferred to v2.0 per D-11-CSRF-DEFER. |
| Explicit per-route `operation_id=` annotations | Suffix-strip via `generate_unique_id_function` chosen per D-11-OPID — 1 atomic diff vs 103 edit sites. |
| SMTP adapter for email integration | Mailpit profile added (RUN-06) but adapter itself deferred to INFRA-02; current SES-V2 path stays. |
| `--unsafe-fixes` in ruff sweep | PITFALLS Pitfall #5 — risks semantic rewrite (e.g. `is` ↔ `==`, Protocol-required arg removal). |

## Decisions Locked at Milestone Open (2026-05-26)

| ID | Decision | Rationale |
|---|---|---|
| **D-11-OPID** | Phase 64 cleans 102 operation IDs via `generate_unique_id_function` suffix-strip, not explicit per-route `operation_id=`. | 1 atomic diff vs 103 edit sites; lower schema.d.ts churn risk; TypeScript function names unchanged. |
| **D-11-IDM-USER** | Phase 66 binds `verify_idempotency` to `Depends(get_current_user)`; Redis key includes `user.id`. | Closes cross-user replay attack under multi-user admin (v1.6); PITFALLS Pitfall #7. |
| **D-11-IDM-WEBHOOK** | ЮKassa webhook explicitly excluded from the new `verify_idempotency` user-scope (it uses `cc:yk:webhook:*` separate dedup). | Two-system harmony; webhook has no `current_user` to scope to. |
| **D-11-CSRF-DEFER** | `sportzal_csrf` cookie name retained in v1.11; rename to `clubcore_csrf` deferred to v2.0. | Coordinated admin-web cutover risk mid-handoff; documented as known carry-over in auth runbook. |
| **D-11-RUN-AUDIT** | Phase 67 plan 1 = staleness audit of all 4 runbooks before any live walkthrough. | PITFALLS Pitfall #11; v1.5 Phase 40 retrospective showed 4 hotfixes on first execution. |
| **D-11-NEWMAN-LOCAL** | Newman is a local handoff smoke tool, NOT a CI gate. | The 6 existing CI gates enforce contract correctness; Newman serves external integration partners, not developers. |
| **D-11-DOCS-PRIVATE** | Redocly doc-site is private (gitignored output, no public publish). | CLAUDE.md private-commercial constraint. |
| **D-11-MAILPIT-PROFILE** | Phase 67 adds Mailpit to `docker-compose.yml` under `profiles: ["dev"]` only; does NOT add SMTP adapter (current path is SES-V2). | Profile is cheap insurance for future INFRA-02; adapter is out of v1.11 scope. |
