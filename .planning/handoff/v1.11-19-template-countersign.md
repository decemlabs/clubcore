## Finding RUN-03-F1 — the 4 Phase-52 `EMAIL_*` identifiers have no rendered email copy

**Discovered during RUN-03 visual review (2026-05-29).** These 4 are `Final[str]` *identifier constants* in
`app/modules/online_payments/email_templates.py` (no `TEMPLATES` dict). The email dispatcher's
`_resolve_template` walker (`app/integrations/email/dispatcher.py:82-91`) only consults the
auth / users / memberships / bookings / payments registries — **`online_payments` is absent**.

Consequence: `_dispatch_email(...)` (`online_payments/tasks.py:256-291`) calls
`dispatcher(template_id="EMAIL_ONLINE_PAYMENT_SUCCEEDED", ...)` for these kinds, which raises
`KeyError`; that exception is caught and swallowed in the best-effort `try/except … continue`
at `tasks.py:477`. **Net effect: the email channel for the 4 online-payment notifications silently
no-ops** — only the Telegram DM is delivered.

The actual user-facing copy for these notifications is the **Telegram DM** in
`app/modules/online_payments/notifications.py` (`ONLINE_PAYMENT_*_DM` / `FISCAL_RECEIPT_FAILED_DM`),
which carries `OWNER-COPY-LOCK signed-off 2026-05-23` markers (Phase 52, see `52-01-SUMMARY.md`).
So there is **no email copy to countersign** for these 4 — the DM copy was already owner-attested.

**Disposition (D-67-06: log, do not fix in Phase 67):** Recorded as a finding; routed to the
backlog as a wiring-gap fix (out of Phase 67 execution-only scope). No code changed here.
