## 1. Docker Compose bring-up

Стек запускается одной командой из директории `apps/backend/`.
`migrate` — one-shot сервис (Alembic `upgrade head`), гарантирован `condition:
service_completed_successfully` до старта `backend` и воркеров.

```bash
cd apps/backend

# Скопируйте .env.example в .env, заполните секреты (SECRET_KEY, OWNER_EMAIL/PASSWORD, etc.)
cp .env.example .env
# <отредактируйте .env>

# Запуск: postgres + redis → migrate → backend + telegram-bot + arq-worker
docker compose up --build
```

При успехе: в stdout появляются строки вида
`backend-1  | INFO:     Application startup complete.`
Убедитесь, что `migrate-1 exited with code 0` (Alembic applied all migrations).

Smoke-check — backend отвечает:

```bash
curl -i http://localhost:8000/api/v1/health
# → HTTP/1.1 200 OK  {"data":{"status":"ok"}}
```

## 2. Revenue golden-path (owner-only, eyeball-match с DST-тестом)

Этот сценарий проверяет детерминированный golden amount из
`apps/backend/tests/integration/reports/test_reports_dst.py`:

```
GROSS_KOPECKS   = 250 000 kop  (2 500,00 RUB)
REFUND_KOPECKS  =  50 000 kop  (  500,00 RUB)
NET_KOPECKS     = 200 000 kop  (2 000,00 RUB)
```

Граничный timestamp: **2026-01-01 21:30 UTC = 2026-01-02 00:30 MSK** — платёж
должен попасть в bucket `GOLDEN_DATE_MSK_NEXT = "2026-01-02"`, а НЕ в
`GOLDEN_DATE_UTC_PREV = "2026-01-01"`.

**Шаг 2.1 — Login as owner, сохранить cookie jar:**

```bash
curl -i -s -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -c cookies.txt \
  -d '{"email":"verify_owner@local.dev","password":"<owner-password>"}'
```

При успехе: `HTTP/1.1 200 OK` + три `Set-Cookie` + body
`{"data":{"user":{"id":"...","role":"owner",...}}}`.

**Шаг 2.2 — Запрос revenue-отчёта за window 2026-01-01..2026-01-02 (groupBy=day):**

```bash
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/reports/revenue?fromDate=2026-01-01&toDate=2026-01-02&groupBy=day"
```

При успехе: `HTTP/1.1 200 OK` + ResponseEnvelope с `data.buckets`.

**Ожидаемое:** в массиве `data.buckets` присутствует объект с `"period": "2026-01-02"`.
В этом bucket значение `"netKopecks"` должно включать `NET_KOPECKS = 200 000` от
границы + любые дополнительные платежи на ту же MSK дату.
Bucket с `"period": "2026-01-01"` **отсутствует** (граничный платёж не должен
попасть в UTC-дату).

Это eyeball-match крест-валидирует автоматический тест
`test_dst_revenue_net_of_refund_golden_amount` (VER-02 / ROADMAP SC#3).

## 3. Audit-log filter narrowing (owner-only)

`GET /api/v1/audit-log` принимает AND-комбинируемые фильтры (AUD-03, D-05).
Параметры даты — `from` / `to` (НЕ `fromDate`/`toDate` — route-level
`Query(alias=...)`, см. `apps/backend/app/modules/reports/router.py:226`).

```bash
# Без фильтров — вся история, страница 1 (default pageSize=20):
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/audit-log"
```

При успехе: `HTTP/1.1 200 OK` + `{"data":{"items":[...],"total":N,"page":1,"pageSize":20}}`.

**Filter 1 — по action:**

```bash
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/audit-log?action=login_success"
```

Все вернувшиеся элементы должны иметь `"action":"login_success"`.

**Filter 2 — AND-сужение action + resourceType:**

```bash
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/audit-log?action=login_success&resourceType=session"
```

Все элементы должны иметь одновременно `"action":"login_success"` и
`"resourceType":"session"`.

**Filter 3 — дата-окно (route-level `from`/`to`):**

```bash
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/audit-log?from=2026-01-01&to=2026-01-31"
```

Все вернувшиеся записи должны иметь `createdAt` в пределах января 2026 (MSK).

**Filter 4 — actorUserId (UUID пользователя):**

```bash
# Подставьте реальный UUID из предыдущего ответа (поле actorUserId):
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/audit-log?actorUserId=<owner-uuid>"
```

Все записи принадлежат указанному актору.

**Негативный кейс — неизвестный action → 422:**

```bash
curl -i -s -b cookies.txt \
  "http://localhost:8000/api/v1/audit-log?action=not_an_action"
# → HTTP/1.1 422 Unprocessable Entity  {"code":"audit_filter_invalid",...}
```

## 4. Reception 403 на /reports/* и /audit-log

Все endpoints `/api/v1/reports/*` и `/api/v1/audit-log` — owner-only:
`(VIEW, REPORTS)` и `(LIST, AUDIT_LOG)` входят в `OWNER_ONLY` frozenset
(`apps/backend/app/core/permissions.py`). Reception получает `403 forbidden`
(AUD-05, SC#1, T-57-05).

**Шаг 4.1 — Login as reception:**

```bash
curl -i -s -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -c cookies_reception.txt \
  -d '{"email":"verify_reception@local.dev","password":"<reception-password>"}'
# → HTTP/1.1 200 OK  {"data":{"user":{"role":"reception",...}}}
```

**Шаг 4.2 — Попытка GET /reports/revenue → 403:**

```bash
curl -i -s -b cookies_reception.txt \
  "http://localhost:8000/api/v1/reports/revenue?fromDate=2026-01-01&toDate=2026-01-31"
# → HTTP/1.1 403 Forbidden  {"code":"forbidden","message":"..."}
```

**Шаг 4.3 — Попытка GET /reports/clients → 403:**

```bash
curl -i -s -b cookies_reception.txt \
  "http://localhost:8000/api/v1/reports/clients?fromDate=2026-01-01&toDate=2026-01-31"
# → HTTP/1.1 403 Forbidden  {"code":"forbidden","message":"..."}
```

**Шаг 4.4 — Попытка GET /audit-log → 403:**

```bash
curl -i -s -b cookies_reception.txt \
  "http://localhost:8000/api/v1/audit-log"
# → HTTP/1.1 403 Forbidden  {"code":"forbidden","message":"..."}
```

Все три запроса должны вернуть `403` + body `{"code":"forbidden",...}`.
Это ручная кросс-валидация RBAC-граней, автоматизированных в 57-02 тестах.

## 5. CSV download — все четыре эндпоинта + открыть в Excel (проверка кириллицы)

Phase 56 (EXP-01..04, D-13) добавила UTF-8 BOM + RFC-4180 CSV для всех четырёх
отчётов. BOM гарантирует, что Excel (Windows) открывает файл без настройки импорта
и кириллица отображается без mojibake (валидация D-13, SC#5, T-57-06).

Убедитесь, что вы залогинены как owner (cookies.txt из §2 выше).

**Шаг 5.1 — Скачать revenue.csv:**

```bash
curl -i -s -b cookies.txt -OJ \
  "http://localhost:8000/api/v1/reports/revenue.csv?fromDate=2026-01-01&toDate=2026-01-31&groupBy=day"
# Сохраняется как `revenue.csv`
```

**Шаг 5.2 — Скачать clients.csv:**

```bash
curl -i -s -b cookies.txt -OJ \
  "http://localhost:8000/api/v1/reports/clients.csv?fromDate=2026-01-01&toDate=2026-01-31"
# Сохраняется как `clients.csv`
```

**Шаг 5.3 — Скачать visits.csv:**

```bash
curl -i -s -b cookies.txt -OJ \
  "http://localhost:8000/api/v1/reports/visits.csv?fromDate=2026-01-01&toDate=2026-01-31"
# Сохраняется как `visits.csv`
```

**Шаг 5.4 — Скачать audit-log.csv:**

```bash
curl -i -s -b cookies.txt -OJ \
  "http://localhost:8000/api/v1/audit-log.csv?from=2026-01-01&to=2026-01-31"
# Сохраняется как `audit-log.csv`
# Обратите внимание: параметры даты здесь — `from`/`to`, НЕ `fromDate`/`toDate`
```

**Шаг 5.5 — Открыть в Excel и подтвердить кириллицу:**

Откройте каждый из четырёх файлов двойным кликом в Excel (Windows) или через
Файл → Открыть (macOS Numbers / LibreOffice Calc).

Ожидаемое:
- Excel открывает файл сразу, без диалога импорта кодировки.
- Заголовки и поле `payload` в `audit-log.csv` отображают кириллицу без ?.
- `revenue.csv`: денежные суммы в рублях (десятичные, напр. `2000.00`).
- `audit-log.csv`: поле `createdAt` — формат `YYYY-MM-DD HH:MM:SS` (Europe/Moscow).

Если кириллица отображается как `?` или `Ã` — BOM повреждён; зафиксируйте
скриншот и сообщите команде backend.
