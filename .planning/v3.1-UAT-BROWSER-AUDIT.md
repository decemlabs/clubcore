## Bugs (root-caused)

### BUG-1 — PT-package-plan list breaks (major) — Phase 107 T3, T4
`apps/admin-app/src/features/pt-packages/schemas.ts:28` — `PtPackagePlanSchema.active: z.boolean()` is required, but backend `PtPackagePlanResponse` (`apps/backend/app/modules/pt_packages/schemas.py:121`) never returns `active`. `z.array(...).parse()` throws → /plans «Доп. услуги» shows «Не удалось загрузить данные», and the PtPackageSellModal plan `<select>` is empty (verified: optionCount=1). Create works (POST 201); list + edit + sell are dead.
**Fix:** drop `active` (PT-plans have no active concept) or make it optional; add a real-response contract test.

### BUG-2 — PT-package instance schema mismatch (blocker) — Phase 107 T4/T6/T7/T8
`schemas.ts:69` — `PtPackageSchema` expects nested `planSnapshot` + `sessionsTotal`/`sessionsUsed`/`amountKopecks`, but backend `PtPackageResponse` returns FLAT `planNameSnapshot`/`sessionCountSnapshot`/`priceKopecksSnapshot`/`validityDaysSnapshot` + `sessionsRemaining`/`isActive` (no `planSnapshot`, no `sessionsTotal`/`sessionsUsed`/`amountKopecks`). With any real PT-package, `GET /pt-packages` parse throws → the client «Тренировки» tab renders **blank** (no row, no error). Blocks the kebab cancel/refund dialogs entirely. (Same class as the memberships flat-vs-nested bug fixed in v3.0 hux — not fixed for PT-packages.)
**Fix:** rewrite `PtPackageSchema` to the flat wire shape and map to UI fields; verify sell success-response + cancel/refund hooks; add an `isError` branch to TrainingsTab; contract test.

### BUG-3 — Gym card (CFG-01) fails to load (major) — Phase 108 T1, T3
`apps/admin-app/src/features/settings/schemas.ts:57` — `GymInfoSchema.amenities: z.array(z.string())`, but `GET /api/v1/gym` returns `amenities` as an array of objects `[{icon,label}]`. Parse throws → BranchSection shows «Не удалось загрузить настройки.»; the form never renders so edit/save/422-inline are unreachable.
**Fix:** type `amenities` (and `social`) to the object shape (or `z.unknown()`); contract test.

### BUG-4 — Working-hours day labels show «День undefined» (major) — Phase 108 T4
`GET /api/v1/settings/hours` returns schedule items keyed `day_of_week` (snake_case) because `WorkingHoursResponse.schedule` is `list[Any]` (`apps/backend/app/modules/settings/schemas.py:43`) so the camelCase alias generator does not recurse, and seed 0071 stored `day_of_week`. The FE reads `day` (`ScheduleDaySchema`, `schemas.ts:101`) → every row labelled «День undefined». Round-trip is also inconsistent (FE PUT sends `day`, backend stores/returns `day_of_week`). Grid + save mechanic otherwise work.
**Fix:** pick one field name (recommend camelCase `dayOfWeek`), align backend seed + serialization (typed inner model, not `list[Any]`) + FE read + FE PUT body.

### BUG-5 — Wrong current password logs the user out (major) — Phase 109 T6
`POST /api/v1/auth/change-password` returns **HTTP 401 invalid_credentials** when the *current* password is wrong. The admin-app global client treats any 401 as access-token expiry → `/auth/refresh` → retry → 401 again → **redirect to /login?state=expired (full logout)**. No inline «Неверный текущий пароль»; the modal and session are destroyed.
**Fix:** backend should return 400/422 (`fields.currentPassword`) for a wrong current password, not 401; FE maps it inline and keeps the modal/session; optionally exempt change-password from the global 401→refresh→logout path.

## Lesson (unchanged from v3.0)

The formal gate validated FE Zod schemas against **mock fixtures**, so mock↔real wire drift shipped silently again (PT-packages, gym amenities, hours day key). Add ≥1 contract test per domain that parses a **real** backend response (or validate Zod schemas against `openapi.json`) so this class fails in CI.
