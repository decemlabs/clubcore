<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to GET /client/gym | Untrusted client principal crosses here; must pass require_client |
| staff to PUT /gym | Reception (untrusted for writes) must be rejected; only owner may write |
| owner write payload | Untrusted JSON body crosses into the upsert; must be validated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-86-04 | Elevation of Privilege | PUT /gym by reception | mitigate | require_permission(Action.EDIT, Resource.GYM) returns 403; integration test test_reception_put_gym_info_forbidden asserts 403 |
| T-86-05 | Spoofing / Info disclosure | GET /client/gym without client auth | mitigate | require_client() gate; integration test test_anonymous_get_gym_info_rejected asserts non-200 |
| T-86-06 | Tampering (CSRF) | owner PUT cross-site forgery | mitigate | verify_csrf dependency required on PUT (declared after require_permission per RBAC-04) |
| T-86-07 | Tampering (mass assignment) | unknown/extra keys in PUT body | mitigate | GymInfoUpdateRequest extra='forbid' -> 422; test_owner_put_gym_info_rejects_unknown_key asserts 422 |
| T-86-08 | Information disclosure | gym data is non-PII shared facility info | accept | No client-scoped/PII data in gym singleton; same content visible to every authenticated client by design |
| T-86-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan — no legitimacy checkpoint needed |
</threat_model>
