## TL;DR — Direct Answers

1. **JWT/cookie machinery split:** primitives in `app/core/security.py` (pure functions, no DB), business orchestration in `app/modules/auth/service.py`. Other modules consume only re-exported `Depends` callables surfaced via **`app/core/dependencies.py`** (the auth dependency lives in core because it's infrastructure shared by all modules — not a module-to-module import).
2. **Cross-module RBAC:** put `require_permission(action, resource)` in **`app/core/dependencies.py`**. The `Role`/`Resource`/`Action` enums and `OWNER_ONLY` matrix live in **`app/core/permissions.py`** (pure data, no DB, no FastAPI). The `User` ORM model lives in `app.modules.auth.models`; the dependency loads it via a registered loader (registered by `app/main.py` — the composition root, the only place that knows about all modules).
3. **Postgres schema:** UUIDv4 primary keys with `server_default=text("gen_random_uuid()")` (Postgres 13+ native; no `pgcrypto` extension needed in PG16). Soft-delete via `deleted_at: Mapped[datetime | None]`. Audit columns via `TimestampMixin`. **Refresh tokens: hybrid** — DB row (audit, family rotation, theft detection) + Redis index (fast revoke check on every request).
4. **Telegram boundary:** OTP code generation + TTL + verification = `app.modules.auth.service` (owns the `otp_codes` table). Sending Telegram message = `app.integrations.telegram.sender` (pure adapter). Bot polling worker = `app.workers.telegram_bot` running long-polling **as a separate process** (NOT an ARQ task — long-running event loop is the wrong fit for ARQ).
5. **`packages/api-client`:** **single thin generated package** with `openapi-typescript` producing one `schema.d.ts` (types only) + a hand-written ~80-line `fetcher.ts`. No per-module split. TanStack Query keys remain in `apps/admin-web/src/features/<domain>/api/keys.ts`.
6. **OpenAPI pipeline:** `openapi.json` is a **checked-in artifact** at `apps/backend/openapi.json`, regenerated by `scripts/export_openapi.py` that calls `create_app().openapi()` without booting uvicorn. CI runs the script + `git diff --exit-code` to detect drift.
7. **Build order:** `core/security primitives → User model + auth Alembic migration → email/password auth endpoints → RBAC dependency → Telegram OTP → Clients model + migration → Clients CRUD → openapi.json export → packages/api-client codegen → admin-web /login wiring → admin-web /clients wiring`.

### 2.2 The cross-module RBAC pattern (the central question)

**Problem:** `modules/clients/router.py` needs `require_permission('delete', 'clients')`. That dependency knows about JWT, sessions, and the `User` model — all owned by `auth`. But `import-linter`'s `modules-independent` contract forbids `clients` importing from `auth`.

**Solution: lift the dependency into `core`.** The dependency function does not know it belongs to "auth" — it's framework-level infrastructure shared by all modules.

```python
# app/core/permissions.py — NEW (pure data, no DB, no FastAPI)
from enum import StrEnum

class Role(StrEnum):
    OWNER = "owner"
    RECEPTION = "reception"

class Action(StrEnum):
    VIEW = "view"; CREATE = "create"; EDIT = "edit"; DELETE = "delete"; REFUND = "refund"

class Resource(StrEnum):
    CLIENTS = "clients"; FINANCE = "finance"; REPORTS = "reports"
    PAYROLL = "payroll"; COMPENSATION = "compensation"; SETTINGS = "settings"
    OWNER_AREA = "owner-area"; TEMPLATES = "templates"

OWNER_ONLY: frozenset[tuple[Action, Resource]] = frozenset({
    (Action.VIEW, Resource.FINANCE),
    (Action.VIEW, Resource.REPORTS),
    (Action.VIEW, Resource.PAYROLL),
    (Action.VIEW, Resource.COMPENSATION),
    (Action.VIEW, Resource.SETTINGS),
    (Action.VIEW, Resource.OWNER_AREA),
    (Action.EDIT, Resource.TEMPLATES),
    (Action.DELETE, Resource.CLIENTS),
    (Action.REFUND, Resource.FINANCE),
})

def can(role: Role, action: Action, resource: Resource) -> bool:
    if role is Role.OWNER:
        return True
    return (action, resource) not in OWNER_ONLY
```

```python
# app/core/dependencies.py — FILLED (registered-loader pattern)
from collections.abc import Awaitable, Callable
from typing import Annotated, Any, Protocol
from fastapi import Depends, Request
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.database import get_db
from app.core.exceptions import ForbiddenError
from app.core.permissions import Action, Resource, Role, can
from app.core.security import decode_access_token

class CurrentUser(Protocol):  # structural type — no module import
    id: object
    role: Role
    is_active: bool

UserLoader = Callable[[AsyncSession, str], Awaitable[CurrentUser]]
_user_loader: UserLoader | None = None

def register_user_loader(loader: UserLoader) -> None:
    global _user_loader
    _user_loader = loader

async def get_current_user(
    request: Request,
    session: Annotated[AsyncSession, Depends(get_db)],
) -> CurrentUser:
    token = _extract_access_cookie(request)
    payload = decode_access_token(token)
    if _user_loader is None:
        raise RuntimeError("user_loader not registered; auth module not wired")
    user = await _user_loader(session, payload["sub"])
    if not user.is_active:
        raise ForbiddenError("user_inactive")
    return user

def require_permission(action: Action, resource: Resource):
    async def _checker(
        user: Annotated[CurrentUser, Depends(get_current_user)],
    ) -> CurrentUser:
        if not can(user.role, action, resource):
            raise ForbiddenError(f"forbidden:{action}:{resource}")
        return user
    return _checker
```

```python
# app/main.py — composition root wires the loader
from app.core.dependencies import register_user_loader
from app.modules.auth.service import load_user_by_id

def create_app() -> FastAPI:
    register_user_loader(load_user_by_id)
    ...
```

**Key insight:** `app/main.py` is the only place that knows about all modules. `import-linter` does NOT constrain `main.py` — it's the composition root. This pattern keeps cross-module knowledge in the one acceptable place.

`clients/router.py` then writes:

```python
from fastapi import Depends
from app.core.dependencies import require_permission
from app.core.permissions import Action, Resource

@router.delete("/{client_id}", dependencies=[Depends(require_permission(Action.DELETE, Resource.CLIENTS))])
async def delete_client(...): ...
```

`clients` only imports from `core` — no contract violation.

## 3. Auth Data Model (Postgres)

### 3.1 Mixins (in `app/core/database.py`)

```python
from datetime import datetime
from uuid import UUID
from sqlalchemy import func, text
from sqlalchemy.dialects.postgresql import UUID as PgUUID, TIMESTAMP
from sqlalchemy.orm import Mapped, mapped_column

class UUIDPkMixin:
    id: Mapped[UUID] = mapped_column(
        PgUUID(as_uuid=True),
        primary_key=True,
        server_default=text("gen_random_uuid()"),  # PG13+ native, no pgcrypto needed
    )

class TimestampMixin:
    created_at: Mapped[datetime] = mapped_column(
        TIMESTAMP(timezone=True), server_default=func.now(), nullable=False,
    )
    updated_at: Mapped[datetime] = mapped_column(
        TIMESTAMP(timezone=True), server_default=func.now(), onupdate=func.now(), nullable=False,
    )

class SoftDeleteMixin:
    deleted_at: Mapped[datetime | None] = mapped_column(
        TIMESTAMP(timezone=True), nullable=True, index=True,
    )
```

**Decision: server-side UUID generation.** Single source of truth, audit trail intact.

### 3.2 Auth tables

```python
# app/modules/auth/models.py
class User(UUIDPkMixin, TimestampMixin, SoftDeleteMixin, Base):
    __tablename__ = "users"
    email: Mapped[str | None] = mapped_column(String(254), unique=True, index=True)
    password_hash: Mapped[str | None] = mapped_column(String(255))  # argon2; null if Telegram-only
    telegram_chat_id: Mapped[int | None] = mapped_column(unique=True, index=True)
    full_name: Mapped[str] = mapped_column(String(255))
    role: Mapped[Role] = mapped_column(String(32), default=Role.RECEPTION)
    is_active: Mapped[bool] = mapped_column(default=True)

class RefreshToken(UUIDPkMixin, TimestampMixin, Base):
    __tablename__ = "refresh_tokens"
    user_id: Mapped[UUID] = mapped_column(ForeignKey("users.id", ondelete="CASCADE"), index=True)
    token_hash: Mapped[str] = mapped_column(String(64), unique=True)  # SHA-256, never raw
    family_id: Mapped[UUID]  # rotation family — reuse detection revokes whole family
    expires_at: Mapped[datetime]
    revoked_at: Mapped[datetime | None]
    user_agent: Mapped[str | None] = mapped_column(String(512))
    ip: Mapped[str | None] = mapped_column(String(64))

class OtpCode(UUIDPkMixin, TimestampMixin, Base):
    __tablename__ = "otp_codes"
    user_id: Mapped[UUID | None] = mapped_column(ForeignKey("users.id"))  # null until claimed
    telegram_chat_id: Mapped[int | None]
    code_hash: Mapped[str] = mapped_column(String(64))  # SHA-256, no raw codes at rest
    deep_link_token: Mapped[str | None] = mapped_column(String(64), unique=True, index=True)
    purpose: Mapped[str] = mapped_column(String(32))  # 'login' | 'register'
    expires_at: Mapped[datetime]
    consumed_at: Mapped[datetime | None]
    attempts: Mapped[int] = mapped_column(default=0)
```

### 3.3 Refresh token storage — DB + Redis hybrid

Pattern: Store full row in Postgres; mirror `jti → user_id` in Redis with TTL = token expiry. Logout deletes from Redis + sets `revoked_at` in DB. Refresh path: Redis `EXISTS` → DB lookup for rotation. If token presented but absent from Redis → check DB → if `revoked_at IS NOT NULL`, revoke entire `family_id` (theft detected).

## 4. Telegram OTP — Call Graph

### 4.1 Process topology

Two separate processes share Postgres + Redis:

1. **`uvicorn app.main:create_app --factory`** — HTTP API.
2. **`python -m app.workers.telegram_bot`** — long-polling **(NEW process)**.
3. **`arq app.workers.arq_app.WorkerSettings`** — ARQ jobs.

The bot is **NOT an ARQ task**. ARQ is for fire-and-forget jobs (send a message). Long-polling is a long-running event loop — wrong fit for ARQ.

### 4.2 Module assignment

| Concern | Owner |
|---------|-------|
| OTP code generation (random, hash, store) | `app.modules.auth.service` |
| Deep-link token generation | `app.modules.auth.service` |
| `otp_codes` table & queries | `app.modules.auth` (models + repository) |
| Sending Telegram message (HTTP to api.telegram.org) | `app.integrations.telegram.sender` |
| Bot polling + dispatching `/start` | `app.workers.telegram_bot` |
| Wiring `/start` handler → auth verification | `app.workers.telegram_bot` (composition root for the bot process) |

### 4.3 Call graph — "Telegram OTP login"

```
[1] User on /login clicks "Войти через Telegram"
    Browser → POST /api/v1/auth/otp/request { channel: "telegram" }

[2] auth.router.request_otp → auth.service.create_otp_request()
    - generates 6-digit code, hashes → otp_codes row
    - generates deep_link_token (32 bytes urlsafe)
    - returns { deep_link_url: "https://t.me/SportzalBot?start=<token>" }

[3] Frontend renders QR + deep link, polls GET /auth/otp/status?token=<deep_link_token>

[4] User opens Telegram → presses /start <deep_link_token>

[5] Bot dispatcher (in app.workers.telegram_bot) receives update
    - handler reads args → deep_link_token
    - calls auth.service.bind_telegram_to_otp(token, chat_id)
        - sets otp_codes.telegram_chat_id = chat_id
    - calls integrations.telegram.sender.send_message(chat_id, "Ваш код: 123456")

[6] Frontend's polling endpoint sees otp_codes.telegram_chat_id IS NOT NULL
    → frontend shows "Введите код из Telegram"
    User enters 123456 → POST /api/v1/auth/otp/verify { token, code }

[7] auth.router.verify_otp → auth.service.consume_otp(token, code)
    - finds otp_codes row by token, checks code_hash, attempts < 5, not consumed, not expired
    - upserts User (find by telegram_chat_id OR email, else create)
    - issues access (15min) + refresh (30d) tokens
    - sets httpOnly cookies: sz_access (Path=/, SameSite=Lax, Secure), sz_refresh (Path=/api/v1/auth, ...)
    - returns 200 { user: { id, role, full_name } }
```

**Security notes:**
- OTP code never stored raw — only `code_hash = sha256(code)`.
- `attempts` field rate-limits brute force (lock at 5).
- `deep_link_token` is single-use; consumed on bot side.
- TTL: 5 minutes for OTP, 10 minutes for deep-link token.

## 6. OpenAPI Pipeline — Build vs Runtime

### 6.1 Recommended: checked-in artifact, build-time export

```
apps/backend/scripts/export_openapi.py    ← NEW
apps/backend/openapi.json                 ← NEW, checked in
packages/api-client/src/schema.d.ts       ← gitignored, regenerated by codegen
```

```python
# scripts/export_openapi.py
import json
from app.main import create_app

def main() -> None:
    app = create_app()
    with open("openapi.json", "w") as f:
        json.dump(app.openapi(), f, indent=2, sort_keys=True)

if __name__ == "__main__":
    main()
```

CI step:
```bash
cd apps/backend && uv run python scripts/export_openapi.py
git diff --exit-code openapi.json    # fails if spec drifted
```

Frontend codegen:
```json
{
  "scripts": {
    "codegen": "openapi-typescript ../../apps/backend/openapi.json -o src/schema.d.ts"
  }
}
```

### 6.2 Why checked-in, not live-fetch

| Approach | Pro | Con |
|----------|-----|-----|
| Fetch live `/openapi.json` from running backend | Always current | CI must boot full app + DB; flaky; slow |
| **Checked-in artifact + drift check** | Fast CI, reviewable in PRs, works offline | Requires discipline; one extra commit per API change |

### 7.2 Why this order

- **DB/auth before Telegram:** Telegram is the riskiest dependency (external API, separate process, polling fragility). Get email/password proving the JWT pipeline first; Telegram becomes additive.
- **Auth before Clients:** Clients needs `require_permission`. Doing Clients without auth = throwaway work.
- **Backend complete before frontend wiring:** `openapi.json` must be stable before codegen lands.
- **Auth wiring before Clients wiring on frontend:** without login, `/clients` route can't be tested in `VITE_API_MODE=http`.

## 8. Drift / Risks Surfaced

| Risk | Severity | Mitigation |
|------|----------|------------|
| Pagination contract drift: backend uses `limit/offset`, frontend uses `page/pageSize` | MEDIUM | **Recommendation: change backend `Page[T]` to `{items, total, page, pageSize}`** — single change, frontend stays untouched. Alternative: translation layer in fetcher. |
| `app/modules/members` placeholder vs new `app/modules/clients` | MEDIUM | PROJECT.md uses both terms. Frontend `can.ts` uses `clients`. **Recommendation: rename `members` → `clients`** in `app/modules/` and update `.importlinter`. Members concept doesn't exist yet. |
| Telegram bot process crash → no OTPs delivered | HIGH | `docker-compose.yml` adds `restart: unless-stopped` on `telegram-bot` service. Health check via Bot.get_me() on startup. |
| OpenAPI drift if developer forgets to run export script | MEDIUM | Pre-commit hook + CI `git diff --exit-code`. |
| Cookie SameSite + cross-origin dev (Vite 5173 ↔ FastAPI 8000) | MEDIUM | Dev: `SameSite=Lax` works because both are localhost. Prod: must serve admin-web from same origin OR use `SameSite=None; Secure` + CSRF token. **Phase I needs a concrete decision.** |
| `noUncheckedIndexedAccess: true` in admin-web tsconfig + generated `paths` types | LOW | `openapi-typescript` generates `paths[P]` always defined; verify after first codegen. |
| Reception lockout at backend must mirror frontend exactly | HIGH | `OWNER_ONLY` matrix duplicated across `apps/admin-web/src/shared/session/can.ts` and `apps/backend/app/core/permissions.py`. **Add a contract test** that imports both and compares. |
