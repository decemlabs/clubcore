<objective>
Build the messaging REST surface inside app/modules/messaging/: schemas (camelCase, with unreadCount),
repository (raw-SQL cross-module reads + ON CONFLICT get-or-create thread + newest-first list with
optional after-cursor + mark-read), service (send/list/mark-read + internal record_staff_message + the
Redis pub/sub publish seam), and the router (GET/POST/PATCH) mounted at /client. The pub/sub publish is
wired here as notification-only (id-only frame, DB-first) so Plan 03's WS subscriber has something to
receive — but no WS endpoint is added in this plan.

Purpose: REST must exist before WS can call the service functions and before the pub/sub channel has a
publisher. This plan delivers MSG-01..04 fully and lays the RT-04 catch-up cursor + the RT-03 publish
side of the fan-out (the subscribe side is Plan 03).

Output: schemas.py, repository.py, service.py, router.py, the mount in api/v1/router.py, REST + camelCase
tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA client → REST API | Untrusted JSON body + headers; client_id MUST come from principal, never body |
| REST handler → DB | Parameterised SQL only (text() with :params); no string interpolation of UUIDs |
| REST handler → Redis pub/sub | Channel name derived from principal client_id only (publish side of RT-03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-90-04 | Information Disclosure | GET /messages, PATCH /messages/read | mitigate | client_id from require_client() principal ONLY (D-20-IDOR); thread resolved from principal; another client's thread is unreachable — 404-collapse semantics. IDOR test asserts B never sees A's messages |
| T-90-05 | Spoofing | POST /messages body claiming another client | mitigate | No client_id/thread_id accepted in request body; SendMessageRequest carries only `body`; extra='forbid' rejects injected ownership fields (422) |
| T-90-06 | Tampering | POST replay / double-submit | mitigate | Idempotency-Key via verify_idempotency + idempotent_execute (reused infra, 24h TTL); duplicate key+body replays, key+different body → 422 idempotency_key_reuse |
| T-90-07 | Tampering | CSRF on mutations | mitigate | verify_client_csrf (double-submit, constant-time) on POST + PATCH; ordering require_client→verify_client_csrf→get_db; missing header → 403 |
| T-90-08 | Repudiation | message send / read not audited | mitigate | audit.emit("message_sent") on send, ("message_read") on mark-read; pairs registered Plan 01 |
| T-90-09 | Tampering | whitespace/empty body persisted | mitigate | SendMessageRequest min_length=1 + strip validator → 422 before DB (no empty messages; attachments arrive Phase 92) |
| T-90-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan; all deps in pyproject.toml. slopcheck N/A |
