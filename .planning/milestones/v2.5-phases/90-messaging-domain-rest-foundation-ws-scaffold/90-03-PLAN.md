<objective>
Add the real-time WebSocket transport to the messaging module, locking all six WS invariants from day
one: (1) cookie-based auth via require_client() over the WS upgrade (no URL token), (2) per-principal
channel cc:messaging:client:{client_id} (IDOR-safe), (3) per-connection redis.pubsub() subscriber (not
a global lifespan task), (4) session-per-operation via app.state.sessionmaker (not Depends(get_db)),
(5) application-level heartbeat + idle cleanup with finally teardown, (6) DB-first delivery (frames are
id-only; the PWA refetches via REST). A CSWSH Origin guard (verify_ws_origin) gates the upgrade.

This plan ALSO establishes the WS test convention as its FIRST deliverable: Starlette
TestClient.websocket_connect() (httpx ASGITransport cannot do WS upgrade — P6/P13). All WS tests use
this convention.

Purpose: RT-01 (real-time delivery), RT-02 (auth + IDOR over WS), RT-03 (multi-worker fan-out via Redis
pub/sub — the publish side shipped in Plan 02; this plan adds the subscribe side and proves cross-context
delivery), RT-04 (reconnect catch-up — the cursor shipped in Plan 02; this plan proves the reconnect path).

Output: ws.py (subscriber loop + heartbeat), the @router.websocket endpoint, verify_ws_origin, a WS test
conftest, and three WS test suites (smoke, auth/IDOR, fan-out).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → WS upgrade | Untrusted; cookie auth + Origin check are the only gates (no CSRF header possible on handshake) |
| WS connection → Redis pubsub | Subscriber channel derived from principal ONLY; never from client-supplied data |
| WS handler → DB pool | Long-lived connection must NOT hold a pooled DB session (pool exhaustion) |
| Redis pub/sub → WS subscribers | At-most-once; missed messages recovered via DB-first REST cursor, never assumed delivered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-90-10 | Spoofing | WS auth via URL token (CSWSH + log leak) | mitigate | NO URL token; httpOnly cc_client_access cookie (SameSite=Lax, confirmed) sent automatically on same-origin upgrade; require_client() over WebSocket. No `?token=` anywhere (P1) |
| T-90-11 | Spoofing | Cross-Site WebSocket Hijacking | mitigate | verify_ws_origin dependency validates Origin against the CORS allowlist; disallowed origin → close 1008 (P1). Test asserts rejection |
| T-90-12 | Information Disclosure | IDOR over WS subscribe | mitigate | Channel = cc:messaging:client:{principal.client_id} ONLY (Anti-Pattern 5); test asserts client A never receives client B's frames (P2, D-20-IDOR) |
| T-90-13 | Denial of Service | DB pool exhaustion from session-per-connection | mitigate | session-per-operation via app.state.sessionmaker; NO Depends(get_db) in the WS handler (P3); grep gate asserts absence |
| T-90-14 | Denial of Service | zombie connections leak Redis subscribers | mitigate | App-level heartbeat (~30s ping) + asyncio.wait_for idle timeout → close 1001; finally block unsubscribes + aclose (P6) |
| T-90-15 | Denial of Service | multi-worker fan-out silently broken | mitigate | Redis pub/sub is the only fan-out mechanism (no module-level dict); cross-context delivery test mandatory before close (P4, RT-03) |
| T-90-16 | Tampering | at-most-once pub/sub message loss | mitigate | DB-first: every message persisted before publish (Plan 02); frames are id-only; reconnect catch-up via GET ?after= cursor (P5, RT-04); test proves recovery |
| T-90-SC | Tampering | npm/pip/cargo installs | accept | No package installs (httpx-ws explicitly deferred per CONTEXT; Starlette TestClient is already a dependency). slopcheck N/A |
</threat_model>
