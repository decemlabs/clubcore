The _v24Checks pattern (schema.contract.test.ts:537-573) is the template:
  - one `type _Xxx = AssertNonNever<paths['<path>']['<method>']>` per path×method
  - a `const _vNNChecks: [ ...types ] = [ true, true, ... ]` tuple
  - an `it('compiles against ... vNN surface', () => { expect(_vNNChecks).toHaveLength(N) })`
  AssertNonNever<T> = [T] extends [never] ? false : true  (defined at top of file)

The SIX v2.5 messaging contract surfaces to guard (paths from the frozen openapi.json):
  GET   /api/v1/client/messages                            (MSG-01)
  PATCH /api/v1/client/messages/read                       (MSG-04)
  POST  /api/v1/client/messages                            (MSG-02/03)
  POST  /api/v1/client/messages/attachments                (ATT-01/02)
  GET   /api/v1/client/messages/attachments/{attachment_id} (ATT-03)
  GET   /api/v1/client/ws/messages                         (RT-01 — manual WS doc; emitted as a `get` op by Plan 01)
NOTE: openapi-typescript types absent request bodies as `never`; only guard
requestBody on the POST ops where a body exists (POST /messages has a body;
POST /messages/attachments is multipart — guard the operation, not the body, to
avoid a false `never` like the _v24 trainers-PATCH-body precedent).
