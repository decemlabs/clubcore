## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA client → `PATCH /client/me` (write) | Untrusted client input crosses here; server strict-validates |
| PWA client → `GET /client/me` (read) | Server returns only the caller's own profile |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-78-03 | Tampering | PATCH /client/me notifPrefs body | mitigate | The PATCH sends ONLY the 4 boolean notif keys. The backend `ClientProfileUpdateRequest` / `NotifPrefs` schema is strict 4-key with `extra=forbid` (D-04/D-05) — any injected extra field is server-rejected. Client cannot widen the write surface. |
| T-78-04 | Elevation of Privilege | client writing another principal's prefs | accept | PATCH /client/me is scoped to the authenticated ClientPrincipal (require_client, aud:"client" cookies — D-20-PRINCIPAL); there is no client_id parameter to forge. Server resolves the target from the session. |
| T-78-05 | Information Disclosure | notifPrefs in client state | accept | notifPrefs are 4 booleans owned by the principal; no secrets/PII. Dropping localStorage REDUCES local persistence surface. |

No high-severity threats. The only write sends 4 server-strict-validated booleans for the authenticated principal; no secrets in client state; localStorage notif store removed.
</threat_model>
