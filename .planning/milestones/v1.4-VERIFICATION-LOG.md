    evidence: "apps/backend/app/modules/pt_sessions/service.py:267 — `performed_by_user_id=actor.id` (raw UUID) was the sole non-stringified UUID in the `pt_session_recorded` audit emit payload. Other UUID fields (pt_session_id, pt_package_id, client_id, trainer_id) were already str()-cast (line 261-264). When the payload dict is persisted to the JSONB column by SQLAlchemy/asyncpg, the raw UUID fails json.dumps(): `TypeError: Object of type UUID is not JSON serializable`. Pydantic `AUDIT_PAYLOAD_SCHEMAS[(pt_session_recorded, pt_session)].model_validate(payload)` accepts both str and UUID (its `performed_by_user_id: UUID` field coerces strings) but does NOT mutate the original dict — so the raw UUID survives validation and trips the JSON encoder downstream. Fix: `performed_by_user_id=str(actor.id)`. This bug shipped in commit 8d8ed09 (Phase 34-02) and went undetected because the affected integration test (`test_concurrent_record_pt_session_decrement_at_db_layer`) was authored under the same commit but never successfully run end-to-end."
  - gap: REG-36-04

    evidence: "apps/backend/tests/integration/pt_sessions/test_pt_session_record_race.py:204 — `assert refreshed_pkg.sessions_remaining == 0` failed with `assert 1 == 0` even though the route handler successfully committed the decrement on its own connection (verified in SQL log). Cause: `db_session_real_commit` fixture uses `expire_on_commit=False`; the seed code at lines 136-138 loaded PtPackage into the test session's identity map with `sessions_remaining=1`. Fix: `db_session_real_commit.expire_all()` before the re-read forces fresh-from-DB load. This test bug also shipped in 4bdb584 (Phase 34-02) and was masked by the REG-36-03 failure happening first."
