# Phase 81.1 Plan 01: Checkout Save-Card Capture Summary

**One-liner:** Save-card opt-in checkbox in CheckoutSheet threading `savePaymentMethod:true` through both checkout mutation hooks to close the PAYM-01 PWA-capture gap.

## What Was Built

### Task 1: Thread savePaymentMethod through both checkout hooks (`7ec28764`)

Both `useClientCheckoutMembership` and `useClientCheckoutPtPackage` in `apps/client-pwa/src/lib/clientQueries.ts` now accept an optional `savePaymentMethod?: boolean` argument.

The request body is built with conditional spreads:
- When `savePaymentMethod` is truthy: `savePaymentMethod: true` appears in the body
- When falsy/absent: no `savePaymentMethod` key in the body — byte-identical to prior behavior
- `promoCode` and `savePaymentMethod` can coexist in the body
- `params`, idempotency header, and `onSettled` invalidation are unchanged

### Task 2: Add save-card opt-in to CheckoutSheet (`582aae22`)

- `savePaymentMethod` boolean state (default `false`) added to top-level `CheckoutSheet` component alongside `promoCode`/`promoResult` state — NOT inside `ReviewStage`, so it survives the email-gate → `launchCheckout` transition
- `ReviewStage` receives `savePaymentMethod` + `setSavePaymentMethod` as props
- A new section renders in the review body: "Карта" label (co-sec-label) + switch control labeled "Сохранить карту для будущих оплат" with sub-label "Карта сохраняется для удобства — автосписаний не будет" (mirrors the existing `bonusOn` switch markup — `role="switch"`, `aria-checked`, `co-bonus-switch`/`co-bonus-knob` classes)
- `launchCheckout` spreads `savePaymentMethod: true` into both `checkoutMembership.mutateAsync` and `checkoutPtPackage.mutateAsync` args when the flag is truthy; no key is passed when OFF
- No ФЗ-376 consent prompt added — mere card storage is not a recurring-charge event

### Task 3: Vitest coverage + byte-stable contract re-generation (`c03af0a2`)

Created `CheckoutSheet.savecard.test.jsx` covering:
- **Sub opt-in OFF (default):** membership `mutateAsync` arg has no truthy `savePaymentMethod` key
- **Sub opt-in ON:** `mutateAsync` called with `savePaymentMethod: true` after toggling the switch
- **PT opt-in ON:** PT `mutateAsync` called with `savePaymentMethod: true`

Contract byte-stability confirmed: `uv run python -m scripts.export_openapi` + `pnpm --filter @clubcore/api-client codegen` + `git diff --exit-code` → zero diff on both `apps/backend/openapi.json` and `packages/api-client/src/schema.d.ts` (field already frozen from Phase 79).
