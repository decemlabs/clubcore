<objective>
Close the PAYM-01 PWA-capture gap: thread a client save-card opt-in from `CheckoutSheet` through both checkout mutation hooks into the request body, so a card can finally be linked through the PWA UI. The backend already saves a card when a checkout request carries `savePaymentMethod=true` (Phase 79 webhook step 8.5), and `CardSheet` already manages the saved card (Phase 81 PAYM-05) — but no PWA surface ever sent the flag.

Purpose: A real authenticated client can opt to save their own card at their own checkout, completing the end-to-end card-on-file path that was otherwise unreachable from the UI.

Output: `savePaymentMethod?: boolean` arg on both checkout hooks (default OFF → byte-identical body to today), a save-card checkbox in `CheckoutSheet`, vitest coverage for both off/on paths, and a byte-stable contract re-generation (zero diff expected — the field is already frozen).

NO backend change. NO migration. NO contract change. NO ФЗ-376 consent at checkout (mere storage is not a recurring-charge event — autopay enable is the consent gate, handled in `CardSheet`).
</objective>
