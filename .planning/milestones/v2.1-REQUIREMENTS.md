# Requirements: clubcore — v2.1 Client PWA — Fill the Gaps

**Defined:** 2026-06-02
**Core Value:** Соло backend-разработчик с AI-агентами должен уметь поэтапно наращивать бизнес-фичи зала на стабильном, архитектурно ограниченном каркасе — без переписывания структуры по мере роста.

**Milestone framing:** Turn on already-built-but-hidden client-PWA functionality via feature-flag flips + small backend field additions to existing schemas + pure-frontend wiring (Groups A+C from the client-pwa inventory). **No new backend domains. The payment/activation path is not touched.** Plus fold-in of the two deferred v2.0 warnings.

---

## v1 Requirements

### Profile & Membership (PMEM)

- [ ] **PMEM-01**: Клиент видит стоимость своего абонемента и признак автопродления на экране Профиль (`price_kopecks` + `auto_renew` добавлены в `ClientMembershipResponse` / `/client/membership`).

> Стаж членства (бейдж + стат «N недель») и `tier`/«PREMIUM» **исключены из v2.1** по решению пользователя 2026-06-02 — флаги `tenureBadge`/`weeksStat` остаются OFF, поля `tier`/`member_since_at` в backend не добавляются.

### Notification Preferences (NOTIF)

- [ ] **NOTIF-01**: Клиент включает/выключает категории уведомлений (промо / расписание / тренер / звук) в Настройках, и выбор сохраняется на сервере (`notif_prefs` JSONB через `PATCH /client/me`), переживая перезагрузку, переустановку PWA и смену устройства (а не только `localStorage`).

### Checkout Promo (PROMO)

- [ ] **PROMO-01**: Клиент применяет рекомендованный промокод одним нажатием на чип в чекауте; код (`FIT15`) реально засеян в БД и валидируется существующим `POST /client/promo/validate` (платёжный путь и server-authoritative цена не меняются).

### Newbie Home Wiring (NHOME)

- [ ] **NHOME-01**: На newbie-Home клиент видит реальных тренеров (аватары/инициалы + overflow-счётчик) из `GET /client/trainers`, а не из mock-массива `TRAINERS`.
- [ ] **NHOME-02**: На newbie-Home инфо-чипы тарифов («N тарифов · от X ₽/мес») вычисляются из реального каталога `GET /client/plans` (количество планов + минимальная цена), а не из захардкоженной строки.

### Personal Data (PDATA)

- [ ] **PDATA-01**: Клиент видит свои реальные персональные данные (имя, телефон, email и прочие подкреплённые API-поля) в шите «Личные данные», подгруженные из `GET /client/me` — без захардкоженных значений.
- [ ] **PDATA-02**: Клиент редактирует подкреплённые поля профиля (имя / email / цель / рост / вес) в «Личные данные», и изменения сохраняются на сервере через `PATCH /client/me` (а не остаются локальным tweak'ом).

### v2.0 Debt Fixes (FIX)

- [ ] **FIX-01**: Клиент отменяет свою бронь из PWA, и отмена реально доходит до backend через `POST /client/booking/{id}/cancel` (вызывается `useCancelBooking()`), а не только косметически закрывает шит — закрывает v2.0 WARNING-1 / фронтовый разрыв CBOOK-05.
- [ ] **FIX-02**: После успешной оплаты клиент видит, куда отправлен фискальный чек (email или телефон), согласованно с `999.5-UI-SPEC` §Screen 2 D-09 — закрывает v2.0 WARNING-2 (вернуть плашку «чек отправлен на …» с использованием `receiptEmail`/`receiptPhone`, либо явно привести UI-SPEC в соответствие с принятым решением).

### Cleanup (CLEAN)

- [ ] **CLEAN-01**: Бейдж непрочитанных сообщений чата не отображает mock-значение — зависимость от mock `CONVERSATIONS` убрана; пока домен чата не реализован, бейдж показывает 0 / скрыт.

## v2 / Future Requirements (deferred — Group B net-new domains)

Net-new backend domains, each likely its own milestone. Several require a staff/owner side, but `apps/admin-web` is a frozen mock-reference — the staff-side question must be resolved before planning these.

| Feature | Note |
|---------|------|
| Chat / messaging (ChatScreen) | New `messaging` domain + staff side to reply |
| Referral program (ReferralSheet) | New `referral` domain: codes, rewards, history |
| Trainer reviews + detail/bio (TrainerDetailSheet) | New `trainer_profile` + `trainer_review`, модерация (staff) |
| In-app notification inbox (NotificationsSheet) | New `notification_inbox` + push-token registration |
| Gym-info / hours / occupancy (GymInfoSheet, `data/gym.js`) | New `gym_info` (CMS) + real-time occupancy source |
| Card-on-file + autopay (CardSheet, flag `linkedCard`) | YooKassa saved-methods + `GET /client/payment-method` |
| Loyalty / club bonuses (flag `clubBonuses`) | Balance + Gold-tier + server-authoritative `price_override` + webhook redemption (touches payment path) |
| Booking reschedule (BookingManageSheet calendar) | New `POST /client/booking/{id}/reschedule` endpoint |
| Weekly activity analytics (flag `weeklyActivity`) | Per-day workout-minutes aggregate endpoint |
| Phone-change via OTP | New OTP-based phone-change flow |

## Out of Scope

Explicitly excluded for v2.1 to keep it a low-risk "fill the gaps" milestone.

| Feature | Reason |
|---------|--------|
| All Group B net-new domains (above) | Each needs new tables/services/endpoints (and several need a staff side); out of scope for a flag-flip milestone — separate milestones after the staff-side decision |
| Touching the ЮKassa checkout / activation path | v2.1 must not alter server-authoritative pricing or webhook-only activation; promo chip reuses the existing validated path only |
| Unfreezing / editing `apps/admin-web` | Remains a frozen mock-reference; revisit when a Group B domain that needs a staff side is planned |
| `linkedCard` feature flag | Depends on the deferred card-on-file domain — stays OFF |
