<objective>
Make tags explicit on every router so operations group correctly under their business-domain heading in Redocly preview — no "default" stray folder. Lock the 10-domain order (+ Users as 11th + Internal as 12th/last) in `openapi_tags` at the composition root per **D-64-TAG-ORDER** and **D-64-TAG-INTERNAL**. Resolve the aggregator-tag duplication risk surfaced in PATTERNS.md open-question #1.

Purpose: Redocly preview (Phase 65 dependency) groups operations by their tag. With auto-derived tags from include_router() AND router-level tags both present, operations would get DOUBLE tags (or non-deterministic dedup behavior). Phase 65 Postman `folderStrategy=Tags` also depends on clean per-operation tags.

Output: All 16 module router files + 2 `_internal/*` router files declare explicit `APIRouter(tags=[...])`; aggregator `app/api/v1/router.py` no longer passes `tags=` on `include_router(...)` calls (single source of truth = the router-level tag); `openapi_tags` ordered list in `app/main.py`; regen byte-stable; drift gate green.

**D-64-TAG-USERS resolution (PATTERNS.md open-question #3):** `app/modules/users/router.py` exists (multi-user admin from Phase 43) but is not in the locked 10-domain list. **Decision:** add an 11th `"Users"` tag positioned between `"Auth"` and `"Clients"` in `openapi_tags` ordering. Rationale: users are the operator admins (owner/reception) who manage the rest of the system; tagging them with `Auth` would conflate identity/credential lifecycle with operator management. Documented inline in the openapi_tags definition with `D-64-TAG-USERS`.

Depends on 64-01 because `app/main.py` constructor edits stack on the 64-01 baseline. Sibling of 64-02 (both touch `app/main.py` but on disjoint kwargs — `generate_unique_id_function` vs `openapi_tags`); both committed in Wave 2 sequentially.
