<objective>
Define the 6 shared error response objects (`401_Unauthorized`, `403_Forbidden`, `404_NotFound`, `409_Conflict`, `422_ValidationError`, `429_RateLimited`) in a new `app/core/openapi_responses.py` module per **D-64-RESPONSES-LOCATION**, then migrate inline operation responses to `$ref` via the existing `_customize_openapi()` post-processor (extending the security half from Plan 64-04) per **D-64-RESPONSES-APPLY**.

Purpose: The current spec has every operation declaring its own inline 401/403/422 schemas — they will drift apart as routes get added. Shared `components.responses` + `$ref` is the OpenAPI-idiomatic fix and the Redocly lint will eventually flag inline drift.

Output: New `openapi_responses.py` module mirroring the `LOCKED_AUDIT_EVENTS` registry idiom; extended post-processor; regen byte-stable; drift gate green.
