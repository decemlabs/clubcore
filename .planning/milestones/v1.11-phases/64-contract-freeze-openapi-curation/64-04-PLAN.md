<objective>
Wire OpenAPI `securitySchemes` (cookieAuth + csrfHeader) into the spec via a post-processor on `app.openapi`, then opt public endpoints out via a frozenset-based per-operation `security=[]` override. The `sportzal_csrf` cookie name is documented in the `csrfHeader` description as a known v1.x carry-over per **D-11-CSRF-DEFER** (rename to `clubcore_csrf` deferred to v2.0).

Purpose: Downstream codegen (Phase 65 Postman) needs the spec to declare *how* auth is sent so request templates auto-include the cookie + CSRF header. Without `securitySchemes`, every request appears unauthenticated to Redocly/Postman and the handoff package would be unusable.

Output: `SECURITY_SCHEMES` + `PUBLIC_ENDPOINT_OPERATION_IDS` constants in `app/main.py`; `_customize_openapi()` post-processor (security half — `components.responses` is added in Plan 64-05) wired via `app.openapi = _customize_openapi`; regen byte-stable.

**Depends on:**
- 64-02 (operation IDs must be stable before the public-endpoint allowlist keys on them — `PUBLIC_ENDPOINT_OPERATION_IDS` contains identifiers like `"login"`, `"healthz"` that only exist post-FRZ-02).
- 64-03 (tags drive security defaults — confirming the `Internal` tag is in place lets us opt out `_internal/*` operations cleanly).
</objective>
