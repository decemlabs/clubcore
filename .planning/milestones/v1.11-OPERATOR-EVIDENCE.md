**Captured via:** live `docker compose --profile dev up` against a real Docker daemon (Engine v29.4.3) in the dev environment. Real command output below — no fabrication (D-67-03).

```
$ docker compose config --services

migrate

```
`mailpit` is absent from the default service list. With the default stack partially running (`docker compose ps --services` → `postgres`, `redis`), **no `mailpit` container exists** — the profile gate holds.

### Step B — start under `--profile dev`


### Step C — mailpit Up + web UI loads

```
$ docker compose --profile dev ps mailpit

backend-mailpit-1   axllent/mailpit:latest   "/mailpit"   mailpit   Up (healthy)              0.0.0.0:1025->1025/tcp, 0.0.0.0:8025->8025/tcp

$ curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://localhost:8025/

```

### Step D — cleanup (prior stack untouched)

```
$ docker compose --profile dev rm -sf mailpit

$ docker compose ps --services
postgres
redis                                             # pre-existing stack intact; mailpit gone
```

### Result: PASS

- Default `docker compose` excludes mailpit; `--profile dev` brings it up `healthy` on SMTP **1025** + web UI **8025** (HTTP 200). ✓
- Image is `axllent/mailpit:latest` (running v1.30.1). ✓

### D-67-11 note (mandatory)

Mailpit is a **DEV-ONLY SMTP trap** gated behind `profiles: ["dev"]` — it never starts in a default/production `docker compose up`. The current production email path is **Yandex SES-V2 / aioboto3**, which sends over the SES-V2 HTTP API and is **NOT intercepted by Mailpit**. This profile is forward-wiring for a future SMTP adapter (INFRA-02, deferred per D-11-MAILPIT-PROFILE); **no SMTP adapter was added in this phase**. No secrets appear in the captured output.
