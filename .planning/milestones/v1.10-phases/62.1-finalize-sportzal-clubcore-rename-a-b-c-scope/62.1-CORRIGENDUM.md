# Corrigendum to Phase 62 VERIFICATION (5 -> 6 email_templates count)

## Provenance

This file records a documentation-precision correction to
`.planning/phases/62-clubcore-rebrand/62-VERIFICATION.md`. The imprecision
appears at line 41 (D-62-02 decision-honor row) and at line 60 (Required
Artifacts table row for `apps/backend/app/core/branding.py`), both of which
state the codebase has "5 email_templates.py modules" importing `CLUB_BRAND`.

Per **D-62-09** the Phase 62 artefacts are byte-frozen audit trail; they must
not be edited in place. Per **D-62.1-C1** (the decision that mandated this
corrigendum's content) and **D-62.1-C2** (the decision that ratifies the
corrigendum-as-pattern as **D-62.1-01**), corrections to immutable phase
artefacts are recorded as sibling files in the NEXT phase's folder — never as
in-place edits to the original artefact.

Surfaced by `.planning/v1.10-MILESTONE-AUDIT.md` line 124 (cross-phase
integration section, "One documentation-precision warning") and
`tech_debt[0].items[2]` (line 20 in the frontmatter YAML block).

## Original Claim

> `apps/backend/app/core/branding.py` exists (12 lines,
> `CLUB_BRAND: Final[str] = "Sportzal"`); imported by all 5
> email_templates.py modules (auth/users/memberships/bookings/payments).
> RBAC parity tests + 2185 pytest green confirm zero behaviour change.

*Source: `62-VERIFICATION.md` line 41, D-62-02 decision-honor row.*

A nearly identical claim appears at line 60 of the same document:

> File tracked in git; 12 lines; imported by 5 email_templates.py modules.

## Correction

The codebase has **6** files matching
`apps/backend/app/modules/*/email_templates.py`. The 6th file is
`apps/backend/app/modules/online_payments/email_templates.py`.

It is a **constants-only stub with no Jinja body interpolation** — it
defines template constants (subject lines, payload keys) but does NOT
compose any Russian-language body string that would interpolate `CLUB_BRAND`.
Therefore it correctly does NOT `import` the `CLUB_BRAND` constant from
`app.core.branding`.

The original VERIFICATION count of 5 is correct for the set of files that
interpolate `CLUB_BRAND` in body text. The imprecision is conflating "files
named `email_templates.py`" with "files that import `CLUB_BRAND`". These are
not the same set: all 5 email-body modules import and use `CLUB_BRAND`;
the 6th (`online_payments/email_templates.py`) contains only constants and
has no body interpolation whatsoever.

## Functional Impact

**None.** All `email_templates.py` modules that need `CLUB_BRAND` import it;
the 6th file legitimately does not need it. No missing integration, no broken
email, no test gap. Phase 62 G7-A..L smoke gauntlet (12/12 PASS) is
unaffected.

## Root Cause

Description-only imprecision in the verification narrative: the auditor
counted `import CLUB_BRAND` occurrences and used that count as the file count
for "email_templates.py modules". The two counts happen to agree for the
5 body-interpolating modules but diverge by one when the constants-only stub
is included. Not a missing integration. No code change required.

## Pattern Ratification (D-62.1-01)

This file establishes the **corrigendum-as-pattern** convention now ratified
as project decision **D-62.1-01**.

Future factual inaccuracies discovered in immutable phase artefacts
(`.planning/phases/<N>-*` frozen under D-62-09 or its successors) MUST be
recorded as `<correcting-phase>-CORRIGENDUM.md` in a SUBSEQUENT phase folder
— never as in-place edits to the original artefact. This honors D-62-09's
spirit (audit-trail immutability) while leaving a discoverable correction
trail that future readers can locate by grepping for the corrigendum filename
pattern.

Pattern threshold: if corrigenda accumulate more than 3 files over future
phases, revisit the D-62-09 amendment per the deferred-items block in
`62.1-CONTEXT.md`. That discussion should happen at the point of accumulation,
not in advance.

## Scope

- This corrigendum corrects ONLY the 5-vs-6 count narrative.
- All other claims in `62-VERIFICATION.md` remain accurate.
- The audit's overall PASSED verdict (8/8 requirements, 12/12 smoke gates,
  11/11 locked decisions) is unaffected.
- `apps/backend/app/modules/online_payments/email_templates.py` is the single
  file whose exclusion from the "import CLUB_BRAND" count is correct by
  design; no action is required on that file.
