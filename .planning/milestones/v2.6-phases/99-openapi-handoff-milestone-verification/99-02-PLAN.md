  GET   /api/v1/i/{code}                       (REFER-02 — public resolver)
  GET   /api/v1/client/referral/code           (REFER-01)
  GET   /api/v1/client/referral/summary        (REFER-06)
  POST  /api/v1/client/referral/capture        (REFER-03 — JSON body {code})
  GET   /api/v1/referral/config                (REFER-07 — owner read)
  PUT   /api/v1/referral/config                (REFER-07 — owner write, JSON body {referrerBonusKopecks, refereeWelcomeKopecks})

BODY REALIZATION (arity = 8): TWO of these ops carry a realized JSON requestBody and BOTH should be
guarded as a body (mirrors _v25Checks[3] = _ClientSendMessageBody guarding the POST /messages body):
  - POST /client/referral/capture  → guard ['post']['requestBody']  (ReferralCaptureRequest {code})
  - PUT  /referral/config          → guard ['put']['requestBody']   (ReferralConfigUpdateRequest, two ints)
Both are application/json bodies that openapi-typescript realizes as a non-never type (NOT multipart,
NOT body-less). GET ops and the public resolver have no body → guard the operation only.
=> 6 operation guards + 2 body guards = 8 entries; toHaveLength(8).
(Phase 95 precedent: D-95-02-GUARD-7 guarded only the single POST JSON body and skipped the multipart
upload body to avoid a false `never`; here both v2.6 bodies are JSON so both realize.)
