# Requirements: Sportzal — v1.8 Reports + Audit Log read API

**Defined:** 2026-05-24
**Core Value:** Соло backend-разработчик с AI-агентами должен уметь поэтапно наращивать бизнес-фичи зала на стабильном, архитектурно ограниченном каркасе — без переписывания структуры по мере роста.
**Milestone goal:** Read-side backend для аналитики зала + аудита действий — агрегированные отчёты поверх существующих ledger/clients/visits таблиц + фильтруемый read API над пишущимся `audit_log`, с CSV-экспортом. Никаких новых бизнес-сущностей; read-only over v1.4–v1.7 data.
**Phase numbering:** v1.7 ended at Phase 53 → v1.8 continues at **Phase 54**.

## v1.8 Requirements

### Foundations (INFRA)

- [ ] **INFRA-41**: Новый `app/modules/reports/` module scaffold зарегистрирован в `.importlinter` `modules-independent`; read-only дисциплина (нет write-путей — SVC001 commit-gate не применяется, но модуль не выполняет INSERT/UPDATE/DELETE по бизнес-таблицам)
- [ ] **INFRA-42**: `Resource.REPORTS` + `Resource.AUDIT_LOG` + `Action.READ`/`Action.LIST` добавлены в backend enums; соответствующие owner-only пары в `OWNER_ONLY` frozenset, mirrored byte-for-byte в admin-web `can.ts` + `registry.ts` (three-way parity test green)
- [ ] **INFRA-43**: Aggregation-индексы под отчёты и фильтры (Alembic): `payments(received_at)`, `audit_log(created_at)`, `audit_log(action)`, `audit_log(resource_type)` (или композиты по плану запросов); миграция round-trips clean, `alembic check` green

### Revenue report (REV)

- [ ] **REV-01**: Owner может получить выручку за период с разбивкой по дням (`GET /api/v1/reports/revenue?from=&to=&groupBy=day`)
- [ ] **REV-02**: Owner может получить выручку с разбивкой по месяцам (`groupBy=month`)
- [ ] **REV-03**: Выручка разбивается по методу оплаты (`cash` / `online`)
- [ ] **REV-04**: Выручка разбивается по `subject_kind` (`membership` / `pt_package`); возвраты учитываются как signed amounts (net revenue корректен — refund-строки v1.4 ledger вычитаются)
- [ ] **REV-05**: Все денежные значения — integer kopecks; day/month-бакеты детерминированы по Europe/Moscow (как `visits.gym_date STORED` / cron-окна)

### Clients report (CLR)

- [ ] **CLR-01**: Owner может получить число активных абонементов на текущий момент (`GET /api/v1/reports/clients`)
- [ ] **CLR-02**: Owner может получить число абонементов, истекающих в окне N дней (параметр `within`, 1..30, default 7 — паритет с v1.3 expiring-soon)
- [ ] **CLR-03**: Owner может получить число новых клиентов за период (`from`/`to` по `clients.created_at` в Europe/Moscow)
- [ ] **CLR-04**: Все счётчики clients report исключают soft-deleted строки (`deleted_at IS NULL`)

### Visits report (VIS)

- [ ] **VIS-R-01**: Owner может получить число посещений по дням за период (`GET /api/v1/reports/visits?from=&to=`)
- [ ] **VIS-R-02**: Owner может получить посещения с группировкой по часу суток (пиковые часы)
- [ ] **VIS-R-03**: Owner может получить среднюю посещаемость за период (visits / число дней)
- [ ] **VIS-R-04**: Все visits-бакеты используют `visits.gym_date` (STORED Europe/Moscow) — без повторного TZ-преобразования в запросе

### Audit Log read API (AUD)

- [ ] **AUD-01**: `GET /api/v1/audit-log` owner-only; возвращает пагинированный `{items, total, page, pageSize}` (контракт проекта — не голый массив)
- [ ] **AUD-02**: Фильтр по actor — `actorUserId` и/или `actorEmailSnapshot` (substring/exact по `actor_email_snapshot`)
- [ ] **AUD-03**: Фильтр по resource (`resource_type`) и по event-kind (`action`, значение из 69-event `LOCKED_AUDIT_EVENTS`)
- [ ] **AUD-04**: Фильтр по time-window (`from`/`to` по `created_at`, интерпретация в Europe/Moscow)
- [ ] **AUD-05**: reception получает 403 на любой `/audit-log` и `/reports/*` запрос (RBAC `Depends(require_permission)` + route-introspection guard покрывает новые маршруты)
- [ ] **AUD-06**: Результаты упорядочены детерминированно (`created_at DESC, id DESC` tiebreak) — стабильная пагинация

### CSV export (EXP)

- [ ] **EXP-01**: CSV-экспорт revenue report (`GET /api/v1/reports/revenue.csv` или `?format=csv`) через `StreamingResponse`, owner-only
- [ ] **EXP-02**: CSV-экспорт audit-log с теми же фильтрами, что и JSON-эндпоинт, owner-only
- [ ] **EXP-03**: CSV-экспорт clients + visits reports
- [ ] **EXP-04**: CSV корректно кодирует кириллицу для Excel (UTF-8 BOM) + RFC 4180 escaping (кавычки/запятые/переводы строк); деньги — рубли с разделителем, дата — Europe/Moscow

### OpenAPI handoff (HND)

- [x] **HND-01**: Byte-stable atomic regen `apps/backend/openapi.json` + `packages/api-client/src/schema.d.ts`, экспонирующий все v1.8 пути (reports/* + audit-log + CSV variants); CI `git diff --exit-code` green на обоих артефактах
- [x] **HND-02**: `packages/api-client/src/schema.contract.test.ts` расширен `AssertNonNever` forward-guards для v1.8 путей (+ runtime count assertion по дисциплине каждого milestone)

### Milestone verification (VER)

- [x] **VER-01**: Operator runbook — сценарии reports + audit read API против live `docker compose up` стека (revenue golden-path с известными суммами, audit фильтрация, reception 403, CSV download)
- [x] **VER-02**: Корректностные/race тесты — агрегаты сверены с детерминированными фикстурами (kopecks net-of-refund; Europe/Moscow day-buckets; visits hour-buckets); пагинация audit-log стабильна; RBAC-denial покрыт
