**BAK-01 CNPG `Cluster.spec.backup.barmanObjectStore` (in-tree, postgresql.cnpg.io/v1) — verified field shape:**
```
spec:
  backup:
    barmanObjectStore:
      destinationPath: s3://<bucket>/postgres        # s3:// URL into the SeaweedFS bucket
      endpointURL: http://<release>-seaweedfs-s3:8333 # SeaweedFS in-cluster S3 endpoint
      s3Credentials:
        accessKeyId:
          name: <existing S3 secret>
          key: S3_ACCESS_KEY_ID
        secretAccessKey:
          name: <existing S3 secret>
          key: S3_SECRET_ACCESS_KEY
      wal:
        compression: gzip
      data:
        compression: gzip
    retentionPolicy: "30d"
```
The daily base backup is a SIBLING `ScheduledBackup` CR (postgresql.cnpg.io/v1): `spec.schedule` (6-field cron, e.g. `"0 0 2 * * *"`), `spec.cluster.name: <cluster>`, `spec.backupOwnerReference: self`, `spec.method: barmanObjectStore`. WAL archiving begins automatically once `barmanObjectStore` is present.

**Existing S3 secret to reuse (NEVER mint new):** the app reads S3 creds from keys `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` in `clubcore-app-secret` (app-secret.yaml:85-86), sourced from `.Values.secrets.s3AccessKeyId` / `.Values.secrets.s3SecretAccessKey`. The SeaweedFS S3 endpoint service is `<release>-seaweedfs-s3:8333` (values.yaml `config.s3EndpointUrl` auto-derive). The bucket is `config.s3Bucket: clubcore`. Use these exact coordinates — reference the existing app-secret via `secretKeyRef`.

**Restore to scratch (BAK-04):** CNPG restores via a NEW Cluster with `spec.bootstrap.recovery` from an `externalCluster`/`barmanObjectStore` source into a SCRATCH namespace/cluster name — NEVER `spec.bootstrap.recovery` on the live cluster. The verify CronJob creates a scratch Cluster, waits for it healthy, runs a row-count query, compares, then deletes the scratch cluster.
