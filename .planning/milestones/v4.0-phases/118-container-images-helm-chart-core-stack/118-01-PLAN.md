<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public base image registry → build | Upstream `ghcr.io/astral-sh/uv`, `python:3.12-slim-bookworm`, `node:20-alpine`, `nginx:1.27-alpine` are untrusted supply-chain inputs |
| build context → image layers | Source tree (incl. `.env*`, secrets) could be copied into a layer if `.dockerignore` is wrong |
| browser → frontend nginx | Static asset + SPA fallback serving; SW cache of authed `/api/*` data is a leak vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-01 | Tampering | base images (4 upstream) | mitigate | Pin all base images by `@sha256:` digest (IMG-01) — digest mismatch breaks the build, preventing a swapped/poisoned tag |
| T-118-02 | Tampering | npm/pip/apt installs in build | mitigate | `uv sync --frozen` (lockfile-pinned) + `pnpm install --frozen-lockfile`; trivy HIGH/CRITICAL gate (IMG-04) blocks vulnerable transitive deps |
| T-118-03 | Information Disclosure | image layers | mitigate | `.dockerignore` excludes `.env*`, `.git/`, `tests/`; no `ENV`/`COPY` of any secret; `docker history` asserted secret-free |
| T-118-04 | Elevation of Privilege | runtime containers | mitigate | All images run `USER app` / `USER nginx` (non-root); nginx listens on unprivileged `:8080` — prep for SEC-03 securityContext in Phase 119 |
| T-118-05 | Information Disclosure | PWA service worker | mitigate | client-pwa nginx sets `no-cache` on sw.js/manifest and `no-store` on `/api/*` (P10) so authed API data is never persisted in the SW cache |
| T-118-SC | Tampering | container base/dep supply-chain | mitigate | trivy `--severity HIGH,CRITICAL --exit-code 1` gate (IMG-04); no `:latest` tags (git-SHA pinned). No new npm/pip PACKAGES are added in this phase (deps already in `uv.lock`/`pnpm-lock.yaml`); Package Legitimacy Gate is N/A — no new installs. |
</threat_model>
