Map every backend configuration variable into a ConfigMap (non-sensitive) / Secret (sensitive) split, and author the Alembic migrate Job as a Helm `pre-install,pre-upgrade` hook that runs `alembic upgrade head` BEFORE any app pod starts — the structural fix for the migrate-races-API pitfall (P4).

Output: ConfigMap + Secret + SeaweedFS-S3 Secret + migrate hook Job templates.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ConfigMap vs Secret | A sensitive value placed in a ConfigMap is world-readable to anything that can `get configmap` — a real disclosure boundary |
| migrate hook → database schema | The migrate Job has write authority over the entire schema; a failed/partial run can corrupt startup |
| values.yaml plaintext secrets → git | Local-k3d plaintext secret defaults could be committed and mistaken for production config |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-10 | Information Disclosure | ConfigMap | mitigate | Hard split: SECRET_KEY/DATABASE_URL/tokens/keys ONLY in Secret objects; `helm template` asserted to show NO sensitive key in `clubcore-config` (APP-05 block-worthy gate) |
| T-118-11 | Tampering | migrate Job race | mitigate | P4 invariant: `pre-install,pre-upgrade` hook + weight `-5` runs migrations to completion BEFORE any app pod; `backoffLimit: 0` prevents a half-applied migration from silently retrying; `activeDeadlineSeconds: 300` bounds a hung migration; Postgres-wait initContainer prevents premature start |
| T-118-12 | Information Disclosure | plaintext secret defaults | mitigate | `app-secret.yaml` + values carry an explicit "local-k3d ONLY / Phase-119 SealedSecret replacement" comment; no live value is shipped; Phase 119 SEC-01 seals them |
| T-118-13 | Spoofing | SeaweedFS S3 identity | mitigate | The S3 Secret identities match the backend S3 creds exactly so `enableAuth: true` authenticates the real client and rejects others |
| T-118-SC | Tampering | image used by migrate Job | mitigate | Job uses the same git-SHA-pinned `clubcore/backend` image that passed the plan-01 trivy gate; no separate image, no `:latest`. No new packages — Package Legitimacy Gate N/A. |
</threat_model>
