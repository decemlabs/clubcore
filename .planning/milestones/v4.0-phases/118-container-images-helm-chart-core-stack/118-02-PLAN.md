<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chart values → rendered manifests | A secret placed in a ConfigMap or values default could leak in `helm template`/git |
| operator (CNPG) → cluster | The CNPG operator runs privileged; trusting `ghcr.io/cloudnative-pg` images is a supply-chain decision |
| StorageClass → PVC lifecycle | `reclaimPolicy: Delete` (the local-path default) would silently destroy DB data on PVC removal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-06 | Tampering | CNPG/Redis/SeaweedFS images | mitigate | CNPG `ghcr.io/cloudnative-pg/postgresql:16.x` pinned by version; `redis:7-alpine` plain (no Bitnami paywalled images); SeaweedFS via official chart 4.33.0 — no `bitnamilegacy` anywhere (DATA-01) |
| T-118-07 | Information Disclosure | Postgres app-user Secret | mitigate | Credentials live in a `kubernetes.io/basic-auth` Secret (not a ConfigMap); the plaintext local-k3d value is explicitly flagged for Phase-119 SealedSecret replacement; never committed to a live path |
| T-118-08 | Denial of Service (data-loss) | PVC reclaim on local-path | mitigate | StorageClass `reclaimPolicy: Retain` + Postgres `nodeSelector` pinning (DATA-04 P1) so the PV is never auto-deleted and the volume never strands on a node mismatch |
| T-118-09 | Tampering | SeaweedFS S3 anonymous access | mitigate | `s3.enableAuth: true` with `existingConfigSecret` — anonymous writes blocked; same identity model as the dev `s3.json` |
| T-118-SC | Tampering | Helm subchart supply-chain | mitigate | SeaweedFS dependency pinned to exact `version: "4.33.0"` from the official repo; `helm dependency build` vendors it; no floating version range. No new npm/pip/cargo PACKAGES — Package Legitimacy Gate N/A. |
</threat_model>
