<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migrate hook → backend startup | A backend that starts before migrations complete races the schema (P4) |
| worker rollout overlap → external systems | Two arq-workers = duplicate cron side-effects; two telegram-bots = duplicate message consumption |
| local k3d registry → cluster | Images imported into k3d are the same SHA-pinned, trivy-scanned artifacts from plan 01 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-14 | Tampering | backend schema race | mitigate | `alembic check` initContainer on the backend Deployment exits non-zero if migrations are pending — belt-and-suspenders on top of the plan-03 pre-install hook (P4); readinessProbe keeps the pod out of rotation until healthy |
| T-118-15 | Repudiation / DoS | arq-worker cron double-fire | mitigate | `strategy: Recreate` + fixed `replicas: 1` (P2) — no rollout overlap, no second scheduler; replicas is not a user-overridable knob |
| T-118-16 | DoS | telegram-bot long-poll double-consume | mitigate | `strategy: Recreate` + fixed `replicas: 1` (P3) — exactly one long-poll consumer at all times |
| T-118-17 | Tampering | privileged container runtime | accept (this phase) | securityContext stubs (non-root) are present; full `readOnlyRootFilesystem`/drop-ALL-capabilities hardening is Phase 119 SEC-03 — accepted as deferred-by-design within the milestone |
| T-118-SC | Tampering | image provenance into k3d | mitigate | `deploy-local.sh` imports only the git-SHA-tagged images that passed the plan-01 trivy gate; no `:latest`, no external pull at deploy time. No new packages — Package Legitimacy Gate N/A. |
</threat_model>
