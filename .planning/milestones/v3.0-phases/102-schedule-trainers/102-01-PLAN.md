<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser admin-app → staff API (`/api/v1/*`) | Untrusted client input (slot/template/time-off bodies, force flag) crosses here over `staffRequest` (sz_* cookies + X-CSRF-Token). |
| UI can()-gate → backend RBAC | can() FAB/modal gating is defense-in-depth ONLY; backend OWNER_ONLY is the authority for slot/template/time-off mutations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-102-IDOR | Elevation/Info | slot/template/time-off mutations by id | accept (UI) / mitigate (backend) | UI sends ids only; backend is authoritative on ownership and OWNER_ONLY. No client-side authorization trust. can()-gate on FAB is UX, not security. |
| T-102-IDEM | Tampering | publish/cancel slot, create/deactivate template, create/delete time-off | mitigate | `crypto.randomUUID()` Idempotency-Key generated INSIDE each mutationFn at submit time (fresh per attempt) — prevents double-publish/double-block on retry. Verified by api.test.ts. |
| T-102-FORCE | Tampering/Repudiation | time-off `force=true` cascade (cancels bookings) | mitigate | force=true is NEVER the default path. It requires an explicit second user action (the «Заблокировать принудительно» danger button) shown only after a 409 conflict, with explicit counts of affected bookings/slots. No accidental force. |
| T-102-PII | Info disclosure | error Callouts/toasts | mitigate | Error copy is a fixed Russian ERROR_COPY map keyed by ApiError.code; raw backend message only as fallback. Conflict state shows counts, not client names/PII. |
| T-102-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies introduced (reuses zod, @tanstack/react-query, sonner already in package.json). No install task → supply-chain gate N/A. |
</threat_model>
