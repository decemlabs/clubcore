<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser admin-app → staff API `/api/v1/payroll/*` | Comp-config + accrual + mark-paid requests cross here; ALL endpoints are OWNER_ONLY (backend authority). Money values (kopecks/bps) cross here. |
| reception session → payroll surface | Reception must never reach payroll data; gated in UI AND backend. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-102-PAY-RBAC | Elevation/Info | all payroll endpoints (owner-only) | mitigate (defense-in-depth) | Reception gated BEFORE any hook fires (`if (!can(role,'view','payroll')) return <Lock EmptyState>`); every hook additionally `enabled: can(...)` so NO payroll request is issued for reception. Backend OWNER_ONLY 403 is the authority. Test asserts zero staffRequest calls for reception. |
| T-102-PAY-MONEY | Tampering | comp-config kopecks/bps conversion + accrual amounts | mitigate | All wire amounts are integer kopecks (sessionFeeKopecks) and bps (commissionPctBps); display divides by 100, send uses `Math.round(rubles*100)`/`Math.round(pct*100)` so no float drift reaches the wire; zod schemas enforce `.int()` ranges. Test asserts the PUT body integer kopecks. |
| T-102-PAY-VERSION | Tampering/Repudiation | comp-config PUT | mitigate | PUT is INSERT-only versioned per the backend contract — each save creates a new immutable version (never an in-place UPDATE); the UI calls PUT once per explicit save and refetches the active version. No silent overwrite of history. |
| T-102-PAY-TERMINAL | Tampering | accrual run + mark-paid double-submit | mitigate | Accrual run guarded by 409 `payroll_period_already_run` (append-only, period-unique) → handled calmly, preview cleared. Mark-paid is terminal: 409 `already_paid` → friendly toast + refetch (no double-pay, no crash). |
| T-102-PAY-PII | Info disclosure | error states | mitigate | Fixed Russian copy keyed by ApiError.code; no raw backend payload or other-trainer financial data echoed. |
| T-102-PAY-SC | Tampering | npm installs | mitigate | No new dependencies. Supply-chain gate N/A. |
</threat_model>
