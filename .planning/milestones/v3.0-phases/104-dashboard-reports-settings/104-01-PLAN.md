<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → backend (cookie auth) | All `staffRequest`/`downloadCsv` calls cross here; auth is HttpOnly cookie + CSRF cookie |
| arbitrary JSONB `payload` → React render | audit `payload` is server-controlled but arbitrary; rendered downstream (Wave 2) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-01 | Information Disclosure | `useAuditLog`, `useClientsReport`, `useTrainersReport` (owner-only data) | mitigate | `enabled: can(role,'view',<resource>)` gates the query so reception fires ZERO owner-only calls; backend authoritative — UI gate is defense-in-depth. |
| T-104-02 | Information Disclosure | `downloadCsv` URL | mitigate | No token/secret in URL — auth is cookie via `credentials:'include'`; query carries only filter/date params. GET, CSRF-exempt. |
| T-104-03 | Tampering | audit `payload` (JSONB) schema | mitigate | `z.record(z.unknown()).nullable()` parses without trusting shape; never `eval`/`dangerouslySetInnerHTML` — Wave 2 renders as escaped text/JSON.stringify only. |
| T-104-SC | Tampering | npm/pnpm installs | accept | No new dependencies added in this plan (reuse zod, @tanstack/react-query already in lockfile). No install task → no slopcheck checkpoint required. |
</threat_model>
