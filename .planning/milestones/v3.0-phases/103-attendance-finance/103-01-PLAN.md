## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin-app UI → staff API | Untrusted staff input (clientId, date ranges, filter params) crosses to the backend over `staffRequest` (cookies + X-CSRF-Token). |
| reception role → owner-only endpoints | RBAC boundary — reception must make ZERO calls to `/reports/*` and global `/payments`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-103-01-RBAC | Elevation of Privilege | usePaymentsLedger / useVisitsReport / useRevenueReport | mitigate | `enabled: can(role,'view',{payments|reports})` — query never fires for reception (UI defense-in-depth). Backend remains the authority (403 if bypassed). Reception fires zero owner-only calls. |
| T-103-02-IDOR | Information Disclosure | useVisitsList (clientId filter) / usePaymentsLedger | accept (UI) / mitigate (backend) | UI passes filter params verbatim; backend authoritatively scopes visit/payment access by id. No client-side id-trust assumption is made. |
| T-103-03-409BYPASS | Tampering | useCheckIn | mitigate | The 3 server-enforced 409s (outside_gym_hours / no_active_membership / duplicate_checkin) are NOT swallowed or auto-retried by the hook; optimistic row is rolled back and the raw ApiError.code is re-thrown to the caller. duplicate_checkin is a DB-UNIQUE (1/day) — UI never bypasses it. |
| T-103-04-MONEY | Tampering | RevenueBucketSchema / PaymentSchema | mitigate | All amounts parsed as integer kopecks; `netKopecks`/`amountKopecks` are signed numbers (refunds negative). No float kopeck math; no rounding in the data layer. |
| T-103-SC | Tampering | npm installs | mitigate | NO new packages added. `date-fns-tz` explicitly NOT introduced (utils use already-installed `date-fns`). Zero install surface this plan. |
</threat_model>
