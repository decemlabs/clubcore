## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA service worker → cached storage | SW may persist responses to the Cache Storage API on the client device |
| PWA browser → /api/v1/client/* | Authed requests carrying cc_client_* cookies cross to the backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-69-07 | Information Disclosure (stale authed data via SW cache) | vite-plugin-pwa / service worker | mitigate | PWA-07: VitePWA config sets `navigateFallbackDenylist: [/^\/api\//]` and `workbox.runtimeCaching: []` — the SW NEVER caches `/api/*`. Asserted by grep in Task 1 + build emits SW with no API runtime-caching rule. |
| T-69-08 | Spoofing (CSRF on state-changing client requests) | clientFetcher.ts | mitigate | clientFetcher reads the `clubcore_client_csrf` cookie (client-scoped, isolated from staff `clubcore_csrf` per CISO-05) and attaches it as the CSRF header on unsafe methods, mirroring the staff fetcher contract. |
| T-69-09 | Tampering / session-fixation (wrong refresh endpoint) | clientRefreshOnce | mitigate | Refresh single-flights to `/api/v1/client/session/refresh` (NOT the staff `/api/v1/auth/refresh`); asserted absent staff URL in Task 2. Prevents cross-principal cookie rotation. |
| T-69-10 | Information Disclosure (offline cache of owned data) | offline-first caching | accept | Offline-first deferred to Future OFFL-01; this phase ships installable shell only, no owned-data precache. No authed payload is precached. |
</threat_model>
