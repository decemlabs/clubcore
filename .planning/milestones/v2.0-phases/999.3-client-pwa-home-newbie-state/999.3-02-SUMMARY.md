## What Was Built

**`deriveOnboardingSteps(me, homeData, bookings)`** — exported pure helper, null-safe. Returns `{ steps, doneCount, title, badge }`:
- Step 1 Аккаунт: always `done`
- Step 2 Абонемент: always `next` (single source of truth for the `.step.next` marker)
- Step 3 Профиль: `done` iff `me.birthday && me.gender` (per critical_resolution — birthday+gender instead of photo/height/weight which do not exist on the model)
- Step 4 Первый визит: `done` iff any booking (bookings.total > 0 OR items.length > 0 OR homeData.nextBooking != null)
- doneCount: count of `done` steps (the `next` step is NOT counted)
- badge: `${doneCount} / 4`; title: `Ещё ${4 - doneCount} шага до полного старта`

**Newbie components** (all named exports in HomeScreen.jsx):
- `HeroNewbie({ onOpenPlans })` — dark hero card with pulse eyebrow dot, title "Остался один шаг до зала", CTA "Выбрать абонемент" → onOpenPlans
- `OnboardingStrip({ steps, doneCount, title, badge, onOpenPlans, onTab })` — dismissible card reading `.step` / `.step.done` / `.step.next` from helper output; horizontal-scrolling chips; progress bar via `.progress-track` / `.onboard-fill`; dismiss triggers `@keyframes onboard-collapse` (360ms) → session-scoped `dismissed` state
- `FirstVisitNudge({ onTab })` — dashed-border tappable row → onTab('book')
- `QrPlaceholder()` — static non-interactive div (no onClick, no `.press`), `role="img"`, lock icon
- `HomeNewbie({ me, homeData, bookings, userName, greeting, onOpenPlans, onOpenGymInfo, onTab })` — top-level composer with `.stagger` container; header as first stagger child

**Render gate** in `HomeScreen`: `homeData?.membershipState === 'newbie'` → render `<HomeNewbie>`; else render shared header + existing variant dispatch (classic/qr-hero/minimal) unchanged.

**CSS tokens** added to styles.css: `.step`, `.step.done`, `.step.next`, `.onboard-fill`, `@keyframes onboard-collapse`, `.onboard-card.dismissing`.

**Icon**: `lock` (padlock) added to Icon.jsx, mirroring the `card` entry shape.

**Type**: `membershipState: 'active' | 'newbie' | 'lapsed'` added to `HomeData` interface in clientQueries.ts.

## Deviations from Plan

### Accepted Trade-offs (pre-documented in plan)

**1. [Accepted] Animation stagger timing ~0.02s deviation**
- Pre-documented in `<accepted_tradeoffs>`: the existing `.stagger` container delays (0.02/0.06/0.10/0.14/0.18s) differ from UI-SPEC's 0/0.05/0.10/0.15/0.20s. Delta ≤ 0.02s, imperceptible. Reused `.stagger` to avoid new `.d1..d4` classes per PATTERNS.md.

**2. [Accepted] Step 3 meta override from critical_resolution**
- `Дата рождения, пол` (NOT `Фото, рост, вес`) — per the plan's `<critical_resolution>`: photo/height/weight fields do not exist on `ClientMeResponse`. This is binding.

### Auto-fixed during development

**3. [Rule 1 - Bug] visitDone logic used ?? instead of independent OR clauses**
- Found during Task 1 GREEN phase: `bookings.total ?? bookings.items.length` would never check items.length when total was 0 (0 is not null/undefined). Fixed to independent `||` clauses.
- Fix: `(bookings?.total ?? 0) > 0 || (bookings?.items?.length ?? 0) > 0 || homeData?.nextBooking != null`

### Out of scope (pre-existing)

- Duplicate `background` key warning in pre-existing `HomeMinimal` component (line ~936). Pre-existing issue, unrelated to this plan. Logged here; not fixed (out of scope per SCOPE BOUNDARY rule).
