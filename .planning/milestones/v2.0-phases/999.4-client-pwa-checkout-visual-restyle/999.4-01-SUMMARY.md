# Phase 999.4 Plan 01: promo_codes Backend Module — Models, Migration, Seeds Summary

**One-liner:** PromoCode + PromoRedemption ORM models with partial-UNIQUE index, Alembic migration 0046, idempotent demo seeds (FIT10 percentage / FIRST500 fixed), and import-linter boundary registration.

## What Was Built

Created the `promo_codes` backend module as the data foundation for real promo codes (D-02). Three tasks executed:

**Task 1 — ORM Models**
- `PromoCode(Base, UUIDPkMixin, TimestampMixin, SoftDeleteMixin)`: code, discount_type, discount_value (integer kopecks/percent*100), max_uses, per_client_limit, valid_from/until, is_active, applicable_to
- Two CHECK constraints (discount_type IN clause, discount_value > 0); partial UNIQUE index `uq_promo_codes_code_alive` on `upper(code)` WHERE deleted_at IS NULL
- `PromoRedemption(Base, UUIDPkMixin)`: append-only ledger with three RESTRICT FKs (promo_code_id, client_id, online_payment_id), discount_kopecks, redeemed_at; UNIQUE(online_payment_id) enforces one-redemption-per-payment

**Task 2 — Alembic Migration**
- `0046_promo_codes.py` with `down_revision = "0045_visits_channel_client_qr"`
- Creates both tables with all constraints; partial UNIQUE index created with literal name (not via `op.f()`) per 0034/0037 precedent
- Round-trip tested: upgrade → downgrade -1 → upgrade head — all clean; single alembic head

## Decisions Made

1. **PromoRedemption append-only composition** — Base+UUIDPkMixin only (no TimestampMixin), matching `online_refunds/models.py` discipline. The single temporal column (`redeemed_at` with `server_default=func.now()`) provides the timestamp without the full TimestampMixin (created_at + updated_at) overhead for a ledger that is never updated.

2. **import-linter Option B (direct ignore edges)** — Chose direct ignore edges over Protocol slot per plan guidance. Forward-safe: edges registered now for `promo_codes.service` which ships in Plan 02; `unmatched_ignore_imports_alerting = warn` keeps build green during the gap.

3. **discount_value encoding** — `'percentage'` stored as `percent * 100` integer (10% → 1000). `'fixed'` stored in kopecks (500₽ → 50000). Neither path uses float at any layer.
