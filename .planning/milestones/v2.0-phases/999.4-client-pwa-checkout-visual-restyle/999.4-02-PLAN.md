payment-status response carries `receiptUrl` when a succeeded fiscal receipt exists.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (PWA) → POST /promo/validate | Untrusted: code string + kind + planId. NO price is accepted from client. |
| client_portal.service → promo_codes / membership_plans / pt_package_plans | In-process cross-module read; price authority stays server-side. |
| client_portal.service → fiscal_receipts (receipt_url) | In-process read-only SELECT; receipt URL constructed server-side from the stored ЮKassa receipt id, only for succeeded receipts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-999.4-04 | Tampering | discount/price tampering | mitigate | Server reads plan price + computes discount; client passes only the code (D-06). No amount field accepted in the request schema. |
| T-999.4-05 | Information Disclosure | promo code enumeration via distinct error messages | accept | D-09 explicitly accepts distinct per-reason messages for this single-gym pet-project; documented accepted risk. No rate-limit added (out of scope, single-gym). |

| T-999.4-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed. |
