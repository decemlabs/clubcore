<objective>
Close the UAT blocker that traps every unauthenticated PWA load in an infinite redirect loop and prevents reaching any wired screen.

The PWA has no real client login and no `/login` route. On load, `useClientHome()` → `GET /client/home` 401 → single-flight `POST /client/session/refresh` 401 → `clientFetcher` throws `ApiError('session_expired')` → `queryClient.ts` does `window.location.replace('/login')` → App.jsx has no `/login` route → catch-all `* → <Navigate to="/home">` → re-fires `useClientHome()` → loop. The OTP screen in `flows.jsx` is a pure mock and never authenticates.

This plan delivers a real client login (OTP request+verify against the existing Phase-68 `/api/v1/client/otp/*` endpoints), an auth context that bootstraps via a `GET /client/me` probe, a react-router-based auth guard, and replaces the `window.location` hard-redirect with a router-friendly session-expiry signal — breaking the loop end-to-end.

Purpose: Without authentication the entire phase is untestable (all three HUMAN-UAT items are blocked). This restores a usable authenticated state so checkout + wired screens can be exercised.

Output: Login screen + auth context + auth guard + loop fix; client can authenticate and reach /home, session expiry returns to login cleanly.
</objective>

- POST /api/v1/client/otp/request  body: { phone: string }                → 202 ResponseEnvelope[None]
  Anti-oracle: byte-identical 202 for known/unknown/unlinked phones (T-68-22).
- POST /api/v1/client/otp/verify   body: { phone: string, code: string }  → 200 ResponseEnvelope[None]
  On success sets cc_client_access / cc_client_refresh / clubcore_client_csrf cookies.
  Invalid/expired code → non-200 ApiError (surface inline; the verify path is itself
  CLIENT_AUTH_EXEMPT so a 401 here is a wrong-code, not a session-refresh trigger).
- GET  /api/v1/client/me            → 200 ResponseEnvelope[ClientMeResponse]  (authed)
                                     → 401 when no/expired session (probe signal).
  /client/me is in CLIENT_AUTH_EXEMPT_PATHS — a 401 from it does NOT trigger

  ApiError('<code>') from the 401 body. Treat any thrown error from the probe as anon.
