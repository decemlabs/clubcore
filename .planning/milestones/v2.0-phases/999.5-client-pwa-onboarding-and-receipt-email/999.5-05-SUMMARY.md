## Accomplishments

- Built `ReceiptEmailGate.jsx` matching the `receipt-email.html` mockup: email field with regex validation, 4 domain-suggestion chips (gmail.com, yandex.ru, mail.ru, icloud.com), 54-FZ `.note` block, «Продолжить к оплате» (disabled when empty/invalid, spinner while saving) and «Чек не нужен» CTAs

- Added `useUpdateClientEmail` mutation (PATCH /client/me {email}, invalidates me()) and extended `PaymentStatusData` with `receiptEmail`/`receiptPhone`; added domain-chip, `.note`, `.done-flash` CSS primitives

## Decisions Made

- **D-02/D-03 gate logic:** Conditional on `clientMe.email` empty/present — the gate is never shown twice in the same session because the mutation invalidates `clientPortalKeys.me()`, so next load reads the saved email
- **UI-SPEC Note 9:** The `done-flash` CSS is added for completeness but NOT used in the primary flow — checkout proceeds directly to paying after saving; `PaymentSucceededView` is the canonical receipt confirmation
- **Anti-oracle preserved:** `receiptEmail`/`receiptPhone` block lives strictly inside `status === 'succeeded'` branch; backend (Plan 02 T-999.5-09) also only populates these on succeeded — two independent gates (T-999.5-16)
- **«Чек не нужен» is honest:** Per D-10/T-999.5-18, the skip path routes to a real 54-FZ phone receipt via ЮKassa `customer.phone`; it is not a silent no-receipt escape
