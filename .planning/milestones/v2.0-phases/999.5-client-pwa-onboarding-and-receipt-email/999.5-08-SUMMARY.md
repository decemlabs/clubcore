# Phase 999.5 Plan 08: Phone-Only Webhook Fiscalization Summary

One-liner: Closed UAT-12 Issue 2 (BLOCKER) end-to-end — a «Чек не нужен» phone-only client (email NULL) who completes a real ЮKassa payment now gets a 200 webhook, succeeded flip, activated membership, and a phone-carrying fiscal receipt fiscalized to the phone, instead of a permanent HTTP 500 / stuck-`pending`.

## What Was Built

### Task 1 — Webhook reads email-OR-phone (TDD: RED in same commit, commit fa2eba15)
- Replaced `_read_customer_email(session, client_id) -> str` (narrow `SELECT Client.email`, raised `RuntimeError` when email was NULL — encoding the obsolete Phase-49 PAY-06 invariant) with `_read_client_receipt_contact(session, client_id) -> tuple[str | None, str]`: a local twin of `online_payments/service.py::_read_client_receipt_contact_or_raise` (`SELECT Client.email, Client.phone WHERE id=:id AND deleted_at IS NULL`; no cross-module import — D-54-08). It returns `(email_or_None, phone)` and raises `RuntimeError` only when the row is genuinely missing (orphaned `client_id` still rolls back for ЮKassa retry) — never merely because email is NULL. Docstring cites D-10 (Phase 999.5) and retires PAY-06.
- Call site (handlers.py ~426): `customer_email, customer_phone = await _read_client_receipt_contact(...)`.
- `insert_fiscal_receipt(...)` now also passes `customer_phone=(customer_phone if customer_email is None else None)` — email-preferred-else-phone, never both (mirrors create_payment contact routing). With the NULL-email RuntimeError gone, the phone-only UoW commits.
- Contact is still NEVER added to a `_log`/`audit.emit` structlog kwarg in handlers.py (PII discipline preserved).
- Test harness: `_seed_client(..., phone_only=True)` now persists `email=NULL` (no coercion to a default); added `seeded_online_payment_pending_phone_only` fixture and a `client_phone` field on `SeededOnlinePayment`. New `test_wh07_phone_only_succeeded.py`: 4 tests — phone-only UoW completes (200 + succeeded + membership + ledger), fiscal_receipts row has email NULL + phone set (status='sent', kind='payment'), email-path regression (email set + phone NULL), and phone never logged.

### Task 2 — ARQ dispatch forwards phone (TDD: RED then GREEN, commit ba6eecf2)
- `dispatch_fiscal_receipt`: snapshot `customer_phone = fr_row.customer_phone` inside the session block (alongside `customer_email`, before the session closes for the HTTP call); forward both to `create_receipt(...)` (Plan 07's `create_receipt` already routes to the present contact — email preferred). Multi-session pattern (T-51-05-08), never-flip-to-succeeded (D-51-13), retry/breaker logic all untouched.
- `fiscal_receipt_dispatched` audit emit now carries `customer_phone=fr_row.customer_phone` next to `customer_email` (audit DB only — PII-acceptable; not a structlog kwarg).
- Added phone-only dispatch scenario fixture (`seeded_dispatch_scenario_phone_only`, customer_email NULL + phone set) + `customer_phone` field on `SeededDispatchScenario`. 4 new tests: phone-only forwards `receipt.customer.phone` (and stashes receipt_id without flipping status), email regression forwards `receipt.customer.email`, audit row records both contacts, no phone leak to structlog.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Extended the locked `FiscalReceiptDispatchedPayload` audit schema**
- **Found during:** Task 2 (first GREEN run).
- **Issue:** The plan instructed adding `customer_phone=fr_row.customer_phone` to the `fiscal_receipt_dispatched` audit emit, but `FiscalReceiptDispatchedPayload` is a locked v1.4 audit schema with `model_config = ConfigDict(extra="forbid")` and `customer_email: str` (non-nullable). Both the new `customer_phone` key (extra input) and a phone-only row's `customer_email=None` tripped `schema.model_validate(payload)` in `audit.emit` (D-30-03 hard-fail), failing 10 dispatch/e2e tests.
- **Fix:** Relaxed the schema — `customer_email: str -> str | None = None`, added `customer_phone: str | None = None`, updated the docstring to document the email-OR-phone delivery contract. Re-ran the locked-audit-schema unit tests + phase51 audit-chain invariants (76 passed).
- **Files modified:** `apps/backend/app/core/audit_payloads.py`
- **Commit:** ba6eecf2

This was a correctness requirement, not optional: the plan's interface block did not list this schema, but the audit emit cannot succeed for a phone-only row without it.
