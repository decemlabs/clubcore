**1. [Rule 1 - Bug] hash_password is async — conftest fixture corrected**
- **Found during:** Task 2 RED (test setup failure — `coroutine 'hash_password' was never awaited`)
- **Issue:** The make_user conftest fixture called `hash_password("test_password")` synchronously; the function is async and returns a coroutine, not a string.
- **Fix:** Changed to `await hash_password("test_password")`.
- **Files modified:** apps/backend/tests/modules/client_portal/conftest.py
- **Commit:** cbe70354 (included in RED commit)

**2. [Rule 1 - Bug] User model field name is password_hash not hashed_password**
- **Found during:** Task 2 RED (test setup TypeError)
- **Issue:** Initial conftest used `hashed_password=...` which is not a valid SQLAlchemy column keyword for the User model.
- **Fix:** Changed to `password_hash=` and added `full_name=` (also required).
- **Files modified:** apps/backend/tests/modules/client_portal/conftest.py
- **Commit:** cbe70354 (included in RED commit)

**3. [Rule 1 - Bug] online_payments table schema mismatch in tests**
- **Found during:** Task 2 GREEN (test failure — `column "subject_kind" does not exist`)
- **Issue:** Initial payment-status tests used a simplified INSERT with `subject_kind` column, which does not exist in `online_payments`. The table uses `membership_plan_id` / `pt_package_plan_id` FKs + `yookassa_payment_id` + `confirmation_type` + `audit_correlation_id` (all required).
- **Fix:** Rewrote `_insert_online_payment` helper to create a real membership_plan row first (satisfies FK), then insert the online_payment row with all required columns.
- **Files modified:** apps/backend/tests/modules/client_portal/test_client_me_service.py
- **Commit:** 39ebb6af (included in GREEN commit — test update portion)
