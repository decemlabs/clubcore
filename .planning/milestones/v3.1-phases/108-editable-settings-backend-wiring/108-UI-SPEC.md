## Interaction & State Contracts

This section is the primary addition for a wiring phase. It defines the required UI states for
each of the four sections being wired, plus cross-cutting interaction contracts.

---

### Cross-Cutting: Owner-Gate (Lock Card)

**Applies to:** BranchSection, HoursSection, BookingSection, NotificationsSection — all four
sections in this phase are `Resource.SETTINGS` (edit), owner-only.

**Pattern (copy from TeamSection — established exemplar in `SectionsBottom.tsx:718-721`):**

```
{!can(role, 'edit', 'settings') ? (
  <EmptyState
    icon={Lock}
    title="Недостаточно прав"
    message="Этот раздел доступен только владельцу. Обратитесь к владельцу клуба."
    className="py-12"
  />
) : /* normal section body */ null}
```

Rules:
- Reception sees Lock card INSIDE `SectionCard` body — the card itself remains visible.
- Reception NEVER triggers any query for settings data (query `enabled` must be gated by
  `can(role, 'edit', 'settings')`).
- BranchSection (CFG-01) uses existing `Resource.GYM` + `Action.EDIT` — same Lock pattern,
  gate with `can(role, 'edit', 'gym')`.
- The SectionCard header (title, icon, desc) remains visible to reception; only the body
  is replaced with the Lock card.
- No 403 error toast for reception — the Lock is pre-emptive, not a response to an API error.

---

### Cross-Cutting: Global SaveBar + Per-Section Mutations

**Established contract (existing `SaveBar.tsx` + `SettingsContext`):**

- SaveBar appears at bottom when `dirty.size > 0`. Pill format, sticky bottom-4, z-20.
- "Сохранить" button: dispatches mutations for ALL dirty sections in parallel. On all
  mutations settled (success or error), clears dirty state for succeeded sections.
- "Отменить" button: resets forms to last-fetched server values, clears all dirty flags.
  Use react-hook-form `reset(serverData)` to restore.
- During save: SaveBar button shows "Сохраняем…" + `disabled` (existing `saving` state in
  `SaveBar.tsx`). Each section independently shows its own mutation pending state if needed
  (a subtle `Loader2` in the section header `action` slot is acceptable).
- Per-section mutation errors: Sonner `toast.error(...)` with retry instruction. Do NOT
  block the SaveBar from resetting dirty state for sections that succeeded.
- Per-section mutation success: Sonner `toast.success(...)` (e.g. "Карточка зала обновлена").

---

### Cross-Cutting: Unsaved-Changes Navigate-Away Guard

- When any section is dirty (`dirty.size > 0`) and the user navigates away (TanStack Router
  `beforeLeave` or equivalent), show a browser `confirm()` dialog or an `open('confirm', {...})`
  modal:
  - Title: "Выйти без сохранения?"
  - Message: "Есть несохранённые изменения. Если выйти — они будут потеряны."
  - Confirm label: "Выйти"
  - Cancel label: "Остаться"
  - Tone: neutral (not danger)
- If confirmed, abandon changes and navigate. If cancelled, stay on the page.
- The existing `markDirty` infra in `SettingsContext` supports this; connect via TanStack
  Router `shouldBlockNavigation` / `useBlocker`.

---

### Cross-Cutting: Loading State (Initial Data Fetch)

Each of the four sections fetches its own data via a TanStack Query hook. Use the established
pattern from `ProfileSection` and `SecuritySection`:

- **Pending:** Render `Skeleton` placeholders inside `SectionCard` body.
  - For form-heavy sections (BranchSection, BookingSection): 3–4 skeleton rows,
    `h-[38px] w-full rounded-[10px] bg-surface-3`.
  - For the matrix (NotificationsSection): skeleton rows `h-[36px] w-full rounded-lg bg-surface-3`
    × 7 (one per trigger).
  - For hours (HoursSection): 7 skeleton rows `h-8 w-full rounded-lg bg-surface-3`.

- **Error:** Inline error message with retry link:
  ```
  Не удалось загрузить настройки.{' '}
  <button onClick={() => void refetch()} className="font-semibold text-fg hover:underline">
    Повторить
  </button>
  ```

- **Success:** Form pre-populated from server data via `react-hook-form defaultValues`.

### CFG-01: BranchSection (Gym Card)

**Wiring target:** `PUT /api/v1/gym` (existing endpoint, `Resource.GYM`).

**Form fields (react-hook-form + Zod):**

| Field | Control | Validation |
|-------|---------|------------|
| Короткое название | `TextField` | required, max 40 chars |
| Полное название | `TextField` | required, max 120 chars |
| Адрес | `TextField` | required |
| Широта | `TextField` (inputMode numeric) | optional, float −90..90 |
| Долгота | `TextField` (inputMode numeric) | optional, float −180..180 |
| Телефон | `TextField` | optional, max 20 chars |
| Email | `TextField` (type email) | optional, valid email format |
| Описание | `TextArea` | optional, max 500 chars |
| Вместимость | `Stepper` | min 1 |
| Amenities chips | Chip list + add/remove | optional, array of strings |

**Interaction states:**

- Amenity chips: clicking an existing chip removes it (with `markDirty`). "+" button opens an
  inline `<input>` (or existing GhostBtn pattern) to type and add a new amenity on Enter/blur.
  No modal required.
- Capacity stepper: reads from server, writes back as integer.
- Character counter for description: live `{current} / 500 символов` below TextArea (existing
  hint pattern).

**Validation errors (422 field-error mapping):**

Display inline below the offending field as `<div className="mt-1 text-[11px] text-danger">` text.
- `name_short`: "Укажите название"
- `address`: "Укажите адрес"
- `latitude` / `longitude`: "Некорректные координаты"

**Success toast:** "Карточка зала обновлена"

### CFG-02: HoursSection (Working Hours, Breaks, Closures)

**Wiring target:** new endpoint (plan-phase determines path, e.g. `PUT /api/v1/gym/hours` or
`PATCH /api/v1/settings/hours`).

**Form structure:**

1. **Weekly schedule table** — 7 rows (Mon–Sun), each row:
   - Day name (label, highlighted in `text-primary-deep dark:text-primary` for Sat/Sun)
   - Open time `<input type="time">` (or text `hh:mm`, existing `h-8 w-[72px]` class)
   - Close time `<input type="time">`
   - "Закрыто" toggle (when on, open/close inputs are disabled, opacity-50)
   - Trash button to mark day as closed (existing `hover:bg-danger-soft hover:text-danger`)

2. **Technical breaks** — chip list with `tone="warn"`. Each chip is clickable to remove.
   "+" button opens an inline mini-form (start time, end time, label, repeat: daily/specific day)
   rendered inline (no modal needed for this phase — a simple collapsed row is acceptable).

3. **Holidays / closures** — chip list (`tone="neutral"` for reduced hours, `tone="warn"` for
   full closure). Each chip clickable to remove. "+" button opens an inline date-picker row
   (date input + optional hours override + closure toggle).

**Validation:**
- Close time must be after open time for each day (Zod `.refine()`).
- Break times must fall within the day's open/close window.
- No date-picker library required: use `<input type="date">` and `<input type="time">` native
  inputs styled with the existing `h-8 rounded-lg border-[0.5px] border-border-strong bg-surface-2`
  class.

**Success toast:** "График работы обновлён"

**Validation error toast (non-field):** "Проверьте корректность времени в графике работы"

### CFG-03: BookingSection (Online Booking Rules)

**Wiring target:** new endpoint (e.g. `PUT /api/v1/settings/booking`).

**Form fields (all existing controls — no new components needed):**

| Field | Control | Notes |
|-------|---------|-------|
| Шаг расписания | `RadioGroup` | Options: "15 мин", "30 мин", "60 мин", "90 мин" |
| Окно записи вперёд | `Stepper` unit="дней" | min 1, max 365 |
| Закрытие записи | `Stepper` unit="минут" | min 0, max 1440 |
| Бесплатная отмена за N часов | `Toggle` + `Stepper` unit="ч." (shown when toggle on) | Stepper min 1 |
| Перенос в пределах суток | `Toggle` | |
| Штраф за неявку | `Toggle` + `MoneyField` suffix="₽" (shown when toggle on) | Value in kopecks internally; display/edit in rubles |
| Лимит участников группового | `Stepper` unit="чел." | min 1 |
| Лист ожидания | `Stepper` unit="чел." | min 0 |
| Авто-перенос из вейтлиста | `Toggle` | |
| Самозапись клиента к тренеру | `Toggle` | |
| Показывать пустые окна тренеров | `Toggle` | |

**Conditional visibility:** No-show penalty `MoneyField` only renders when the штраф toggle is on
(control with `useState` local to the BookingSection or react-hook-form `watch`).

**Validation:**
- Booking window ≥ 1 day.
- Cutoff window ≥ 0 minutes, ≤ 1440 minutes.
- No-show penalty ≥ 0 kopecks when enabled (entered as rubles, multiply × 100 before POST).

**Success toast:** "Правила записи обновлены"

### CFG-04: NotificationsSection (Notification Matrix)

**Wiring target:** new endpoint (e.g. `PUT /api/v1/settings/notifications`).

**Matrix layout (existing grid — do not change):**

```
MATRIX_COLS = 'grid grid-cols-[minmax(0,1fr)_56px_56px_56px_56px] items-center gap-2'
```

- Column headers: Push (Bell), Email (Mail), SMS (MessageSquare), TG-бот (Send)
- Each row = one notification trigger (7 triggers from dispatcher `NotificationKind` enum)
- Each cell = `Toggle` (controlled, from react-hook-form) OR `Switch` (for always-on rows)

**Always-on triggers (non-disablable):**

Triggers for payment failure and security notifications MUST render as disabled `Toggle` locked to
`on`. Visual: `opacity-65` + `disabled` attribute on the toggle button. Hint below the matrix row:
"Нельзя отключить — требуется по правилам платёжных систем."

These rows use `disabled` prop on `Toggle` (already supported by `controls.tsx:Toggle`).

**Channels rendered:** Only channels the dispatcher actually supports. Plan-phase grounds the exact
channel list against `notifications/service.py`. This contract assumes 4 channels (Push, Email, SMS,
TG-бот) matching the existing stub — plan-phase may reduce to fewer if channels are not implemented.

**Sender signature field:**

- `TextField` bound to react-hook-form.
- Max 11 characters (Latin), uppercase enforced via `onChange` `toUpperCase()`.
- Helper text: "до 11 латинских символов · зарегистрирован в МТС, МегаФон, Билайн, Т2"
- Note: signature appended to Telegram and email outbound messages only, NOT in-app notifications.

**Quiet hours fields:**

- Two time inputs `h-8 w-[72px]` styled with existing `border-[0.5px] border-border-strong bg-surface-2`.
- Label: `<input type="time">` (or `hh:mm` text), Europe/Moscow timezone label next to them.
- Helper text: "По московскому времени. В тихие часы срочные уведомления не подавляются."
- Validation: start ≠ end; no max/min constraint (a quiet window can cross midnight).

**Success toast:** "Настройки уведомлений обновлены"
