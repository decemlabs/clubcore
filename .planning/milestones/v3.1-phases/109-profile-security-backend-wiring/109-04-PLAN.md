## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-17 | Information Disclosure | password fields | mitigate | Task 1: all three inputs are `type="password"` (masked); fields reset on modal close (setTimeout pattern) so they don't linger in state |
| T-109-18 | Tampering | client-only validation bypass | accept | Client zod is UX-only; the backend (Plans 01/02) is the authority — 12-char floor + email uniqueness + current-pw verify are all re-checked server-side |
| T-109-19 | Spoofing | wrong-current-password feedback | mitigate | Task 1 maps the backend InvalidPassword error to a generic inline "Неверный текущий пароль" (no oracle beyond what the backend already returns) |
| T-109-20 | Denial of Service (self-lockout) | self password change | mitigate | Backend keeps the current family alive; the checkpoint step 5 verifies THIS session stays logged in (no redirect) after the change |
| T-109-21 | Information Disclosure | stale identity in sidebar | mitigate | Task 2: useUpdateProfile invalidates authKeys.me so the displayed identity matches the server (verified in checkpoint step 1) |
| T-109-SC | Tampering | npm/pip/cargo installs | accept | No new packages — all UI primitives (AdaptiveModal/ModalButton/IconChip/SaveBar) already exist; react-hook-form is NOT introduced (D-101-01-NOHOOKFORM) |
