## Interaction & State Contracts

### A. ProfileSection — Idle → Dirty → Saving → Success / Error

This section currently reads `useSession()` and is fully read-only (D-104-04-PROFILE-READONLY).
Phase 109 makes `full_name` and `email` inline-editable via `PATCH /api/v1/auth/me`.

#### States

| State | Visual Indicator | User Action |
|-------|-----------------|-------------|
| **Idle (clean)** | Fields rendered in read-only style; no SaveBar pulse; SectionCard desc: "Личные данные. Имя и email можно изменить." | — |
| **Dirty** | Input borders active (`focus:border-fg-subtle`); SaveBar appears at bottom of page with animated pulse dot; SectionCard desc unchanged | User edits full_name or email input |
| **Saving** | SaveBar shows "Сохраняем…", disabled; inputs remain editable | SaveBar "Сохранить" clicked |
| **Success** | SaveBar disappears; Sonner toast: "Профиль обновлён" (success); `authKeys.me` query invalidated → header/sidebar reflects new full_name | Server returns 200 `MeResponse` |
| **Error — network/server** | SaveBar stays visible; Sonner toast: "Не удалось сохранить. Попробуйте ещё раз." | Server returns 5xx |
| **Error — email taken (422/409)** | SaveBar stays visible; inline field error below email input: "Email уже занят" | Server returns 422 with field error `email` |
| **Cancel** | Form reverts to server snapshot (`serverDataRef.current`); field errors cleared; SaveBar disappears | SaveBar "Отменить" clicked |

#### Field Contract

| Field | Input Type | Validation | Placeholder |
|-------|-----------|-----------|-------------|
| `full_name` | `<input type="text">` | min 2 chars (client), required | "Имя и фамилия" |
| `email` | `<input type="email">` | RFC email regex (client), uniqueness (server 422) | "email@example.com" |

- Theme toggle (`ThemeToggle`) remains on its own `SettingRow` below the editable fields — unchanged from Phase 104.
- `full_name` field does NOT accept the value as the label for the `Initials` avatar until after successful save + query invalidation.
- SectionCard `id` stays `'profile'` — matches existing SaveBar `markDirty(ID_PROFILE)` mechanism.
- `registerSave` / `registerCancel` props added to `ProfileSection` (same signature as `BranchSection`).

#### SaveBar Integration

Follows the `BranchSection` pattern exactly:
- `registerSave` → `handleSave()` (calls `PATCH /api/v1/auth/me`, invalidates `authKeys.me` on success)
- `registerCancel` → `handleCancel()` (resets form to `serverDataRef.current`, clears field errors)
- `markDirty(ID_PROFILE)` called on any input change
- SaveBar count increments when section is dirty; decrements when saved/cancelled

### B. SecuritySection — Password-Change Modal

The existing `SecuritySection` has a read-only `GhostBtn` labelled "Сменить пароль" (line 237).
Phase 109 wires this button to open a `ChangePasswordModal` (new component, not InviteModal — separate concern).

#### Modal: ChangePasswordModal

- **Component:** `ChangePasswordModal` (new, in `pages/settings/components/` or `features/auth/components/`)
- **Pattern:** Mirrors `InviteModal` — uses `AdaptiveModal` + `IconChip` + `ModalButton` + `FIELD` class
- **Trigger:** `GhostBtn` "Сменить пароль" in SecuritySection's first `SettingRow`
- **Icon:** `<IconChip tone="accent" icon={Lock} />` (Lock icon, accent tone)
- **Title:** "Сменить пароль"
- **Description:** "Введите текущий пароль и новый пароль (не менее 12 символов)."

#### Modal States

| State | Visual |
|-------|--------|
| **Form (initial)** | Three inputs: current password, new password, confirm new password; all password type; submit button disabled until all fields non-empty and new == confirm and new.length >= 12 |
| **Submitting** | Submit button shows "Сохраняем…" + disabled; inputs remain visible but not re-triggerable |
| **Success** | Modal closes (onOpenChange(false)); Sonner toast: "Пароль изменён. Другие сессии завершены."; sessions list refetched (`sessionsKeys.list`) |
| **Error — wrong current password** | Modal stays open; inline field error on current-password input: "Неверный текущий пароль"; submit button re-enabled |
| **Error — new password too short** | Client-side inline error below new-password input: "Пароль должен содержать не менее 12 символов" |
| **Error — confirm mismatch** | Client-side inline error below confirm input: "Пароли не совпадают" |
| **Error — server/network** | Modal stays open; Sonner toast: "Не удалось изменить пароль. Попробуйте ещё раз." |
| **Close** | Modal resets all fields + errors when reopened (same as InviteModal setTimeout reset pattern) |

#### Modal Field Contract

| Field | Input Type | Validation | Placeholder |
|-------|-----------|-----------|-------------|
| Текущий пароль | `<input type="password">` | required; server verifies | "Текущий пароль" |
| Новый пароль | `<input type="password">` | min 12 chars (client + server NIST floor) | "Новый пароль (не менее 12 символов)" |
| Подтвердите пароль | `<input type="password">` | must equal new password | "Повторите новый пароль" |

#### Modal Footer Actions

```
[Отмена (ghost)]    [Сменить пароль (primary, disabled when invalid/submitting)]
```

- `ModalButton variant="ghost"` → calls `onClose()`
- `ModalButton variant="primary"` (or `PrimaryBtn`) → calls `handleSubmit()`

#### Post-Submit Behaviour

- On 204: close modal + `toast.success('Пароль изменён. Другие сессии завершены.')` + invalidate `sessionsKeys.list` so the reduced session count appears in the SecuritySection sessions list.
- The current device session is NOT revoked — user stays logged in.
- The "Сменить пароль" `GhostBtn` hint text updated to show last-change info (deferred — can remain static "Последняя смена — …" in this phase).
