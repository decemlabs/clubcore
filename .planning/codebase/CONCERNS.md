## Structural

### 🔴 Empty `backend/` directory

`/Users/andre/Workspace/Development/clubcore/backend/` exists at the repo root but contains zero files (no manifest, no README). This is the most surprising thing about the repo today.

- **Risk:** New contributors will assume there's a backend to run, an out-of-tree script will scan it, or a future migration will accidentally write over a stub.
- **Recommendation:** Decide explicitly. Either (a) delete the directory until a real backend is added, (b) add a stub `backend/README.md` documenting the placeholder + the v1 frontend-only stance, or (c) move the frontend to repo root and drop the two-folder layout.

There's a `frontend/README.md` and a `frontend/CLAUDE.md`, but the repo root has nothing. Anyone landing on `/Users/andre/Workspace/Development/clubcore/` directly has no orientation.

- **Recommendation:** Add a root README pointing at `frontend/` (and the empty backend decision once made).

## Type Safety

### 🟡 `@ts-nocheck` on the auto-generated route tree

`src/routeTree.gen.ts` opens with `// @ts-nocheck`. This is generated by `tanstackRouter` so it's not a project bug, but the file is non-trivial and any TypeScript regression in route definitions will not surface until runtime.

- **Mitigation:** TanStack Router's compile-time route types still flow through `Register` declaration in `src/app/router.ts:23-27`, so most type-safety is preserved.
- **Recommendation:** Track upstream issue in `@tanstack/router-plugin` for a typed regen path; revisit each minor bump.

### 🟢 No branded ID types yet

`CLAUDE.md` mandates branded UUIDv4 ID types (`type ClientId = Brand<string, 'ClientId'>`) but no `entities/<entity>/` folder exists yet — domain entities haven't been introduced.

- **When to fix:** Phase 2 entity scaffolding.

## Testing

8 test files for ~3 K lines of source. Coverage is concentrated in pure utilities (`money`, `plural`, `date`, `can`) and stores. Almost nothing exercises:

- `AppShell`, `Header`, `Sidebar`, `ProfileMenu`, `RoleSwitcher`, `NotificationsBell`, `ThemeSwitcher` (`src/shared/ui/app-shell/`).
- Route-level `beforeLoad` redirects (`src/routes/clients.tsx`, `staff.tsx`, `finance.tsx`, `schedule.tsx`, `settings.tsx`).
- `RoleGate.tsx` integration with components.
- `ThemeProvider` flicker behavior across re-mounts.

- **Recommendation:** Once Phase 2 introduces the first feature, add component-level tests for the shell and at least one happy-path route loader test using `createMemoryHistory()` from TanStack Router.

### 🟡 No coverage instrumentation

No `@vitest/coverage-*` provider installed; no `test:coverage` script. We literally cannot tell coverage trends today.

- **Recommendation:** Add `@vitest/coverage-v8` and a `pnpm test:coverage` script before features start landing, so subsequent phases can be measured.

### 🟢 No E2E layer

Expected for this phase. Plan for Playwright (or equivalent) once the first real feature ships.

## Security

### 🟡 CSP uses `'unsafe-inline'`

`frontend/index.html` includes:

```html
<!-- TODO Phase 7: replace 'unsafe-inline' with nonce/hash for the bootstrap script -->
<meta http-equiv="Content-Security-Policy"
      content="... script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; ..." />
```

The blocking inline `<script>` in `<head>` reads `localStorage['sportzal:ui:v1']` to apply the dark class before React mounts. `'unsafe-inline'` is required as long as that script is inline.

- **Mitigation:** The TODO is already tagged for Phase 7 (productionization). The script reads only its own storage key and does not interpolate user data, so XSS surface is minimal.
- **Recommendation:** When Phase 7 lands, replace with a per-build nonce or move to a hashed inline script (Vite plugin `vite-plugin-csp-guard` or similar).

### 🟡 No HTTP service / token handling stubs

`src/shared/api/services/http/index.ts` is an empty placeholder. The auth + token storage / refresh / 401 redirect strategy is not designed yet. This is fine while v1 stays mock-only, but several decisions (where the token lives, how the swap seam exposes it to mocks for parity, how `useSession()` learns about expiry) will need to be made together.

- **When to fix:** Before Phase 7 (HTTP integration). Best discussed during Phase 6 planning so the contracts don't have to be re-shaped later.

### 🟢 No XSS / input-validation surface yet

Expected — there are no forms, no user-generated content rendering, no dangerously-set HTML. `react/no-danger` is intentionally `off` in ESLint (`eslint.config.js:84`) but that's a lint allow-list, not real risk yet.

- **When to revisit:** Phase 2 (forms) and Phase 3 (rich text / notes fields if any).

## Performance

### 🟡 Bundle size warning likely as features grow

Phase 1 already pulls in TanStack Router, Query, Table, Radix primitives, Lucide, Sonner, react-hook-form, Zod, date-fns, Faker (via mock services), Zustand. The base bundle is non-trivial before any feature code lands.

- **Recommendation:** When the first features arrive, audit:
  - Code-splitting: TanStack Router has `autoCodeSplitting: true` in `vite.config.ts` — verify each route lands in its own chunk.
  - Tree-shaking the swap seam: ensure prod builds don't ship the unused `services/mock` branch when `VITE_API_MODE=http`.
  - Faker is dev-time only — confirm it doesn't slip into prod bundles.

### 🟢 React 19 strict mode + persisted store rehydrate

`src/app/main.tsx` `await`s persistence rehydrate for both stores before render. Good — avoids a flash of `role: undefined` content. Worth re-checking when adding more persisted stores so the await list doesn't grow unboundedly.

## Architecture Drift Risks

### 🟢 Per-feature `xKeys` factories not yet defined

`CLAUDE.md` mandates them but no feature exists yet to host one. Without an example, the first contributor in Phase 2 might omit it.

- **Recommendation:** Provide a `clientsKeys` reference factory the moment the clients module starts so the convention has a concrete anchor.

### 🟢 Mock services container is empty

`src/shared/api/services/mock/index.ts` exports `services = {} as const`. The contract (latency 120–300 ms, configurable failure rate, role enforcement, `faker.seed(42)`, versioned `sportzal:mock:v1` localStorage DB) lives in `CLAUDE.md` only. Until at least one mock service exists, that contract is not exercised.

- **Recommendation:** Land the first mock service end-to-end (clients) including latency and role enforcement, so the contract becomes copy-pasteable.

### 🟢 Placeholder routes

`src/routes/{clients,staff,schedule,finance,settings}.tsx` are placeholders with role guards but no real content. Expected through Phase 2/3 — flagged so the placeholder pattern doesn't accidentally become permanent.
