# REV-01 — Revoke pending invitation (Variant B)

**Root cause:** FE sends no body (422) and passes `user.id` instead of the
`password_reset_tokens.id` row id, which the list never exposes. **Fix:** expose the token
row id in `GET /users` (completes the D-43-19 design), then have the FE pass it + a body.

The revoke endpoint, service, audit, RBAC, and DB schema are **NOT touched** — no migration.

---

## Task 1 — Backend: expose `invitationTokenId` in the users list

**files:**
- `apps/backend/app/modules/users/schemas.py`
- `apps/backend/app/modules/users/repository.py`

**action:**
1. In `schemas.py`, add to `UserListItemResponse` (beside `invitation_expires_at`):
   ```python
   invitation_token_id: UUID | None = None
   ```
   (`UUID` is already imported. camelCase alias → wire `invitationTokenId` automatically.)
2. In `repository.list_alive`, change the `invitation_subq` to also carry the token id.
   Because the partial unique `(user_id, purpose) WHERE consumed_at IS NULL` (D-41-05)
   guarantees **≤1 active invitation per user**, drop the `func.max(...)`/`group_by`
   aggregation and select the row directly:
   ```python
   invitation_subq = (
       select(
           PasswordResetToken.user_id.label("u_id"),
           PasswordResetToken.id.label("inv_token_id"),
           PasswordResetToken.expires_at.label("inv_expires_at"),
       )
       .where(
           PasswordResetToken.purpose == "invitation",
           PasswordResetToken.consumed_at.is_(None),
           PasswordResetToken.expires_at > now,
       )
       .subquery()
   )

   stmt = select(
       User, invitation_subq.c.inv_token_id, invitation_subq.c.inv_expires_at
   ).outerjoin(invitation_subq, invitation_subq.c.u_id == User.id)
   ```
   Update the row-unpack loop to `for user_row, inv_token_id, inv_expires_at in rows:` and
   pass `invitation_token_id=inv_token_id` into `UserListItemResponse(...)`. Update the
   docstring note about the join (no longer aggregated; relies on the partial unique).

**verify:** `cd apps/backend && uv run ruff check app && uv run mypy app`

**done:** mypy + ruff clean; `UserListItemResponse` has `invitation_token_id`; `list_alive`
selects and maps the token id.

## Task 3 — Frontend: pass the token id + send a body on revoke

- `apps/admin-app/src/features/users/schemas.ts`
- `apps/admin-app/src/features/users/api.ts`
- `apps/admin-app/src/pages/settings/components/SectionsBottom.tsx`

**action:**
1. `schemas.ts` — add to `UserSchema`: `invitationTokenId: z.string().nullable().optional(),`
   (Zod strips unknown keys, so this opts the field into `UserData`. Null for
   active/deactivated rows.)
2. `api.ts` `useRevokeInvitation` — change the mutation input to carry the token id + reason
   and send a JSON body:
   ```ts
   mutationFn: ({ tokenId, reason }: { tokenId: string; reason?: string }) =>
     staffRequest('post', '/api/v1/users/invitations/{token_id}/revoke', {
       params: { token_id: tokenId },
       body: { reason: reason ?? null },
     }),
   ```
   Keep the `onSettled` list invalidation. Update the JSDoc (now sends a body + token row id).
3. `SectionsBottom.tsx` — in the `pending_invitation` branch `onConfirm`, replace the
   `revokeInv.mutate(user.id, …)` call (and drop the stale
   `// tokenId = user.id for pending_invitation rows` comment) with:
   ```ts
   onConfirm: () => {
     if (!user.invitationTokenId) {
       toast.error('Не удалось определить приглашение. Обновите страницу.');
       return;
     }
     revokeInv.mutate(
       { tokenId: user.invitationTokenId, reason: 'Отозвано владельцем' },
       { onError: () => toast.error('Не удалось выполнить действие. Попробуйте ещё раз.') },
   ```
