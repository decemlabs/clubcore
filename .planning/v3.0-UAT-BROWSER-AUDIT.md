# v3.0 — Automated Browser UAT Audit

**Date:** 2026-06-14
**Scope:** Full automated browser run of the ~31 deferred *live-browser* UAT items across phases 100–104 (`apps/admin-app` wired to the real backend).
**Method:** Brought up the full docker stack (Postgres+Redis+S3+FastAPI), reseeded the DB, ran the `admin-app` dev server on `:5173`, drove Chrome (chrome-devtools MCP) as **owner** and **reception**, inspected network + console + Zod parse paths, and root-caused failures against source.

> **Headline:** The formal v3.0 gate (30/30 requirements, 7/7 phases) passed on **unit tests + source review + integration checks**. This live run — the explicitly-deferred step — found that **a large share of the wired screens break against real backend data**. The unit tests used mock fixtures whose shapes diverge from the real API, so the frontend Zod contracts were never validated against live responses. **8 distinct bugs** (7 contract/parse + 1 optimistic-update crash), one systemic money-formatting bug, and one structural gap (membership lifecycle unreachable) were confirmed.

## Bug details (root-caused)

### BUG-1 — clients `telegramUserId` int vs string (HIGH)
- Backend `app/modules/clients/models.py:100`: `telegram_user_id: Mapped[int | None]` → serialized as JSON **number**.
- Frontend `apps/admin-app/src/features/clients/schemas.ts:33`: `telegramUserId: z.string().nullable().optional()`.
- A number fails `z.string()` → `z.array(ClientSchema)` throws → **entire clients list PageErrors** (and client detail, which also returns `telegramUserId`).
- **Proof:** nulling the seeded client's `telegram_user_id` made the list render immediately; restoring it re-breaks the list.
- **Fix:** `telegramUserId: z.union([z.string(), z.number()]).nullable().optional()` (or coerce). Same field appears in detail responses.

### BUG-2 — membership response shape (HIGH)
- Backend membership = flat: `planNameSnapshot, durationDaysSnapshot, priceKopecksSnapshot, freezeDaysLimitSnapshot, …`.
- Frontend `features/memberships/schemas.ts:37-38` requires nested `planSnapshot: MembershipPlanSchema` + `paidAmountKopecks` — both absent → parse throws.
- **Effect:** client-detail memberships card PageErrors as soon as the client has any membership. (Per-section isolation works — the tabs below still render.)
- **Fix:** align schema to flat wire shape (`planNameSnapshot`/`priceKopecksSnapshot`) or have the backend nest + rename.

### BUG-3 — `formatRub(kopecks)` 100× (HIGH, systemic but scoped)
- `lib/format.ts:4-12`: `RUB = Intl.NumberFormat('ru-RU',{currency:'RUB',maximumFractionDigits:0})`; `formatRub(v)=RUB.format(v)` — **no /100**.
- 14 call sites pass `*Kopecks` directly: `PlansPage.tsx:84,161` (**visually confirmed**: 5 000 ₽ → "500 000 ₽"), `ClientPage.tsx:116`, `PaymentsTab.tsx:63`, `TrainingsTab.tsx:71`, `SubscriptionModal.tsx` (×4), `memberships/api.ts:91`.
- **Not universal:** Cashbox renders 5 000 ₽ **correctly** (different path), so the bug is confined to the `formatRub(*Kopecks)` callers. Mocks used pre-divided ruble strings (`priceBig:'4 900'`), hiding it pre-wiring.
- **Fix:** divide by 100 at the call sites, or add `formatKopecks()`.

### BUG-4 — Schedule `trainerId=undefined` → 422 (HIGH)
- On load the schedule fires `GET /trainer-slots?trainerId=undefined&fromTime=…&toTime=…` → backend 422 → page PageErrors. Reproduced **with a trainer present**, so it's a default-selection defect, not empty-data.
- **Fix:** default-select the first active trainer (or omit the param) before issuing the slots query; handle the no-trainers empty state.

### BUG-5 — reports revenue/trainers schema (HIGH)
- `features/reports/schemas.ts:53`: `bySubjectKind: { membership, pt_package }` (snake) vs real `{ membership, ptPackage }` (camel).
- `:86-98`: `data.rows[]` with `name/uniqueClients/utilizationPct:number/totalRevenueKopecks` vs real `data.trainers[]` with `trainerNameSnapshot/uniqueClientCount/utilizationPct:null/revenueKopecks`.
- **Effect:** Reports page (default Выручка tab) **and** Finance page crash once revenue exists; dashboard "Выручка за 30 дней" / "Топ тренеры" silently show "Нет данных" despite real data. (Empty arrays parsed, which is why the dashboard worked pre-sale.)
- **Fix:** align field names/casing/nullability; allow `utilizationPct` null.

### BUG-6 — audit-log null actor fields (HIGH)
- `features/audit/schemas.ts:15-16`: `actorUserId: z.string()`, `actorEmailSnapshot: z.string()` (non-nullable).
- Real rows: `login_success` → `actorEmailSnapshot:null`; `loyalty_accrued` (system) → both null. → Журнал действий PageErrors basically always.
- **Fix:** `.nullable()` on both.

### BUG-7 — sessions `userAgent` null (MED-HIGH)
- `features/settings/schemas.ts:19`: `userAgent: z.string()` vs real `userAgent: null` → Active Sessions widget errors (blocks revoke / self-revoke UAT).
- **Fix:** `userAgent: z.string().nullable()`.

### BUG-8 — check-in optimistic onMutate crash (HIGH)
- `features/visits/keys.ts:33`: `meta() = [...all, '_meta']` (under `visitsKeys.all`).
- `features/visits/api.ts:131-152` `useCheckIn.onMutate`: `getQueriesData({queryKey: visitsKeys.all})` also matches the gym-meta query; the loop does `{...data, items:[optimisticRow, ...data.items]}` — meta `data` has no `.items` → **TypeError before mutationFn**.
- **Proof:** backend logs show the UI's "Отметить визит" clicks fired **zero** POSTs; only a direct API POST created a visit (201). UI always shows generic "Не удалось выполнить чек-ин".
- **Fix:** skip non-list entries: `if (!data || !Array.isArray(data.items)) continue;` (or scope to `visitsKeys.lists()` + `byClient`).

### GAP-1 — membership lifecycle has no reachable UI trigger (HIGH, structural)
- `SubscriptionModal` (sell/freeze/renew/cancel/refund) is real + unit-tested, backend works (`POST /memberships` + Idempotency-Key → 201 verified).
- But the only openers are: `ProfileSide.tsx` (**referenced nowhere** — dead), mock `ProfileHero.tsx` (**not rendered**; `ProfileHeroReal` is), and `messages/ClientPanel.tsx` (Messages is **removed from nav** — `nav-items.ts:22` — and uses mock data).
- The live client page (`ProfileHeroReal` + read-only `MembershipsSection`) offers **no** way to sell/freeze/renew/cancel/refund.
- **Effect:** UAT items #6 (sell + Idempotency-Key), #7 (freeze optimistic), #8 (refund), and the owner-positive side of #9 (cancel) are untestable via UI.

## What PASSED (live-validated)

- **P100 login round-trip + 401→refresh→retry** — POST `/auth/login` 200 → `/auth/me` 200; pre-login `me`→401→`refresh`→redirect chain observed; and a **15-min access-token expiry auto-refresh** (`me`→401→`refresh`→200→retry) caught live mid-session.
- **Clients list / server search (`q=`) / pagination envelope / create (happy path)** — PASS (once telegram int issue avoided). "Клиент добавлен" toast, server-side `q` filtering, `{total,page,pageSize}` controls.
- **Client detail per-tab loading + error isolation** — `/clients/{id}`, `/memberships?clientId=`, `/visits?clientId=`, `/payments/by-client/{id}` each load independently; one section erroring (memberships, BUG-2) does not take down the tabs.
- **Cashbox** — real data, money correct (sale shows +5 000 ₽; Приход/Нетто correct; Возвраты column present).
- **Attendance / Load** — render, clean empty states, **no NaN** ("0.0 визитов") — satisfies P103 "Load no-NaN".
- **Trainers list / Users list / Settings profile (read-only)** — render + parse correctly.
- **RBAC (CISO-01) — strong PASS:**
  - Reception nav correctly hides owner-only items (Касса, Отчёты, Финансы, Загруженность, Журнал, Настройки).
  - Reception dashboard fires **zero** owner-only calls (only `bookings` + `memberships?expiring`; no `reports/*`).
  - Direct URL to `/finance` as reception → Lock state "Недостаточно прав", **zero** finance/report calls (route-guarded before any request).
  - Plans as reception → Lock state (no CRUD).
  - Client delete correctly gated: reception Edit-client modal has **no Delete** button.

## Recommended priority

1. **One PR fixes most of it.** BUG-1/2/5/6/7 are all the same class — frontend Zod contracts that don't match real wire shapes (nullability, casing, field names, nesting, int-vs-string). A schema-vs-OpenAPI reconciliation pass closes 5 of the 8.
2. **BUG-8** (check-in onMutate guard) — 1-line fix, unblocks all of P103 check-in.
3. **BUG-3** (money /100) — high user-visible impact; mechanical.
4. **BUG-4** (schedule default trainer) — unblocks P102.
5. **GAP-1** (wire a sell/lifecycle entry point on the live client page) — larger; product decision.
6. **UX-1** (localize `phone_exists` + map to inline field error).

**Process note:** these all slipped because unit tests asserted against mock fixtures, not real responses. Add at least one integration test per domain that parses a *real* backend response (or contract-tests the Zod schemas against the OpenAPI spec) so mock/real divergence is caught in CI.
