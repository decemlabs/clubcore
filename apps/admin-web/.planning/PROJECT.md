# SportZal Adminka

## What This Is

Админ-панель (CRM) для управления тренажёрным залом: клиенты и абонементы, расписание, тренеры, финансы, дашборд, уведомления. Фронтенд на React + shadcn/ui + reui.io, работает полностью на мок-данных — фундамент под будущий реальный продукт, к которому позже подключат бэкенд.

## Core Value

Владелец зала и ресепшн видят цельный, готовый к ежедневной работе интерфейс управления залом — так, что архитектуру можно показать и продавать как MVP, а позже подключить к нему настоящий API без переписывания UI.

## Context

- Продукт задумывается как будущая коммерческая CRM для залов; текущий этап — показать работающий UI-фундамент.
- Стек жёстко задан пользователем: React + shadcn/ui + reui.io. Это влияет на выбор компонентов и подход к темам.
- Фронт должен жить на моках, но структура слоя данных (типы, сервисы, хуки) должна быть такой, чтобы замена мока на реальный API была локальной правкой.
- Две роли, но без настоящего auth: переключатель ролей в UI должен скрывать/показывать разделы и действия.
- Язык общения с пользователем — русский, документация GSD — на английском.

## Constraints

- **Tech stack**: React + shadcn/ui + reui.io — зафиксировано пользователем.
- **Data**: Только мок-данные, без backend-вызовов — фронт должен полностью работать оффлайн.
- **Локализация**: RU-only для v1 — i18n-инфраструктуру не тянем.
- **Auth**: Login-экрана нет — роль переключается прямо в UI как dev-переключатель.
- **Архитектура**: Data-слой изолирован от UI, чтобы замена моков на реальный API была безболезненной.
- **Темы**: Обязательно light + dark с переключателем — через shadcn/reui theming.
